# Chrome-Remote-Desktop 학습 로드맵

**생성일**: 2026-09-20
**방법론**: VibeLearn AI
**버전**: 1.0

---

## 📚 학습 개요

### Topic 소개

구글 Chrome Remote Desktop 으로 외부에서 집 컴퓨터에 접속해 실제 작업 환경을 운영하는 방법을 배우고, 직접 설치·설정·실사용까지 한 뒤, 그 과정을 한국어 공익 안내 영상 1편으로 만든다.

**대상은 모든 사용자.** 기준선은 「IT 지식이 없는 일반인」에 맞춘다 — 시민단체 실무자·시니어를 포함한 보통 사람 누구나가 산출물과 영상만 보고 혼자 설치하고 안전하게 쓸 수 있어야 한다.

### 이 Topic 의 두 가지 목적

1. **집을 비워도 작업 환경을 쓴다** — 방송·영상 제작(OBS · Remotion · 볼트)
2. **밖에서도 AI 작업을 이어 간다** — AI 와 일하는 시간의 상당 부분이 「AI 가 한 일을 리뷰하고 승인 여부를 정하는 것」이다. 그 일은 컴퓨터 앞에 앉아 있을 필요가 없다. 원격으로 결과를 보고 승인·수정 지시만 하면 작업이 계속 돈다.

> 둘째 목적의 검증 기준은 「화면이 보이나」가 아니라 **「AI 작업 한 바퀴가 도나」**다.

### 학습 목표

- [ ] Chrome Remote Desktop 이 무엇이고 언제 쓰는지, 다른 원격 접속 방식과 무엇이 다른지 설명할 수 있다
- [ ] 호스트(집에 켜 둘 컴퓨터)와 클라이언트(밖에서 쓰는 기기) 양쪽을 직접 설치·로그인·연결할 수 있다
- [ ] 외부 기기에서 집 컴퓨터에 접속해 실제 작업(볼트 편집 · OBS 확인 · 파일 열기)을 수행할 수 있다
- [ ] 밖에서 AI 작업을 리뷰·승인할 수 있다 — 결과물 확인 → 승인/수정 지시 → 다음 작업 진행까지 한 바퀴를 원격으로 (폰·태블릿의 작은 화면에서도)
- [ ] PIN·세션 종료·잠금 화면·절전·공유 권한을 포함한 보안 점검 항목을 스스로 점검하고 기록할 수 있다
- [ ] 무료·안전한 대안을 최소 1개 실제로 설치·접속해 두어, CRD 에 문제가 생기면 바로 갈아탈 수 있다
- [ ] Grok Bot 같은 「AI 전용 클라우드 컴퓨터」 방식이 내 방식과 무엇이 다른지, 언제 그쪽이 나은지 설명할 수 있다
- [ ] 설치·사용·보안 확인 과정을 한국어 공익 안내 영상 1편으로 만들어 공개할 수 있다
- [ ] 산출물과 영상이 IT 지식이 없는 사람도 그대로 따라 할 수 있는지 스스로 점검할 수 있다

### 예상 학습 기간

**2주 (2026-09-20 ~ 2026-10-04)**, 주당 5~6시간 · 총 약 13.5시간
(사용자 결정 2026-09-20: 「범위 조정」 — 기간은 2주 유지, 대안 비교를 실제 설치까지 넓혀 7모듈)

### 학습 환경

- **OS**: Windows 11 Home (호스트 = 집 데스크톱, i7-1355U · 16GB · GPU 없음)
- **접속 기기**: iPad · Android 폰 · 노트북
- **도구**: Chrome + Chrome Remote Desktop 호스트 · 모바일 앱 · Google 계정(2단계 인증) · Windows 전원·잠금 설정 · OBS 32.2 · Remotion Studio · Obsidian 볼트 · Remotion + edge-tts(영상)
- **사전 지식**: Windows 설정 변경 경험 · Google 2단계 인증 사용 경험 (권장: 공유기 기본 개념 · Remotion 제작 흐름)

### 🔴 모든 모듈에 적용되는 전달 기준

| 지킬 것 | 어떻게 |
|---|---|
| 용어를 쓰면 그 자리에서 푼다 | 호스트 → 집에 켜 둘 컴퓨터 · 클라이언트 → 밖에서 쓰는 기기 · 세션 → 접속해 있는 동안 |
| 누를 곳을 화면으로 보여 준다 | 버튼 이름과 위치를 캡처로 (개인 정보·PIN·기기 이름 마스킹) |
| 왜 하는지 한 줄 먼저 | 「PIN 6자리 이상」이 아니라 「누가 몰래 내 컴퓨터를 켤 수 없게 하려고」 |
| 막히는 자리를 미리 적는다 | 모듈마다 `troubleshooting/` |
| DoD 에 「따라 하기 검증」 | 그 문서만 보고 처음 하는 사람이 끝까지 갈 수 있는가 |
| 집단을 한정하지 않는다 | 「시민단체 담당자라면」 ✗ → 「사무실 컴퓨터를 쓰는 경우」 ○ |

### M1 — 원격 접속이란 무엇인가 · 개념과 선택 기준

**난이도**: ⭐
**예상 시간**: 1.5h
**산출물 폴더**: `01-Concepts-and-Choice/`

#### 학습 목표
- [ ] 원격 접속이 무엇을 하는 것인지 그림 한 장으로 설명할 수 있다
- [ ] 「집에 켜 둘 컴퓨터」와 「밖에서 쓰는 기기」의 역할 차이를 설명할 수 있다
- [ ] 포트포워딩·고정 IP 없이 연결되는 이유를 한 문장으로 말할 수 있다
- [ ] 내가 Chrome Remote Desktop 을 고른 이유(무료·구글)를 기준으로 정리할 수 있다

#### 주요 개념
1. **원격 접속**: 멀리 있는 컴퓨터의 화면을 내 기기에 가져와 마우스·키보드를 대신 움직이는 것. 파일을 옮기는 게 아니라 **그 컴퓨터를 그대로 쓰는 것**이다.
2. **호스트(집에 켜 둘 컴퓨터)** vs **클라이언트(밖에서 쓰는 기기)**: 호스트는 켜져 있고 잠들지 않아야 한다. 클라이언트는 브라우저나 앱만 있으면 된다.
3. **왜 공유기 설정이 필요 없나**: 집 컴퓨터가 구글 서버에 먼저 「나 여기 있다」고 연결해 두고, 밖에서 접속하면 그 통로를 이용한다. 밖에서 집으로 들어가는 문을 새로 뚫는 방식이 아니다. (⚠️ 오해하기 쉬운 점: 그래도 **구글 계정이 열쇠**다 — 계정이 털리면 전부 열린다)
4. **세션**: 접속해 있는 동안. 끊으면 집 컴퓨터는 그대로 켜져 있다.

#### 실습 과제

**실습 1: 내 상황 그림 그리기** ⭐
- **목적**: 내 집·기기·인터넷이 어떻게 연결되는지 스스로 그려 보면 나중에 문제가 생겼을 때 어디를 볼지 알게 된다
- **단계**:
  1. 종이나 Excalidraw 에 「집 컴퓨터 · 공유기 · 인터넷 · 내 폰/태블릿」을 그린다
  2. 화면이 어느 방향으로 흐르는지, 키보드 입력이 어느 방향으로 가는지 화살표로 표시
  3. 「구글 서버」를 가운데 넣고 왜 거기를 지나는지 한 줄 적는다
- **예상 시간**: 20분
- **검증**: 그림만 보고 다른 사람에게 1분 안에 설명할 수 있다

**실습 2: 선택 기준표 만들기** ⭐⭐
- **목적**: M6 대안 비교의 잣대를 미리 만든다. 나중에 도구가 바뀌어도 같은 기준으로 판단할 수 있다
- **단계**:
  1. 5가지 질문을 적는다 — 무료 범위 / 내 화면이 누구 서버를 지나나 / 계정 털리면 / 만든 나라 / 내 Windows 11 Home 에서 되나
  2. Chrome Remote Desktop 을 그 표에 먼저 채운다 (공식 문서 확인)
  3. 빈 칸으로 둔 대안 6개는 M6 에서 채운다
- **예상 시간**: 30분
- **검증**: 표의 CRD 열이 출처(공식 문서 URL)와 함께 채워져 있다

### M2 — 설치와 첫 연결 · 호스트와 밖에서 쓰는 기기

**난이도**: ⭐
**예상 시간**: 2h
**산출물 폴더**: `02-Install-and-First-Connect/`

> 📌 Live #28(9/20) 방송 2부에서 설치·접속을 시작했다. **이 모듈은 그것을 처음부터 다시 정리하는 것**이다 — 방송에서 넘어간 화면을 캡처로 남기고, 어디서 막혔는지 기록한다.

#### 학습 목표
- [ ] 집 컴퓨터에 Chrome Remote Desktop 호스트를 설치하고 이름·PIN 을 설정할 수 있다
- [ ] 폰/태블릿/노트북 중 최소 2개에서 접속할 수 있다
- [ ] 접속이 안 될 때 확인할 4가지를 순서대로 점검할 수 있다
- [ ] 설치 단계를 화면 캡처와 함께 다른 사람이 따라 할 수 있게 적을 수 있다

#### 주요 개념
1. **호스트 설치**: 집 컴퓨터에만 하는 설치. 한 번 해 두면 계속 대기한다
2. **PIN**: 구글 계정과 **별개**인 두 번째 열쇠. 계정만 뚫려도 PIN 을 모르면 못 들어온다
3. **기기 이름**: 여러 대면 구분용. ⚠️ 이름에 집 주소·본명을 넣지 않는다 (화면 공유·캡처 때 노출)
4. **절전/잠금**: 집 컴퓨터가 잠들면 접속이 안 된다 — M3 에서 다룬다

#### 실습 과제

**실습 1: 호스트 설치 · PIN 설정** ⭐
- **목적**: 밖에서 들어올 문을 만든다
- **단계**:
  1. 집 컴퓨터 Chrome 에서 `remotedesktop.google.com/access` 열기
  2. 「원격 액세스 설정」 → 호스트 프로그램 다운로드·설치
  3. 기기 이름 정하기 (개인 정보 없는 이름)
  4. PIN 6자리 이상 설정 — 생일·전화번호 금지
  5. 각 화면 캡처 (PIN 입력 화면은 숫자가 안 보이게)
- **예상 시간**: 30분
- **검증**: 같은 컴퓨터의 다른 브라우저에서 목록에 기기가 「온라인」으로 보인다

**실습 2: 밖에서 쓰는 기기에서 접속** ⭐⭐
- **목적**: 실제로 들어와 본다
- **단계**:
  1. 폰/태블릿에 Chrome Remote Desktop 앱 설치, 같은 구글 계정 로그인
  2. 기기 선택 → PIN 입력 → 접속
  3. 화면이 뜨면 마우스·키보드 조작 해 보기 (확대/축소, 키보드 띄우기, 마우스 모드)
  4. **집 와이파이를 끄고 LTE/5G 로** 다시 접속 (밖에서와 같은 조건)
  5. 노트북 브라우저에서도 접속
- **예상 시간**: 40분
- **검증**: LTE 로 접속해 메모장에 글자를 입력하고 저장까지 된다

**실습 3: 안 될 때 점검 순서 만들기** ⭐⭐
- **목적**: 막혔을 때 헤매지 않는다
- **단계**: 실제로 아래를 하나씩 일부러 만들어 보고 증상을 기록
  1. 집 컴퓨터를 절전으로 → 목록에서 「오프라인」
  2. 다른 구글 계정으로 로그인 → 기기가 아예 안 보임
  3. PIN 틀리게 입력 → 메시지 확인
  4. 인터넷 끊기 → 어떤 화면이 나오나
- **예상 시간**: 25분

### M3 — 보안 점검 · 편해진 만큼 열린 문 닫기

**난이도**: ⭐⭐
**예상 시간**: 2h
**산출물 폴더**: `03-Security-Checklist/`

> **이 모듈의 원칙**: 항목마다 **「왜」를 한 줄 먼저** 쓰고 설정 방법을 쓴다.

#### 학습 목표
- [ ] 원격 접속을 켜면 무엇이 위험해지는지 3가지로 말할 수 있다
- [ ] 구글 계정 2단계 인증·기기 목록·접속 기록을 직접 확인할 수 있다
- [ ] 잠금 화면·절전·자동 잠금을 원격 접속에 맞게 설정할 수 있다
- [ ] 「원격 지원(일회성 코드)」과 「내 기기 접속」의 위험 차이를 설명할 수 있다
- [ ] 점검표를 만들어 매달 한 번 스스로 점검할 수 있다

#### 주요 개념
1. **열쇠가 둘**: 구글 계정 + PIN. 계정이 첫 번째 문이므로 **2단계 인증이 사실상 가장 중요한 설정**이다
2. **세션 종료 ≠ 컴퓨터 종료**: 끊어도 집 컴퓨터는 켜져 있다. 끊을 때 **화면이 잠기는지** 확인해야 한다 (안 잠그면 집에 있는 사람이 그대로 볼 수 있다)
3. **원격 지원(일회성 코드)**: 남에게 내 화면을 보여 주는 기능. 코드 하나로 들어오므로 **아무에게나 주면 안 된다**. 지원이 끝나면 즉시 종료
4. **절전의 딜레마**: 절전을 끄면 접속은 항상 되지만 전기를 더 쓰고, 화면이 켜진 채 방치될 수 있다 → 「화면만 끄고 잠들지 않게」가 답

#### 실습 과제

**실습 1: 구글 계정 쪽 점검** ⭐⭐
- **목적**: 첫 번째 문을 잠근다
- **단계**:
  1. 2단계 인증 켜져 있는지 확인 (없으면 켠다)
  2. 「내 계정에 로그인된 기기」 목록 확인 — 모르는 기기 제거
  3. 최근 보안 활동 확인
  4. 복구용 전화·이메일이 지금 쓰는 것인지 확인
- **예상 시간**: 25분
- **검증**: 캡처와 함께 4개 항목이 ✅ 로 기록됨 (개인 정보 마스킹)

**실습 2: Windows 쪽 설정** ⭐⭐
- **목적**: 집에 있는 사람도, 밖에 있는 나도 안전하게
- **단계**:
  1. 전원 설정 — 「절전 모드: 안 함」, 「화면 끄기: 10분」 (전원 연결 시)
  2. 「다시 시작할 때 로그인 요구」 켜기
  3. 세션을 끊었을 때 **화면이 잠기는지** 실제로 확인 (밖에서 끊고 집 화면 보기)
  4. Windows 계정 비밀번호/PIN 이 추측 가능한지 점검
- **예상 시간**: 30분
- **검증**: 원격 종료 후 집 컴퓨터 화면이 잠금 화면이다

**실습 3: 월간 점검표 만들기** ⭐
- **목적**: 한 번 설정하고 잊는 것을 막는다
- **단계**: 위 항목을 체크리스트 한 장으로. 「매달 1일」 같은 주기를 정하고 달력에 등록
- **예상 시간**: 20분
- **검증**: 점검표 1장 + 캘린더 반복 일정 등록

### M4 — 실사용 ① 집을 비우고 작업하기

**난이도**: ⭐⭐
**예상 시간**: 2h
**산출물 폴더**: `04-Real-Use-Work/`

> ⚠️ **데모가 아니다.** 실제로 집을 비운 상태에서 **작업 한 건을 끝까지** 해 본다. 외출 기회에 맞춰 진행한다.

#### 학습 목표
- [ ] 밖에서 접속해 볼트 문서를 편집하고 저장할 수 있다
- [ ] 화면 크기·키보드·한글 입력의 실제 불편을 기록할 수 있다
- [ ] 회선(카페 Wi-Fi · LTE)에 따른 차이를 수치로 비교할 수 있다
- [ ] 「밖에서 되는 일 / 안 되는 일」을 갈라 목록으로 만들 수 있다

#### 주요 개념
1. **해상도 차이**: 집 모니터가 크면 폰 화면에서는 글씨가 작다. 확대/축소와 「화면에 맞추기」를 쓴다
2. **한글 입력**: 모바일 키보드로 원격 한글 입력은 IME 때문에 어긋날 수 있다 — 실제로 확인할 항목
3. **지연**: 회선이 느리면 타이핑이 늦게 보인다. 글쓰기는 견디지만 영상 편집은 어렵다
4. **파일**: 원격 화면 안에서 여는 파일은 **집 컴퓨터의 파일**이다. 내 폰으로 내려오지 않는다

#### 실습 과제

**실습 1: 작업 한 건 끝내기** ⭐⭐

- **단계**:
  1. 외출 시 폰/태블릿으로 접속
  2. Obsidian 볼트에서 오늘 문서 한 개를 실제로 편집·저장
  3. 파일 탐색기에서 폴더 하나 정리
  4. OBS 를 열어 상태 확인 (방송용 프로필 그대로인지)
  5. 세션 종료 → 집 화면이 잠겼는지 나중에 확인
- **예상 시간**: 40분
- **검증**: 편집한 문서가 집 컴퓨터에 저장돼 있고, 종료 후 화면이 잠겨 있었다

**실습 2: 회선·기기별 실측표** ⭐⭐
- **목적**: 어디서 쓸 만한지 미리 안다
- **단계**: 같은 작업(문서 한 줄 입력 → 저장)을 조건별로 반복하고 기록
  - 기기: 폰 / 태블릿 / 노트북
  - 회선: 집 Wi-Fi / LTE·5G / 카페 Wi-Fi
  - 기록: 접속까지 걸린 시간 · 타이핑 지연 체감 · 끊김 횟수 · 한글 입력 되는가
- **예상 시간**: 40분
- **검증**: 표가 채워지고 「이 조합은 쓸 만하다/아니다」가 한 줄씩 적혀 있다

### M5 — 실사용 ② 밖에서 AI 작업 리뷰·승인 한 바퀴

**난이도**: ⭐⭐⭐
**예상 시간**: 2h
**산출물 폴더**: `05-Remote-AI-Review-Loop/`

> **이 Topic 의 둘째 목적을 검증하는 모듈.** 기준은 「화면이 보이나」가 아니라 **「AI 작업 한 바퀴가 도나」**다.

#### 학습 목표
- [ ] 밖에서 AI 결과물을 확인할 수 있다 (문서 변경 · 영상 프리뷰 · 렌더 진행률)
- [ ] 승인 또는 수정 지시를 원격으로 전달하고 다음 작업을 시작시킬 수 있다
- [ ] 작은 화면에서 **되는 것과 안 되는 것**을 갈라 기록할 수 있다
- [ ] 외출 전 「AI 가 이어서 일하게 두는」 준비 절차를 만들 수 있다

#### 주요 개념
1. **리뷰·승인 루프**: 결과 확인 → 승인/수정 지시 → 다음 작업 시작. 이 세 동작만 되면 밖에서도 일이 돈다
2. **긴 작업과 짧은 확인**: 렌더·합성 같은 긴 작업은 집 컴퓨터가 하고, 나는 **확인만** 한다
3. **입력의 한계**: 긴 지시를 폰으로 타이핑하는 것은 괴롭다 → 음성 입력·짧은 승인 문구를 준비해 둔다
4. **끊겨도 계속**: 원격 세션이 끊겨도 집 컴퓨터의 작업은 계속된다 (Grok Bot 과의 차이는 M6)

#### 실습 과제

**실습 1: 외출 전 준비 절차 만들기** ⭐⭐
- **목적**: 나가기 전 3분으로 밖에서의 1시간을 산다
- **단계**:
  1. AI 에게 맡길 작업을 시작시켜 두기 (예: 렌더 · 긴 문서 작성)
  2. 절전 꺼짐 확인 · 필요한 창을 미리 열어 두기
  3. 승인에 쓸 짧은 문구 정해 두기 (「좋아요, 다음 진행」 / 「2번만 고쳐 주세요」)
  4. 체크리스트 1장으로 정리
- **예상 시간**: 25분
- **검증**: 체크리스트대로 한 번 실행해 본다

**실습 2: 밖에서 한 바퀴 돌리기** ⭐⭐⭐
- **목적**: 진짜 되는지 본다
- **단계**:
  1. 외출 상태에서 접속
  2. AI 가 만든 결과 확인 — 문서 변경 내용 읽기 / 영상 프리뷰 재생 / 진행률 보기
  3. 승인 또는 수정 지시 입력 (폰 키보드·음성 입력 둘 다 시도)
  4. 다음 작업 시작시키기
  5. 세션 종료 후에도 작업이 계속되는지 나중에 확인
- **예상 시간**: 45분
- **검증**: **한 바퀴가 돌았다** — 확인 → 지시 → 다음 작업 시작이 밖에서 완료됨

**실습 3: 되는 것 / 안 되는 것 표** ⭐⭐
- **목적**: 밖에서 할 일과 집에서 할 일을 나눈다
- **단계**: 동작별로 기록 — 문서 읽기 / 짧은 지시 / 긴 지시 / 영상 프리뷰 / 렌더 확인 / 터미널 명령 / 파일 정리 / 스크린샷 확인
- **예상 시간**: 25분
- **검증**: 각 항목이 ○△✗ 와 한 줄 이유로 채워짐

```
05-Remote-AI-Review-Loop/
```

### M6 — 대안 비교 · 무료·안전한 2번째 카드와 Grok Bot

**난이도**: ⭐⭐
**예상 시간**: 2.5h
**산출물 폴더**: `06-Alternatives-and-GrokBot/`

> **읽고 끝내지 않는다.** A 부류에서 **최소 1개는 실제 설치·접속**해 CRD 가 막혔을 때 바로 쓸 수 있게 둔다.

#### 학습 목표
- [ ] 원격 접속 도구 6개를 같은 기준 5가지로 비교해 표로 만들 수 있다
- [ ] 무료·안전한 대안 1개를 설치해 실제로 접속할 수 있다
- [ ] Windows 11 Home 에서 RDP 호스트가 왜 안 되는지 설명할 수 있다
- [ ] Grok Bot 방식이 CRD 와 **무엇이 다른 범주**인지, 언제 그쪽이 나은지 설명할 수 있다

#### 주요 개념
1. **A 부류 — 내 화면을 원격 조작**: CRD · RustDesk · AnyDesk · TeamViewer · RDP · Parsec · Tailscale
2. **B 부류 — AI 에게 컴퓨터를 따로 줌**: Grok Bot — 전용 클라우드 컴퓨터(브라우저·파일·터미널)에서 봇이 돌고, **내 PC 를 꺼도 계속**된다. 봇 창을 원격 데스크톱처럼 쓸 수 있다. 유료
3. **자체 서버(self-host)**: RustDesk 는 중계 서버를 내 것으로 둘 수 있다 — 내 화면이 남의 서버를 지나지 않는다
4. **「개인 무료」의 경계**: TeamViewer·AnyDesk 는 상업적 사용으로 판정되면 막힌다. 무엇이 판정 근거인지 확인

#### 실습 과제

**실습 1: 비교표 완성** ⭐⭐
- **목적**: M1 에서 만든 기준표의 빈 칸을 채운다
- **단계**: 6개 도구 × 5개 질문(무료 범위 / 어느 서버를 지나나 / 계정 털리면 / 만든 나라 / Win11 Home 가능)을 **공식 문서 출처와 함께** 채운다
- **예상 시간**: 45분
- **검증**: 모든 칸에 출처 URL 이 붙어 있다

**실습 2: 2번째 카드 실제 설치** ⭐⭐⭐
- **목적**: 대안을 「알기」에서 「쓸 수 있기」로
- **단계**:
  1. 비교표 결과로 하나 고른다 (RustDesk 유력 — 오픈소스·무료·자체 서버 가능)
  2. 집 컴퓨터와 폰에 설치
  3. 접속해서 M4 실습 1과 같은 작업 해 보기
  4. CRD 와 다른 점 기록 (설치 난이도 · 속도 · 화면 품질 · 보안 설정)
- **예상 시간**: 50분
- **검증**: 대안 도구로 문서 편집·저장까지 성공

**실습 3: Grok Bot 비교 정리** ⭐⭐
- **목적**: 「내 컴퓨터를 본다」와 「AI 에게 컴퓨터를 준다」의 차이를 내 상황에 맞춰 판단
- **단계**:
  1. 공식 문서로 사실 확인 (무엇인지 · 어디서 도는지 · 내 PC 를 꺼도 되는지 · 비용)
  2. 6가지 기준으로 CRD 와 나란히 표: 작업이 도는 곳 / 내 PC 꺼도 / 내 파일·프로그램 / 비용 / 내가 쓰는 AI 생태계 / 집 컴퓨터를 켜 둬야 하나
  3. **「언제 어느 쪽을 쓰나」**로 결론 — 둘 중 하나를 고르는 것이 아니라
  4. (선택) 지인에게 실제 사용 경험 물어 기록
- **예상 시간**: 40분
- **검증**: 비교표 + 「내 경우의 판단」 3~5줄

### M7 — Capstone · 누구나 따라 하는 안내 영상 1편

**난이도**: ⭐⭐⭐
**예상 시간**: 3.5h
**산출물 폴더**: `07-Public-Guide-Video/`

> DFS·Caregiver·Active-Shooter 편과 같은 Remotion 파이프라인. **9/18 에 배운 것을 그대로 적용한다** — 약어는 글자로 발음, 용어는 그 자리에서 풀기, 한 화면에 한 가지.

#### 학습 목표

#### 주요 개념
1. **무엇을 넣고 무엇을 뺄까**: 전부 넣으면 아무것도 남지 않는다. **「설치 → 안전하게 → 밖에서 쓰기」** 세 덩어리
2. **나레이션 원칙(9/18 확립)**: 약어는 글자로 (씨알디 아님 — 「크롬 리모트 데스크톱」으로 풀어 말한다) · 용어는 그 자리에서 풀기 · 상대 날짜 금지
3. **화면 캡처의 개인 정보**: 계정 이메일·PIN·기기 이름·집 주소가 보이면 안 된다
4. **QR**: GitHub Topic 문서로 가는 QR 을 아웃트로에 (DFS 편 기준)
