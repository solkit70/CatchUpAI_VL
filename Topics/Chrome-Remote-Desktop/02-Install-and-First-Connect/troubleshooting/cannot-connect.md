# 안 될 때 — 증상별로 어디를 보나

> **먼저 가를 것**: 「**안 보인다**」와 「**보이는데 느리다**」는 원인이 완전히 다르다.
> 안 보이면 연결 자체가 안 된 것이고, 느리면 연결은 됐고 회선 문제다.

## 실제로 겪은 것 (2026-09-20)

### 1. iPad 에서 App Store 에 앱이 없다

| | |
|---|---|
| **증상** | App Store 에서 「Chrome Remote Desktop」을 검색해도 앱이 나오지 않는다 |
| **원인** | 구글이 **2025년 9월 iOS 앱을 폐지**했다. 없어진 것이 맞다 |
| **조치** | **Safari** 로 `remotedesktop.google.com/access` 접속 → 공유 버튼 → **홈 화면에 추가**. Chrome for iOS 가 아니라 **Safari** 여야 홈 화면 추가가 제대로 된다 |
| **헷갈리는 이유** | 검색하면 예전 앱 안내가 그대로 나온다. 안드로이드는 앱이 **그대로 있어서** 「나만 안 되나?」 싶어진다 |

### 2. 기기 이름이 내 본명으로 등록돼 있었다

| | |
|---|---|
| **증상** | 기기 목록에 본명이 그대로 보인다 |
| **원인** | 이름 입력 칸에 **Windows 사용자 이름이 기본값**으로 채워져 있고, 그냥 「Next」를 누르면 그대로 등록된다 |
| **조치** | 목록에서 이름 옆 **연필(✏️)** → 새 이름 → 저장. 공개돼도 괜찮은 이름으로 |
| **주의** | 이 이름은 화면 공유·캡처·영상에 그대로 보인다 |

### 3. 캡처에 남의 이름·사진이 들어갔다 (iPad 공유 메뉴)

| | |
|---|---|
| **증상** | 「홈 화면에 추가」 하려고 공유 버튼을 누르면 **최근 연락처의 이름과 사진**이 메뉴 위쪽에 뜬다 |
| **원인** | iOS 공유 메뉴의 기본 동작. 원격 접속과는 무관하지만 **캡처에 그대로 찍힌다** |
| **조치** | 문서·영상에 쓰기 전에 그 줄을 가린다. 캡처 전에 연락처 줄을 「View Less」로 접는 방법도 있다 |
| **왜 중요한가** | 내 정보가 아니라 **남의 정보**다. 안내 영상에 남의 얼굴이 나가면 안 된다 |

### 4. 같은 컴퓨터가 두 번 보인다

| | |
|---|---|
| **증상** | 「Remote devices」와 「This device」에 같은 이름이 하나씩, 총 두 줄 |
| **원인** | 기기가 두 대인 것이 아니라 **같은 컴퓨터를 두 시점에서 보여 주는 것** |
| **확인법** | 한쪽 이름을 바꿔 본다 — **같이 바뀌면 같은 컴퓨터다** |
| **진짜 문제일 때** | 모르는 기기가 목록에 있으면 **휴지통으로 삭제**한다 |

## 증상별 점검표

### 2026-09-23 추가 실측 — PIN과 iPad 인터넷

| 일부러 만든 조건 | 실제 표시 | 다시 사용할 때 |
|---|---|---|
| 잘못된 PIN 입력 | “The PIN is invalid. Please try again, or visit g.co/crd/setup on the remote computer to change it.” | 올바른 PIN을 입력하자 정상 접속 |
| iPad Wi-Fi 끄기 | Safari가 iPad의 인터넷 연결이 없어 원격 데스크톱 페이지를 열 수 없다고 표시 | Wi-Fi를 켜자 인터넷은 즉시 복구. 원격 접속에는 PIN 재입력이 필요했음 |

이 실측은 **iPad 쪽 인터넷을 끊은 경우**다. 집 컴퓨터 쪽 인터넷을 끊었을 때의 화면은 아직 확인하지 않았다.

### 2026-09-23 추가 실측 — Disconnect와 Windows 잠금은 별개

iPad에서 원격 연결을 끊은 직후에도 노트북 물리 화면에는 메모장 작업 화면이 그대로 남았고, iPad 재접속은 정상 작동했다. 이 환경에서 **Disconnect는 Windows를 자동으로 잠그지 않았다**. 연결이 끝났다는 표시를 잠금 완료로 해석하지 말고 [M3 잠금 실측 및 후속 절차](../../03-Security-Checklist/guides/windows-power-and-lock.md#3-원격-세션-종료-뒤-잠금-실측)를 확인한다.

### 일반 점검표

| 증상 | 가장 흔한 원인 | 확인 순서 |
|---|---|---|
| **기기 목록이 텅 비었다** | 구글 계정이 다르다 | ① 폰/브라우저에 로그인된 계정이 집 컴퓨터에 설정한 계정과 같은가 ② 계정을 바꾼 적 있나 |
| **「오프라인」으로 보인다** | 집 컴퓨터가 꺼졌거나 잠들었다 | ① 전원 ② 절전 설정(M3) ③ 집 인터넷 |
| **PIN 이 틀리다고 한다** | 계정을 바꾸면 **PIN 도 새로 만들어진다** | 최근에 계정·설정을 바꿨는지 |
| **들어가지는데 느리다** | 내 쪽 회선 | ① Wi-Fi ↔ LTE 바꿔 보기 ② 화면 크기 줄이기 ③ 집 컴퓨터에서 무거운 작업이 도는지 |
| **작은 버튼을 못 누르겠다** | 터치 모드 | **트랙패드 모드**로 전환 |
| **한글이 안 써진다** | 모바일 키보드와 원격 입력기(IME) 충돌 (iPad 에서는 문제 없었음) | ① 물리 키보드 연결 ② 짧게 영문으로 대체 ③ 다른 기기에서 재현되는지 확인 |

## 컴퓨터 쪽에서 확실히 확인하는 법 (Windows)

브라우저 화면 말고 **컴퓨터 자체**에서 보는 방법이다. 「설치가 된 건가?」가 확실해진다.

| 볼 곳 | 정상이면 |
|---|---|
| 작업 관리자 → 프로세스 | `remoting_host` 가 있다 (보통 2개) |
| 서비스(services.msc) | `chromoting` 이 **실행 중**, 시작 유형 **자동** |
| 설치 폴더 | `C:\Program Files (x86)\Google\Chrome Remote Desktop\` 가 있다 |

> 💡 `chromoting` 이 「자동」이면 **컴퓨터를 다시 켜도 알아서 대기**한다. 매번 실행할 필요가 없다.
