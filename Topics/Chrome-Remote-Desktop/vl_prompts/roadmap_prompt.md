**Topic 설명**:
```
구글 Chrome Remote Desktop 으로 외부에서 집 컴퓨터에 접속해 실제 작업 환경을 운영하는

**대상은 모든 사용자.** 기준선은 「IT 지식이 없는 일반인」에 맞춘다 — 시민단체 실무자·시니어를
```

**학습 목적**:
```
- 집을 비울 때도 방송·영상 제작 환경(OBS · Remotion · 볼트)을 이어서 쓸 수 있게 한다
- **AI 에게 맡긴 일이 밖에 있는 동안에도 계속 돌아가게 한다** — AI 와 일하는 시간의 상당 부분이
  「AI 가 한 일을 리뷰하고 승인 여부를 정하는 것」이라, 그 일은 컴퓨터 앞에 앉아 있을 필요가 없다.

- 원격 접속의 보안 위험(무단 접근·PIN 관리·세션 종료·잠금 화면)을 실제 설정으로 확인한다

- IT 지식이 없는 사람도 혼자 설치하고 안전하게 쓸 수 있는 안내를 만든다
```

## [1.5단계] 🔴 이 Topic 의 전달 기준 (로드맵 생성 시 반드시 반영)

### 0-b. 대안 비교는 「읽고 끝」이 아니라 실제 설치까지

사용자가 CRD 를 고른 기준은 **「구글이 만들어 믿을 수 있고 무료」**다. 같은 잣대로 대안도 본다.

- **A 부류(화면 원격 조작)**: RustDesk · AnyDesk · TeamViewer · Windows RDP · Parsec · Tailscale.
  표로 비교하고, 그중 **무료·안전한 것 최소 1개는 실제로 설치·접속까지** 해서 CRD 가 막혔을 때
  바로 쓸 수 있게 둔다 (실습 과제로 배치).
- **B 부류(AI 에게 클라우드 컴퓨터를 줌)**: **Grok Bot (xAI)**. 내 컴퓨터를 보여 주는 것이 아니라
  AI 가 쓸 컴퓨터를 클라우드에 따로 둔다 — 내 PC 를 꺼도 작업이 계속되고, 봇 창을 원격 데스크톱처럼
  쓸 수 있다. 유료. **이 Topic 의 둘째 목적과 정확히 같은 문제를 다른 방식으로 푸는 대안**이므로
  「작업이 도는 곳 · 내 파일 접근 · 비용 · 내가 쓰는 AI 생태계 · 집 컴퓨터를 켜 둬야 하는가」
  기준으로 CRD 와 나란히 비교하는 절을 반드시 넣는다. 결론은 「둘 중 하나」가 아니라
  **「언제 어느 쪽을 쓰나」**로 쓴다.

### 0. 두 가지 목적을 모두 모듈로 만든다

이 Topic 에는 목적이 둘이다. **둘째 목적을 「덤」으로 넣지 말고 독립 실습·검증으로 다룬다.**

1. **집을 비워도 작업 환경을 쓴다** — 방송·영상 제작(OBS · Remotion · 볼트)
2. **밖에서도 AI 작업을 이어 간다** — AI 와 일하는 시간의 상당 부분이 「AI 가 한 일을 리뷰하고
   승인 여부를 정하는 것」이다. 그 일은 컴퓨터 앞에 앉아 있을 필요가 없다. 원격으로 결과를 보고
   승인·수정 지시만 하면 작업이 계속 돈다.

둘째 목적의 검증 기준은 「화면이 보이나」가 아니라 **「AI 작업 한 바퀴가 도나」**다 —
결과물 확인 → 승인 또는 수정 지시 → 다음 작업 시작. **폰·태블릿의 작은 화면에서** 되는 것과
안 되는 것을 갈라 기록하는 실습을 반드시 포함한다.


모든 모듈의 산출물·실습·검증 기준에 아래를 적용한다.

1. **독자는 IT 지식이 없는 일반인**이다. 용어를 쓰면 그 자리에서 풀어 쓴다
   (호스트 → 집에 켜 둘 컴퓨터 · 클라이언트 → 밖에서 쓰는 기기 · 세션 → 접속해 있는 동안).
2. **각 모듈에 「막혔을 때」 문서를 둔다** (`troubleshooting/`) — 안 될 때 어디를 보는지.
3. **보안 항목은 「왜」를 먼저 한 줄** 쓰고 설정 방법을 쓴다.
4. **화면 캡처가 필요한 단계를 모듈마다 명시**한다 (개인 정보·PIN·기기 이름은 마스킹).
5. **DoD 에 「따라 하기 검증」 항목을 넣는다** — 그 문서만 보고 처음 하는 사람이 끝까지 갈 수 있는가.
6. 특정 집단을 한정하는 표현(「시민단체 담당자라면」)을 쓰지 않는다. 필요하면 상황으로 쓴다.

#### 실습 설계 원칙 (중요!)

실습 과제를 설계할 때 다음 원칙을 **반드시** 준수하세요:

##### 1. 실습 우선
- 이론 설명: 20-30%
- 실습 시간: 70-80%
- "개념 설명 → 즉시 실습" 패턴 반복

##### 2. 점진적 복잡도
- 실습 1: 간단 (⭐) - "Hello World" 수준
- 실습 2: 중간 (⭐⭐) - 실용적 기능
- 실습 3: 고급 (⭐⭐⭐) - 선택사항, 심화

##### 3. 검증 가능성
- 모든 실습은 실행 결과로 성공 여부 확인 가능
- 예: "로그 출력", "파일 생성", "API 응답 성공"
- 명확한 성공 기준 제시

##### 4. AI 시대 학습 범위
**인간이 알아야 할 것**:
- 개념적 이해 (무엇, 왜, 언제)
- 아키텍처 및 구조
- AI에게 효과적으로 지시하는 방법
- 기본 사용 패턴 (3-5개 핵심 기능)

**암기 불필요**:
- 상세 API 파라미터 목록
- 모든 옵션과 플래그
- 내부 구현 디테일

##### 5. 산출물 중심
- 매 모듈마다 폴더 생성 (`01-xxx/`, `02-xxx/`)
- **"교과서 품질"**: 다른 학습자가 이것만으로 학습 가능한 수준
- 🔴 **Topic 최상위 `README.md` 도 반드시 만든다** — 모듈 README 와 별개다.
  - Topic 이 무엇을 다루고 **무엇을 알아냈는지** 한눈에
  - **모듈 목록을 학습 순서대로** 상대 경로 링크와 함께
  - 결과물(영상·아티팩트·공개 문서)이 있으면 링크
  - ⚠️ **이 레포는 GitHub 에 공개된다.** 최상위 README 가 없으면 방문자는 **폴더 목록만** 보게 된다
- **모듈 README.md는 반드시 포함** — 아래 내용을 갖춰야 함:
  - 모듈 번호/제목/상태/예상 학습 시간 헤더
  - 이 폴더의 모든 문서를 **학습 순서대로** 번호 매겨 나열
  - 각 문서에 **상대 경로 링크** (예: `[concepts/overview.md](concepts/overview.md)`)
  - 각 문서마다 1줄 설명 (무엇을 배우는 문서인지)
  - 이전/다음 모듈 링크
  - **처음 이 폴더를 여는 사람이 README만 보고 순서대로 학습 가능한 수준**

##### 6. 환경 고려
- 사용자가 입력한 OS/도구에 맞는 명령어 사용
- Windows: PowerShell 명령어
- macOS/Linux: Bash 명령어
- 경로 표기도 OS에 맞게 조정
