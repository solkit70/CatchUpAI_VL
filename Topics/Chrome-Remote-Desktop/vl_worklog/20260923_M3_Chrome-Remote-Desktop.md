**결과**:

- 2단계 인증 **켜짐**.

- 저장된 비밀번호 점검과 Enhanced Safe Browsing 선택은 이 실습의 복구 연락처 확인과 별개다. 권장 사항을 곧바로 계정 침해의 증거로 해석하거나 설정을 임의로 변경하지 않는다.

**개인정보 처리**: 사용자가 제공한 화면에는 복구 연락처와 계정 활동 정보가 보인다. 원본 이미지는 공개 Topic에 저장하지 않고 상태만 기록한다.

### 활동 3 — 노트북 화면 끄기와 절전 설정

**시간**: 2026-09-23 (사용자 실습, 세부 시각 미기록)

**결과**: 사용자가 제공한 Windows 설정 화면에서 전원 연결 시 화면 끄기 **10분**, 절전 **안 함**을 확인했다. 배터리 사용 시 화면 끄기와 절전은 각각 **3분**으로 유지됐다. 이어서 **계정 → 로그인 옵션** 화면에서 재로그인 요구가 **Every Time**으로 표시됨을 확인했다. Windows Hello 때문에 선택 메뉴는 비활성화돼 있었으며, 값을 변경하지 않았다.

**다음 단계**: 지문 로그인이 정상 작동함을 확인했다. iPad 원격 연결 종료 직후 물리 화면이 잠기는지는 아래 활동에서 별도 실측했다.

### 활동 4 — iPad Disconnect 직후 잠금 실측

**시간**: 2026-09-23 (사용자 실습, 세부 시각 미기록)

**사용자 보고 원문**:

> 평소 하던 대로 지문 로그인이 잘 됩니다.  그리고 아이패드에서 접속한 뒤 Disconnect 를 눌렀습니다. 노투북은 메모장 화면 그대로 입니다. 아이패드에서 재접속도 잘 됍닏.

**결과**: iPad에서 원격 접속 후 **Disconnect**를 선택해도 노트북 물리 화면에는 메모장 작업 화면이 그대로 남았다. iPad에서 재접속도 정상 작동했다. 따라서 이 환경에서는 **원격 연결 종료가 Windows 잠금을 자동으로 실행하지 않는다**. 지문 로그인은 사용자가 평소처럼 정상 작동한다고 확인했다.

**당시 남은 검증**: Disconnect만으로 잠기지 않아, iPad에서 Windows **잠금**을 명시적으로 실행하는 절차가 필요했다. 그 결과는 아래 활동 5에 기록했다.

### 활동 5 — iPad에서 Windows 잠금 후 연결 종료·재접속

**시간**: 2026-09-23 (사용자 실습, 세부 시각 미기록)

**사용자 보고 원문**:

> iPad 에서 윈도우즈를 Lock 한 후 iPad 에서 Disconnect 해도 노트북은 여전히 잠겨 있는 상태 입니다. Lock 을 눌러도 원격 연결이 끊기지 않습니다. 원격 연결을 끊고 다시 연결한 다음에 윈도우즈의 Lock 을 해제하고 다시 윈도우즈를 Open 할 수 있습니다. 이 때 지문으로 인증하지 않고 Pin Code 로 인증하면 됩니다.

**결과**: iPad 원격 화면에서 Windows **Lock**을 실행해도 CRD 연결은 유지됐다. 이어 **Disconnect**한 뒤에도 노트북 물리 화면은 잠긴 상태를 유지했다. iPad로 다시 원격 연결한 다음 **Windows PIN**으로 잠금을 해제해 작업 화면으로 돌아갈 수 있었다. 실제 PIN 숫자는 기록하지 않는다.

**확인된 안전 종료 절차**: 이 환경에서는 원격 작업 종료 시 **Windows Lock → 잠금 화면 확인 → CRD Disconnect** 순서가 동작했다. CRD 호스트에 접속할 때의 PIN과 Windows 잠금을 해제할 때의 PIN은 서로 다른 인증 단계이며, Disconnect만으로는 Windows가 잠기지 않는다.

### 활동 6 — 월간 보안 점검 반복 일정 등록

**시간**: 2026-09-23 (등록, 세부 시각 미기록)

**목적**: 한 번의 보안 설정 확인으로 끝내지 않고, 매달 [월간 점검표](../03-Security-Checklist/examples/monthly-checklist.md)를 다시 확인한다.

**결과**: 기본 Google Calendar에 **매월 1일 10:00–10:20, America/Los_Angeles**, 첫 일정 **2026-10-01**로 반복 일정을 등록했다. 첫 일정은 등록 직전 해당 시간대가 비어 있음을 확인했으며, 등록 후 반복 규칙도 다시 읽어 확인했다. 일정에는 점검 항목과 로컬 점검표 경로만 적고 PIN·복구 연락처 등 비밀 값은 넣지 않았다.

### 활동 7 — 안내서 따라 하기 검증과 자기평가

**사용자 보고 원문**: [[2026-09-23#Chrome Remote Desktop M3 따라 하기 검증과 원격 성능 (구술 원문)|2026-09-23 Journal 원문]]에 보존했다.

**따라 하기 결과**: 사용자는 M3 안내서를 끝까지 확인했고 막히는 부분이 없다고 보고했다. Disconnect만 하면 노트북 작업 화면이 그대로이며 Sharing 표시만 사라진다는 실측도 다시 설명했다. 원격으로 연결된 모니터를 볼 수 있고 YouTube 음성을 들을 수 있다는 점, 노트북을 휴대하지 않고 조작할 수 있다는 점을 유용한 경험으로 꼽았다.

**개념 피드백**: Google 계정과 CRD 호스트 PIN은 내 기기 접속에 필요한 두 관문이지만, 호스트 PIN 자체가 Google 계정의 2단계 인증은 아니다. 원격 지원은 다른 사람의 기기에 접속하는 경우뿐 아니라 내가 내 기기를 타인에게 공유하는 경우도 포함한다. Google 계정의 보안 활동을 개별 CRD 접속의 완전한 기록으로 단정하지 않는다. 이 구분을 개념·원격 지원 문서에 보완했다.

**새 질문**: 원격 중 CPU·메모리 사용량이 높아 Windows가 느려질 때 iPad에서 작업 관리자로 특정 프로세스를 종료할 수 있는가. 이는 M3 보안 DoD와 별개인 실사용·문제 해결 과제로 남기며, 원격에서 직접 검증하기 전에는 동작을 실측 완료로 적지 않는다.

**마지막 확인**: 사용자는 **Windows Lock → 잠금 확인 → Disconnect**라는 안전 종료 순서를 이해했다고 명시적으로 답했다. Google 계정의 2단계 인증과 CRD 호스트 PIN의 차이, 원격 지원의 양방향 사용은 문서에서 구분해 두었으며 별도 실기 검증을 했다고 주장하지 않는다.

## 문제 해결 로그

### 문제 1 — 전원 연결 시 화면 끄기와 절전이 모두 「안 함」이었던 초기값

**증상**: 전원 연결 중에는 컴퓨터뿐 아니라 화면도 계속 켜져 있다.

**원인**: 원격 접속을 위해 절전을 끄면서 화면 끄기도 함께 끈 것으로 보인다.

**해결**: 사용자가 Windows 설정에서 전원 연결 시 화면 끄기를 **10분**으로 바꾸고, 절전은 **안 함**으로 유지한 화면을 제공했다. 재로그인 요구는 **Every Time**으로 확인됐다. 잠금과 재접속 동작은 활동 5에서 실측했다.

### 문제 2 — Disconnect 후 Windows가 잠기지 않음

**증상**: iPad 원격 메뉴에서 Disconnect를 눌러도 노트북에 메모장 작업 화면이 그대로 보였다.

**원인/해석**: 이 환경에서 Disconnect는 원격 세션 종료였고, Windows 잠금은 실행되지 않았다. 재접속은 정상 작동했다.

**해결**: 원격에서 Windows Lock을 명시적으로 실행한 뒤 Disconnect하면 물리 화면이 잠겨 있었다. 재접속 후 Windows PIN으로 해제도 가능했다. 노트북 앞에서 자리를 비울 때는 Windows 키 + L로 직접 잠글 수도 있다.

## Module Retrospective — M3

### 학습 목표 달성도

- 원격 접속의 주요 위험 세 가지(계정 접근, 연결 종료 뒤 잠기지 않은 화면, 절전·화면 켜짐 설정)를 문서로 설명했고, 이 노트북에서 실제 화면·전원 상태를 확인했다.
- Google 2단계 인증, Mac을 포함한 로그인 기기·최근 활동, 복구 연락처를 사용자가 점검했다. 복구 연락처의 실제 값은 저장하지 않았다.
- Disconnect만으로는 노트북이 잠기지 않았고, **Windows Lock → 잠금 확인 → Disconnect** 후에는 잠금이 유지되며 iPad 재접속과 Windows PIN 해제도 가능함을 실측했다.
- 원격 지원의 일회성 코드와 내 기기 접속의 호스트 PIN을 문서에서 구분했다. 원격 지원 코드를 실제로 만들거나 공유하지는 않았다.
- 월간 점검표와 2026-10-01 시작의 매월 1일 캘린더 반복 일정을 마련했다. 사용자가 안내서를 따라 읽으며 막힘이 없다고 보고했고, 안전 종료 순서를 다시 확인했다.

### 핵심 인사이트와 보완

사용자는 노트북을 휴대하지 않고 연결된 여러 모니터를 보며 작업하고 음성도 들을 수 있는 점을 유용하게 경험했다. 동시에 원격 연결 종료는 Windows 잠금을 대신하지 않는다는 보안상 핵심 차이를 실측했다. 자기평가에서 Google 계정의 2단계 인증과 CRD 호스트 PIN, 원격 지원의 방향을 혼동할 여지가 드러나 두 문서의 설명을 보완했다. 원문은 [[2026-09-23#Chrome Remote Desktop M3 따라 하기 검증과 원격 성능 (구술 원문)|Journal]]에 보존했다.

### 다음 모듈 준비와 미실측 범위

M4에서 외부 회선 접속과 실사용 작업을 검증한다. 원격 중 CPU·메모리 사용량이 높을 때 Windows 작업 관리자에서 안전한 테스트 앱을 식별·종료하는 것은 **아직 원격 실측 전**이다. 노트북 덮개를 닫을 때의 동작도 이번 M3에서 실측하지 않았으며, 원격 접속을 위해 덮개 전원·발열 설정을 임의로 바꾸지 않는다.
