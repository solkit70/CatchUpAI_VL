## 준비한 실습

검토 대상은 [M6 대안 비교표의 「이번 선택」](../06-Alternatives-and-GrokBot/guides/comparison-table.md#이번-선택)이다. 사용자는 iPhone CRD에서 이 부분을 읽었고 Pinch 확대 후 문제없이 읽을 수 있었다고 보고했다. 현재 세션에서 내용 승인을 받아 [M5 실습 문서](../05-Remote-AI-Review-Loop/README.md)를 작성했으며, 사용자가 Disconnect 뒤 재접속과 M5 문서 확인 성공을 보고했다. 확인 메시지는 CRD로 보이는 노트북 대화 창에서 입력했다고 확인했으며 노트북에 새 원격 앱을 설치하지 않았다.

**환경 확인**: [M4 실측](20260923_M4_Chrome-Remote-Desktop.md#활동-4--iphone-모바일-데이터-첫-실측)에서는 iPhone 모바일 데이터 접속, 한글·영문 입력·저장, Windows 잠금·Disconnect·재접속이 작동했다. M5의 초기 실습은 집 안에서 iPhone Wi-Fi를 끈 모바일 회선 테스트였고, 그때는 외출 실측이 아니었다. 이후 9/27 Post & Pour 카페 Wi-Fi에서도 별도 실측을 완료했다. M5 모바일 회선의 LTE/5G 구분은 기록하지 않았다.

> 처음에는 글자가 작아서 읽기 힘들었지만 Pinch 로 화면을 확대할 수가 있어서 문제 없이 글을 읽을 수 있었습니다.

[[Journal/2026-09-27#Chrome Remote Desktop 비교 내용 승인 (구술 원문)|승인 원문]]은 다음과 같다. 내용 승인을 수신한 뒤 실제 후속 작업으로 M5 README, 외출 전 체크리스트, 폰 검토 안내서, 한 바퀴 기록, 여덟 동작 표, 입력 문제 해결 문서 여섯 개를 저장했다. 결과 확인 → 내용 판단 → 후속 작업은 진행됐으나, 승인 지시가 원격 노트북 창에서 입력됐는지는 아직 확인하지 못했다.

> 내용 승인 — 다음 실습 진행

## Disconnect 뒤 재접속과 결과 확인

사용자는 안내한 1번 단계인 Windows 잠금 → Disconnect → 재접속을 완료했고, M5 문서도 확인했다고 보고했다. 작성한 결과가 접속 종료 뒤에도 남아 있어 다시 검토할 수 있음을 확인했다. 원문은 [[Journal/2026-09-27#Chrome Remote Desktop M5 재접속 결과 (구술 원문)|Journal 원문]]에 보존했다.

> 1번 완료 했습니다. 재접속도 잘 됩니다.     재접속 후 M5 문서 확인 완료

이 결과는 저장된 문서를 재확인한 실측이다. 접속이 끊긴 동안 실행 중이던 긴 작업이 계속 진행됐다는 검증과는 구분한다. 사용자는 확인 메시지를 CRD로 보이는 노트북 대화 창에서 입력했다고 확인했다.

## 테스트 장소와 회선

장소·회선 보충 보고 원문을 [[Journal/2026-09-27#Chrome Remote Desktop M5 테스트 장소와 회선 (구술 원문)|Journal 원문]]에 보존했다. 초기 결과는 집 안에서 iPhone Wi-Fi를 끈 모바일 회선 테스트로 분류했다. 이후 집 밖 실측은 [Post & Pour 기록](#집-밖-접속--post--pour)에 추가했다.

> 집 안에서 테스트 했고 WiFi 를 Off 로 한 상태에서 테스트 했습니다.

### 집 밖 접속 — Post & Pour

2026-09-27 저녁, 사용자가 Post & Pour 카페에서 iPhone을 카페 Wi‑Fi에 연결하고 집 노트북 `CatchUpAI_laptop`으로 CRD 접속을 시도했다. 접속에 성공했으며 사용자가 보고한 연결 시간은 대략 5초다. 이 결과는 집 밖 카페 Wi‑Fi 경로의 첫 접속 성공을 확인한다. 이후 같은 연결에서 문서 읽기·검토, 짧은 원격 입력, 저장 결과와 Disconnect 후 재접속은 아직 진행 중이며 결과를 별도로 기록한다.

> 접속에 성공 했고 대략 5초 정도 걸렸습니다.

#### M7 기획안 원격 열람

사용자는 CRD로 노트북 화면에서 M7 기획안을 확인했고 읽기 편했다고 보고했다. 슬라이드 플랜 수정 의견이 있으나 현재는 iPhone 외부 접속 실험 중이므로 편집은 나중으로 미룬다. 다음 동작은 CRD 화면을 통해 노트북의 대화 입력창에 테스트 문구를 보내는 것이다.

> 예 M7 기획안이 잘 보입니다. 읽기 편했습니다. 슬라이드 플랜 관련해서 수정고 싶은 부분이 있지만 지금은 아이폰에서 테스트하는 과정이라 그것은 나중에 하겠습니다.

#### 카페에서 원격 입력

사용자는 안내한 테스트 입력을 마쳤다고 보고했다. 이를 집 노트북 CRD 화면에서의 원격 대화 입력으로 기록한다. 입력 문구가 Disconnect 후 재접속 뒤에도 남아 있는지 확인은 아직 남았다.

> 입력 완료

#### 집 밖에서 잠금 화면 확인

사용자는 Post & Pour에서 CRD로 집 Windows 노트북을 잠근 뒤 잠금 화면이 CRD에 보인다고 확인했다. 이제 Disconnect 후 같은 카페 회선으로 재접속해 입력과 문서가 유지되는지 확인한다.

> 잠금 화면이 CRD 에 보입니다.

#### 집 밖에서 Disconnect

사용자는 Post & Pour에서 CRD Disconnect를 완료했다고 보고했다. 다음 단계는 같은 카페 Wi‑Fi에서 `CatchUpAI_laptop`으로 재접속하고, 잠금 화면을 로컬 로그인 정보로 해제한 뒤 테스트 입력과 기획안이 보존됐는지 확인하는 것이다.

> Disconnect 됐습니다.

#### 집 밖에서 재접속

사용자는 Post & Pour 카페 Wi‑Fi에서 `CatchUpAI_laptop` 재접속에 성공했고 컴퓨터 화면이 정상 표시된다고 확인했다. 이제 노트북 대화창의 테스트 문구와 M7 문서가 세션 종료 뒤에도 남아 있는지 확인한다.

> 예 재접속 성공했고 컴퓨터 화면이 잘 뜹니다.

#### 재접속 뒤 원격 입력 이력 유지

사용자는 Disconnect·재접속 후 노트북 대화창의 `M5 카페 Wi‑Fi 입력 테스트 — Post & Pour` 문구가 계속 남아 있다고 확인했다. 이는 외부에서 보낸 대화 입력이 연결 종료 뒤에도 대화 이력에서 확인되는 결과다. M7 파일을 재접속 뒤 다시 여는 확인은 남았다.

> 예 그 문구가 계속 남아 있습니다.

#### 재접속 뒤 M7 문서 유지

사용자는 재접속 뒤 M7 기획안을 다시 열어 내용이 그대로 보인다고 확인했다. Post & Pour 카페 Wi‑Fi에서 CRD 접속 → 문서 열람 → 원격 대화 입력 → Windows 잠금 → Disconnect → 재접속 → 입력 이력과 문서 재확인의 순환이 성공했다. 이번 접속을 Windows 잠금 화면 확인 후 Disconnect로 안전하게 종료한다.

> 예 다시 열었고 그 내용이 그대로 보입니다.

사용자는 마지막으로 Windows 잠금 화면을 확인한 뒤 Disconnect까지 완료했다고 보고했다. 이로써 집 밖에서 시작한 카페 Wi‑Fi 세션도 잠금 후 안전하게 끝났다.

> 예 잠금화면이 보이고 Disconnect 까지 성공 했습니다.

## 원격 노트북 대화 창 입력

사용자는 재접속 결과 보고를 **CRD로 보이는 노트북 대화 창**에서 입력했다고 확인했다. 따라서 원격 화면에서 문서를 읽는 것뿐 아니라 AI 대화 창에 짧은 메시지를 보내는 동작도 성공으로 기록한다. 원문은 [[Journal/2026-09-27#Chrome Remote Desktop M5 원격 대화 입력 (구술 원문)|Journal 원문]]에 보존했다.

> CRD 로 보이는 노트북의 대화 창에서 입력 했습니다.

집 안·iPhone Wi-Fi Off 상태에서 문서 확인 → 내용 승인 → 후속 문서 작성 → 재접속 후 결과 확인 → 원격 창에서 보고까지 진행했다. 집 밖 실측과 실행 중 작업의 Disconnect 후 지속 여부는 아직 검증하지 않았다.

## DoD 진행

- [x] 외출 상태에서 확인 → 원격 입력 → 후속 기록 작업 한 바퀴 — Post & Pour에서 M7 문서 읽기, 수정은 나중에 하겠다는 판단, 집 노트북 대화창 테스트 입력 및 M5 기록 후속 갱신
- [x] 되는 일/안 되는 일 8항목 이상 기록 — 집 밖 Wi‑Fi 실측을 반영하고 미확인 동작은 그대로 표시
- [x] 외출 전 체크리스트 1장 작성·사용 — 사용자 완료 보고 확인
- [x] 세션 종료 후 결과 재확인 — 카페에서 Disconnect 뒤 재접속하여 입력 문구와 M7 파일이 그대로 보임. 별도 45초 백그라운드 작업도 확인; 장기 렌더는 미실측
- [x] README·링크·WorkLog·Retrospective 최종 점검 — 문서 상태와 실측 기록을 맞췄다. 카페 실측 후 추가한 내부 링크는 대상 파일·섹션을 수동 확인했다. 전체 링크 스크립트는 실행 환경 프로세스 초기화 오류로 재실행하지 못했다; 이전 점검은 173개 정상.
- [x] 학습자가 M5 문서를 검토 — 사용자가 「M5 문서들 리뷰 했습니다. 잘 정리 했습니다. 검토 결과 승인 입니다.」라고 확인

**완료율**: 6/6 — 2026-09-27. Post & Pour 카페 Wi‑Fi에서 약 5초 만에 집 노트북에 접속했고, M7 문서를 읽고 원격 대화 문구를 입력했다. Windows 잠금 → Disconnect → 같은 카페 Wi‑Fi에서 재접속 → 입력 문구와 문서 유지 → 다시 잠금·Disconnect까지 성공했다. 사용자가 M5 안내서 전체를 검토하고 승인했다.

## 다음 확인

M5의 집 밖 실측과 문서 검토·승인을 완료했다. 자동 링크 스크립트는 실행 환경 초기화 오류로 재실행하지 못했으나 이전 173개 링크 검사는 정상이었고, 이번에 추가한 내부 링크의 대상과 섹션을 수동 검증했다. 다음 모듈은 M7이며 슬라이드 수정 의견은 사용자가 원할 때 반영한다.

## Daily Retrospective

집 안에서는 iPhone Wi-Fi를 끈 상태로, 집 밖에서는 Post & Pour 카페 Wi‑Fi를 통해 CRD를 확인했다. 카페에서 첫 접속은 약 5초였고, 문서 열람·원격 대화 입력·잠금·Disconnect·재접속·입력과 문서 재확인·최종 잠금 종료까지 완료했다. 같은 원격 문서 확인 흐름이 실제 외출 환경에서도 작동했지만, 이 결과는 한 카페의 한 회선에 한정된다. 사용자는 M5 문서가 잘 정리되었다고 확인하고 승인했다. 자동 링크 검사기는 이 세션에서 시작되지 않아 추가한 링크는 파일·섹션을 직접 확인했으며, M7 기획안 수정은 사용자가 원할 때 진행한다.

## Disconnect 중 실행 지속 실험

Windows 백그라운드 작업이 CRD 연결과 별도로 45초 대기한 뒤 이 WorkLog에 완료 시각을 기록했다. 완료 시각 (Seattle): **2026-09-27 20:03:45 -07:00**. 사용자는 CRD를 끊었다가 재접속한 뒤 이 문장이 잘 보인다고 확인했다. 이 실험은 짧은 백그라운드 작업의 지속을 검증한다. 영상 렌더처럼 긴 작업의 품질·완료 여부까지 검증한 것은 아니다.
