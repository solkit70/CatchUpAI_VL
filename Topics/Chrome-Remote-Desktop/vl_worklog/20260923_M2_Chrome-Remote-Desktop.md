## 진행 내용

### 활동 1 — 실습 범위 조정

**시간**: 05:12~05:15

**목적**: 보유하지 않은 Android 기기를 전제로 학습이 멈추지 않도록 하면서, 검증하지 않은 내용을 검증한 것처럼 기록하지 않는다.

**과정**:

1. 사용자가 Android 폰을 보유하지 않아 해당 실습이 어렵다고 밝혔다.
2. 기존 iPad에서 Safari 웹앱 접속, 집 Wi‑Fi, LTE 핫스팟, 한글 입력, `Ctrl+S` 저장까지 성공한 기록을 재확인했다.
3. M2의 환경 조정 완료 기준을 **보유한 외부 모바일 기기 1대에서 서로 다른 두 회선 조건으로 실제 작업 성공**으로 변경하기로 했다.

**결과**:

- Android 앱 방식은 **미검증 범위**로 명시한다.
- iPad 실측 결과만 M2 완료 판단에 사용한다.
- PIN 오입력과 인터넷 단절은 iPad에서 추가로 확인한다.

**메모/인사이트**: 장비가 없는 실습을 억지로 요구하면 학습이 중단된다. 대신 사용할 수 있는 장비에서 네트워크 조건과 실제 작업을 더 엄격하게 검증하고, 플랫폼 차이는 미검증으로 남기는 편이 재현성과 정직성을 함께 지킨다.

### 활동 3 — iPad 장애 상황 실측

**시간**: 2026-09-23 (사용자 실습, 세부 시각 미기록)

**목적**: 잘못된 PIN과 iPad 인터넷 단절 때 나타나는 메시지와 복구 절차를 확인한다.

**결과**:

| 조건 | 관찰한 화면 | 복구 |
|---|---|---|
| 잘못된 PIN 1회 입력 | “The PIN is invalid. Please try again, or visit g.co/crd/setup on the remote computer to change it.” | 올바른 PIN을 입력하자 정상 접속 |
| iPad Wi-Fi 끄기 | Safari가 iPad의 인터넷 연결이 없어 페이지를 열 수 없다고 표시 | Wi-Fi를 켜자 인터넷은 즉시 복구. 원격 접속에는 PIN 재입력 필요 |

**기록 범위**: 원본 캡처에는 계정 관련 정보가 있을 수 있어 Topic에 복사하지 않았다. 오류 문구와 복구 결과만 남긴다.

## 문제 해결 로그

### 문제 1 — Android 실습 기기 없음

**증상**: 이전 WorkLog와 Roadmap이 Android 폰을 두 번째 접속 기기로 예정했지만 사용자가 Android 기기를 보유하지 않는다.

**원인**: 로드맵 작성 때 실제 보유 장비를 충분히 반영하지 못했다.

**해결**: iPad에서 Wi-Fi와 LTE라는 서로 다른 실제 사용 조건을 검증한 결과로 M2를 평가하고, Android 앱 방식은 미검증 범위로 명시한다.

### 문제 2 — 잘못된 PIN과 iPad 인터넷 단절

**증상**: PIN 오입력 시 PIN 오류 메시지. iPad Wi-Fi를 끄면 Safari가 인터넷 연결 없음으로 페이지를 열지 못함.

**해결**: 올바른 PIN으로 다시 접속. 인터넷 단절은 iPad Wi-Fi를 켠 뒤 PIN을 다시 입력해 접속.
