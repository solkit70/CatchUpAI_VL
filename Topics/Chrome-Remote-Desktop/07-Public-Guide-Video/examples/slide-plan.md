## v4 에서 바뀐 것

Codex 가 만든 v3(21장)을 사용자 요청(2026-09-30)에 맞춰 고쳤다. 사용자 요청은 네 가지였다: ① 나레이션이 딱딱하니 **초심자가 따라 하기 쉽고 친근하게**, ② **길어져도 좋다**, ③ 카페에서 문서를 확인하는 것만 다루지 말고 **집 컴퓨터에서 AI(CLI)에게 계속 일을 시키는 사용법**을 다룰 것, ④ 에이전트 앱의 원격 기능이 막혔을 때 **앱을 다시 켜거나 컴퓨터를 다시 시작할 수 있는 장점**을 다룰 것(사실 확인 필요).

| 바뀐 곳 | v3 | v4 |
|---|---|---|
| 나레이션 | 설명문에 가까움 | 옆에서 같이 해 주는 말투 · 비유(리모컨 · 창문과 현관문) · 「화면에서 여기를 보세요」 · 헷갈리는 곳을 먼저 짚어 주기 |

## 영상의 목적과 스타일

**제목 후보**: 밖에서도 집이나 사무실 컴퓨터로 일하기 — 크롬 리모트 데스크톱 처음부터 따라 하기
**부제 후보**: 문서 확인부터 AI 에게 일 시키기까지, 아이패드 하나로

**대상**: 원격 접속을 처음 해 보는 한국어 시청자. 집이나 사무실에 둘 Windows 11 컴퓨터와 밖에서 쓰는 **iPad**를 기준으로 설명한다 (사용자 9/30 결정 — 기존 iPad 캡처와 C09 실측이 모두 iPad). iPhone도 Safari 브라우저로 같은 흐름이라 나레이션에서 짚고, Android 폰은 앱 설치부터 트랙패드 조작까지 보충 슬라이드로 안내한다. IT 지식을 가정하지 않는다. 집이나 사무실 컴퓨터에서 Claude Code · Codex 같은 AI 도구를 쓰는 사람에게는 PART 4가 추가로 도움이 된다.

**이 영상을 다 보면**: 집이나 사무실 컴퓨터를 준비하고 → 모바일 기기로 연결해 → 실제로 글을 쓰고 저장하고 → 안전하게 잠그고 끝낸 뒤 → 다시 들어와 확인하는 **한 바퀴**를 혼자 할 수 있다. AI 도구를 쓰는 사람은 밖에서도 원격 컴퓨터의 AI 작업을 지켜보고, 앱의 원격 기능이 멈췄을 때 **컴퓨터 화면으로 들어가 다시 켜는 방법**까지 안다.

**스타일**: 밝은 생활 속 실습 안내. 아이보리 `#FAF8F2` · 흰 패널 `#FFFFFF` · 코발트 블루 `#2563EB` · 민트 `#34D399` · 본문 먹색 `#18324A`. 밝은 종이 질감에 아주 느린 선 · 점 움직임. 실제 Windows 잠금 화면처럼 원본이 어두운 캡처만 흰 카드 안에 넣어 보여 준다.

**밝기 대역**: **L1 밝음** (배경보다 먼저 정함)
**직전 2편 대역**: `claude-mobile-remote` v4 **L2** → `bl5-sms-outro-0924` **L1**. 원장 규칙 ①은 다른 대역(L3/L4)을 권하지만, [영상 스타일 기준](../../../../../../AI/RemotionStudio/video-style-guide.md#밝고-읽기-편한-전체-분위기)의 **사용자 선호 「기본 화면은 밝고 선명하게」** 를 우선했다. 초심자 따라 하기 영상이라 밝은 쪽이 맞다. 직전 영상과의 차이는 색(민트-화이트 → 아이보리-코발트)과 레이아웃(실제 화면 캡처 + 확대 영역 연결)으로 만든다. ⚠️ **확인 요청**: 원장 권장과 다르므로 사용자가 L1 유지를 승인해 주면 확정한다.

**구성**: **28장**(기존 27장 + Android 보충 슬라이드 1장, 내용 24장 + 섹션 카드 4장) · edge-tts 초벌 음성 교체 후 길이를 다시 측정한다. 화면 위 작은 진행 리본으로 「PART 1 컴퓨터 준비 → PART 2 모바일 기기 연결 → PART 3 안전하게 끝내기 → PART 4 AI 와 함께 쓰기」를 늘 보여 준다.

**새 효과 (최소 2개)**: ① 스크린샷 전체 → 확대 영역을 선으로 잇는 「돋보기 연결」 ② 설치에서 재접속까지 이어지는 진행 리본(체크가 하나씩 채워짐) ③ PART 4 의 「창문 vs 현관문」 비교 일러스트 애니메이션. 제작 · 검수 뒤 실제 채택한 것만 [효과 라이브러리](../../../../../../_Settings_/Skills/remotion-video/effects-library.md)에 기록한다.

**시각 자료**: 실제 스크린샷 중심 + SVG 도식 + AI 이미지 3개 + AI 짧은 무음 영상 2개. 이미지 · 영상은 사용자가 직접 생성하도록 프롬프트만 준비한다(API 호출 없음). 실제 앱의 버튼 · 메뉴 · 성공 화면을 AI 로 만들어 대체하지 않는다.

**Remotion 자산 위치**: `AI/RemotionStudio/public/crd-guide-0927/` · video-id `crd-guide-0927`

## 나레이션 원칙 (v4)

- **옆에 앉아 같이 해 주는 말투**. 「~해 주세요」「~하시면 돼요」「여기서 많이들 헷갈리세요」. 설명문 어미(「~합니다. ~입니다.」의 연속)를 피하고 「~해요 / ~거든요 / ~죠」를 섞는다
- **한 장면 = 「지금 보이는 화면 → 누를 곳 → 나와야 할 결과」** 순서로 말한다. 결과를 확인할 1~2초 쉼을 둔다
- **쉬운 비유를 먼저, 용어는 나중에**: 호스트 → 「집이나 사무실에 두는 컴퓨터」, PIN → 「원격 접속용 숫자 비밀번호」, CLI → 「글자로 명령하는 작업 창」
- **헷갈리는 지점을 먼저 짚는다**: 「Chrome 에 추가했는데 끝이 아니에요」「비밀번호가 두 개예요」「연결 끊기와 잠그기는 달라요」
- **안심시키는 한마디**: 틀려도 괜찮은 곳은 괜찮다고 말해 준다. 위험한 곳(PIN 공유 · 결제)만 분명히 경고한다
- **사실 경계는 지키되 짧게**: 시험한 것과 안 한 것을 나누되, 한계 설명이 장면의 대부분을 차지하지 않게 한다
- **TTS 표기**: 제품명은 「크롬 리모트 데스크톱」, PIN 은 「핀」, Safari 는 「사파리」, Wi-Fi 는 「와이파이」, CLI 는 「씨엘아이」로 적는다. 화면 글자는 원래 표기를 둔다
- **음성 배분**: 기본 `nova 1.10` · 오프닝과 마무리 `shimmer 1.00~1.05` · PIN · 잠금 같은 안전 구간은 `onyx 1.05` 로 차분하게

## 장면별 계획과 나레이션 초안

> 나레이션은 플랜 검토용 초안이다. 슬라이드 플랜이 승인되면 다듬어 `gen_audio.py` 로 옮긴다.

### Slide 01 `[AI_VIDEO + TITLE]` — Hook

**화면**: 밝은 카페 무음 클립(V1) → 아이패드 화면에 실제 원격 접속 화면(C04)이 떠오르며 확대 → 제목 등장. 5초 안에 「컴퓨터 화면이 아이패드에 뜨는 장면」까지 보여 준다.
**화면 문구**: 「집이나 사무실 컴퓨터에서 AI 에게 일을 시켜 놓고 나왔는데… 잘 되고 있을까?」 → 제목

**나레이션** `[voice: shimmer | speed: 1.05 | 호기심]`:
> 집이나 사무실 컴퓨터에 AI 일을 맡겨 두고 카페에 나왔어요. 그런데 문득 잘 되고 있을까 궁금해지죠. 컴퓨터에 두고 온 문서도 확인해야 하는데요. 이럴 때 iPad로 그 컴퓨터 화면을 그대로 열 수 있다면 얼마나 편할까요? 오늘은 크롬 리모트 데스크톱을 처음부터 끝까지 같이 해 볼게요. 무료고요, 컴퓨터를 잘 몰라도 따라오실 수 있게 천천히 가겠습니다.

## C09 재부팅 시험 기록 (2026-09-30)

> Slide 26 의 「다시 시작 뒤 다시 연결된다」를 확인하는 시험이다. ⚠️ 이 PC(`CHANGSOO`)는 Claude Code 가 돌고 있는 바로 그 컴퓨터라, 다시 시작하면 **이 대화 세션도 끝난다.** 결과는 재부팅 뒤 새 세션에서 이 표에 채운다.

**시험 전 점검 (07:56 PDT, Claude Code 확인)**

| 항목 | 결과 |
|---|---|
| 호스트 서비스 `chromoting` | **Running · 시작 유형 Automatic** |
| 대기 중인 재부팅 (Windows 업데이트 · 구성 요소) | **없음** — 업데이트 설치 화면에 걸릴 가능성 낮음 |
| 마지막 부팅 | 2026-09-30 06:28 |
| BitLocker 부팅 전 PIN | 관리자 권한이 필요해 확인 못 함 — 부팅 때 PIN 을 묻는 설정이면 원격 재접속은 안 된다 |

**시험 순서**

1. 열린 작업을 모두 저장한다 (VS Code · 메모장 등)
2. **아이패드(밖에 있다고 가정, 가능하면 Wi-Fi 끄고 LTE)** 으로 크롬 리모트 데스크톱 연결
3. 원격 화면에서 시작 → 전원 → **다시 시작** — 이 순간 시각을 적는다 (캡처 ①)
4. 연결이 끊긴 화면 캡처 ②
5. 아이패드 목록에서 컴퓨터가 **오프라인 → 온라인**으로 바뀌는지 20~30초마다 새로고침 — 온라인이 된 시각을 적는다 (캡처 ③)
6. 다시 연결 → 핀 → **Windows 잠금 · 로그인 화면**이 보이는지 (캡처 ④)
7. 원격으로 Windows 로그인 → 바탕화면이 뜨는지 (캡처 ⑤) → 다시 잠그고 연결 끊기

**결과 (재부팅 뒤 채움)**

| 항목 | 결과 |
|---|---|
| 다시 시작 누른 시각 | **07:59:22 PDT** — Windows 시스템 로그(이벤트 1074, 시작 메뉴에서 다시 시작) |
| Windows 가 다시 켜진 시각 | **07:59:50** 부팅 → 08:00:14 이벤트 로그 서비스 시작 (시스템 로그 · `LastBootUpTime`) — 누른 뒤 **약 30초** 만에 다시 켜짐 |
| `chromoting` 서비스 | 재부팅 뒤 **Running · Automatic** (08:04 확인) |
| 2차 시험 (캡처용) | **08:09:25** 다시 시작(이벤트 1074) → **08:09:46** 부팅 → 08:10 잠금 화면에 연결 → 08:10~08:11 바탕화면 (캡처 시계) |
| 다시 연결까지 걸린 시간 | ✅ **1~2분** (사용자 체감, 두 번 시험) |
| 다시 연결 성공 여부 | ✅ **성공 · 2회** — 사용자 9/30: 「Restart 는 성공 했습니다」 |
| 로그인 전 화면(잠금 화면)에 바로 연결됐나 | ✅ 된다 — 재부팅 뒤 아무도 로그인하지 않은 상태에서 **Windows 잠금 화면으로 연결**됐다 (`c09_4_lockscreen`) |
| 원격으로 Windows 로그인 됐나 | ✅ 된다 — 잠금 화면에서 로그인해 바탕화면까지 (`c09_5_desktop`) |
| **예상과 다른 점** | 연결이 끊겼을 때 목록의 컴퓨터가 **오프라인으로 바뀌지 않고 계속 「Online」으로 보였다.** 대신 화면 **왼쪽 아래에 「Your Chrome Remote Desktop session has ended. RECONNECT」** 알림이 잠깐 떴다가 사라졌다 (`c09_2_disconnected`). 그래서 「오프라인 → 온라인」을 보고 기다리는 방법은 쓸 수 없고, **1~2분 기다렸다가 컴퓨터를 눌러 다시 연결**하는 방법이 맞다 |
| 촬영 기기 | **iPad** (캡처 2732×2048) — 영상 기준 기기도 iPad 로 확정 (9/30) |

**캡처 파일** (`AI/RemotionStudio/public/crd-guide-0927/captures/raw/`): `c09_1_restart` · `c09_2_disconnected` · `c09_4_lockscreen` · `c09_5_desktop`. 목록이 계속 Online 이라 `c09_3_online` 은 없다.

**가림 처리 필요 (masked 버전에서)**: 원격 화면 아래의 초록 막대 「Your desktop is currently shared with (이메일)」의 이메일 · 시작 메뉴의 사용자 이름 · 오른쪽 아이패드 연결 패널의 기기 이름 · 통화 기록(이름 · 전화번호) · 최근 파일 이름 · 목록 화면의 프로필 사진 · 잠금 화면 날씨의 지역 이름 · 바탕화면 아이콘 중 금융 · 개인 파일 이름.
