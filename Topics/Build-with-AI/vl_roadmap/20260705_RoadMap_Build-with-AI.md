**생성일**: 2026-07-05
**방법론**: VibeLearn AI
**버전**: 1.0

## 📊 학습 기간 적정성 분석

**사용자 입력 기간**: 1주 또는 4-6시간 집중 연구
**Topic 복잡도**: 중간
**권장 기간**: 1주, 총 6.5-8시간

**분석 결과**:
- ⚠️ **부분적으로 짧음**: Build with AI 12부작을 읽고 영상 angle과 brief를 만드는 범위라면 4-6시간도 가능하다.
- ⚠️ **영상 작업 착수까지 포함하면 부족함**: 스크립트, 슬라이드 플랜, 시각 자료 후보, 제작 체크리스트까지 만들려면 6.5-8시간이 더 현실적이다.
- ✅ **범위 조정 가능**: 이번 Roadmap은 "첫 영상 제작 착수 패키지"를 목표로 하고, 완성 영상 렌더링은 후속 Topic 또는 별도 제작 세션으로 분리한다.

**조치 제안**:
- 현재는 사용자의 요청대로 연구와 영상 작업 시작을 목표로 진행한다.
- 전체 영상 완성까지 확장하려면 M5 이후에 `Remotion` 또는 별도 영상 제작 Roadmap을 추가한다.

**사용자 확인 필요**:
- 현재 Roadmap은 "첫 영상의 연구, angle, script starter, slide plan, production package"까지 다룬다.
- 완성 영상 렌더링까지 포함하려면 학습 기간을 늘리거나 별도 제작 Roadmap으로 분리한다.

## 📚 학습 개요

### Topic 소개

Build-with-AI는 송재희님의 Build with AI 12부작 자료를 학습하고, Catch Up AI / Builders Lounge 관점에서 "AI로 데모는 만들었는데 왜 서비스는 안 되는가"라는 영상 산출물로 전환하는 Topic이다. 핵심 연구 축은 비개발자 빌더, 문제 구조화, 데이터/워크플로 병목, 에이전트/바이브 코딩, 데모에서 프로덕션으로 넘어가는 기준이다.

> **🔄 순서 재구성 (2026-07-05)**: 원래 계획은 처음부터 "영상으로 쓸 수 있는가"를 기준으로 원문을 분류하는 순서였다. 사용자 피드백에 따라 **원문을 실제로 읽고 이해하는 것을 최우선**으로 바꾼다. 영상 관련 산출물(Source Map, Angle, Script, Slide, Package)은 그 이해에서 자연스럽게 나오는 결과물이며, 학습 → 산출물 → 영상 제작 순서로 진행한다. M1의 첫 실습이 "완독 및 이해"로 바뀐 것이 이 재구성의 핵심이다.

### 학습 목표

- Build with AI가 어떤 자료인지, 공식 다운로드 위치와 로컬 원본 파일 위치를 먼저 확인한다.
- Build with AI 완전판을 실제로 읽고, 각 파트의 핵심 주장을 자신의 언어로 설명할 수 있다 (최우선 목표).
- 그 이해를 바탕으로 Build with AI 12부작의 전체 구조와 핵심 메시지를 Source Map으로 정리한다.
- Builders Lounge Product Discovery 및 Bila AI Agent 프로젝트와 연결되는 영상 논지를 도출한다.
- 첫 영상의 타깃 시청자, 후킹 질문, 스토리라인, 시각 자료 후보를 정리한다.
- 후속 영상 제작을 위한 브리프와 스크립트 초안을 만든다.

### 예상 학습 기간

## 📖 모듈별 상세 계획

### M1 - Build with AI 원본 자료 확인·완독·이해 → Source Map/Thesis

**난이도**: ⭐
**예상 시간**: 2.5h
**산출물 폴더**: `01-Source-Map/`

> **재구성 안내**: 실습1이 "영상 분류"에서 "완독 및 이해"로 바뀌었다. 영상 매핑(실습2)은 실습1의 이해가 끝난 뒤에만 진행하며, 원문을 다시 읽지 않고 실습1 노트를 근거로 정리한다.

#### 학습 목표

- [ ] Build with AI가 어떤 자료인지, 공식 다운로드 위치와 Topic 안의 로컬 PDF/EPUB/치트시트 위치를 설명할 수 있다.
- [ ] Build with AI 완전판(`build-with-ai-complete-ko.pdf`)을 실제로 읽고, 각 파트의 핵심 주장을 자신의 언어로 설명할 수 있다.
- [ ] AI가 작성한 `reading-notes.md` 초안을 사용자가 직접 읽고, 동의/수정/반박/추가 생각을 자신의 언어로 정리한다.
- [ ] "데모에서 서비스로 넘어가는 벽"이 왜 생기는지 원문 근거로 설명할 수 있다.
- [ ] (이해 완료 후) 읽으며 남긴 노트를 Source Map과 핵심 thesis로 정리한다.

#### 주요 개념

1. **비개발자 빌더**: 코딩 직군이 아니어도 AI 도구로 실제 작동하는 산출물을 만들 수 있는 사람을 뜻한다. 오해하기 쉬운 점은 "코딩을 몰라도 된다"가 아니라 "문제 구조화가 더 중요하다"는 점이다.
2. **AI 레고 스택**: 여러 AI 도구와 데이터, 자동화 도구를 조합해 작업 흐름을 만드는 관점이다. 단일 도구의 기능보다 조합 구조가 중요하다.
3. **데모-서비스 간극**: 통제된 입력에서 작동하는 데모와 실제 사용자/데이터/운영 책임을 견디는 서비스 사이의 차이다.
4. **검증 경계**: AI가 만든 결과를 어디까지 자동 처리하고 어디서 사람이 확인해야 하는지 정하는 기준이다.
5. **Source Orientation**: 학습 전에 원본 자료의 성격, 공식 배포 위치, 로컬 보관 위치, 보조 자료의 역할을 확인하는 단계다.

#### 실습 과제

**실습 0: 원본 자료 확인 및 학습 입구 정리** ⭐ (최우선)
- **목적**: Build with AI가 어떤 자료인지, 원본은 어디에 있는지, 어떤 순서로 읽을지 먼저 정리한다.
- **단계**:
  1. `01-Source-Map/source-materials.md`에서 Build with AI 설명, 공식 홈, 다운로드 페이지를 확인한다.
  2. `vl_materials/` 안의 완전판 PDF/EPUB과 치트시트 4종 한/영 자료를 확인한다.
  3. 주 학습 자료는 `build-with-ai-complete-ko.pdf` 또는 `.epub`, 대조 자료는 `build-with-ai-complete-en.pdf`로 정한다.
  4. 치트시트는 본문 학습 뒤 복습/도식 후보로 사용한다고 기록한다.
- **예상 시간**: 30분
- **검증**: `01-Source-Map/source-materials.md`에 Build with AI 설명, 공식 다운로드 정보, 로컬 원본 파일 목록, 학습 순서가 있다.

**실습 1: Build with AI 완독 및 이해 노트 작성** ⭐ (최우선)
- **목적**: 원문을 실제로 읽고 이해한다. 이 단계에서는 영상 활용 여부를 판단하지 않는다.
- **단계**:
  1. `vl_materials/build-with-ai-complete-ko.pdf`(또는 `.epub`)를 처음부터 끝까지 읽는다. 필요하면 하위 챕터(`prompt-patterns-ko.pdf`, `ai-lego-stack-ko.pdf`, `trust-tier-ko.pdf`, `data-readiness-ko.pdf`)도 참고한다.
  2. **한국어 표현이 어색하거나 의미가 모호한 부분은 영어 원문(`build-with-ai-complete-en.pdf` + 하위 챕터 EN 4종)을 함께 대조해서 정확한 의미를 확인한다.** 한국어판은 영어 원문의 번역본으로 보이며, 번역 과정에서 뉘앙스가 달라진 부분이 있을 수 있다.
  3. 각 파트를 읽으며 핵심 주장을 1-2문장으로 **자신의 언어**로 적는다.
  4. 이해가 안 되거나 모호한 부분은 표시해두고, 다 읽은 뒤 다시 확인한다.
- **예상 시간**: 75분
- **검증**: 12개 파트 모두에 대해 "내 언어로 된 핵심 주장"이 `reading-notes.md`에 있다 (아직 영상 분류 없음). 한/영 대조가 필요했던 부분은 어느 표현을 기준으로 삼았는지 노트에 남긴다.

**실습 2: 이해 노트 → Source Map/Thesis 정리** ⭐⭐ (실습1 완료 후에만 진행)
- **목적**: 실습1에서 쌓인 이해를 영상 매핑과 핵심 thesis로 정리한다. 원문을 다시 읽는 작업이 아니라 이해를 정리하는 산출물 작업이다.
- **단계**:
  1. `reading-notes.md`를 기준으로 12개 파트를 `source role`/`video use`로 분류한다.
  2. `데모`, `서비스`, `문제 구조화`, `데이터`, `검증` 키워드로 핵심 thesis 문장을 만든다.
  3. Builders Lounge/Bila AI Agent 연결 문장 1개를 작성하고 출처를 표시한다.
- **예상 시간**: 35분
- **검증**: `01-Source-Map/build-with-ai-source-map.md`에 12개 파트 매핑 + thesis가 포함된다.

### M2 - Audience and Product Discovery Angle

**난이도**: ⭐⭐
**예상 시간**: 1.25h
**산출물 폴더**: `02-Video-Angle/`

#### 학습 목표

- [ ] 첫 영상의 타깃 시청자를 구체적인 막힘 상황으로 정의한다.
- [ ] Build with AI 전체 소개형과 문제 중심형 angle을 비교해 1개를 선택한다.
- [ ] Builders Lounge Product Discovery와 Bila AI Agent 연결을 본론/bridge/후속 주제로 분리한다.

#### 주요 개념

1. **Audience Fit**: 영상이 누구의 어떤 문제를 해결하는지 맞추는 작업이다. 넓은 대상보다 구체적인 막힘이 더 중요하다.
2. **Product Discovery**: 사용자의 문제, 니즈, 반복 행동, 검증 기준을 찾아 제품 가설로 만드는 과정이다.
3. **Bridge Topic**: 본론을 흐리지 않으면서 다음 영상이나 프로젝트로 연결하는 보조 주제다.
4. **Review Decision**: 사용자가 승인해야 할 제작 방향 선택지다.

#### 실습 과제

**실습 1: Angle 후보 비교** ⭐
- **목적**: 첫 영상을 너무 넓게 만들지 않기 위해 후보를 비교한다.
- **단계**:
  1. Build with AI 전체 소개형 angle을 작성한다.
  2. 데모-서비스 전환 문제형 angle을 작성한다.
  3. Catch Up AI 시청자 적합성 기준으로 비교한다.
- **예상 시간**: 25분
- **검증**: 추천 angle과 보류 angle이 명확히 분리된다.

**실습 2: Story Flow 설계** ⭐⭐
- **목적**: 8-12분 영상의 흐름을 만든다.
- **단계**:
  1. Hook, Source Setup, Barrier 1-3, Bridge, Close 구조를 작성한다.
  2. 각 segment의 목적과 자료 연결을 표로 만든다.
  3. 사용자가 승인해야 할 결정 사항을 마지막에 분리한다.
- **예상 시간**: 35분

### M3 - Script Starter and Narrative Design

**난이도**: ⭐⭐
**예상 시간**: 1.5h
**산출물 폴더**: `03-Video-Starter/`

#### 학습 목표

- [ ] 첫 영상의 opening script를 30-60초 분량으로 작성한다.
- [ ] 핵심 설명 block을 5개 이하로 정리한다.
- [ ] 각 block을 Source Map과 연결해 근거 없는 주장으로 흐르지 않게 한다.

#### 주요 개념

1. **Hook**: 시청자가 이미 겪은 문제를 첫 문장에 호출하는 장치다.
2. **Promise**: 영상을 끝까지 봤을 때 얻는 결과를 명확히 말하는 문장이다.
3. **Explanation Block**: 영상 본문을 구성하는 독립 설명 단위다.
4. **CTA**: 다음 행동을 요청하는 마무리다. 이번 영상에서는 리뷰/후속 실험 예고가 CTA가 된다.

#### 실습 과제

**실습 1: Opening Script 작성** ⭐

- **단계**:
  1. 시청자 문제를 1문장으로 호출한다.
  2. Build with AI 자료 출처를 짧게 소개한다.
  3. 오늘 설명할 벽을 3개로 예고한다.
- **예상 시간**: 25분
- **검증**: 30-60초 안에 읽히는 opening script가 생성된다.

**실습 2: Explanation Blocks 구성** ⭐⭐
- **목적**: 영상 본문을 제작 가능한 단위로 나눈다.
- **단계**:
  1. `Demo is easy to show`, `Service must survive reality`, `Coding is not the first bottleneck` 등 block을 정한다.
  2. 각 block마다 메시지와 source connection을 기록한다.
  3. 불필요한 도구 나열을 제거한다.
- **예상 시간**: 40분
- **검증**: `03-Video-Starter/video-brief.md`의 Key Explanation Blocks가 완성된다.
