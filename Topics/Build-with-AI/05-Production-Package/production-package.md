## Status

이 문서는 2026-07-19 M5 학습 진행으로 작성한 Build with AI 첫 영상 제작 착수 패키지다. M1-M4 산출물을 통합해, 실제 스크립트 작성·슬라이드 제작·영상 제작으로 넘어가기 위한 기준 문서로 사용한다.

## Final Recommendation

첫 영상은 **송재희님의 Build with AI 12부작 전체를 비개발자·시니어 도메인 전문가에게 쉽게 설명하는 통합 해설 영상**으로 제작한다. 12개 Part를 이번 영상 안에서 모두 다루되, 원문을 길게 해설하는 방식이 아니라 각 Part의 핵심을 쉬운 말로 설명하고, 사용자의 의견과 실제 경험을 붙여 이해를 돕는 방식으로 구성한다.

## Target Viewer

대상은 도메인 지식은 풍부하지만 컴퓨터·IT에는 익숙하지 않은 비개발자, 특히 시니어 도메인 전문가다. 이들은 자기 분야의 문제, 고객, 현장 경험, 반복 업무를 잘 알고 있지만, 그것을 앱·자동화·워크플로·교육 자료·업무 보조 제품으로 바꾸는 데에는 익숙하지 않다.

이 영상은 그런 분들에게 "AI가 모든 것을 대신해 준다"는 환상을 주기보다, 자기 도메인 지식을 AI에게 설명하고 제품화하려면 어떤 생각의 순서를 가져야 하는지 알려준다.

## Core Promise

시청자는 Build with AI 12부작의 각 Part가 무엇을 말하는지 쉬운 말로 이해하고, 자기 도메인 지식을 AI 제품으로 바꾸기 위해 준비해야 할 다섯 가지를 얻는다.

1. AI를 버튼이 아니라 협업자로 대하는 관점
2. 자기 경험과 기록을 AI에게 줄 context로 만드는 법
3. 문제와 사용자를 먼저 정의하는 이유
4. 데모와 다른 사람이 쓰는 제품의 차이
5. AI를 리드하거나 전문가와 협업해야 하는 현실적 태도

| 3. 대상 시청자 선언 | 1:20-2:00 | 도메인 지식은 많지만 컴퓨터에 익숙하지 않은 비개발자·시니어 대상 명확화 | 3요소 카드 |

| 6. Part 3-6 | 4:20-6:20 | 재료와 브리핑: 맥락, 데이터, 문제 정의, 프롬프트. 도메인 지식과 기록의 가치를 강조한다. | 도메인 지식→AI 브리핑 흐름 |
| 7. Part 7-9 | 6:20-8:10 | 만드는 방식: Agent, 바이브 코딩, 코드 어시스턴트. 계획 없이 만들면 생기는 위험도 함께 설명한다. | 3도구 비교 표 |
| 8. Part 10-11 | 8:10-10:00 | 남이 쓰는 제품의 벽: 배포, 검증, 책임. 실제 경험 사례로 이해를 돕는다. | 데모→제품 체크리스트 |
| 9. Part 12 | 10:00-10:50 | 도메인 지식과 AI 활용 능력의 장기 가치 | 도메인 지식+AI 활용 능력=해자 |
| 10. 사용자 해석 통합 | 10:50-12:20 | 기록/context, AI 리드, 전문가 협업 필요성을 12부 전체 결론으로 연결 | 배워서 리드하기 vs 전문가 협업하기 |

**Length note**: 12개 Part를 이번 영상에서 모두 다루므로 권장 길이는 12-14분이다. 8-12분 안에 억지로 압축하기보다, 각 Part의 쉬운 설명과 사용자 의견/예시가 살아나는 길이를 우선한다.

## Part-by-Part Coverage Rule

각 Part는 영상 안에서 다음 3요소를 가진다.

| 요소 | 내용 |
|---|---|
| 원문 핵심 | Build with AI 해당 Part가 말하는 핵심을 1-2문장으로 소개 |
| 쉬운 설명 | 컴퓨터·IT에 익숙하지 않은 도메인 전문가도 이해할 수 있는 생활 언어로 재설명 |
| 사용자 의견/예시 | 사용자의 관점, 실제 경험, 또는 적용 예시를 짧게 붙여 이해를 도움 |

이 규칙 때문에 이번 영상은 단순 12부 목록 소개가 아니라, **Build with AI를 사용자의 타깃 시청자에게 맞게 다시 해설하는 영상**이 된다.

## Opening Script

요즘 AI를 보면 이런 생각이 듭니다. "이제 코딩을 몰라도 내 아이디어를 앱이나 서비스로 만들 수 있는 시대가 온 것 아닐까?" 특히 자기 분야에서 오랫동안 경험을 쌓아 온 분들에게는 이 변화가 굉장히 중요합니다. 예전에는 아이디어가 있어도 개발자를 찾아야 했지만, 이제는 AI와 대화하면서 직접 초안을 만들고, 고치고, 실험해 볼 수 있기 때문입니다.

오늘 소개할 자료는 시애틀에 계신 송재희님이 자신의 경험을 바탕으로 정리한 **Build with AI**입니다. 이 자료는 단순한 AI 도구 목록이 아니라, 비개발자가 AI와 함께 실제 결과물을 만들기 위해 어떤 생각의 순서를 가져야 하는지 12부로 정리한 가이드입니다.

저는 이 내용을 도메인 지식은 많지만 컴퓨터에는 익숙하지 않은 분들도 이해할 수 있게 쉬운 말로 풀어보려고 합니다. 핵심은 하나입니다. 여러분의 도메인 지식은 AI 시대의 큰 자산입니다. 다만 AI가 모든 것을 대신해 주지는 않기 때문에, 문제를 정의하고, 맥락과 데이터를 준비하고, 검증과 책임을 생각하면서 AI를 리드하는 법을 배워야 합니다.
