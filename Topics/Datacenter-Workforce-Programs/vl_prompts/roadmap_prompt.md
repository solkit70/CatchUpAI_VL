### ⚠️ 이 Topic 고유의 설계 제약 (로드맵에 반드시 반영)

**1. 범위가 둘이다 — 모듈을 두 구간으로 나눈다**

| 구간 | 범위 | 목적 |
|---|---|---|
| 전반부 | 미국 전 지역 | 커뮤니티·시청자 정보 제공 |
| 후반부 | 워싱턴주 + 원격·온라인 가능 경로 | 본인이 실제로 지원 |

**2. 외부 마감일이 로드맵을 앞지를 수 있다**

지원에는 모집 기간(intake window)이 있다. 로드맵 후반에 가서야 마감을 확인하면
이미 닫혀 있을 수 있다.

→ **초반 모듈(M2)에 "모집 주기·마감일 조기 스캔"을 넣는다.** 로드맵 기간 안에 닫히는
  프로그램이 있으면 그 건만 지원 준비를 앞으로 당기는 규칙을 로드맵에 명시한다.

**3. 실제 제출은 사람이 한다**

지원서 제출은 되돌리기 어렵고 외부로 나가는 행동이다.
→ AI는 요건 정리·서류 초안·체크리스트까지 만들고 **제출 직전 사용자 확인**을 받는다.
  개인정보가 들어가는 문서는 볼트의 개인정보 취급 규칙을 따른다.

**4. 트랙을 미리 정하지 않는다**

숙련직과 기술직은 요건·기간·수입·신체 조건이 전부 다르다. 한쪽으로 미리 기울면
다른 쪽 정보가 부실해진다. → 적합성 판별 모듈 전까지는 **양쪽을 같은 깊이로** 조사한다.

**5. 이 Topic의 "실습"은 코드가 아니다**

실습 과제는 실제 조사·연락·서류 작성이다. "검증 방법"도 그에 맞게 쓴다
(예: "기관 3곳의 담당자 연락처와 다음 모집 시작일을 표로 확보").

- 명확한 성공 기준 제시

##### 4. AI 시대 학습 범위
**인간이 알아야 할 것**:
- 개념적 이해 (무엇, 왜, 언제)
- 아키텍처 및 구조
- AI에게 효과적으로 지시하는 방법
- 기본 사용 패턴 (3-5개 핵심 기능)

**암기 불필요**:
- 상세 API 파라미터 목록
- 모든 옵션과 플래그
- 내부 구현 디테일

##### 5. 산출물 중심
- 매 모듈마다 폴더 생성 (`01-xxx/`, `02-xxx/`)
- **"교과서 품질"**: 다른 학습자가 이것만으로 학습 가능한 수준
- **README.md는 반드시 포함** — 아래 내용을 갖춰야 함:
  - 모듈 번호/제목/상태/예상 학습 시간 헤더
  - 이 폴더의 모든 문서를 **학습 순서대로** 번호 매겨 나열
  - 각 문서에 **상대 경로 링크** (예: `[concepts/overview.md](concepts/overview.md)`)
  - 각 문서마다 1줄 설명 (무엇을 배우는 문서인지)
  - 이전/다음 모듈 링크
  - **처음 이 폴더를 여는 사람이 README만 보고 순서대로 학습 가능한 수준**

##### 6. 환경 고려
- 사용자가 입력한 OS/도구에 맞는 명령어 사용
- Windows: PowerShell 명령어
- macOS/Linux: Bash 명령어
- 경로 표기도 OS에 맞게 조정
