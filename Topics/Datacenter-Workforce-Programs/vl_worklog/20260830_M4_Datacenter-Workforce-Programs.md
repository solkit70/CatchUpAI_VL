## 📚 진행 내용

### 1. 실습 1 — 클러스터 목록화

**순서**: 첫 번째.

용량 자료가 **단위가 섞여 있었다.** 콜로케이션 상면 전력(북버지니아 4,000MW)과 주 단위 인입/계획 용량(텍사스 127,662MW)이 같은 검색 결과에 나온다. 30배 차이라 한 표에 넣으면 순위가 뒤집힌다.

**표를 A(콜로 시장)·B(주 용량)로 나누고 "직접 비교 금지"를 명시**했다.

세 번째 표 C를 따로 만든 것이 이 모듈에서 가장 쓸모 있었다 — **용량 순위로는 상위가 아니지만 프로그램이 실제로 열려 있는 곳**(중부 워싱턴·데모인·컬럼버스·인디애나폴리스·배턴루지·휴스턴)이다. 이 Topic에는 A·B보다 C가 중요하다.

### 2. 실습 2 — 매트릭스

**순서**: 두 번째. 이 세션의 본체.

표를 그리기 전에 막혔다. **6개가 같은 방식으로 지역에 매이지 않는다.**

| 종류 | 프로그램 |
|---|---|
| 지정 도시 | ① Meta AWA |
| 지정 대학 | ② MS Datacenter Academy |
| 광역 네트워크 | ③ NABTU(34개 주) · ④ Google/etA(20개 주+) |
| 채용 공고 | ⑤-a AWS WBLP |
| 전국 온라인 | ⑥ AWS 견습 |

이걸 구분하지 않고 표를 채우면 **"○"가 칸마다 다른 뜻**이 된다. 범례를 `✅ 확인된 개설` / `⭕ 광역 대상에 포함(지역 지부 확인 필요)` / `❌` / `❓ 확인 불가` 네 가지로 나눴다.

**③④가 거의 전부 ⭕인데, 그게 함정이다.** M5가 실물로 확인한 것이 그 함정이었다 — 워싱턴주는 "34개 주에 포함"인데 PSEJATC 접수는 **5월부터 닫혀 있었다.**

### 3. 공백 해석 — 북버지니아

미국 최대 시장인데 ①②가 모두 없다. 가설 셋을 세웠고, **셋째를 배제하지 못한 것을 그대로 적었다.**

- A. 이미 인력 시장이 형성돼 신규 파이프라인이 덜 급하다
- B. 성숙 시장은 가동 중심이라 필요 직종이 다르다
- **C. 측정의 문제 — 있는데 못 찾았다** (② 파트너 대학 전체 목록 비공개)

**C를 배제해야 A·B를 말할 수 있다.** 그래서 매트릭스의 해당 칸을 `❌`가 아니라 **`❓`** 로 뒀다.

### 4. `find-your-region.md`

**순서**: 세 번째.

DoD가 *"타인이 그대로 따라 할 수 있는 절차"* 를 요구한다. 5단계로 만들고, **각 단계에 "직접 전화" 지점을 명시**했다 — 홈페이지에 접수 상태가 없는 경우가 많기 때문이다.

**5단계를 "아무것도 없으면"으로 둔 것이 중요하다.** 미국 최대 3개 시장조차 지정 프로그램이 없으므로, **없음이 가장 흔한 결과**다. 그때 무엇을 할지가 없으면 이 문서는 절반만 쓸모 있다.

## 🐛 문제 해결 로그

### 문제 1: API가 멀쩡한 질의에 간헐적으로 0을 돌려준다 ← 가장 중요

M5가 쓴 `amazon.jobs` 검색 API를 다시 호출했더니 **전부 0이 나왔다.**

```
work-based learning              0
data center technician           0     ← 있을 리가 없는 결과
technician                       0
```

`data center technician`이 0인 건 말이 안 된다. **대조군을 넣어 봤다.**

```
software    10,000     ← API는 살아 있다
learning         0     ← 방금 전
learning     7,023     ← 2초 뒤 같은 질의
```

**같은 질의가 2초 사이에 0 → 7,023으로 바뀐다.** 요청 단위로 따로 실패한다.

**대조군을 같은 회차에 붙이는 방어로는 부족했다** — 대조군이 10,000건을 반환하는 동안에도 대상 질의만 0이 나왔다.

**시간 간격을 두고 4회 반복해 일관성으로 판정**하는 방식으로 바꿨다.

| 질의 | 4회 결과 | 판정 |
|---|---|---|
| `technician` | 2352 ×4 | 안정 |
| `data center technician` | 1334 ×4 | 안정 |
| `work-based learning` | **3 ×4** | 안정적으로 3건 |

### 문제 2: M5의 결론이 바뀌었다

일관된 값으로 다시 재니 **WBLP 전 세계 3건이고 전부 해외**다.

| 조사일 | 전 세계 | 미국 |
|---|---:|---|
| M5 (8/28) | 4건 | Ohio 1건 |
| **M4 (8/30)** | **3건** | **0건** |

M5 표의 1번(Plain City, Ohio)이 빠졌다. **M2가 "이 Topic 최적 후보"로 꼽은 경로가 미국에서 완전히 닫혔다.**

M5 산출물([wa-institutions.md](../05-WA-Deep-Dive/examples/wa-institutions.md))에 정정 절을 추가하고, M5 방법의 취약점(단발 조회)도 함께 적었다.

### 문제 3: 검색 결과의 채용 공고가 전부 마감된 것이었다

웹 검색으로 WBLP를 찾으니 **버지니아 공고가 여러 개**(Sterling·Herndon·Manassas·Chantilly) 나왔다. LinkedIn·Indeed·Vaia 등이었다.

라이브 API 전수에는 **하나도 없다.** 전부 날짜 없는 애그리게이터 캐시다.

그 요약에는 *"12주 프로그램"* 이라고도 적혀 있었는데, M2가 1차 출처에서 확인한 것은 **12개월**이다. 2차 자료를 그대로 믿었으면 기간까지 틀릴 뻔했다.

### 문제 4: `data center technician` 주별 분포를 못 얻었다

클러스터별 AWS 채용 분포를 매트릭스 교차 검증에 쓰려 했는데, **6회 재시도에도 응답이 없었다.**

**`확인 불가`로 기록했다. 0으로 적지 않았다.**

## 💡 Daily Retrospective

### What went well

- **대조군을 넣어 본 것.** `data center technician`이 0으로 나왔을 때 "그럴 리 없다"고 의심하고 `software`를 넣어 봤다. 그게 아니었으면 **"미국에 데이터센터 기술직 공고가 없다"** 는 터무니없는 결론을 적을 뻔했다
- **4회 반복으로 판정 기준을 바꾼 것.** 대조군만으로는 부족했는데, 그것도 실패를 보고 나서 알았다
- **매트릭스를 그리기 전에 "지역성의 종류"부터 나눈 것.** 그냥 표를 채웠으면 ③④의 ⭕가 ①②의 ✅와 같은 무게로 읽혔을 것이다
- **표 C(프로그램 관점 클러스터)를 따로 만든 것.** 용량 순위 표만 있었으면 이 Topic에 정작 중요한 중부 워싱턴·데모인이 목록에서 빠졌다

### What could be improved

- **M5의 숫자를 그대로 인용할 뻔했다.** "전 세계 4건"을 매트릭스에 옮겨 적으려다 재조사했고, 이틀 만에 바뀌어 있었다. **채용 공고처럼 자주 바뀌는 값은 모듈이 바뀔 때마다 다시 재야 한다** — 그런데 재는 비용이 싸다는 것을 알기 전까지는 안 하게 된다
- **웹 검색 결과의 채용 공고를 처음에 그대로 믿었다.** 버지니아 공고 4곳을 매트릭스에 ✅로 넣으려다 라이브 API와 대조해서 걸렀다. **채용 공고는 1차 출처(고용주 사이트)에서만 확인한다**를 규칙으로 삼아야 한다
- ② MS DCA 전체 파트너 목록을 못 찾은 채로 끝냈다. Microsoft 공식 페이지를 직접 파고들 여지가 남았다

### Insights

**같은 0이라도 "없다"와 "못 읽었다"는 다르고, 이 구분은 조사 도구가 불안정할수록 중요해진다.** API가 안정적이면 0은 0이다. 그런데 이 엔드포인트는 간헐적으로 실패하면서 **오류가 아니라 빈 결과로 실패한다.** 실패가 정상 응답과 같은 모양이면 구분할 방법은 반복밖에 없다.

**신뢰도는 값이 아니라 값의 일관성에서 나온다.** 한 번 조회한 3건과 네 번 조회해 매번 같은 3건은 **다른 데이터**다. M5가 단발로 얻은 4건이 우연히 맞았지만, 방법이 옳았던 것은 아니다.

**"지도를 만든다"는 일에는 두 가지 좌표가 있다 — 어디에 무엇이 있나, 그리고 그 정보가 언제까지 유효한가.** 클러스터 위치는 몇 년 간다. 프로그램 개설지는 몇 달 간다. **채용 공고는 이틀 만에 바뀐다.** 같은 문서에 셋을 섞어 적으면 전체가 채용 공고의 수명을 갖게 된다. 그래서 `find-your-region.md` 말미에 *"프로그램 존재 여부는 오래가지만 문이 열렸는지는 반드시 다시 확인하라"* 를 넣었다.

**공백에는 해석이 필요하고, 해석에는 "못 찾았을 가능성"이 먼저 와야 한다.** 북버지니아에 프로그램이 없는 이유로 그럴듯한 가설 두 개(A·B)를 먼저 떠올렸는데, 정작 확인해야 할 것은 C(내가 못 찾았나)였다. **A·B는 흥미롭고 C는 지루한데, 순서는 C가 먼저다.**

**"광역 대상에 포함"은 거의 정보가 아니다.** ③은 34개 주, ④는 20개 주 이상이다. 표에서는 거의 모든 칸이 ⭕가 된다. 그런데 실제 문은 **지역 노조 지부**가 열고 닫고, M5가 확인한 워싱턴주는 5월부터 닫혀 있었다. **범위가 넓다는 것과 지금 들어갈 수 있다는 것은 무관하다.** 오늘 이걸 매트릭스의 범례로 못 박아 뒀다.
