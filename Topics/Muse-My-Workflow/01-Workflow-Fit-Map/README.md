# M1 — 작업 목록과 Muse 적합도 지도

**상태**: ✅ 완료 (2026-10-18, Live #32 방송 4부) · ✅ v2.0 보강 완료 (2026-10-25, Live #33 1부) — 기능 표 v2 · 앱 커넥터 화면 확인 · 판정 기준 ③ · 작업 v1.1 확정 · 연결 · 이름 규칙 결정
**예상 학습 시간**: 1.5시간 + 보강 0.75시간

Muse 를 어디에 쓸지부터 정한 모듈이다. 박창수의 작업 18개를 「맡김 · 초안만 · 맡기지 않음」으로 판정하고, Muse 에 올리면 안 되는 것을 정리하고, 필요한 기능을 Meta 공식 자료로 확인했다. Roadmap v2.0 보강에서 직접 확인한 사실 · 새 커넥터 · 바뀐 판정 기준으로 다시 다듬었다.

## 이 모듈에서 알아낸 것

- 판정 결과는 **맡김 3 · 초안만 10 · 맡기지 않음 5**(v1). 밖에서는 생각을 붙잡아 두고 형식은 집에서 맞추는 「초안만」이 가장 많다.
- 상위 6개: 이동 중 아이디어 · 할 일 메모 · VibeLearn AI Topic 이어가기 · 구술 원문 받아쓰기 · 공개 행사 리서치 · 공개 글 초안 · Remotion 슬라이드 플랜 · 대본.
- Muse 는 **Markdown 파일을 만들고 Library 에 저장**하며, **내 데이터 전체 내려받기**가 있다(공식 자료). **파일 하나씩 내려받기**는 아직 공식 자료에 없다 — M2 에서 직접 확인한다.

### v2.0 보강 (2026-10-25)

- **음성 입력 · Gmail · Google Calendar · 반복 알림은 직접 써서 확인했다**(2026-10-20~22, 안드로이드). 남은 것은 말한 그대로 파일로 남는가(M2)다.
- 커넥터가 늘었다 — 앱 목록에서 **Google Drive · GitHub · Dropbox** 가 보인다(직접 확인, 연결은 안 함). 볼트를 Muse 와 잇는 해법(M4)의 후보가 된다. Box · Notion 은 목록 전체를 안 봐서 미확인이다.
- **전체 데이터 내려받기**를 직접 받아 보니 zip 하나에 대화 txt · 폴더 구조가 남은 Markdown · 올린 파일 · manifest 가 들어 있었다. 한꺼번에 가져오는 용도이고 매일 쓰는 방법은 아니다.
- 판정 기준 ③ 을 「밖에서 생기는 일인가」에서 **「Muse 가 더 나은 이유가 있는가」**로 바꿨다. 그 기준으로 메일 · 일정 · 행사 전후 · 백그라운드 리서치 등 **5개를 더했다**(확정 — 맡김 3 · 초안만 2).
- 볼트 맥락이 많은 5개(#1 · #3 · #5 · #9 · #10)는 「Muse 가 볼트를 못 본다」는 전제로 판정했다 — **M4 결과에 따라 다시 판정**한다.
- **연결하면 이미 올린 것과 같다** — 그래서 연결 규칙(메일 · 캘린더까지, 저장소는 M4 에서 따로)과 이름 규칙(이름 · 관계만, 연락처 · 금액 · 내부 결정은 뺀다)을 정했다.
