## 상태와 근거 범위

**기존 가이드 사용자 확인 완료 · 11/21 관찰 마감.** 외부에서 시작해 Vault에서 마무리한 행사 업무 두 건과 집에서 시작한 공개 영상 글 초안을 구분해 반영했다. M5 최종 제안은 [일상 사용 관찰 기록](../examples/one-week-log.md)과 기존 왕복 시험을 바탕으로 정리했다. 현장 업무의 상세 근거는 내부 WorkLog에서 관리한다.

경로 선택 근거는 [작업 종류별 경로표](../../04-Vault-Connection/guides/task-route-table.md), Vault 편입 단계는 [받는 곳 정리 프롬프트](../../02-Muse-to-Vault/guides/vault-cleanup-prompt.md), 포함·제외 원칙은 [승인된 사본 정책](../../04-Vault-Connection/guides/mirror-policy.md#승인-기록)을 따른다. 실제 사용으로 확인된 예는 11월 12일 공개 행사 후원 방법 조사와 11월 13일 이메일 초안 작성이며, 두 건 모두 완료 뒤 수정량·Vault 편입 경로 기록은 충분하지 않다([11월 15일 M5 WorkLog](../../vl_worklog/20261115_M5_Muse-My-Workflow.md#확인한-사용-사례)).

## 매일 사용하는 흐름

1. **업무와 자료 등급을 정한다.** 공개 자료 중심의 조사·아이디어·초안처럼 Muse가 유용한 일인지 고른다. 내부 자료, 개인 정보, 계정 비밀, 의뢰인 정보, `🔒 내부 자료`는 Muse나 외부 사본에 넣지 않는다. 입력할 자료가 허용되는지 불명확하면 진행을 멈추고 확인한다.
2. **Muse에서 작업을 시작한다.** 요청에는 목표, 사용할 공개 맥락, 원하는 형식, 사실 확인이 필요한 항목, 포함하면 안 되는 정보를 명시한다. 발송·게시·예약·일정 변경 등 외부 효과가 있는 행동은 초안까지만 요청하고 사람이 직접 검토한다.
3. **결과와 출처를 확인한다.** 근거 링크와 인용을 원자료와 대조하고, 사실·추정·미확인을 구분한다. 타인의 이름은 M1 이름 규칙을 따르며, 확인할 수 없는 개인정보나 관계를 보충하지 않는다.
4. **결과를 회수한다.** 기본 경로는 Muse에서 필요한 결과만 수동으로 가져오는 방식이다. 이미 승인된 Dropbox 경로를 사용하는 건은 PC의 Dropbox 폴더에서 파일이 실제로 열리는지 확인한다. 원본 Vault에 반영하는 단계는 수동으로 한다.
5. **집에서 검토하고 Vault에 편입한다.** 최종 위치가 미정이면 `_Inbox_/`를 쓴다. 일정이면 예정과 현장을 구분하고, 영상 글이면 원어 자막으로 수치와 맥락을 확인한다. 원문과 수정본을 구별하고, 사람이 읽기 전에는 `reviewed: false`를 유지한다. 최종 위치, 출처, 변경량과 회수 시간을 WorkLog에 기록한다.

## M5 최종 제안 — 업무별 자료 묶음으로 원격 작업

집의 Vault를 원본으로 두고, 자주 이어갈 업무마다 공유 가능한 Markdown과 한 장짜리 `INDEX.md`를 준비한다. 인덱스에는 최신 상태·갱신 날짜·다음 할 일·근거 파일의 상대 경로를 담는다. 밖에서는 Muse가 인덱스를 먼저 읽고 필요한 파일만 열도록 한다. 결과는 Muse에서 회수하거나 승인된 Dropbox 경로에 새 Markdown으로 저장한 뒤, 집에서 원본과 대조해 필요한 부분을 Vault에 반영한다.

Dropbox의 경로를 직접 지정하면 내장 검색에 덜 의존한다. PC 종료 중 작성한 시험 파일이 재가동 후 로컬에 도착한 경로는 이미 확인했다. 반복 업무에서 제목이나 본문을 찾느라 시간이 계속 든다면 같은 자료 묶음에 한해 Muse 작업 공간 사본과 키워드 검색을 비교한다. 필요할 때 frontmatter와 링크 경로를 추출하고, 관련 문서를 찾지 못하는 사례가 쌓이면 의미 검색을 검토한다.

다음에 공개 자료로 시험할 때는 최신 상태 찾기, 연결된 근거 찾기, 결과 한 건 회수를 같은 질문으로 비교한다. 출처 정확성, 찾는 데 걸린 시간, 귀가 후 수정량을 기록한다. 운영에 앞서 새 사본 범위와 커넥터 접근 범위를 확인한다.

## 작업 유형별 빠른 선택

| 업무 | Muse 사용 | 귀가 후 마무리 |
|---|---|---|
| 공개 행사·도구 조사 | 조사와 출처가 있는 초안 | 원 출처를 재확인하고 필요한 결과만 Vault에 보관 |
| 공개 글·이메일 초안 | 초안 작성과 선택지 비교 | 수신자·사실·톤을 사람이 검토하고 직접 발송 |
| 이동 중 아이디어·음성 메모 | 원문을 보존하고 구조화 초안 생성 | 원문과 초안을 대조한 뒤 `_Inbox_/`에 편입 |
| Vault 맥락을 요구하는 작업 | 승인된 자료만 포함된 Muse 내부 작업 공간에서 수행하거나 집에서 처리 | 실제 Vault 연결은 별도 구체적 실행 승인과 최신 미리 보기 후에만 판단 |
| 내부·개인·의뢰인 자료 | 사용하지 않음 | Vault 내부에서 처리하고 외부 반출 금지 |

## 작업 기록 최소 항목

각 실제 업무는 날짜, 업무 유형, Muse 입력 방식, 작업 시작 위치, 결과 회수 경로, Vault 최종 경로, 소요 시간, 수정량(거의 그대로·일부 수정·다시 작성), 막힌 점, 영상 캡처 여부를 남긴다. Muse를 사용하지 않은 날도 이유를 한 줄로 기록한다. 기록이 없으면 사용 여부나 수정량을 추정하지 않는다.

집/밖의 위치와 실제 입력 기기·컴퓨터 사용 가능 여부는 따로 기록한다. 집에서도 휴대기기로 원격 작업할 수 있고, 위치가 바뀌어도 Muse가 참고할 수 있는 자료 범위는 자동으로 넓어지지 않는다.

## 영상용 화면 캡처 메모

화면 캡처는 실제로 작업을 수행하는 장면에서만 수집한다. 계정 이름·이메일·대화 목록·개인 정보가 보이면 캡처 전에 가리고, 공개 가능한 합성 자료만 사용한다. 장면마다 WorkLog에 촬영 날짜, 장면 목적, 캡처 파일 경로, 공개 검토 상태를 적는다. 기존 M4 합성 화면은 M4 기술 시험 장면의 근거로만 사용할 수 있으며 M5 실제 업무 장면처럼 제시하지 않는다.

### 매일 남길 관찰 기록

아래 한 줄 양식을 11/21까지 날짜별로 작성한다. Muse를 쓰지 않은 날도 이유와 기기/환경 제약을 기록한다. 영상에 설명력이 있는 장면은 별도로 화면 캡처를 남긴다: 호텔에서 iPhone 음성 입력 후 결과가 저장된 장면, iPad/노트북에서 같은 작업을 다시 연 장면, 노트북에서 개별 파일을 회수해 확인한 장면. 캡처 전에 계정 이름·이메일·대화 목록·참석자 정보와 비공개 화면을 가리고, WorkLog에 캡처 경로와 장면 목적을 기록한다. 캡처를 남기기 위해 민감한 화면을 열지 않는다.

## 11월 17일 현장 실습 평가 반영

PC가 꺼진 상태에서 Dropbox 사본을 Muse로 참조한 실제 사례를 확보했다. 질문·메시지 17항목과 사전 브리프 3건을 검토했으며, 등록 폼 탐색은 사용자 링크 제공으로 복구됐다. 다음 질문부터 읽은 파일 경로·문서 날짜·인용 구절을 함께 남기고, 찾지 못한 정보는 검색 범위를 기록한다. 일정 충돌과 시간 차이는 진행 담당자가 확인할 항목으로 유지한다. 사례별 근거와 판정은 [현장 업무 평가](../examples/real-work-trials.md#실험-판정)에 정리했다.

## 11월 18일 현장 테스트 계획

사전 시험으로 노트북 Muse 웹에서 Dropbox 비-Markdown 원본 7개를 확인했다. 이는 사용자의 현장 실습이 아니며, PC-off·iPhone/iPad 실습 완료나 end-to-end 업무로 세지 않는다. 형식별 결과와 제약은 [실제 업무 평가](../examples/real-work-trials.md#비-markdown-파일-형식-시험) 및 [WorkLog](../../vl_worklog/20261118_M5_Muse-My-Workflow.md#비-markdown-원본-접근-사전-시험)에 기록했다.

오늘은 오전에 만든 인덱스를 행사 중 실제 질문에 적용한다. 필수 세 건은 각각 2~5분, 저녁 기록·회수 5분, 예비 시간 5분으로 총 20~25분을 잡는다. 질문은 같은 Muse 행사 대화에서 iPhone으로 보낸다. 노트북을 끈 구간은 시작·종료 시각을 메모하고, Dropbox 클라우드 동기화 완료를 확인한 뒤 전원을 끈다. 외부에서 성공한 질문도 단말과 PC 전원 상태가 기록된 경우에 PC-off 관찰로 남긴다. 정확한 속도 비교를 하려면 전송 시각과 답변 완료 시각을 직접 기록한다.

### 테스트 1 — 오늘 일정과 충돌 처리

행사 시작 전 또는 다음 세션을 준비할 때 요청한다.

> 오늘은 시애틀 2026년 11월 18일입니다. 현재 인덱스를 이용해 오늘 행사 일정과 제가 다음에 확인할 사항을 짧게 정리해 주세요. 축사 시간·도착 요청이 다른 자료는 출처별로 보여 주고, 담당자 역할은 제가 정정한 기록을 반영해 주세요. 출처 날짜와 이번에 새로 읽은 자료인지 기존 기록인지 알려 주세요. 확정되지 않은 사항은 확인 대상으로 남겨 주세요.

성공 기준은 11/18 일정, 출처별 시간 차이, 담당자·미확인 사항을 사용자가 현재 진행표와 대조할 수 있게 답하는 것이다. 오늘 현장에서 확정된 변경이 있으면 사용자가 결정자·확정 시각과 함께 전달하고, 다음 질문에 반영되는지 확인한다.

### 테스트 2 — 등록 폼 재검색과 최신 인원

명단 확인이 실제로 필요할 때 요청한다.

> 기존에 공유한 참석자 등록 폼과 보기용 명단 링크를 알려 주세요. 내일 11월 19일 오전·오후 참석 등록 인원과 중복을 제거한 총인원을 확인해 주세요. 시트를 지금 열 수 있으면 새로 집계하고 조회 시각·명단 기준일·집계 조건을 적어 주세요. 열 수 없으면 접근 한계와 기존 기록의 기준일을 밝혀 주세요. 기존 기록을 현재 인원으로 제시하지 말아 주세요.

성공 기준은 기존 링크를 찾아 주고, 현재 조회 성공 여부를 밝히며, 등록과 실제 참석을 구별하는 것이다. 새 집계가 가능하면 표의 오전·오후·합집합과 중복 제거를 사용자가 시트에서 표본 대조한다. 시트 접근에 실패하더라도 검색 범위를 설명하고 필요한 링크를 요청하면 실패 대응 기준을 충족한다.

### 테스트 3 — Dropbox 원문을 사용한 기업 미팅 준비

오늘 실제로 만날 기업 하나를 골라 회사명을 넣는다.

> 오늘 만날 기업은 [회사명]입니다. Dropbox /KACCWA에서 관련 원문을 이번에 직접 읽고, 회사가 원하는 협력과 제가 물어볼 질문 세 개를 정리해 주세요. 회사의 요구사항은 근거 구절·파일 전체 경로·자료 기준일을 붙이고, 제안 질문은 제안이라고 표시해 주세요. 인덱스에서 어떤 파일로 이동했는지 알려 주세요. 파일을 못 열면 읽지 못한 범위를 알려 주세요.

성공 기준은 실제 해당 기업 파일을 열었다는 경로·인용이 있고, 질문이 회사 요구와 연결되는 것이다. 사용자는 기억이나 보유 자료에서 사실 두 개를 대조하고, 실제 미팅에서 쓴 질문이 있으면 기록한다. 파일 읽기의 실행 자체는 Muse의 보고와 도구 기록 가용 범위에 맞춰 평가한다.

### 저녁 마무리 — 결과 회수와 기기 전환

iPad가 있으면 같은 대화를 열어 위 결과를 다시 찾는다. 저녁에는 아래 요청을 보낸 뒤 노트북으로 파일을 내려받아 내용을 확인한다. Vault 편입은 실제 다운로드본과 최종 저장 위치를 확인한 뒤 완료로 기록한다.

> 오늘 수행한 테스트별 질문·답변, 사용한 출처, 새 조회 여부, 제가 고친 내용과 남은 확인 사항을 KSDD-2026/field-test-2026-11-18.md로 저장해 주세요. 시간·기기·PC 전원 상태·현장 채택 여부는 제가 알려 준 것만 기록하고, 미기록 항목은 미기록으로 남겨 주세요. 저장 파일을 다시 읽어 확인하고 이 대화에서 내려받을 수 있게 제공해 주세요.

매 건 기록은 질문 목적 / 사용 기기 / PC 전원 / 전송·완료 시각 / 맞고 틀린 부분 / 실제 사용 여부 / 추가 입력 횟수로 남긴다. 영상에 쓸 장면은 출처가 붙은 답변, 변경사항이 반영된 답변, 파일 회수 완료 화면 중에서 고른다. 연락처·명단·메일 본문이 보이는 화면은 내부 보관 대상으로 취급하고 공개 영상용 화면은 가린 뒤 사용한다.

행사가 바쁘면 테스트 3 한 건과 저녁 회수부터 수행한다. 오늘 목표는 인덱스가 실제 질문 해결에 기여하는지와 결과가 다른 기기·로컬로 이어지는지 확인하는 것이다. 계획 작성 시점에는 현장 테스트 결과를 완료로 기록하지 않는다.
