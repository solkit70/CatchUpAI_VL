# 집에서 이어받는 방법

## 밖에서 준비할 것

Muse에서 공개 Topic의 이름, 목적, 기간, 목표, 환경을 정한다. 사용자 확인을 거쳐 Topic 정보와 두 프롬프트를 만들고, 어디에서 멈췄는지 적어 둔다. 이번 예시는 기간 검토 뒤 사용자의 선택을 기다리는 단계였다. [Muse 작업 기록](../../vl_worklog/20261101_M3_Muse-My-Workflow.md#1-실습-2--순서-지키기-시험-웹-새-대화)

## 집에서 확인할 것

1. Muse Library → **System files** → **workspace** → **Topics**에서 해당 Topic을 연다. 각 Markdown 파일의 **More actions → Download**를 사용한다.
2. 볼트의 `_Inbox_/<Topic>/`에 `topic_info.md`를, 그 안의 `vl_prompts/`에 두 프롬프트를 두고 원래 구조를 유지한다.
3. `roadmap_prompt.md`와 `daily_learning_prompt.md`의 [2단계]·[3단계]를 원본 템플릿과 비교한다. 집의 Codex나 Claude Code로 실제 입력을 읽고, 승인 대기 지점부터 이어받는다.
4. 파일이 빠졌거나 지시가 달라졌다면 어떤 파일이나 절이 누락됐는지 기록한다. 기간 확인 이후의 로드맵 생성은 사용자가 해당 Topic의 기간을 확정한 뒤 진행한다.

**이번 판정은 가능**이다. 파일 3개를 수동 다운로드해 기간 검토까지 이어받았으며, 로컬 볼트에 파일을 두고 원본 템플릿과 대조하는 일은 집에서 했다. [검증 결과](../../vl_worklog/20261105_M3_Muse-My-Workflow.md#실습-4-결과)
