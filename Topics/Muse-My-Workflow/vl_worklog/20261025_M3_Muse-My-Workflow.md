## 📚 진행 내용

### 1. 실습 1 — 지시 파일 읽기 시험 (웹, 새 대화)

**지시**: 공개 레포 주소를 주고 `AGENTS.md` 와 `templates/workflow_guide.md` 에서 ① 단계 이름 · 결과물 ② Topic 폴더 구조 ③ 사용자 승인을 기다리는 지점을 요약시켰다. 「파일에 없는 내용은 지어내지 말고 파일에 없다고 말해 줘」를 덧붙였다. (두 파일은 공개 레포에 올라가 있고 로컬과 같다 — `git ls-files` · 변경 없음 확인.)

**대조 방법**: Claude Code 가 같은 두 파일(로컬 `Ingest/CatchUpAI_VL/AGENTS.md` · `templates/workflow_guide.md`)을 읽고 Muse 의 답을 항목별로 맞췄다.

**결과**: 읽고 사실대로 요약했다. 두 파일의 **불일치를 숨기지 않고 따로 적은** 점이 가장 좋았다. 틀린 곳 · 지어낸 곳은 찾지 못했다.

**참고**: 같은 도식 안에서 `topic_starter`(입력 템플릿)와 `topic_info.md`(결과 파일)가 함께 나온다. 이 볼트의 최신 Topic 들은 Topic 루트에 `topic_starter.md` 를 쓰므로, 공개 지시 파일의 용어(`topic_info.md`)와 현재 관행이 어긋날 수 있다 — 실습 2 에서 Muse 가 어느 이름을 쓰는지 본다.

### 2. 오늘 세션 리뷰 (Opus 로 바꿔 진행)

박창수 요청으로 오늘 Muse-My-Workflow 작업 전체를 다시 봤다. 결과와 처리:

- **시각 기록**: M2 · M3 WorkLog 의 `created` 가 실제 시각이 아니었다 → 파일 시각 · 시험 파일 시각으로 근거를 찾아 고쳤다(M3 07:43:38, M2 는 「06:23~06:31 사이, 시각 미상」).
- **학습 끄기 근거**: 기능 표의 「직접 · 10/22」 표시는 원래 근거가 없었다 → 「웹 화면에는 없음 · 휴대폰 앱 미확인」으로 고쳤다. 웹 한 화면만 보고 「끌 수 없다」고 가정한 것도 성급했다.
- **회사 계정 문구**: 로드맵 「지킬 것」을 오늘 결정(필요하면 승인 뒤 연결)에 맞췄다.
- **공개 범위 — 박창수 결정 (2026-10-25)**: 공개 문서에 들어 있는 계정 연결 상태 · 메일 범위에 대한 개인 판단 · 기기 이름 · 볼트 폴더 구조 · Task 경로 · 메일 시각을 **전부 그대로 공개해도 된다**. 문서끼리 남은 어긋남도 박창수가 허용한 것이다. → 다음 세션의 에이전트는 이 항목들을 「규칙 위반」으로 고치지 않는다.
- **방송 중 실수**: 메일 시험 지시문에 실제 이메일 주소를 넣어 보여 준 적이 있다(한 번, 다음부터 「내 Gmail 주소」로 바꿈). 방송 중에는 계정 정보를 지시문에도 넣지 않는다.
