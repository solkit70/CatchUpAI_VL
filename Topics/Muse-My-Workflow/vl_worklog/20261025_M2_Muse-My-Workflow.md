## 📚 진행 내용

### 1. 시험 재료 — 공개 가짜 내용으로 Markdown 파일 만들기

**과정**: Muse 웹 새 대화에 지시문을 보냈다(제목 · 목록 3 · 표 3행 · 링크 1 · 마지막 줄). 지시는 한국어 한 덩어리.

**결과**: 대화창에 파일 카드(「Muse 시험 01 · MD」)와 미리보기가 나왔다. Muse 는 「오늘 날씨」를 실제 시애틀 예보로 채웠다 — 시키지 않은 웹 조회로 빈칸을 채우는 성향이다.

### 2. 방법 ① 파일 하나씩 내려받기 (웹) — ✅ 됨

- **경로**: 파일 카드 클릭 → 문서 오른쪽 위 「⋯」 → Download (3단계). 같은 메뉴에 View source · Copy · Download as PDF · Print · Delete 가 있다.
- **보존도**: 받은 `.md` 를 열어 대조했다 — 제목(#) · 목록 3 · 표 3행(Markdown 파이프 표) · 링크 `[Meta](https://www.meta.com)` · 마지막 줄까지 **지시한 구조가 전부 그대로** 들어 있다. 앞에 붙은 군더더기 · frontmatter 는 없다.
- **파일 이름**: 문서 제목이 그대로(`Muse 시험 01.md`, 공백 · 한글 포함).
- **이 Topic 의 첫 질문에 대한 답**: 공식 도움말에는 개별 다운로드가 없었지만 **앱에는 있다** (기능 표 「파일 하나씩 내려받기」 ❓ → ✅ 직접).
- 휴대폰에서도 되는지는 미확인.

### 3. 방법 ③ 복사 · 붙여넣기 (웹) — ✅ 됨, Markdown 원문 그대로

- **경로**: 문서 ⋯ → Copy → 메모장에 붙여 넣기 (2단계 + 붙여넣기). 같은 메뉴의 **View source** 는 줄 번호가 붙은 Markdown 원문 화면을 보여 준다.
- **보존도**: 붙여 넣은 글이 렌더된 글이 아니라 **Markdown 원문**이다 — `#` · `|---|---|` 표 · `[Meta](https://www.meta.com)` · 마지막 줄이 모두 남았다. 다운로드한 파일과 같은 내용이다.
- 의미: 파일을 받지 못하는 상황(휴대폰 · 다른 PC)에서도 Copy 로 같은 원문을 옮길 수 있다. 다만 받는 곳(Inbox)에 파일로 두려면 붙여 넣은 뒤 저장하는 한 단계가 더 든다.

### 4. 방법 ② 내 메일로 보내기 — ✅ 됨, 첨부 파일이 바이트까지 같다

- **경로**: Muse 대화에 「내 Gmail 주소로 첨부해서 보내 줘」 → Muse 가 메일을 보냄 (승인 횟수는 박창수에게 확인 대기).
- **확인**: Claude Code 가 Gmail 에서 제목 「Muse 시험 메일」 한 건만 찾아 열었다 — 보낸 사람 · 받는 사람 모두 본인 계정, 도착 시각 06:31(PDT), 본문 한 줄(「요청하신 … 첨부합니다」), 첨부 1개(`Muse 시험 01.md`, text/markdown).
- **보존도**: 첨부를 내려받아 웹에서 받은 `.md` 와 `cmp` 로 비교 — **397바이트, 완전히 같다.**
- 의미: 메일 경로는 **휴대폰에서도 되는 방법**이다(Muse 앱 → 메일 → 집 PC 의 Gmail). 단점은 받은편지함에 들어와 섞이고, 보내기 승인을 거치며, 메일 커넥터 연결이 필요하다는 것.

### 5. 실습 2 — 음성 원문 보존 시험 (박창수 보고)

- 박창수가 휴대폰에서 음성으로 메모를 말한 뒤 「방금 내가 말한 내용을 한 글자도 바꾸지 말고 마크다운 파일로 저장해줘」라고 시켰다. Muse 가 `Muse 시험 02.md` 를 만들었다.
- **대조 결과 — 그대로**: Claude Code 가 받은 파일을 열어 대화창에 남은 음성 입력 글과 맞춰 봤다. 파일은 **한 줄(문장 하나)** 이고 입력 글과 같다 — 군더더기 말(「어」 · 「음」)까지 남았고, 제목 · 머리말 · 덧붙인 말이 없다. Muse 의 말(「문장만 들어 있고 제목이나 다른 내용은 추가하지 않았습니다」)과 파일이 일치한다.
- **한계**: 비교한 것은 「Muse 가 받아 적은 입력 글」과 「저장된 파일」이다. 말소리(음성) 자체와 입력 글이 같은지는 말한 본인만 판단할 수 있다 — 입력 글에서 브랜드 이름 Muse 가 「뮤즈」로 적혔다(음성 인식 한계). 원문 보존 규칙(한 글자도 바꾸지 않는다)은 이 글을 그대로 두고, 고칠 것이 보이면 고치지 말고 박창수에게 확인한다.
- **알아낸 것**: 시킨 한 줄만으로 원문이 지켜졌다 — 지시문을 바꿔 다시 시험할 필요가 없었다. 첫 말에 「아무것도 하지 말고 그냥 내버려둬」라고 먼저 말해 둔 것이 Muse 가 요약 · 답변 대신 그대로 두게 한 단서로 보인다(추정).

### 6. 실습 3 — 집 → 밖 넘기기 (진행 중)

- 넘김 꾸러미(어디까지 했나 · 정한 것 · 다음 할 일 3절, 공개 내용만)를 만들어 Muse 에 세 방법으로 넘긴다: ① 파일 올리기 ② 내 메일로 보내 읽게 하기 ③ 공개 레포 링크.
- **방법 ① 파일 올리기 — ✅ 됨 (웹, 새 대화)**: 꾸러미를 첨부하고 「다음 할 일을 이어서 해 줘」라고만 했다. Muse 는 3절을 읽고 「다음 할 일」 2개를 모두 했다 — Inbox 후보 3개(① 볼트 안 Inbox 폴더 ② Muse 작업 공간 안 Inbox 폴더 ③ Gmail 받은편지함)를 장단점 한 줄씩과 함께 내고, ①을 추천하며, 「정한 것」의 두 번째 규칙(만든 곳 · 날짜 · 검토 여부)을 담은 머리말 예시를 만들었다.
  - **지킨 것**: 「정한 것」 3개 중 원본 = 볼트 · 출처 표시 규칙을 후보 평가 기준으로 썼다. 꾸러미에 없는 것(볼트 실제 위치 · 폴더 구조 · Muse 가 볼트에 쓸 수 있는지)은 **「모른다」고 따로 밝혔다** — 「모르는 것은 지어내지 말고 모른다고 말해 줘」 한 줄이 먹혔다.
  - **고칠 것**: 머리말 키가 **한글**(`만든 곳` · `날짜` · `검토 여부`)이다. 볼트 규칙은 소문자 영어 키(`created` · `source` 등)라 그대로 쓸 수 없다 → 집에서 고쳐야 하고, 꾸러미에 「볼트 frontmatter 는 영어 소문자 키」 한 줄을 넣어야 한다. 또 추천한 후보 ①(Muse 가 볼트에 직접 쓰기)은 지금은 불가능하다(Muse 는 볼트에 직접 닿지 않는다) — Muse 도 불가능할 수 있다고 인정했으나 추천은 그대로 했다.
  - **참고**: 꾸러미에 없던 날짜(2026-10-25)를 Muse 가 스스로 채웠다.
  - ①이 한 번에 3분 안에 된다. 꾸러미를 **가장 짧은 인수인계 단위**로 쓰는 방식이 통한다.
- **방법 ③ 공개 레포 링크 — ✅ 됨 (웹, 새 대화)**: 레포 폴더 주소를 주고 「로드맵을 읽고 M2 가 무엇을 하는 모듈인지 세 줄로」 시켰다. Muse 는 폴더를 열어 로드맵을 읽었고 세 줄 답이 **올라간 10/18 버전의 M2(「Muse 결과를 볼트로 옮기기」)와 일치**했다 — 방법 4가지 이상 · 서식 · 표 · 링크 · 출처 보존도 비교 · 추천 1~2개와 Inbox · 볼트 규칙(frontmatter · 출처 표시)에 맞추는 단계와 프롬프트. 지어낸 부분은 없다. 대조는 `git show HEAD:` 로 올라간 로드맵 M2 절과 했다.
  - **한계**: 레포에 올라간 것은 10/18 버전이라 오늘 정한 v2.0(양방향 · 규칙 · 커넥터)은 읽지 못한다. 링크 방식은 **push 한 것만 보이고**, 그 사이 바뀐 것은 모른다. 공개 문서만 가능(비공개 문서는 링크로 못 준다).
- 참고: 공개 레포(CatchUpAI_VL)의 Muse-My-Workflow 폴더는 **10/18 M1 시점 버전**이 올라가 있다 — ③ 은 올라간 버전만 보인다.

### 6-1. 휴대폰 시험 (박창수 진행, Claude Code 가 메일 확인)

- 학습 끄기 스위치가 웹 화면에 없다는 사실이 연결 규칙 결정 **뒤에** 드러났다. 게다가 웹 한 화면만 보고 「끌 수 없다」고 가정했다 — 휴대폰 앱은 보지 않았다. 규칙을 정하기 전에 앱 화면으로 전제를 확인하는 순서가 낫다.

### Insights
- 방법의 차이는 보존도가 아니라 **단계 수 · 휴대폰 · 연결 필요 여부**다. 원문은 어느 길로 가도 안 깨졌다.
- 정말 비용이 드는 곳은 옮긴 **뒤**의 정리(머리말 · 제목 레벨 · 검토 표시)다. 그래서 정리를 6단계 프롬프트로 만들었다.
- 모르는 것은 모른다고 말하라는 한 줄이 먹힌다. 대신 꾸러미에 없는 **규칙**은 Muse 가 모르니 틀린다 — 규칙은 꾸러미에 넣는다.

## 🎓 가르칠 때

- 도움말과 앱 화면이 다를 수 있다 — 「된다고 했다」가 아니라 「내 화면에서 된다」로 확인한다
- AI 가 만든 파일을 받으면 **열어서 시킨 것과 대조**한다. Muse 는 시키지 않은 날씨를 실제 예보로 채웠다
- 넘김 꾸러미 3절(어디까지 · 정한 것 · 다음 할 일) + 「모르는 것은 모른다고 해」 + **규칙은 꾸러미에 적는다** — 규칙을 안 적으면 AI 는 틀린 형식을 만든다
- 음성으로 남기려면 말을 시작하며 「아무것도 하지 말고 그냥 둬」라고 먼저 말하고, 끝에 「한 글자도 바꾸지 말고 파일로 저장해」라고 시킨다(이번에는 이 한 줄로 충분했다)
- 옮겨 온 문서는 본문을 고치지 않고 머리말만 붙인다 — 「검토 여부」가 있어야 나중에 믿을 수 있다
