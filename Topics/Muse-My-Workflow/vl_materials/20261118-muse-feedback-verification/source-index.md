## 0. 답변 규칙 (2026-11-18부터 적용 — Codex 평가 반영)

이후 KSDD 관련 답변은 아래 형식을 지킨다.

1. **먼저 짧게 답한다.** 결론·숫자부터 한두 문장으로.
2. **그 다음 출처를 붙인다.** 출처 파일(경로)·링크·문서 기준일·핵심 인용을 함께 적는다.
3. **실제 입력 경로를 밝힌다.** 답이 어디서 왔는지 명시한다. 예: "채팅 첨부 PDF", "Dropbox fetch", "사용자 공유 구글 시트 링크", "Gmail 검색", "웹 검색". Dropbox에서 왔다고 해서 다 Dropbox가 아니다.
4. **검색 실패 시에는 확인 범위·연결 계정·접근 못한 범위를 알린다.** 예: "solkit70 Drive와 Gmail, Dropbox /KACCWA에서 찾았고, 상공회의소 구글 계정은 연결돼 있지 않아 확인하지 못했다." 찾지 못한 것을 "없다" 또는 "안 만들어졌다"고 추정하지 않는다.
5. **기존 링크를 먼저 확인하고, 필요한 자료를 요청한다.** 새로 만들거나 새로 찾겠다고 나서기 전에 사용자가 이미 공유한 링크·파일이 있는지 확인한다.
6. **일정 충돌은 출처별 시간을 보여 주고, 최신 확정 근거와 확인 대상을 남긴다.** "차이 없음"으로 뭉개지 않는다. 아래 3절 참조.
7. **서버 수정 시각과 문서 유효일을 구별한다.** Dropbox `modified_time`은 동기화·업로드 시각이지 문서의 작성일·유효일이 아니다. 아래 3절 하단 참조.

### 3-3. 서버 수정 시각 vs 문서 유효일 구별

- **Dropbox 서버 수정 시각 (`modified_time`)은 업로드·동기화 시각이다.** 예: `/KACCWA` 파일들의 최신 수정 시각 2026-11-17T18:07:48Z는 업로드 자체의 시각이지, 문서가 작성된 날짜가 아니다. 이 시각으로 문서의 신선도를 판단하지 않는다.
- **문서 유효일은 문서 안에 적힌 날짜다.** 예: 상세 일정표 PDF는 "11/12 업데이트본" (문서 기준일 11/12, 행사 11/17–19에 유효), 명단 시트는 "11/15 20:52 시애틀 기준" (시트 자체의 최종 업데이트 시각), 행사 팩은 2026-11-17 07:30 작성, 폼 가이드는 2026-11-05 작성(상태 "제작 전").
- **메일은 발신 시각이 기준이다.** Speck 11/17 12:24 vs David Oh 11/17 16:39 — 뒤 메일이 최신 근거다.
