## 목적과 경계

[English](mirror-policy.en.md)

이 규칙은 원본 볼트를 보존하고, 선택한 Markdown 자료만 별도 사본으로 내보내기 위한 초안이다. 현재 기본 설정은 미리 보기이며, 이 문서와 예시 설정은 실제 볼트 자료를 복사하거나 Muse·클라우드 저장소에 연결하지 않는다.

## 포함 기준

- 사용자가 지정한 원본 루트와 그 안의 명시적 포함 경로에 있는 파일만 후보로 본다.
- 확장자가 `.md`이고, 크기가 설정된 상한 이내인 파일만 후보로 본다.
- YAML `visibility` 값이 `public`인 파일만 기본 포함한다. `personal` 파일은 승인과 설정 변경 전까지 제외한다.
- 파일은 원본의 상대 경로를 유지해 별도 목적지에 복사한다.

## 항상 제외

- `visibility: internal` 또는 본문에 `🔒 내부 자료` 표시가 있는 파일
- 분류 표식이 없거나 읽을 수 없는 파일, `personal` 자료, 사용자가 허용 목록에 넣지 않은 경로
- 설정에서 제외한 경로 구성요소 아래의 파일, Markdown 이외 형식, 크기 상한을 넘는 파일, 심볼릭 링크
- 목적지 폴더는 원본 루트 안에 두지 않는다. 이미 목적지에 같은 경로의 파일이 있으면 덮어쓰지 않는다.

## 실행 단계

1. 미리 보기로 후보와 제외 이유를 상대 경로만 사용해 보고한다. 원본 파일은 변경하지 않는다.
2. 보고서를 사람이 검토한다. 내부 표식 파일이 포함 후보에 있거나 설명할 수 없는 분류가 있으면 실행을 멈춘다.
3. 사본 범위, 목적지, 포함 등급을 사용자가 승인한 뒤에만 `--apply`로 복사한다. 새 저장소 연결·업로드는 이 승인과 별도로 확인한다.
4. 실행 후 포함·제외 수와 목적지 파일을 확인하고, 사본에 결과물을 덮어쓰지 않는다.

## 승인 검토안

현재 증거만으로 제안하는 보수적인 운영안은 **자동 미러를 켜지 않고, 명시적으로 지정된 `visibility: public` Markdown만 필요할 때 수동 검토하는 방식**이다. `visibility: internal`, `🔒 내부 자료`, `personal`, 분류 누락·오류, 명시 경로 밖, 비 Markdown, 크기 초과, 심볼릭 링크는 항상 제외한다. 포함 경로는 볼트 전체가 아니라 사용자가 지정한 허용 목록으로 제한하고, 목적지와 권한 범위가 확정될 때까지 실제 복사·커넥터 업로드·예약 실행을 하지 않는다.

Dropbox 시험에서 Muse의 계정 연결은 지정 폴더로 기술적으로 제한됨을 확인하지 못했다. Google Drive도 폴더 제한을 입증하지 못했다. 따라서 현재 증거만으로는 두 커넥터를 실제 볼트 사본에 연결하는 안을 권고하지 않는다. Muse의 수동 단일 파일 전달을 쓰거나, 집 PC가 켜져 있을 때 사용하는 E · Claude Code Remote Control(뮤즈 외부 대안)을 작업 유형에 따라 선택하는 편이 지금 시험 근거에 맞다.

이 안은 제안일 뿐이다. 기존에 별도 승인된 공개 후보 3개의 일회성 Drive 업로드를 반복 미러링 승인으로 확대하지 않는다.

## 승인 대기 사항

이 초안은 정책 확정이 아니다. 내부 미리 보기는 `public` 후보 3개, 제외 55,975개, 복사 0개를 기록했고, 제외 집계에 내부 표식 파일 112개와 `visibility: internal` 58개가 포함됐다. 이는 한 차례 미리 보기 결과이지 정책 승인이나 반복 실행의 안전성 보장은 아니다.

승인 전에 정할 항목:
- 볼트 원본 범위와 명시적 포함 허용 목록
- 저장소·목적지·커넥터 권한 범위
- 매뉴얼 실행 또는 예약 실행, 실행 주기와 사본 보존 기간
- 실패 시 중단·재검토와 목적지 사본 처리 절차

아래 「승인 검토안」은 제안일 뿐이며, 적용·업로드를 승인한 것으로 보지 않는다.
