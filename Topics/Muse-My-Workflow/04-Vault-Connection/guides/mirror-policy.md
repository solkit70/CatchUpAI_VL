## 목적과 경계

[English](mirror-policy.en.md)

이 규칙은 원본 볼트를 보존하고, 선택한 자료만 별도 사본으로 내보내기 위한 초안이다. Markdown이 기본 대상이지만, 필요에 따라 소스 코드, 다른 형식의 문서, 이미지 등 다른 파일 형식도 허용 목록에 명시해 포함할 수 있다. 실제 허용 형식은 사용 목적과 검토된 범위에 따라 정하며, 현재 예시 설정의 기본 확장자는 `.md`뿐이다. 현재 기본 설정은 미리 보기이며, 이 문서와 예시 설정은 실제 볼트 자료를 복사하거나 Muse·클라우드 저장소에 연결하지 않는다.

## 포함 기준

- 사용자가 지정한 원본 루트와 그 안의 명시적 포함 경로에 있는 파일만 후보로 본다.
- 기본적으로 확장자가 `.md`이고 크기가 설정된 상한 이내인 파일을 후보로 본다. 소스 코드, 다른 형식의 문서, 이미지 등 다른 형식이 필요한 경우에는 해당 확장자를 허용 목록에 명시하고 검토한 뒤 포함할 수 있다. 허용 목록에 없는 형식은 제외한다.
- YAML `visibility` 값이 `public`인 파일만 기본 포함한다. `personal` 파일은 승인과 설정 변경 전까지 제외한다.
- 파일은 원본의 상대 경로를 유지해 별도 목적지에 복사한다.

## 항상 제외

- `visibility: internal` 또는 본문에 `🔒 내부 자료` 표시가 있는 파일
- 분류 표식이 없거나 읽을 수 없는 파일, `personal` 자료, 사용자가 허용 목록에 넣지 않은 경로
- 설정에서 제외한 경로 구성요소 아래의 파일, 허용 목록에 없는 형식, 크기 상한을 넘는 파일, 심볼릭 링크
- 목적지 폴더는 원본 루트 안에 두지 않는다. 이미 목적지에 같은 경로의 파일이 있으면 덮어쓰지 않는다.

## 실행 단계

1. 미리 보기로 후보와 제외 이유를 상대 경로만 사용해 보고한다. 원본 파일은 변경하지 않는다.
2. 보고서를 사람이 검토한다. 내부 표식 파일이 포함 후보에 있거나 설명할 수 없는 분류가 있으면 실행을 멈춘다.
3. 사본 범위, 목적지, 포함 등급을 사용자가 승인한 뒤에만 `--apply`로 복사한다. 새 저장소 연결·업로드는 이 승인과 별도로 확인한다.
4. 실행 후 포함·제외 수와 목적지 파일을 확인하고, 사본에 결과물을 덮어쓰지 않는다.

## 승인 검토안

현재 증거만으로 제안하는 보수적인 운영안은 **자동 미러를 켜지 않고, 명시적으로 지정된 `visibility: public` Markdown만 필요할 때 수동 검토하는 방식**이다. Markdown 외 형식은 필요할 때 소스 코드, 다른 문서 형식, 이미지 등을 확장자 허용 목록에 추가해 별도로 검토할 수 있다. `visibility: internal`, `🔒 내부 자료`, `personal`, 분류 누락·오류, 명시 경로 밖, 허용 목록에 없는 형식, 크기 초과, 심볼릭 링크는 항상 제외한다. 포함 경로는 볼트 전체가 아니라 사용자가 지정한 허용 목록으로 제한하고, 목적지와 권한 범위가 확정될 때까지 실제 복사·커넥터 업로드·예약 실행을 하지 않는다.

Dropbox 시험에서 Muse의 계정 연결은 지정 폴더로 기술적으로 제한됨을 확인하지 못했다. Google Drive도 폴더 제한을 입증하지 못했다. 따라서 현재 증거만으로는 두 커넥터를 실제 볼트 사본에 연결하는 안을 권고하지 않는다. Muse의 수동 단일 파일 전달을 쓰거나, 집 PC가 켜져 있을 때 사용하는 E · Claude Code Remote Control(뮤즈 외부 대안)을 작업 유형에 따라 선택하는 편이 지금 시험 근거에 맞다.

이 안은 제안일 뿐이다. 기존에 별도 승인된 공개 후보 3개의 일회성 Drive 업로드를 반복 미러링 승인으로 확대하지 않는다.

## 승인 대기 사항

**2026-11-14 저장소 결정.** 원격 작업 파일은 Muse 내부 작업 공간에서 관리하는 것을 기본으로 한다. Dropbox와 Google Drive는 귀가 후 PC를 켰을 때 작업 결과를 회수하고 Vault에 반영하기 위한 보조 후보다. 보조 저장소 선택은 PC를 끈 상태의 모바일 작업부터 PC 재가동 후 결과 회수와 Vault 반영까지 남은 실험을 마친 뒤 결정한다.

## 승인 기록

**2026-11-15 박창수 승인.** 「승인 검토안」과 아래 승인 대기 사항에 정리된 보수적 원칙을 승인했다. 승인된 기본 원칙은 자동 미러와 예약 실행을 켜지 않고, 지정한 경로 안에서 `visibility: public` Markdown만 수동 미리 보기·검토하는 것이다. `internal`, `personal`, `🔒 내부 자료`, 분류 누락·오류, 허용 경로 밖, 허용 목록에 없는 파일 형식, 크기 초과 파일, 심볼릭 링크는 제외하며 기존 목적지 파일을 덮어쓰지 않는다. 이 승인만으로 실제 파일 복사, 클라우드 업로드·커넥터 연결, 예약 실행은 시작하지 않는다.

특정 실행 전에 실제 원본과 포함 경로, 대상·목적지 폴더와 권한 범위, 최신 미리 보기 보고서, 보존·정리 절차를 구체화한다. 보고서를 검토한 뒤 해당 실행을 별도로 승인한다. 실행 주기·보존 기간은 별도 결정을 받을 때까지 설정하지 않는다.

2026-11-05 내부 미리 보기는 `public` 후보 3개, 제외 55,975개, 복사 0개를 기록했고, 제외 집계에 내부 표식 파일 112개와 `visibility: internal` 58개가 포함됐다. 이는 당시 결과이며 특정한 새 사본 작업을 승인하지 않는다.

승인 전에 정할 항목:
- 볼트 원본 범위와 명시적 포함 허용 목록
- 실험 후 보조 저장소를 선택할 때 해당 목적지 폴더와 커넥터 권한 범위
- 매뉴얼 실행 또는 예약 실행, 실행 주기와 사본 보존 기간
- 실패 시 중단·재검토와 목적지 사본 처리 절차

위 승인 기록에 적힌 정책 원칙은 승인됐다. 적용·업로드는 특정 실행의 별도 승인 대상이다.
