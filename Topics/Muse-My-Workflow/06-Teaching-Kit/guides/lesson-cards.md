# Muse 교육 블록 수업 카드

각 카드의 실습은 가상 자료로 한다. 기기 화면은 학습자가 직접 만든 테스트 대화만 사용한다.

## 블록 1 — Muse 시작과 자료 안전

| 항목 | 내용 |
|---|---|
| 대상과 목표 | L1~L3. 입력하기 전에 자료를 공개·개인·내부로 구분하고, 이번 실습에 넣을 수 있는 자료를 선택한다 |
| 시간 | 40분 |
| 준비물 | Muse 접근 기기, [가상 행사 메모](../examples/sample-course-plan.md#공통-실습-재료) |
| 단계 | 1) 대화 시작 위치 찾기 2) 실습 목적 확인 3) 가상 자료를 공개/개인/내부로 분류 4) 안전한 자료 하나 선택 5) 입력할 내용과 제외할 내용을 말로 설명 |
| 실습 | 가상 행사 소개 문단을 읽고 Muse에 제공 가능한 부분과 제거할 부분을 표시한다 |
| 확인 질문 | 이번 입력에 다른 사람의 개인정보가 필요한가? 결과를 누가 볼 수 있는가? |
| 흔한 실수 | 실습을 빨리 끝내려고 실제 이메일이나 연락처를 붙여 넣음 |
| 안전 규칙 | 실제 개인정보·계정 비밀·내부 문서를 입력하지 않는다. 외부 실행이 일어나는 버튼은 누르지 않는다 |

### Muse 설정에서 알아둘 것

연결하면 연결 범위의 자료를 Muse에 제공하는 셈이다. 수업에서는 설정 경로를 읽어 보고, 계정 연결이나 설정 변경 없이 연습한다. 실제 사용에서는 Settings → Permissions → Connectors에서 「Ask for some actions」나 더 제한적인 설정을 쓰고 「Always allow」는 피한다.

2026-10-25 웹 실습에서는 Settings → Data controls에 학습 사용을 끄는 스위치가 보이지 않았다. 현재 화면에서 직접 확인할 수 있을 때까지 학습 사용을 끌 수 없다고 가정한다. 연결 해제는 Settings → Connectors에서 찾고, 저장된 기억을 지울 때는 Muse의 forget 요청에 대한 범위와 영향을 먼저 확인한다. 다른 사람을 언급해야 할 때는 이름과 관계까지만 남긴다. Muse가 그 사람에 관한 기록을 쌓을 수 있으므로 연락처·금액·내부 결정은 제외한다. [연결 규칙](../../01-Workflow-Fit-Map/guides/do-not-upload.md#연결-규칙--결정-③-메일--캘린더-v20) · [이름 규칙](../../01-Workflow-Fit-Map/guides/do-not-upload.md#이름-규칙--결정-②-이름--관계만-v20)

## 블록 2 — 음성·메모·메일·일정 초안 요청

| 항목 | 내용 |
|---|---|
| 대상과 목표 | L1 중심. 목표·맥락·원하는 형식·제외할 내용을 담아 한 번에 요청한다 |
| 시간 | 45분 |
| 준비물 | 가상 행사 메모, 마이크 사용이 가능한 휴대폰 또는 컴퓨터 |
| 단계 | 1) 휴대폰에서 Muse 입력창을 연다 2) 가상 메모를 보며 음성으로 요청한다 3) 받아 적힌 날짜와 시간을 확인한다 4) 메일 초안 또는 일정 문안을 비교한다 5) 누락 한 가지를 고쳐 달라고 한다 |
| 실습 | 가상 행사 메모로 안내 메일 초안 또는 일정 문안을 만든다. 정규 수업에서는 두 가지를 모두 해 본다 |
| 확인 질문 | 답변에서 원문에 없는 내용은 무엇인가? 내가 원하는 독자는 누구인가? |
| 흔한 실수 | “잘 정리해 줘”만 적고 길이·독자·목적을 말하지 않음 |
| 안전 규칙 | 실제 수신자에게 보내지 않는다. 초안을 직접 검토한다 |

### 원문을 보존하는 편집 요청

내용을 새로 쓰는 일과 맞춤법·배치를 고치는 일을 구분한다. 가상 글을 주고 「원문과 말투는 바꾸지 말고 맞춤법만 고쳐 주세요. 바꾼 부분을 따로 알려 주세요」라고 요청한 뒤 원문과 대조한다. 페이지에 맞추기 위해 내용을 줄여야 하면 먼저 물어보게 하고, 번역본은 원문 보존과 별도로 의미를 확인한다. [막힐 때 확인할 질문](troubleshooting-faq.md#고친-글이-내-글-같지-않아요)

## 블록 3 — Muse에 맡길 업무 고르기

| 항목 | 내용 |
|---|---|
| 대상과 목표 | L2~L3. 자료 민감도·맥락 필요성·Muse를 쓸 이유·결과 편집량을 보고 맡길 수준을 정한다 |
| 시간 | 40분 |
| 준비물 | [가상 업무 카드 6개와 판정 기준](../examples/sample-course-plan.md#공통-실습-재료) |
| 단계 | 1) 업무의 결과를 한 문장으로 쓴다 2) 자료 등급을 정한다 3) 필요한 로컬 맥락을 확인한다 4) Muse 장점이 있는지 본다 5) 맡김·초안만·맡기지 않음로 판정한다 |
| 실습 | 공개 공지·가상 음성 메모·가상 의료/계약 업무의 설명 카드만 분류한다 |
| 확인 질문 | 이 작업은 Muse가 더 편리한 이유가 있는가? 자료를 줄여 공개 정보만으로 할 수 있는가? |
| 흔한 실수 | Muse가 기술적으로 가능하다는 이유만으로 업무를 맡김 |
| 안전 규칙 | 민감한 사례의 설명 카드는 종이에서 분류한다. 원문은 Muse에 입력하지 않고 필요하면 로컬에서 처리한다 |

판정 명칭은 M1 기준을 따른다. [적합도 판정](../../01-Workflow-Fit-Map/guides/workflow-fit-map.md#2-적합도-판정-v1)

## 블록 4 — 결과를 파일로 회수하고 확인하기

| 항목 | 내용 |
|---|---|
| 대상과 목표 | L1~L3. Muse 결과를 저장·회수하고 원문 및 원하는 경로와 대조한다 |
| 시간 | 45분 |
| 준비물 | 가상 행사 메모와 다운로드 가능한 테스트 파일 |
| 단계 | 1) 파일명·형식·경로를 지정한다 2) Muse가 파일을 만들었는지 확인한다 3) 내려받거나 허용된 테스트 폴더에서 연다 4) 문장·파일 수·경로를 확인한다 5) 필요한 부분을 로컬에서 수정한다 |
| 실습 | 가상 행사 메모의 요약을 새 Markdown 파일로 저장한다. Library에서 파일을 하나 내려받아 열고 시간·장소·미정 항목을 확인한다 |
| 확인 질문 | 결과가 실제 파일로 존재하는가? 원문과 달라진 부분은 무엇인가? |
| 흔한 실수 | 채팅 화면에 보인 답만으로 파일 저장까지 됐다고 생각함 |
| 안전 규칙 | 원본을 덮어쓰지 않는다. 테스트 경로에서 먼저 확인한다 |

Library에서 개별 파일을 회수한다. 전체 보관이 필요할 때의 ZIP 경로는 Settings → Data controls → Download your agent data다. 대화와 업로드 파일이 함께 들어갈 수 있어 전체 ZIP은 수업 실습에서 사용하지 않는다. [M2 회수 비교](../../02-Muse-to-Vault/guides/transfer-comparison.md#밖--집-muse-결과를-볼트-쪽으로)

## 블록 5 — 개인 자료와 연결해 검색·작업하기

| 항목 | 내용 |
|---|---|
| 대상과 목표 | L3. 승인된 작은 자료 묶음에서 경로 또는 인덱스로 근거 파일을 찾고 답을 검증한다 |
| 시간 | 50분 |
| 준비물 | [가상 Markdown 3개와 INDEX.md](../examples/sample-course-plan.md#공통-실습-재료), 별도 테스트 폴더 |
| 단계 | 1) 자료가 허용된 범위인지 확인한다 2) 인덱스에서 관련 경로를 찾는다 3) Muse가 원문 파일을 읽는지 확인한다 4) 인용과 답을 대조한다 5) 회수 결과를 검증한다 |
| 실습 | INDEX.md에서 일정 노트를 찾아 겹치는 시간과 근거 경로를 답하게 한다. 원문과 답을 비교한다 |
| 확인 질문 | Muse가 실제로 읽은 파일은 무엇인가? 연결된 자료를 놓친 흔적이 있는가? |
| 흔한 실수 | Dropbox에 파일이 있다는 이유로 Muse가 전체 자료를 검색할 수 있다고 가정함 |
| 안전 규칙 | 실제 Vault 전체를 실습하지 않는다. 연결 범위와 검색 성능은 별도 승인된 환경에서 확인한다 |
