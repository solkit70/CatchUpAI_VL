# Muse 사용 막힐 때 FAQ

각 항목에 근거 링크가 있으면 앞 모듈의 관찰이나 가이드를 참조한 것이다. 링크가 없는 항목은 수업에서 쓰는 일반 원칙이다.

## 시작과 입력

### Muse와 Meta AI 화면이 헷갈려요

웹 실습을 시작할 때 주소가 muse.ai인지 먼저 확인한다. 도움말과 로그인한 앱 화면이 다르면 기기·날짜·메뉴를 기록하고, 해당 화면에서 가능한 동작까지만 설명한다. [M3 재현 순서](../../03-VibeLearn-on-Muse/guides/muse-vibelearn-test.md#재현-순서) · [M1 연결 규칙](../../01-Workflow-Fit-Map/guides/do-not-upload.md#연결-규칙--결정-③-메일--캘린더-v20)

### 「기억해 둘게요」라고 하면 저장된 건가요?

저장한 파일 또는 기억의 위치와 내용을 설명해 달라고 한다. 이후 새 대화에서 적용되는지 확인한다. [M3 재현 순서](../../03-VibeLearn-on-Muse/guides/muse-vibelearn-test.md#재현-순서)

### 커넥터를 쓰거나 연결을 끊을 때 무엇을 확인하나요?

연결 범위는 입력으로 제공하는 자료와 마찬가지로 취급한다. 실제 사용에서는 Settings → Permissions → Connectors에서 승인 설정을 지키고, 연결 해제와 저장된 기억에 대한 forget 요청의 범위를 각각 확인한다. [M1 연결 규칙](../../01-Workflow-Fit-Map/guides/do-not-upload.md#연결-규칙--결정-③-메일--캘린더-v20)

### Muse에 무엇을 입력해도 되나요?

먼저 자료의 민감도와 업무 목적을 확인한다. 공개 자료나 가상 예시를 사용한다. 다른 사람을 언급해야 하면 이름과 관계까지만 남기고 연락처·금액·내부 결정은 빼 둔다. [M1 이름 규칙](../../01-Workflow-Fit-Map/guides/do-not-upload.md#이름-규칙--결정-②-이름--관계만-v20)

### 요청했는데 답이 너무 넓게 나와요

원하는 결과, 독자, 길이, 사용할 자료, 제외할 내용을 추가로 알려 준다. 결과에서 불명확한 항목은 확인 질문으로 분리한다.

### 음성 입력이 잘못 받아 적혔어요

이름·날짜·금액·장소처럼 중요한 항목을 직접 확인해 바로잡는다. 확인할 수 없는 단어는 추정해 넣지 말고 미확인으로 표시한다.

### Muse가 출처 없이 사실을 말해요

「파일에 없는 것은 없다고 말해 주세요」를 요청에 넣는다. 받은 파일은 열어서 원문에 없는 예보, 날짜, 숫자가 실려 있지 않은지 확인한다. [10월 25일 M2 수업 메모](../../vl_worklog/20261025_M2_Muse-My-Workflow.md#-가르칠-때) [M3 재현 순서](../../03-VibeLearn-on-Muse/guides/muse-vibelearn-test.md#재현-순서)

## 맡길 일 선택

### Muse가 할 수 있으면 맡겨도 되나요?

기술적으로 가능한지와 맡기는 편이 나은지는 다르다. 자료 민감도, 필요한 개인 맥락, 작업 장소의 이점, 결과 편집량을 함께 보고 정한다. [M1 적합도 판정](../../01-Workflow-Fit-Map/guides/workflow-fit-map.md#2-적합도-판정-v1)

### 이메일이나 게시글을 대신 보내도 되나요?

수업 실습에서는 초안까지 작성한다. 수신자·사실·톤을 사람이 검토하고 실제 발송이나 게시를 직접 결정한다.

### 내부 문서와 공개 정보를 함께 써야 해요

실습에서는 내부 문서를 제외한다. 가능하면 공개 정보만으로 질문을 다시 만들고, 내부 맥락이 반드시 필요하면 승인된 로컬 환경에서 처리한다.

## 파일과 회수

### Muse가 만든 파일을 찾을 수 없어요

파일 이름·저장 위치·생성 완료 여부를 확인해 달라고 한다. Library에서 개별 파일을 내려받아 연다. Settings → Data controls → Download your agent data는 전체 ZIP을 받는 방법이다. [M2 회수 비교](../../02-Muse-to-Vault/guides/transfer-comparison.md#밖--집-muse-결과를-볼트-쪽으로)

### Markdown 서식이나 링크가 달라졌어요

넘김 자료에 필요한 머리말 키와 파일 규칙을 직접 쓴다. 회수 파일을 열어 키·링크·제목을 원본과 대조한다. [M2 정리 지침](../../02-Muse-to-Vault/guides/vault-cleanup-prompt.md)

### Dropbox에 파일이 있는데 Muse가 못 찾습니다

폴더와 파일의 정확한 경로를 알려 주고 그 파일을 직접 열어 보도록 요청한다. 못 열면 검색어, 대상 범위, 오류를 기록한다. 다른 클라우드와의 검색 차이를 확인하지 않은 채 원인을 단정하지 않는다.

### PC가 꺼져 있어도 결과가 돌아오나요?

검증된 동기화 폴더에서만 기대한다. Muse에서 파일 생성, PC 재시작, 로컬 파일 경로·내용 확인의 세 단계를 실제로 거친다.

### 결과를 Vault에 바로 넣어도 되나요?

먼저 회수 파일의 내용과 출처를 확인한다. 중복·개인 정보·frontmatter·링크를 검토한 뒤 사람이 최종 경로에 편입한다.

## 자료 연결과 검색

### Muse가 Dropbox 전체를 자동으로 훑나요?

그렇게 가정하지 않는다. 정확한 경로를 주거나 인덱스에서 관련 파일을 찾게 한 뒤, 읽은 파일 목록을 확인한다.

### 인덱스만 있으면 원문 검토가 필요 없나요?

아니다. 인덱스는 후보 파일을 찾는 목차다. 답을 만들 때 원문을 열어 사실과 날짜를 대조한다.

### 연결된 노트의 링크까지 따라가나요?

합성 자료 실습에서는 경로가 있는 링크를 한 번 따라갔다. 대상이 접근 범위 밖이면 원문 확인이 끊길 수 있다. 읽은 파일·경로·원문 날짜를 확인한다. 링크 도달은 최신성 확인과 별개다. [M4에서 확인한 범위](../../04-Vault-Connection/README.md#지금까지-알아낸-것)

### 자료를 많이 올리면 검색이 더 정확해지나요?

자료 양만으로 정확도가 보장되지 않는다. 작은 테스트 묶음으로 찾은 파일, 놓친 자료, 근거 일치 여부를 확인한다.

### 개인정보를 포함해도 되나요?

업무 목적과 연결 범위에 꼭 필요한지 판단하고, 허용된 도구·폴더인지 확인한다. 교육 예시는 가상 정보로 바꾼다.

### GitHub에서 방금 고친 문서가 보이지 않아요

로컬 수정이나 커밋만으로 원격 파일은 바뀌지 않는다. 올바른 브랜치에 push됐는지 원격 화면의 경로와 커밋으로 확인한다. [Topic의 놓쳤던 조건](../../README.md#틀렸던-판단과-아직-모르는-것)

## 복구와 다음 단계

### 원하는 결과가 안 나왔어요

질문, 입력 자료, 읽은 파일, 결과, 실패한 지점을 기록하고 한 번에 한 요소만 바꿔 다시 시험한다.

### 언제 로컬 AI로 돌아가야 하나요?

원본 Vault의 복잡한 맥락, 대량 수정, 내부 자료 검토, 정확한 링크·메타데이터 보존이 필요하면 로컬 작업이 적합한지 검토한다.
