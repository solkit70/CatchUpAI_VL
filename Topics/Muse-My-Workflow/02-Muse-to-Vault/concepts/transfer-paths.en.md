# Transfer Paths — Both Ways · Preservation · Original Wording · Inbox · Handoff Packet

[한국어](transfer-paths.md)

> This is the concept summary for M2. For the actual test results by method, see [../guides/transfer-comparison.en.md](../guides/transfer-comparison.en.md).

## 1. Both Ways

"Home and away without interruption" means both directions must work.

| Direction | What it does | Examples |
|---|---|---|
| Away → home | Transfer results made in Muse into the vault | Download a file · email · copy |
| Home → away | Hand work from home to Muse so it can continue | Upload a handoff packet · public repo link |

## 2. Preservation

How much of the headings, lists, tables, links, and sources remain after a transfer. When I tested hands-on, the original Markdown stayed as-is with all four methods. So the way to choose a method is not preservation. It is **the number of steps, whether it works on a phone, and whether a connection is needed**.

## 3. Keeping the Original Wording

The vault rule is to not change a single character of spoken originals. So you must tell Muse "Save it as a file exactly as I said it," and compare the file you get with what you said. This test was done with a voice memo on the phone (Changsoo Park's report: transcribed exactly as spoken; evidence for the comparison to be added in the next session).

## 4. Inbox and Source Marking

Results from away are gathered in one place, then cleaned up at home. If you put them straight into their final place, unreviewed writing gets mixed in. Documents in the inbox keep "made in Muse · date · reviewed or not" so they can be checked later. In the handoff packet test, Muse also used this rule as an evaluation criterion.

## 5. Handoff Packet

A short bundle used when handing work from home → away. It has three sections: **where I left off · what was decided · next steps**. At the end, add one line: "If you don't know something, don't make it up — say you don't know." In the test, Muse followed this line and said it "doesn't know" things that were not in the packet, such as the vault's real location and folder structure.

**What the packet must include**: things Muse will get wrong if it doesn't know them, like the vault rules (for example, frontmatter uses lowercase English keys). In the test, that line was missing, so Muse made Korean keys.

## 6. Easy Misunderstandings

- A share link is not "a transfer." The original is always the vault.
- Things uploaded to Muse's System Files also disappear if deleted or if the account changes.
- Muse does not reach the vault directly. So the last step of "away → home" (putting it in the inbox · cleanup) is done by a person at home.
- With the method of having Muse read a link, **only what was pushed** is visible.
