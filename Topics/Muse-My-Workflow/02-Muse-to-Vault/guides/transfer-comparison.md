# 옮기기 방법 비교표와 기본 방법

> 2026-10-25 Live #33 1부에서 직접 시험한 결과다. 시험 재료는 공개해도 되는 가짜 내용(제목 · 목록 3 · 표 3행 · 링크 1 · 마지막 줄)으로 만든 Markdown 파일 하나(397바이트)다. 시험은 **웹 Muse** 에서 했고, 휴대폰은 칸마다 「미확인」으로 표시했다. 개념은 [../concepts/transfer-paths.md](../concepts/transfer-paths.md).

## 밖 → 집 (Muse 결과를 볼트 쪽으로)

| 방법 | 결과 | 단계 | 보존도 | 휴대폰 | 주의점 |
|---|---|---|---|---|---|
| ① 파일 하나씩 내려받기 | ✅ | 3 (카드 클릭 → ⋯ → Download) | 제목 · 목록 · 표 · 링크 · 마지막 줄 전부 그대로 | ✅ 파일을 열고 ⋯ 를 누르면 메뉴가 뜬다(2단계). 메뉴 이름이 웹과 다르다 — Pin · Search · Share · Copy text · Save to Files · Download as PDF · Delete. 저장 형식은 미확인 | 공식 도움말에는 없던 기능이 앱에 있었다. 파일 이름이 문서 제목 그대로다(공백 · 한글 포함) |
| ② 내 메일로 보내기 | ✅ | Muse 에 한 줄 지시 + 보내기 승인 | 첨부가 **바이트까지 같다**(웹 397B · 휴대폰 279B, 둘 다 비교 도구로 확인) | ✅ 휴대폰에서도 같은 결과 — 휴대폰에서 만든 파일이 집 PC Gmail 에 첨부로 도착했다 | Gmail 커넥터 연결이 필요하다. 받은편지함에 섞인다. 보내기는 「Ask」라 승인이 든다 |
| ③ 복사 · 붙여넣기 | ✅ | 2 (⋯ → Copy → 붙여넣기) | **Markdown 원문**이 그대로 복사된다(렌더된 글이 아니다). View source 도 같은 원문 | 휴대폰 메뉴에는 Copy text 가 있다(웹의 View source 는 없음) — 붙여 넣은 결과는 미시험 | 파일로 두려면 붙여 넣은 뒤 저장하는 단계가 하나 더 든다 |
| ④ 전체 데이터 내려받기 | ✅ | Settings → Data controls → Download your agent data | zip 하나(약 4MB · 103개): 대화 txt · `workspace/` 안에 Muse 가 만든 Markdown 이 폴더 구조 그대로 · 올린 파일 · manifest | ❓ | 요청한 당일에 받았다. **개인 정보가 한꺼번에 든다** — 백업용이지 매일 쓰는 방법이 아니다 |
| 공유 링크 | 시험 안 함 | — | — | — | 「옮긴 것」이 아니다 — 계정이 바뀌거나 링크가 만료되면 볼트에는 아무것도 없다 |

## 집 → 밖 (진행 중인 일을 Muse 가 이어받게)

| 방법 | 결과 | 보존도 · 이어가기 | 주의점 |
|---|---|---|---|
| ① 파일 올리기 (넘김 꾸러미) | ✅ | 한 줄 지시로 「다음 할 일」 2개를 모두 했다. 꾸러미에 없는 것은 「모른다」고 밝혔다 | 한글 frontmatter 키를 만들었다 → 집에서 고쳐야 한다. 꾸러미에 없던 날짜는 스스로 채웠다 |
| ③ 공개 레포 링크 | ✅ | 올라간 로드맵 M2 를 읽고 세 줄로 정확히 요약했다(지어낸 것 없음) | **push 한 것만** 보인다. 공개 문서만 가능하다 |
| ② 내 메일로 보내 읽게 하기 | ✅ (박창수 일상 사용 보고, 2026-10-25) | 집 PC 와 휴대폰 · 태블릿 앱에서 모두 잘 된다고 한다. 이번 세션에서 같은 조건으로 따로 시험하지는 않았다 | Gmail 커넥터 연결이 필요하다. 내용이 자기 받은편지함에 남는다 |

## 음성 원문 보존

| 시험 | 결과 |
|---|---|
| 음성으로 말한 메모를 「한 글자도 바꾸지 말고 마크다운 파일로 저장해줘」 | ✅ 한 줄로 충분했다. 저장된 파일이 Muse 가 받아 적은 입력 글과 같다 — 군더더기 말까지 남고 제목 · 덧붙인 말이 없다 |
| 한계 | 비교한 것은 받아 적은 글과 저장 파일이다. 말소리와 받아 적은 글이 같은지는 본인만 판단한다(브랜드 이름 Muse 는 「뮤즈」로 적혔다) |

## 추천 기본 방법

| 상황 | 추천 | 이유 |
|---|---|---|
| 집 PC 앞에서 Muse 결과 한 건을 가져온다 | **① 파일 하나씩 내려받기** | 단계가 가장 적고 원문이 그대로다 |
| 휴대폰에서 Muse 로 만든 것을 집으로 보낸다 | **② 내 메일로 보내기** (웹 · 휴대폰 모두 시험 완료) | 앱에서 한 줄 지시로 보내고 집 PC 의 Gmail 에서 받는다. 첨부가 원본과 같다 |
| 파일은 못 받고 글만 옮긴다 | ③ 복사 · 붙여넣기 | 원문이 그대로 복사된다 |
| 집 → 밖 | ① 넘김 꾸러미 파일 올리기, 공개 자료면 ③ 레포 링크 | 한 줄 지시로 이어받는다 |

**추천표 승인**: 박창수가 승인했다(2026-10-25, Live #33). 휴대폰 시험 뒤 ② 휴대폰 기본 방법을 확정했다.

**한 줄 요약**: 어느 방법이든 원문은 안 깨진다. 방법의 차이는 **단계 수 · 휴대폰에서 되는가 · 연결이 필요한가**이고, 정말 중요한 일은 옮긴 뒤 볼트 규칙에 맞추는 정리 단계다.

## 받는 곳(Inbox) — 결정: A (`_Inbox_/` 에 바로)

박창수가 추천대로 **A** 를 골랐다(2026-10-25, Live #33). 정리 단계와 프롬프트는 [vault-cleanup-prompt.md](vault-cleanup-prompt.md). 아래는 고를 때 본 후보표다.

볼트에는 이미 `_Inbox_/` 폴더가 있다(「notes waiting for right place」 — 제자리를 못 찾은 노트 보관, 같은 폴더 노트를 자동으로 나열하는 `_Inbox_.md` 가 있다).

| 후보 | 위치 | 장점 | 단점 |
|---|---|---|---|
| **A (추천)** | `_Inbox_/` 에 바로 | 이미 있는 용도 그대로이고 목록이 자동으로 만들어진다. 새 폴더 규칙이 없다 | Muse 에서 온 것과 다른 임시 노트가 섞인다 → 머리말의 출처 표시로 구분 |
| B | `_Inbox_/Muse/` 하위 폴더 | Muse 에서 온 것만 따로 모인다 | `_Inbox_.md` 의 자동 목록은 같은 폴더만 잡아서 하위 폴더 노트는 안 나온다 |
| C | `Ingest/Snippets/` | 밖에서 들어온 짧은 글 보관소 성격 | 이미 정리된 글이 들어 있는 곳이라 「검토 전」 문서가 섞이는 것이 어색하다 |

Muse 도 같은 방향으로 후보 3개를 냈다(볼트 안 Inbox · Muse 작업 공간 안 Inbox · Gmail 받은편지함). 다만 Muse 는 볼트의 실제 폴더를 모르는 상태에서 말한 것이라 이 표가 실제 구조에 맞춘 안이다.
