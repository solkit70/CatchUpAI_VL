## 계획 대비 실제

58건과 결정 9건으로 출발한 계획을 현재 69개 입력·결정 10건으로 검증했다. 새 데이터 규칙을 자동 추정하지 않고 기존 결정과 이후 모듈의 표시 정책을 구분했다. 인덱서의 A1 개선과 문서 마무리로 M1 DoD 6/6을 확인했다. → [요구와 검증](20261002_M1_Personal-Ops-Board.md#오늘-정한-요구--ears)

## 핵심 학습과 문제 해결

전체 볼트 순회를 매번 하는 대신 경로를 직접 확인하고 이름 검색을 지연시켜 현재 실행 5초 목표를 통과했다. 합성 회귀는 10건에서 16건으로 늘렸고 원본 무변경을 확인했다. 링크 검사 도구의 공백 경로 오탐은 토픽의 URL 인코딩 표기로 해결했다. → [ADR 009의 결과](../architecture/decisions/009-%EB%A7%81%ED%81%AC%EB%8A%94%20%EC%A7%81%EC%A0%91%20%ED%99%95%EC%9D%B8%ED%95%98%EA%B3%A0%20%EC%83%89%EC%9D%B8%EC%9D%80%20%EC%A7%80%EC%97%B0%20%EC%83%9D%EC%84%B1.md#결과--대가)

## Roadmap 정확도와 방법론 평가

실제 사용에서 결정 로그가 계속 늘어나므로 계획의 숫자를 영구 사양으로 쓰면 안 된다. 모듈별 EARS·검증·ADR·아키텍처 연결은 이번 범위에서 작동했지만 다른 앱 재사용과 문서 부담 평가는 아직 남아 있다. 개인 입력 오류 1건을 원본 수정 없이 보여 주는 경계도 유지했다.

## 다음 모듈 준비

M0 문서 검토는 10/2 사용자 확인으로 완료했다. M2는 4단계 보드 요구·정렬·경고 표시·완료와 닫음 구분을 먼저 조사·설계하고, Board의 원본 쓰기 금지와 기존 워크플로 유지 경계를 포함한다. 이 단계의 승인 범위는 설계안 검토까지다.

추가 결정은 ADR 009이고 ADR 005는 Go 보류 의미를 명확히 했다. ADR 006의 EARS 미승인 문구는 채택 상태로 갱신했으며, 공개 커밋·push는 별도 요청 조건을 유지한다.
