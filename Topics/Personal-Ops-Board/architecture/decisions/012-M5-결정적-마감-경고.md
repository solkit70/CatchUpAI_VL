# 012 — M5 마감 경고는 결정적 Python renderer로 생성

- **날짜 · 모듈**: 2026-10-03 · M5 Deadline Agent
- **상태**: ✅ 승인된 설계로 구현; 자동 운영 실행 검증 대기

## 맥락

M5는 마감 초과·오늘·사전 경고를 `views/warnings.md`로 매일 보여 준다. 기존 task 원본은 Markdown이며 인덱서와 Board 정렬은 결정적 Python 도구를 쓴다. AI4PKM 오케스트레이터는 이미 cron 노드를 제공한다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| LLM이 매일 날짜를 계산하고 경고 문서를 작성 | 자연어 요약 가능 | 같은 입력에도 표현이 달라지고 단순 경계 규칙을 검증하기 어렵다 |
| 외부 scheduler 또는 데이터베이스 도입 | 별도 확장 여지 | 현재 기능에 필요하지 않은 런타임·동기화 부담 |
| **현재 Python renderer + AI4PKM cron** | 기존 인덱스·실행 로그·운영 런타임을 활용하고 fixture로 경계 검증 가능 | cron scheduler가 실행 중이어야 자동 실행된다 |

## 결정

- `pob_deadline.py`가 `views/index.json`을 읽고 `views/warnings.md`만 생성한다. item 원본, root Task Board, `priority-board.md`는 쓰지 않는다.
- 기한 초과, 오늘 마감, `0 < 남은 날짜 <= warn_days` 사전 경고를 분리한다. 각 task의 `warn_days`를 우선하고 없거나 유효하지 않으면 기본 3일이다. due 당일까지 경고를 매일 표시한다.
- `todo`, `doing`, `waiting`만 대상이다. `waiting.due`는 독촉일이다. `done`, `paused`, 마감일이 없는 task는 경고에서 제외한다.
- 입력에 index error/invalid task가 있거나 활성 task의 due를 읽을 수 없으면 실행 실패로 처리한다. 출력은 완성 후 원자적으로 교체해 이전 정상 파일을 지킨다.
- 기준일은 Windows의 시스템 현지 날짜를 사용한다. 사용자 PC는 시애틀 시간대이며 날짜 전용 due를 시각대로 변환하지 않는다. `--as-of`는 합성 경계 테스트에서만 사용한다.
- 매일 05:00 AI4PKM cron node가 인덱서를 다시 실행한 다음 Deadline renderer를 호출한다. 별도 scheduler를 추가하지 않는다.

## 이유

날짜 경계와 상태 제외는 설명 가능한 고정 규칙이며 자연어 추론이 필요 없다. AI4PKM 공식 workflow 문서는 정해진 cron 시간에 반복 prompt를 실행하는 구조를 지원한다. 따라서 orchestration만 AI4PKM에 두고 계산·렌더링은 Python에 둔다. Python의 표준 `datetime`은 날짜 차이를 직접 계산할 수 있다. ([AI4PKM Workflow Automation](https://jykim.github.io/AI4PKM/workflows.html#workflow-automation) · [Python datetime](https://docs.python.org/3/library/datetime.html))

## 결과와 재검토 조건

- 장점: task 제목은 view에만 나타나고 실행 로그에는 상태별 건수만 남는다. 인덱스·날짜 오류가 있어도 stale view가 지워지지 않는다.
- 대가: 경고 view는 매일 업데이트되지만 외부 push notification은 보내지 않는다. AI4PKM cron scheduler가 실행 중이지 않으면 자동 갱신되지 않는다.
- 재검토: 한 주 실제 사용에서 경고가 너무 많거나, overdue 지속 표시가 유용하지 않으면 `warn_days`·요약 기준을 다시 검토한다. 자동 운영 log 및 다음 날 지속성 확인 뒤 상태를 확정한다.
