# 005 Go 는 보류 — 필요성이 확인되면 재검토

- **날짜 · 모듈**: 2026-09-12 결정 · 2026-09-27 M0 기록
- **상태**: ✅ 채택 (보류)

## 맥락
「멀티 에이전트 시스템을 만들려면 Python 보다 Go 를 써야 한다」는 조언이 있었다 (사용자 질문 9/12). Go 는 동시성과 단일 바이너리 배포가 강점이다.

## 검토한 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| Go | 동시성 · 빠른 상주 서비스 · 배포 쉬움 | 새 언어 · 이 앱에서는 병목이 언어가 아님 |
| **Python (v1~v3)** | 이미 쓰는 언어 · 에이전트는 프롬프트라 언어 무관 | 상주 데몬 성능은 Go 보다 약함 |

## 결정
v1~v3 는 Go 를 쓰지 않는다. 에이전트는 AI4PKM 노드(프롬프트)이고, 파싱·인덱싱은 Python, 화면은 HTML 한 장이다.

여기서 보류는 영구 배제가 아니라 현재 구현에서 도입하지 않는다는 뜻이다. 필요성이 확인되면 버전 번호와 관계없이 새 ADR과 사용자 설계 승인을 거쳐 일부 구성 요소에 Go를 사용할 수 있다. 현재 Python 선택은 유지한다 (2026-10-02 검토 중 의미 명확화).

## 이유
에이전트의 일은 LLM 호출이라 언어의 동시성이 병목이 아니다. 배포 대상도 PC 한 대다. 언어보다 중요한 것은 **에이전트를 작게, 한 역할로, 정해진 계약으로만 소통하게** 만드는 것이다. 그러면 나중에 하나를 Go 로 바꿔도 나머지는 모른다.

## 결과 · 대가
- 다시 볼 조건의 예: 외부 요청에 초 단위로 응답하는 **상주 데몬**이 필요해질 때 (기존 예상 v4). v4는 재검토 시기의 예상이지 필수 조건이 아니다. 그때도 먼저 「오케스트레이터를 노출하면 되지 않나」를 묻는다
