# 009 링크는 직접 확인하고 색인은 지연 생성

- **날짜 · 모듈**: 2026-10-02 M1
- **상태**: 채택 — A1 제안 사용자 승인 후 구현·검증

## 맥락

9/27 인덱서 실행은 86초였다. 링크 검사를 위해 매번 볼트 전체를 `rglob`으로 순회하고, 제외 폴더도 진입한 뒤 걸러냈다. 현재 링크 120개는 모두 경로를 포함하므로 이름 검색용 전체 색인을 먼저 만들 필요가 없다. → [이전 WorkLog의 문제 해결 로그](../../vl_worklog/20260927_M0_Personal-Ops-Board.md#-문제-해결-로그)

## 검토한 선택지

| 선택지 | 판단 |
|---|---|
| 기존 전체 순회 유지 | 매 실행의 불필요한 비용 |
| `os.walk`에서 제외 폴더 진입 전 가지치기 | 이름 색인이 필요할 때의 순회 비용 감소 |
| 경로 직접 확인 + basename 색인 지연 생성 | 현재 입력에서 전체 순회 생략, 이름 중복 판정은 유지 |
| 파일 목록을 별도 영구 캐시로 저장 | 캐시 무효화 규칙이 추가되어 현재 범위에서 제외 |

## 결정

가지치기와 직접 확인을 함께 적용한다. 볼트 루트 경로와 `AI/` 생략 경로는 파일 존재를 직접 검사하고, Markdown의 확장자 생략을 허용한다. 경로가 없는 이름 링크를 직접 해석하지 못할 때만 전체 이름 색인을 한 번 만든다. 같은 이름의 파일이 여러 개면 기존처럼 `link_ambiguous` 경고를 낸다.

제외 폴더 목록은 유지하고 검색 대상 폴더를 임의로 줄이지 않는다. 볼트 밖 경로와 제외 폴더는 직접 검사에서도 허용하지 않는다. 출력 JSON 형태·원본 무변경·파싱 실패 보존·오류 및 경고 규칙은 유지한다. 순회는 [Python 3.13 공식 `os.walk` 문서](https://docs.python.org/3.13/library/os.html#os.walk)의 top-down `dirnames` 수정 방식을 따른다.
