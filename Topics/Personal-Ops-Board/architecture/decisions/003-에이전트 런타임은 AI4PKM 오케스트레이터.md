# 003 에이전트 런타임은 AI4PKM 오케스트레이터

- **날짜 · 모듈**: 2026-09-12 결정 · 2026-09-27 M0 기록
- **상태**: ✅ 채택

## 맥락
멀티 에이전트 앱에는 에이전트를 언제·무엇으로 실행할지 정하는 런타임이 필요하다. 이 볼트에는 이미 매일 돌고 있는 AI4PKM 오케스트레이터(`orchestrator.yaml`)가 있다. `cron` 트리거(예: 매일 04:00 Daily Roundup)와 파일 트리거(`input_type: new_file`)를 지원한다.

## 검토한 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 멀티 에이전트 프레임워크 새로 도입 | 에이전트 간 호출·상태 관리 기능 | 새 의존성 · 기존 자동 정리와 런타임이 둘 |
| 직접 스케줄러·큐 작성 | 자유도 | 만들고 유지할 것이 늘어남 · v1 목표와 무관 |
| **AI4PKM 오케스트레이터** | 이미 운영 중 · cron + 파일 트리거 · 기존 워크플로와 같은 곳 | 에이전트 간 직접 호출 기능은 확인 필요 |

## 결정
에이전트 = `_Settings_/Prompts/POB-*.md` 프롬프트 하나 + `orchestrator.yaml` 노드 하나. 새 스케줄러·큐·프레임워크를 만들지 않는다.

## 이유
v1 의 목표는 보드를 자동으로 만드는 것이지 런타임을 만드는 것이 아니다. 기존 워크플로와 같은 런타임이면 운영·장애 확인도 한 곳에서 한다.

## 결과 · 대가
- 대가: Supervisor · 직접 호출 구조가 필요해지면 이 런타임으로 되는지 먼저 확인해야 한다 → [007](007-에이전트%20연결은%20열어%20둔다.md)
- 다시 볼 조건: 새 구조가 이 런타임으로 안 될 때 — 결정 기록 + 사용자 승인
