# 001 원본은 마크다운 — DB 없음

- **날짜 · 모듈**: 2026-09-12 결정 · 2026-09-27 M0 기록
- **상태**: ✅ 채택

## 맥락
할 일 앱은 보통 DB(SQLite · Postgres · 클라우드 서비스)를 원본으로 둔다. 그런데 이 볼트에서는 할 일이 이미 마크다운(Task Board · Daily Roundup · Journal · 회의록) 안에서 태어나고, 위키링크로 서로 이어져 있다. 사용자의 질문: 「AI 가 일반 텍스트를 잘 읽고 처리하는데 DB 로 관리할 필요가 있을까?」

## 검토한 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| SQLite / DB 원본 | 조회·정렬 빠름 · 업계 표준 | 볼트와 원본이 둘이 된다 · 동기화 필요 · 에이전트가 텍스트 대신 SQL 을 다뤄야 함 |
| JSON 파일 원본 | 파싱 쉬움 | 사람이 읽고 고치기 불편 · 위키링크 그래프 밖 |
| 외부 서비스 (Jira · Trello · Notion) | 화면이 완성돼 있음 | 볼트 문서와 연결이 끊긴다 · 에이전트 접근이 API 경유 |
| **마크다운 + frontmatter 원본** | 사람·AI 모두 읽음 · 위키링크 = 관계 · git 으로 이력 · 이미 쓰는 도구 | 대량 조회는 느림 → 캐시로 해결 |

## 결정
원본은 `items/*.md`(frontmatter). DB 를 만들지 않는다. 파싱 결과 `views/index.json` 은 **언제든 지워도 되는 캐시**다.

## 이유
DB 가 해 주는 것(관계 · 조회 · 트랜잭션)을 이 볼트에서는 위키링크 · 인덱서 캐시 · 파일 단위 쓰기 + git 이 대신한다. DB 가 꼭 필요해지는 순간은 「모르는 사람이 동시에 쓸 때」뿐인데, v1 은 사용자 한 명이다.

## 결과 · 대가
- 대가: 조회마다 파싱이 필요해 인덱서 캐시를 둔다 (M1). 실제로 M1 에서 링크 검사가 느린 문제가 나왔다 (1분 26초)
- 다시 볼 조건: 여러 사람이 동시에 쓰는 기능이 생길 때 (v2+)
