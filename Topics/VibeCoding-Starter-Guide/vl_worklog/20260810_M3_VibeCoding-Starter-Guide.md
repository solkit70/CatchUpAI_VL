## 📚 진행 내용

### 실습 1: VS Code 설치 절차 작성 (45분)

**목적**: 다운로드부터 첫 실행까지를 한 동작 = 한 단계로 쪼갠다.

**과정**: 내려받기 → 설치 → 화면 익히기의 3단계로 구성했다. Windows와 macOS를 **별도 소절로 분리**해 독자가 자기 것만 읽으면 되게 했다(한 문단에 섞으면 매번 "나는 어느 쪽이지"를 판단해야 한다).

문서 맨 앞에 **"내 컴퓨터가 되는지 확인"** 표를 넣어 크롬북·태블릿 사용자를 먼저 걸러냈다.

**결과**: `03-Setup-Environment/01-setup-vscode.md`

**핵심 결정**
- **크롬북 제약을 맨 앞에** — 30분 따라온 뒤 "안 됩니다"를 만나는 것보다 시작 전에 아는 게 낫다. 크롬북인지 알아보는 방법("왼쪽 아래 동그란 버튼, 격자 앱 화면")까지 적었다
- **"VS Code 자체를 배울 필요 없다"고 명시** — 에디터 기능 설명으로 빠지면 독자가 질린다. 열고, 폴더 열고, AI에게 말 걸기까지만
- **한국어 언어팩은 선택으로** — 버튼 이름을 영어로도 병기해 두어 굳이 안 바꿔도 따라올 수 있게 했다

### 실습 2: Claude 유료 가입 + Claude Code 확장 설치 (45분)

**목적**: 계정 만들기부터 확장 로그인까지, 비용 이야기를 정직하게 담아서.

**과정**: 비용 안내 → 계정 만들기 → 유료 구독 → 확장 설치 → 로그인 → 작동 확인의 5단계로 구성했다.

**결과**: `03-Setup-Environment/02-setup-claude.md`

**핵심 결정**
- **비용 이야기를 맨 앞에, 표로** — "왜 필요한가 / 어떻게 내나 / 얼마인가 / 처음엔 어떤 걸 / 그만두려면" 다섯 가지를 미리 답했다. 뒤에 숨겨 두면 절반쯤 진행한 뒤 배신감을 느낀다
- **금액을 못 박지 않았다** — "가입 화면에 표시된 현재 가격을 직접 확인하세요". 가격은 바뀌는데 문서는 그만큼 자주 갱신되지 않는다. 숫자를 적으면 반드시 틀린 문서가 된다
- **"이미 구독 중일 수 있다"를 먼저 확인시킴** — 회사·학교 계정이 있는 경우가 있다. 결제 전에 확인하면 돈이 굳는다
- **미성년 학생 주의 문구 추가** — 이번 대상에 중고등 학생이 포함되므로 보호자 동반 결제를 명시했다
- **"사용량 초과"를 고장이 아니라고 미리 안내** — 요금제 한도는 반드시 겪게 되는 상황인데, 모르면 설치가 잘못된 줄 안다
- **확장 만든 곳이 Anthropic인지 확인**시킴 — 비슷한 이름의 다른 확장이 있을 수 있다

### 실습 3: 작업 폴더 + 막힘 대비 (45분)

**목적**: AI가 일할 자리를 정하고, 실제로 파일을 만드는지 검증한다. 그리고 막힐 때를 대비한다.

**과정**: 폴더 만들기 → VS Code에서 열기 → AI가 폴더를 보는지 확인 → **AI에게 파일을 만들게 하기**의 4단계로 구성했다. 이어서 막힘 대비 문서를 18건 5구간으로 정리했다.

**결과**: `03-Setup-Environment/03-setup-workspace.md`, `03-Setup-Environment/04-troubleshooting.md`

**핵심 결정**
- **마지막에 AI가 실제로 `hello.md`를 만들게 했다** — "설치가 됐습니다"라는 말보다 파일이 눈앞에 생기는 게 확실한 검증이다. 동시에 **첫 성공 경험**이고, 웹 챗봇과 무엇이 다른지 이해되는 순간이기도 하다
- **"AI가 허락을 묻는 것"을 안전장치로 설명** — 귀찮아하지 말고, 오히려 AI가 무슨 일을 하는지 배우는 기회로 프레이밍했다
- **바탕화면을 피하라고 안내** — 파일이 늘면 어지럽고 실수로 지우기 쉽다
- **폴더 이름은 영어로 권장** — 한글도 대개 되지만 가끔 문제가 생기는 도구가 있다. "권장"으로만 두고 강제하지 않았다
- **막힘 대비 맨 앞에 "가장 먼저 해 볼 것 세 가지"** — 무엇이 막혔든 절반은 재시작·인터넷·기다리기로 해결된다. 개별 항목을 뒤지기 전에 이것부터 보게 했다

## 🐛 문제 해결 로그

### 문제 1: 가격을 적을 것인가

**증상**: 유료 구독 안내를 쓰면서 요금제 금액을 적을지 판단이 필요했다. 금액이 없으면 독자가 "얼마인지 모르고 어떻게 결정하나" 싶고, 적으면 곧 틀린 문서가 된다.

**원인**: 이 가이드는 한 번 쓰고 오래 쓰일 문서인데, 가격은 수시로 바뀐다.

**해결**: **금액을 적지 않고, 대신 "무엇을 확인해야 하는지"를 적었다.** "요금제가 여러 단계로 나뉘어 있고 가격은 바뀔 수 있습니다. 가입 화면에 표시된 현재 가격을 직접 확인하세요" + "가장 낮은 단계로 시작해도 된다" + "언제든 해지 가능"까지 함께. 독자가 결정하는 데 필요한 정보는 금액 자체가 아니라 **판단 기준**이었다.

**교훈**: 자주 바뀌는 사실은 문서에 박아 넣지 말고, **확인하는 방법**을 적는다.

### 문제 2: 화면 문구가 실제와 다를 위험

**증상**: 버튼 이름과 화면 문구를 상세히 적었는데, VS Code와 Claude의 화면은 업데이트로 바뀐다.

**원인**: 실제 화면을 보며 쓴 것이 아니라 알려진 절차를 바탕으로 작성했다.

**해결**: 문구를 단정적으로 쓰지 않고 **"~처럼 생겼습니다", "~라고 뜹니다", "보통 ~라고 적혀 있습니다"** 로 완충 표현을 썼다. 또 버튼을 이름만이 아니라 **색·모양·위치**로 함께 설명했다("파란색 Download 버튼", "네모 네 개가 모인 아이콘", "왼쪽 세로 막대"). 이름이 바뀌어도 모양과 위치는 잘 안 바뀐다.

**남은 작업**: 다음 세션에서 **실제 화면과 대조 검증**이 필요하다. Roadmap M3 DoD의 "실제 화면과 문구가 일치하는지 직접 따라가며 확인" 항목은 아직 미완이다.

### 문제 3: 막힘 대비 항목을 무엇으로 채울까

**증상**: 실제 세션을 아직 안 했으므로 "우리가 겪은 문제"가 축적돼 있지 않다.

**원인**: 이 Topic이 세션보다 먼저 진행됐다.

**해결**: 일반적으로 반드시 발생하는 항목(맥 개발자 확인, 관리자 권한, 해외 결제 거절, 사용량 초과, 스팸함 등)으로 18건을 채우고, **학생 세션 후 실제 사례를 추가**하도록 남은 작업에 적었다.

## 💡 Daily Retrospective

### What went well
M1에서 만든 용어 사전과 대체 표현 표가 바로 힘을 발휘했다. "리포지토리", "실행한다", "에러" 같은 말을 쓸 뻔한 순간마다 표가 걸러 줬다. 특히 막힘 대비 문서는 **제목부터 "막힐 때 보는 문서 (자주 있는 일)"** 로 잡으면서 톤이 저절로 정해졌다 — 기준을 먼저 만든 효과다.

비용 이야기를 맨 앞에 정직하게 놓은 것도 잘한 판단 같다. 쓰면서 "이걸 뒤로 미루면 독자가 어떤 기분일까"를 생각하니 답이 분명했다.

### What could be improved
화면 문구를 실제로 확인하지 못한 채 썼다. 완충 표현과 "색·모양·위치" 병기로 위험을 줄였지만, **실물 검증은 반드시 해야 한다.** 특히 Claude Code 확장의 설치·로그인 흐름은 자주 바뀌는 영역이다.

문서가 길어졌다. 02-setup-claude.md는 참가자 기준 10분 읽을 분량이다. M7 통합 때 **표로 압축할 수 있는 부분**을 찾아야 한다.

### Insights
**자주 바뀌는 사실은 적지 말고, 확인하는 방법을 적는다.** 가격 문제에서 얻은 원칙인데, 화면 문구에도 똑같이 적용된다. 버튼 "이름"보다 "색·모양·위치"가 오래 간다.

또 하나 — **검증 단계가 곧 첫 성공 경험이 될 수 있다.** AI에게 `hello.md`를 만들게 한 것은 원래 "제대로 설치됐나" 확인용이었는데, 쓰다 보니 그 자체가 "AI가 내 컴퓨터에서 실제로 일한다"는 걸 체감하는 순간이 됐다. M4의 첫 성공 실습과 연결해서 설계하면 좋겠다.
