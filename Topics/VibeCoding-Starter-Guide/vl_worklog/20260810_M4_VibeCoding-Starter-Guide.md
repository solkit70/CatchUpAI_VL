### 실습 2: 첫 Topic 시작 안내 (50분)

**목적**: 한 문장으로 시작되는 경험을 문서화한다.

**과정**: 한 문장 말하기 → AI 질문에 답하기 → 폴더 생성 → 계획표 받기(승인 게이트) → 계획표 훑어보기 → 전체 3단계 흐름 정리.

**결과**: `04-Setup-VibeLearn/02-first-topic.md`

**핵심 결정**
- **층별 첫 문장 예시 3개** — 학생("광복절 발표 준비"), 만들고 싶은 분("경험을 보여 주는 웹페이지"), 실무자("행사 자료 정리하는 방법")
- **"공부"라는 말의 문턱을 낮춤** — "꼭 학교 공부가 아닙니다. 만들기, 정리하기, 알아보기 전부 됩니다"
- **승인 게이트를 안심 요소로 프레이밍** — "이건 고장이 아니라 안전장치입니다. AI가 여러분 확인 없이 멋대로 확정하지 않도록"
- **계획표에서 확인할 것을 3가지로 압축** — 단계 수 / 예상 시간 / DoD. 전부 이해하라고 하면 부담이 된다
- **DoD를 "Definition of Done, 완료 기준"으로 3중 표기** — 사용자 요청 반영. 이후 약자만 사용
- **"선택형 질문으로 물어봐 주세요" 팁** — 서술형 답변이 부담스러운 분을 위한 우회로. 공식 안내에도 있는 방법이다

## 🐛 문제 해결 로그

### 문제 1: 압축을 풀면 폴더가 이중으로 생기는 문제

**증상**: GitHub에서 ZIP을 받아 풀면 `VibeLearn-AI-main` 안에 또 `VibeLearn-AI-main`이 생기는 경우가 있다. 초보자는 어느 쪽을 열어야 할지 모른다.

**원인**: 압축 프로그램에 따라 상위 폴더를 한 겹 더 만드는 경우가 있다.

**해결**: 막힘 대비 항목에 **"`README.md` 파일이 바로 보이는 쪽이 진짜 폴더입니다"** 라는 판별 기준을 넣었다. 폴더 이름이 아니라 **안에 무엇이 보이는지**로 판단하게 한 것이 핵심이다.

### 문제 2: 폴더 이름 바꾸기를 필수로 할 것인가

**증상**: ZIP으로 받으면 `VibeLearn-AI-main`이 되는데, 안내문들은 `VibeLearn-AI` 기준으로 쓰여 있다.

**원인**: GitHub ZIP은 브랜치 이름을 폴더명에 붙인다.

**해결**: 이름을 바꾸라고 안내하되, 막힘 대비에 **"깜빡했어도 괜찮습니다. 그대로도 잘 작동합니다"** 를 넣었다. 실제로 동작에 지장이 없는데 "필수"로 만들면 불필요한 불안을 준다.

**교훈**: 절차를 안내할 때 **"안 지켜도 되는 것"과 "꼭 지켜야 하는 것"을 구분**해서 알려 줘야 한다. 전부 필수처럼 쓰면 하나 놓쳤을 때 전체를 의심하게 된다.

### 문제 3: 실제 실행 검증을 하지 못했다

**증상**: Roadmap M4 실습 1·2의 검증 방법은 "빈 폴더에 실제로 ZIP을 받아 열어 절차가 맞는지 확인", "실제로 한 문장을 넣어 Topic이 생성되는지 확인"이다. 이번 세션에서 수행하지 못했다.

**원인**: 문서 작성에 시간을 다 썼고, 실물 검증은 별도 시간이 필요하다.

**해결**: 미완으로 명시하고 다음 세션 준비사항에 올렸다. **DoD를 100%로 표시하지 않는다.**
