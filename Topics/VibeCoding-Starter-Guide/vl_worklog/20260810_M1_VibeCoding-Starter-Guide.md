## 📚 진행 내용

### 실습 1: 전체 목차 확정 (30분)

**목적**: M2~M7이 채울 자리를 먼저 정해 중복·누락을 막는다.

**과정**: 독자가 읽는 순서(환영 → 왜 → 설치 → 첫 성공 → 활용 → 다음 단계)로 8장 + 부록 4개를 배열하고, 각 장을 어느 모듈이 채우는지 매핑했다. 층별 동기 부여 문단 자리를 표로 정리하고, Catch Up AI 소개 위치를 0장·7장 두 곳으로 확정했다.

**결과**: `01-Guide-Foundation/01-outline.md`

**핵심 결정**
- **분량 목표 30쪽 내외** — 그 이상이면 대상 독자가 완독하지 못한다
- **설치를 3장에 배치**(2장 개념 뒤) — 무엇을 왜 까는지 모르고 설치하면 막혔을 때 포기할 이유가 생긴다
- **층별 문서 분리하지 않음** — 유지보수 3배 + 서로의 사례에서 배우는 효과 상실
- **Catch Up AI는 두 곳만** — 반복하면 홍보처럼 읽혀 신뢰를 깎는다

### 실습 2: 쉬운 용어 사전 (40분)

**목적**: 모든 문서가 공유할 용어 풀이 기준을 만든다.

**과정**: 설치부터 첫 성공까지 피할 수 없이 등장하는 용어를 5개 범주(컴퓨터 기본 / 도구 / 계정과 비용 / 내려받기 / AI와 일할 때 / VibeLearn AI 용어)로 나눠 정리했다. 이어서 "풀이해서 쓰기보다 아예 안 쓰는 게 나은" 표현을 대체 표현 표로 만들었다.

**결과**: `01-Guide-Foundation/02-glossary.md` — **용어 21개, 대체 표현 16개**

**핵심 결정**
- **"에러"를 금지어로** — 컴퓨터가 낯선 분에게 "에러"는 "내가 뭘 잘못했다"로 읽힌다. "자주 있는 일"로 표현해 심리적 문턱을 낮춘다
- **터미널은 풀이만 두고 실제로는 안 쓰게** 안내 — "겁먹지 않아도 된다"를 명시
- **커밋·푸시·환경 변수·의존성 설치는 이 가이드 범위 밖**으로 선언 — 기여자용 개념이라 학습자에게 불필요
- **DoD는 원어 유지 + 첫 등장 시 "완료 기준" 병기** — VibeLearn AI 문서에서 계속 마주칠 용어라 아예 감추면 나중에 더 혼란

**결과**: `01-Guide-Foundation/03-writing-checklist.md`, `01-Guide-Foundation/README.md`

## 🐛 문제 해결 로그

### 문제 1: 체크리스트를 Roadmap에 적용하니 1번 항목이 걸렸다

**증상**: "glossary에 없는 전문 용어 금지" 기준으로 Roadmap을 검수하니 DoD·Capstone·Self-Assessment 등이 전부 위반으로 잡혔다.

**원인**: Roadmap은 **집필자(나)가 보는 내부 문서**인데, 참가자용 산출물 기준을 그대로 적용했다. 두 문서의 독자가 다르다.

**해결**: 체크리스트 1번에 "Roadmap 등 내부 문서에는 적용하지 않는다"는 단서를 달고, 검수 결과표에 ⚠️로 명시했다. 참가자용 산출물(M2~M7의 본문)에만 엄격히 적용한다.

**교훈**: 검수 기준을 만들 때 **적용 대상 범위를 함께 정의**해야 한다. 안 그러면 내부 문서까지 잡혀 기준 자체가 무력해진다.

## 💡 Daily Retrospective

### What went well
목차를 먼저 확정한 것이 바로 효과를 봤다. 용어 사전을 쓰는 동안 "이 용어가 어느 장에서 처음 나오는지"를 목차에서 확인할 수 있어서, 어디에 풀이를 붙일지 판단이 빨랐다. 순서를 반대로 했으면 용어를 모아 놓고도 배치를 다시 고민했을 것이다.

대체 표현 표는 예상보다 훨씬 유용해 보인다. "풀이를 붙인다"는 원칙만 있으면 결국 어려운 말이 계속 등장하는데, **아예 쓰지 않을 단어 목록**이 있으니 판단이 단순해진다.

### What could be improved
용어 사전의 분량을 21개까지 늘렸는데, 실제 M3·M4를 쓰면서 안 쓰이는 항목이 나올 수 있다. 모듈을 다 쓴 뒤 **실제 사용된 용어만 남기고 정리하는 단계**가 필요하다. 지금은 넉넉히 두고 M7 통합 때 솎아낸다.

### Insights
검수 기준은 **적용 대상을 함께 정의해야 작동한다.** 이번에 Roadmap이 걸린 것처럼, 범위를 안 정하면 내부 문서까지 잡혀서 기준 자체를 무시하게 된다.

또 하나 — "에러"를 금지어로 정한 것이 이 가이드의 성격을 압축해서 보여준다. 이 가이드는 정보를 전달하는 문서가 아니라 **심리적 문턱을 낮추는 문서**다. 단어 선택이 곧 설계다.

### Tomorrow's focus
M3(설치편①) 진행. VS Code 설치 → Claude 유료 가입 → Claude Code 확장 설치·로그인 → 작업 폴더까지, 모든 단계에 체크포인트를 붙인다. 특히 **유료 구독 안내를 정직하게** 쓰는 것과 **크롬북 제약 명시**가 관건이다.
