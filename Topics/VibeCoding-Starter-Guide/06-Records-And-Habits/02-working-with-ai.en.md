## Four principles for working with AI

Let's distill what's come up so far into four. **Keep just these and most things run smoothly.**

## One — set a goal, tell it, then start

The most common mistake is **starting vaguely.** Say "I want to study AI" and the AI answers vaguely too.

Before starting, sort out just these three for yourself.

| Question | Example |
|---|---|
| **What** to make or know | Materials for a 5-minute talk |
| **Why** it's needed | Because I have to give it at a Liberation Day ceremony |
| **How far** counts as done | If I can read the script aloud |

You don't have to decide all three. **Say what you know and the AI asks about the rest.**

## Two — make it plan before making anything

This is a principle many people repeat. That's a sign of how important it is.

> **Don't start by asking the AI to build the whole app; ask for a plan first.**

Here's why. Say "make it" and the AI starts making right away. But if that's not what you wanted, by then it's already far along. **Fixing a plan takes 5 minutes; fixing something already made takes far longer.**

Actually try saying this.

```
I want to make something like this. Please set a plan first.
```

```
Don't fix it right away — tell me how you'll do it first.
```

There's also a feature called **Plan mode** — a mode where the AI plans without editing files right away. Try it once you're used to things.

## Three — leave records

Covered in the previous document. When you finish the day, one line — **"I got this far today, please record it"** — does it.

Especially leave **what got stuck.** Get stuck at the same spot next time and the AI tells you last time's fix.

## Four — ask when you don't know

Just taking what the AI made, without asking, leaves you unable to fix or judge it later.

It's good to build the habit of asking like this.

```
Why did you do it this way?
```

```
If I want to fix this part later, where should I look?
```

**You don't need to become a developer.** But you do need enough to steer the AI. Asking itself builds that ability.

## What not to do

The list the repository organized. Copied as-is.

> 1. **Perfectionism**
>    - No need to memorize every detail
>    - Enough to instruct the AI is enough
>
> 2. **Writing docs only**
>    - Don't just read theory without practice
>    - Always do it hands-on
>
> 3. **Proceeding without a plan**
>    - Don't skip daily_learning_prompt.md
>    - Starting blindly is inefficient
>
> — VibeLearn AI repository, `GETTING_STARTED.md` lines 497–509

Add three we actually run into often.

**Don't start several things at once.** Kick off several Topics at once and none finishes. The repository too notes it "possible but not recommended."

**Don't skip retrospectives.** It's 5 minutes. Skip it and there's nothing for the AI to read tomorrow.

**Don't use only web chat.** If it can't read and write files directly, you have to copy-paste every time. That's exactly why we attached AI to VS Code.

## When it doesn't work, do this

**The AI made something off**
Just say so. "That's not it, I wanted something like this." Saying "please fix it" is the normal way to use it.

**The AI explains too hard**
```
Please explain it again simply, for someone who doesn't know computers.
```

**I just can't make progress today**
Say so. "I'm a bit tired today" and the AI lowers the difficulty and reduces the amount. **Better to reopen tomorrow than to force progress.**

**It says I used too much and can't use it for a while**
Not a malfunction. It's the plan's limit. Record what you did today and take a break.
