## 진행자용 세션 매뉴얼

참가자와 함께 앉아 **바이브 코딩 환경을 세팅하고 첫 성공까지** 데려가는 세션을 위한 매뉴얼이다. 이 문서만 보고 다음 세션을 준비할 수 있게 썼다.

**세션 길이**: 2시간 (1:1 기준) / 3시간 (2~4명 그룹)
**참가자 산출물**: 작동하는 환경 + 결과물 파일 하나
**참가자용 문서**: [바이브 코딩 첫걸음 — 참가자용 가이드북](01-participant-guidebook.md)

## 세션 전 — 반드시 확인할 것

### ⚠️ 이것부터 물어보세요 (일정 잡을 때)

**"어떤 컴퓨터를 쓰시나요? Windows인가요, 맥인가요, 크롬북인가요?"**

| 답 | 조치 |
|---|---|
| Windows / 맥 | 진행 가능 |
| **크롬북** | **이 방법으로는 불가.** 다른 컴퓨터를 준비하시게 하거나 일정을 조정한다 |
| 아이패드·태블릿만 있음 | 불가. 노트북·데스크톱이 필요하다 |
| 회사·학교 컴퓨터 | 설치 권한이 막혀 있을 수 있음. **개인 컴퓨터를 권한다** |

> **크롬북을 세션 당일에 발견하면 그 세션은 통째로 날아간다.** 반드시 사전에 확인한다. 학생 대상이면 크롬북 비율이 높으므로 특히 주의.

### 사전 안내 체크리스트

- [ ] 사용할 컴퓨터 확인 (위 표)
- [ ] **관리자 권한**으로 프로그램을 설치할 수 있는지 확인
- [ ] 인터넷 연결 확인 (AI가 답할 때마다 인터넷을 쓴다)
- [ ] **결제 수단 준비** — Claude 유료 구독이 필요하다. 해외 결제가 되는 카드
- [ ] **미성년자면 보호자 동석 또는 사전 결제 협의**
- [ ] 참가자용 가이드북 링크를 미리 보냄 (2장까지 읽어 오시면 세션이 빨라진다)

### 진행자 준비물

- [ ] 참가자용 가이드북 (인쇄 또는 화면)
- [ ] 이 매뉴얼
- [ ] 화면 공유 가능한 환경 (온라인 진행 시)
- [ ] 내 컴퓨터에도 같은 환경 (시연용)

## 세션 진행 순서

### 0. 여는 이야기 (10분)

**목표**: 긴장을 풀고, 오늘 무엇을 하게 되는지 그림을 준다.

- 참가자가 **무엇을 만들고 싶은지** 먼저 듣는다. 이게 뒤에서 첫 Topic 주제가 된다
- "코딩을 몰라도 됩니다"를 말로 한 번 더 확인시킨다
- 이선생님 사례를 짧게 (30초)
- 오늘 걸리는 시간과 **비용이 든다는 것**을 미리 알린다

> 💡 **참가자가 하고 싶은 일을 여기서 못 들으면 4장에서 헤맨다.** 막연하면 "요즘 어떤 일에 시간을 많이 쓰시나요?"로 우회한다.

### 1. 왜 하는지 (15분) — 참가자 가이드북 2장

**목표**: 설치를 시작하기 전에 "무엇을 왜"를 안다.

핵심만 짚는다. 다 설명하려 하지 않는다.

- 바이브 코딩 = 말로 설명하면 AI가 만든다. **무엇을 만들지 아는 건 여전히 사람 몫**
- **코딩만이 아니다** — 참가자가 0단계에서 말한 일에 대입해 설명한다
- 웹 대화와 다르다 — **파일로 남는다**
- 고속도로 비유 — 오늘 우리가 넘는 게 그 진입로

### 2. 설치 (50~60분) — 참가자 가이드북 3장

**목표**: 작동하는 환경. **이 구간이 세션의 본체다.**

| 순서 | 내용 | 시간 | 자주 막히는 곳 |
|---|---|---|---|
| 2-1 | VS Code 설치 | 15분 | 맥 "확인되지 않은 개발자" / 관리자 권한 |
| 2-2 | Claude 가입 + 유료 구독 | 20분 | **결제 거절**, 확인 메일이 스팸함으로 |
| 2-3 | Claude Code 확장 설치·로그인 | 10분 | 브라우저가 안 열림, 구독 미반영 |
| 2-4 | 작업 폴더 만들고 열기 | 10분 | 폴더 위치를 못 찾음 |
| 2-5 | `hello.md` 만들어 검증 | 5분 | — |

**진행 요령**

- **참가자가 직접 하게 한다.** 대신 해 주면 다음에 혼자 못 한다. 화면을 보며 말로 안내한다
- 각 단계 끝에 **"이 화면이 보이면 성공"** 을 함께 확인한다
- 막히면 [막힐 때 보는 문서](../03-Setup-Environment/04-troubleshooting.md)를 참가자와 **함께 펼쳐 본다.** 문서를 쓰는 법도 같이 익히게 된다
- 결제 단계에서는 **자리를 잠깐 비켜 준다.** 카드 정보를 입력하는 순간에 옆에 붙어 있지 않는다

> ⚠️ **2-5(hello.md 검증)를 건너뛰지 않는다.** 여기서 참가자가 처음으로 "AI가 내 컴퓨터에서 일한다"를 체감한다. 세션 전체에서 반응이 가장 좋은 순간이다.

### 3. VibeLearn AI + 첫 Topic (25분) — 참가자 가이드북 4장

**목표**: 한 문장으로 시작되는 경험 + 계획표.

- ZIP 내려받기 → 폴더 열기 (10분)
- **0단계에서 들은 그 일**로 첫 Topic을 시작하게 한다 (10분)
- 승인 게이트가 나오면 **"이건 AI가 멋대로 안 한다는 뜻입니다"** 라고 짚어 준다 (5분)

> 💡 **기여자용 설정(hook·pip·API 키)은 절대 언급하지 않는다.** 궁금해하면 부록 D를 알려 주고 넘어간다.

### 4. 첫 성공 (15분) — 참가자 가이드북 4-3

**목표**: 눈에 보이는 결과물 하나.

- 세 갈래 중 **참가자가 끌리는 것**을 고르게 한다
- 결과가 나오면 **일부러 한 번 고쳐 보게 한다** — "색을 바꿔 달라고 해 보세요". 고쳐 달라고 말하는 게 정상적인 사용법임을 몸으로 익히는 순간이다

### 5. 어떻게 이어갈지 (15분) — 참가자 가이드북 5·6장

**목표**: 오늘 이후에도 혼자 갈 수 있게.

전부 설명하지 않는다. **셋만 남긴다.**

1. 다음에 열 때는 `VibeLearn-AI` 폴더를 열고 **"오늘 학습을 시작해 주세요"**
2. 하루를 마칠 때 **"오늘 여기까지 했어요, 기록해 주세요"**
3. 막히면 **혼자 오래 붙들지 말고 연락**

### 6. 닫기 (5분)

- 오늘 만든 것을 함께 본다
- 다음에 뭘 해 볼지 한 가지만 정하게 한다
- Catch Up AI(https://catchupai.net/) 안내

## 자주 나오는 질문

**"제가 코딩을 하나도 모르는데 괜찮을까요?"**
괜찮습니다. 오늘 코드를 한 줄도 쓰지 않습니다. 무엇을 만들지 아는 게 더 중요하고, 그건 이미 갖고 계십니다.

**"이거 돈이 계속 나가나요?"**
매달 나갑니다. 언제든 해지할 수 있고, 가장 낮은 단계로 시작하셔도 됩니다. (금액은 말하지 말고 **화면에서 함께 확인**한다 — 가격은 바뀐다)

**"AI가 제 파일을 다 볼 수 있나요?"**
열어 준 폴더만 봅니다. 그리고 파일을 고치기 전에 대개 먼저 물어봅니다.

**"잘못 눌러서 뭔가 망가지면요?"**
되돌릴 수 있습니다. AI에게 "방금 바꾼 걸 되돌려 주세요"라고 하시면 됩니다.

**"영어를 잘 못하는데요?"**
한국어로 말씀하시면 됩니다. 화면 버튼만 영어인데 그건 제가 알려 드립니다.

**"이걸 배우는 데 얼마나 걸리나요?"**
오늘 2시간이면 시작은 됩니다. 그다음은 쓰면서 익히시는 게 빠릅니다.

## 진행자가 저지르기 쉬운 실수

**대신 해 주기.** 시간이 없다고 진행자가 키보드를 잡으면, 참가자는 다음에 혼자 못 한다. **느려도 참가자가 직접 하게 한다.**

**다 설명하려 하기.** 2장과 5·6장은 핵심만 짚는다. 설치가 본체다. 개념을 길게 설명하면 정작 설치할 시간이 없어진다.

**첫 성공을 생략하기.** 시간이 밀리면 5장(어떻게 이어갈지)을 줄이지, **첫 성공은 절대 빼지 않는다.** 그게 없으면 참가자가 다시 열지 않는다.

**어려운 말 쓰기.** 리포지토리·디렉토리·실행·인스톨 대신 폴더·열기·설치. [쉬운 용어 사전](../01-Guide-Foundation/02-glossary.md) 참고.

**"에러"라고 말하기.** "자주 있는 일입니다"로 바꿔 말한다. 컴퓨터가 낯선 분에게 "에러"는 "내가 뭘 잘못했다"로 들린다.

## 시간이 부족할 때 — 자르는 순서

밀렸을 때 이 순서로 줄인다.

1. **5장(어떻게 이어갈지)을 셋만 말하고 끝낸다** — 가이드북을 보시라고 안내
2. **1장(왜 하는지)을 5분으로 압축**
3. 0단계 여는 이야기를 줄인다

**절대 자르지 않는 것**: 2-5(hello.md 검증), 4(첫 성공).

## 세션 후

- [ ] 참가자가 **막힌 지점**을 기록해 둔다 → [막힐 때 보는 문서](../03-Setup-Environment/04-troubleshooting.md)에 추가
- [ ] 가이드북에서 **설명이 안 통한 부분**을 메모 → 다음 개정에 반영
- [ ] 참가자에게 후속 연락 (일주일 뒤 "그 뒤로 해 보셨어요?")

> 세션 기록이 쌓일수록 이 매뉴얼이 정확해진다. **이 가이드 자체가 기록으로 좋아지는 사례**다.
