## M2 - 개념편: 바이브 코딩과 AI 협업이란

**모듈**: M2 / **상태**: ✅ 완료 (2026-08-10) / **예상 학습 시간**: 2시간

이 폴더는 가이드북 **2장(바이브 코딩이 뭔가요)**을 채운다. 설치 앞에 놓이는 장으로, **무엇을 왜 하는지 알고 시작하게** 만드는 것이 목적이다. 무엇을 깔고 있는지 모르는 채 진행하면 막혔을 때 포기할 이유가 생긴다.

**참가자 기준 읽는 시간**: 10~12분

## 📚 학습 순서

1. [01-what-is-vibe-coding.md](01-what-is-vibe-coding.md) — 바이브 코딩의 뜻, "AI가 다 해주지 않는다"는 현실, 고속도로 비유, 이선생님 사례
2. [02-beyond-coding.md](02-beyond-coding.md) — 코딩만이 아니다. 층별 사례 3개(학생·경력자·시민단체) + 웹 대화와의 차이
3. [03-ai-as-partner.md](03-ai-as-partner.md) — 도구 vs 동료 대비표, 계획부터 세우게 하라, 기록이 AI를 강하게 만든다

## 이 모듈에서 정한 것

**"예전에는 / 지금은" 구조로 열었다.** 바이브 코딩을 기술로 설명하면 비개발자는 첫 문단에서 이탈한다. 대신 **"무엇을 만들지 아는 것"과 "만드는 기술"이 원래 한 사람에게 모이지 않았다**는 문제부터 꺼내고, 지금은 두 번째가 줄었다는 식으로 풀었다. 그러면 독자가 자기 위치를 스스로 찾는다.

**현실을 숨기지 않았다.** "AI는 도깨비방망이가 아니다", "계획 없이 붙이면 나중에 고치기 어려워진다", "AI를 이끌 정도는 알아야 한다". 격려만 있으면 첫 실패에서 무너진다.

**고속도로 비유로 이 가이드의 존재 이유를 설명했다.** AI가 넓혀 놓은 건 100마일 중 5마일뿐이고, **진입로는 여전히 좁다**. 이 가이드는 그 진입로를 함께 지나가려고 만든 것이다 — 이 문장이 독자에게 "이걸 왜 읽고 있나"를 답해 준다.

**층별 문서를 나누지 않고 사례로만 갈랐다.** `02-beyond-coding.md`에서 학생·경력자·시민단체 각각의 예시를 실제 부탁 문장으로 보여 주고, 마지막에 **"셋 다 같은 방식"**임을 명시했다. 그래야 남의 사례도 읽는다.

**웹 대화와의 차이를 표로 못 박았다.** 이게 M4의 "첫 성공"에서 몸으로 확인되고, M5·M6에서 다시 근거로 쓰인다. 2장에서 미리 심어 둔 씨앗이다.

**6장 내용을 미리 다 쓰지 않았다.** `03-ai-as-partner.md` 말미에서 "기록이 AI를 강하게 만든다"를 꺼내되 **"6장에서 본격적으로 다룹니다"** 로 넘겼다. 개념편에서 다 설명해 버리면 설치 전에 지친다.

**마지막을 "지금 다 이해하지 않으셔도 됩니다"로 닫았다.** 기억할 것 세 가지(맥락 주기 / 계획 먼저 / 기록 남기기)만 남기고 설치로 넘긴다.
