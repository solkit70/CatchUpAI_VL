**조치**: 2026-08-10 사용자 "그대로 진행" 승인. 다만 학생 세션이 8/10~8/12로 임박해 **M1 → M3 → M4(약 6.5h)를 앞쪽에 배치**한다. M2는 M3의 선행조건이 아니므로 순서를 어기는 것이 아니다.

## 🧭 이 Topic의 제1원칙 — 대상 독자 기준

이 로드맵의 모든 산출물은 아래 독자가 읽는다는 전제로 만든다.

> **IT 엔지니어가 아니다. 컴퓨터가 익숙한 젊은 학생도 있지만, 컴퓨터에 익숙하지 않은 분도 포함된다.**

| 층 | 누구 | 당면 과제 |
|---|---|---|
| ① 학생 | 시애틀 권역 통합한국학교 학생 1~2명 | 이번 주 세션에서 세팅하고 광복절 발표 준비 |
| ② 시니어·경력자 | 도메인 지식은 풍부하나 바이브 코딩 시작이 어려운 분 | 자기 지식을 앱·제품으로 만들고 싶음 |
| ③ 시민단체 실무자 | 업무에 AI를 붙이고 싶은 분 | "AI로 뭘 만들까"보다 "내 일을 AI와 어떻게 할까" |

따라서 모든 모듈에서 다음을 지킨다.

| 원칙 | 실천 방법 |
|---|---|
| 쉬운 언어 | 전문 용어 최소화. 꼭 필요한 용어는 처음 나올 때 일상 언어로 풀이 병기 (예: "터미널 = 컴퓨터에게 글자로 명령을 내리는 창") |
| 한 동작 = 한 단계 | "다운로드하고 설치하세요"(X) → "① 파란색 Download 버튼을 누릅니다 ② 내려받은 파일을 두 번 클릭합니다"(O) |
| 체크포인트 | 단계마다 "이 화면이 보이면 성공"을 명시 |
| 격려 + 현실 | 성공 스토리로 용기를 주되 실제 막히는 지점도 정직하게. 문제를 "오류"가 아니라 "자주 있는 일"로 표현 |
| 이중 용도 | 각 문서는 진행자가 보며 가이드할 수도, 참가자가 혼자 보고 따라할 수도 있게 |
| 출처 명시 | M5·M6의 모든 주장에 레포 파일 또는 볼트 회고의 출처를 붙인다. 추측으로 쓰지 않는다 |
| **영상 링크 병기** | **박창수가 만든 영상을 예로 들면 그 자리에 유튜브 링크를 함께 넣는다.** 독자가 원하면 바로 볼 수 있어야 한다. 링크는 `vl_materials/video-references.md`에서만 가져오고, 그 표에 없는 링크는 쓰지 않는다 |

## 📚 학습 개요

### Topic 소개

컴퓨터에 익숙하지 않은 사람도 따라할 수 있는 "바이브 코딩 + VibeLearn AI 시작·활용 가이드"를 만든다. 단순 설치 절차서가 아니라 도구 설명, 바이브 코딩의 의미, AI를 동료로 대하는 협업 방식, VibeLearn AI를 챗봇처럼 쓰지 않고 제대로 활용하는 법, 기록이 AI의 연료가 된다는 것, AI에게 계획부터 세우게 하라는 원칙까지 담는다. 설치 기본 경로는 **VS Code + Claude 유료 구독 + Claude Code 확장 + VibeLearn AI**로 고정한다.

이 Topic의 산출물은 [AI 활용 가이드 프로그램](../Material_For_Topics/AI-Guidance-Program/project-overview.md)의 **Level 1 — Vibe Coding 입문** 매뉴얼로 그대로 쓰인다.

### 학습 목표

- [ ] 컴퓨터가 낯선 사람도 혼자 따라할 수 있는 설치 가이드를 만들 수 있다 (VS Code + Claude 구독 + Claude Code)
- [ ] VibeLearn AI를 내려받아 첫 Topic을 시작하는 과정을 한 문장 수준으로 안내할 수 있다
- [ ] 바이브 코딩과 AI 협업이 무엇인지 비개발자 언어로 설명할 수 있다
- [ ] VibeLearn AI의 3단계를 "제대로" 쓰는 법(Topic 짓기·승인 게이트·DoD)을 안내할 수 있다
- [ ] 기록과 회고가 왜 AI의 연료가 되는지 실제 사례로 설득할 수 있다
- [ ] 참가자용 가이드북과 진행자용 매뉴얼로 나눠 완성할 수 있다

### M1 - 가이드 뼈대 + 쉬운 용어 사전

**난이도**: ⭐ / **예상 시간**: 1.5h / **산출물 폴더**: `01-Guide-Foundation/`

#### 학습 목표
- [ ] 3층 독자를 하나의 문서로 감당하는 전체 목차를 확정할 수 있다
- [ ] 설치~첫 성공 과정에 등장할 수밖에 없는 용어 12개 이상을 일상 언어로 풀 수 있다
- [ ] "이 용어는 쓰지 말고 이렇게 말하자" 대체 표현 목록을 만들 수 있다
- [ ] 이후 모든 모듈이 따를 집필 체크리스트를 만들 수 있다

#### 주요 개념
1. **3층 독자, 한 문서**: 학생·시니어·시민단체 실무자는 동기는 다르지만 막히는 지점이 같다 — 그래서 문서는 하나로 두고 동기 부여 예시만 층별로 곁들인다
2. **용어 사전이 먼저인 이유**: 용어 기준이 없으면 M3·M4를 쓰면서 매번 다르게 풀이하게 되고, 나중에 통일하는 비용이 훨씬 크다
3. **대체 표현**: 어떤 용어는 풀이보다 아예 안 쓰는 게 낫다 (예: "리포지토리" → "VibeLearn AI 폴더")
4. **집필 체크리스트**: 제1원칙(쉬운 언어·한 동작 한 단계·체크포인트·격려+현실)을 문서 검수용 체크박스로 바꾼 것

#### 실습 과제

**실습 1: 전체 목차 확정** ⭐
- **목적**: M2~M7이 채울 자리를 먼저 정해 중복·누락을 막는다
- **단계**:

  4. **Catch Up AI 웹사이트(https://catchupai.net/) 소개 위치 확정** — 맨 앞(이 가이드는 누가 만들었나)과 맨 뒤(다음 단계·더 알아보기) 두 곳

### M2 - 개념편: 바이브 코딩과 AI 협업이란

**난이도**: ⭐⭐ / **예상 시간**: 2h / **산출물 폴더**: `02-What-Is-Vibe-Coding/`

#### 학습 목표
- [ ] 바이브 코딩을 코드 한 줄 없이 비개발자 언어로 설명할 수 있다
- [ ] 이 도구가 코딩 외에 파일 정리·자료 조사·학습·프로젝트 관리에도 쓰인다는 것을 예시로 보일 수 있다
- [ ] AI를 "도구"가 아니라 "함께 일하는 동료"로 대할 때 무엇이 달라지는지 대비표로 제시할 수 있다
- [ ] 왜 세팅이 장벽인지(고속도로 비유) 설명할 수 있다

#### 주요 개념
1. **바이브 코딩**: 세부 구현은 AI가 처리하고 사람은 설계와 결정에 집중하는 협업 방식. "Vibe Coding의 정수는 코드가 아니라 맥락을 다루는 기술에 있다"
2. **코딩 너머**: 폴더의 파일을 읽고 쓸 수 있다는 점이 핵심 — 그래서 자료 정리, 문서 작성, 학습 관리에도 그대로 쓰인다
3. **도구 vs 동료**: "이걸 설명해줘"(도구) ↔ "내 상태를 파악하고 오늘 계획을 세워줘"(동료)
4. **고속도로 비유**: AI는 100마일 중 5마일만 10차선으로 넓혀 놓은 상태다. 좁은 진입로(세팅)를 함께 넘으면 넓은 길이 나온다 — 이 가이드의 존재 이유

#### 실습 과제

**실습 1: "바이브 코딩이란" 본문 작성** ⭐⭐
- **목적**: 처음 듣는 사람이 한 번에 이해하는 설명
- **단계**:
  1. `easy-12-part-summary.md` Part 8의 시니어 눈높이 설명을 뼈대로 삼기
  2. 일상 비유 1개 선정해 도입부 작성
  3. "AI가 다 해주지는 않는다"는 현실 문단 포함
- **예상 시간**: 40분 / **난이도**: ⭐⭐
- **검증 방법**: M1 용어 사전 기준 위반 0건

**실습 2: "코딩만이 아니다" 사례 작성** ⭐⭐
- **목적**: 독자가 자기 일에 대입할 수 있게
- **단계**:
  1. 층별 사례 3개 작성 — 학생(발표 자료 준비), 시니어(자기 경험을 앱으로), 실무자(회의록·행사 자료 정리)
  2. 각 사례를 "이렇게 부탁하면 이런 게 나온다" 형태로
- **예상 시간**: 40분 / **난이도**: ⭐⭐

### M6 - 활용편②: 기록·회고의 복리 + AI와 일하는 원칙

**난이도**: ⭐⭐ / **예상 시간**: 2.5h / **산출물 폴더**: `06-Records-And-Habits/`

#### 학습 목표
- [ ] WorkLog가 AI의 기억이라는 것을 구조와 함께 설명할 수 있다
- [ ] 회고 3단계를 부담 없는 분량으로 안내할 수 있다
- [ ] 기록이 AI의 연료·컨텍스트가 된다는 것을 실제 사례로 설득할 수 있다
- [ ] "AI에게 계획부터 세우게 하라"를 Plan mode와 함께 안내할 수 있다
- [ ] 격려와 현실을 함께 담아 과장 없이 쓸 수 있다

#### 주요 개념
1. **WorkLog = AI의 기억**: 안 쓰면 AI가 어제를 기억하지 못한다. 필수 6섹션(오늘의 목표 / 진행 내용 / 문제 해결 로그 / DoD 체크 / Daily Retrospective / 참조·산출물)
2. **회고 3단계**: Daily 5~10분(WorkLog 안에), Module 15~20분, Topic 30~60분
3. **기록 → Context → 협업 → 산출물 → 새 경험**의 순환
4. **계획부터**: "전체를 만들어달라"가 아니라 "먼저 계획을 세워달라"로 시작한다
5. **경험의 복리**: 같은 작업이 4.5h → 4h → 2~3h로 짧아진다
6. **정직한 현실**: 시간 예측 편차, "AI가 대부분 하면 도구 사용법 자체가 장벽이 된다"

6. 참조 및 산출물

## 🔍 Retrospective 가이드

**Daily Retrospective** (매일, 5-10분) — WorkLog 안에 작성: What went well / What could be improved / Insights / Tomorrow's focus

**Module Retrospective** (모듈 완료 시, 15-20분) — `vl_worklog/YYYYMMDD_MX_Retrospective.md`: 계획 대비 실제, 핵심 학습, 문제와 해결, Roadmap 정확도, 산출물 품질, 다음 모듈 준비

**Topic Retrospective** (전체 완료 시, 30-60분) — `vl_worklog/YYYYMMDD_VibeCoding-Starter-Guide_Final_Retrospective.md`: 전체 여정 통계, 방법론 효과성, 산출물의 교과서 품질, 향후 개선. **학생 세션 실사용 결과를 반드시 포함한다.**
