## M5 - Using Part 1: How to Use the Three Steps Well

**Module**: M5 / **Status**: ✅ Complete (2026-08-10) / **Estimated time**: 2.5 hours

This folder fills guidebook **chapter 5 (How to use it well).** Its purpose is to keep a participant who finished installing **from sliding back to the old way (chatbot).** Even with the tools, if the way of using them stays the same, nothing changes.

**Reading time for participants**: 12–15 minutes

## What this module decided

**Opened with "a familiar scene."** State the principle first and it goes unread. We raise the experience — "got somewhere good last week, but today can't remember how far" — and pin it: **"the problem isn't your memory, it's using it in a way that leaves nothing behind."**

**Each of the four axes is backed by a source quote.** Memory (`daily_learning_prompt.md` 491–493), completion (`README.md` 317–349), output (`README.md` 207), portability (`CLAUDE.md` 46). The repository has no direct "better than a chatbot" statement, so we **built the argument by combining four clauses and citing each source.**

**We didn't say "chatbots are bad."** We state that for simple questions it's faster, and give a judgment table for when to use what. Insist on always making a Topic and people stop using it.

**We translated the repo's developer examples into ours and set them side by side.** Examples like `Docker-Fundamentals` are kept as source quotes, with a `Liberation-Day-Talk-Prep` / `Excel-PivotTable-Basics` table right below. Erase the original and the source becomes meaningless; keep only the original and the reader can't map it to their own work.

**We explained the approval gate as a "safeguard" and cited the basis.** It's a spot that reads as "why ask instead of doing" at first sight. We quote both gates' original wording to show **it's a designed rule.**

**We reduced the nine items to three to check.** Ask to check them all and no one does. We pointed at just estimated time, DoD, and "I can do" goals.

**We unified the practice ratio at "roughly 3:7."** The numbers diverge inside the repo (70-80% / 70% / 50%, confirmed in M1), so the guide settles on one and cites only `CLAUDE.md` line 97.
