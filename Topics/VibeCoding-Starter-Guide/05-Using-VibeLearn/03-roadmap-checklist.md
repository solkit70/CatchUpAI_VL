## 계획표 받고 확인할 것

Topic을 시작하면 AI가 **계획표(Roadmap)** 를 만들어 줍니다. 그런데 바로 만들지 않고 **먼저 물어봅니다.** 그리고 매일 시작할 때도 **또 물어봅니다.**

이 "물어봄"이 이 방식의 핵심 안전장치입니다. 왜 그런지, 그리고 받은 계획표에서 무엇을 봐야 하는지 알아보겠습니다.

## AI가 멋대로 하지 않는 이유 — 두 번의 확인

### 첫 번째 — 계획표를 만들기 전에

Topic 정보를 다 주고 나면, AI는 계획표를 바로 쓰지 않습니다. **말씀하신 기간이 적당한지 먼저 검토해서 알려 줍니다.** 그리고 이렇게 묻습니다.

> **사용자 확인 필요**:
> 위 분석 결과를 확인하시고 다음 중 선택해주세요:
> 1. "그대로 진행" - 입력한 기간으로 진행
> 2. "기간 조정" - 권장 기간으로 변경
> 3. "범위 조정" - 기간은 유지하되 학습 범위 조정
>
> — VibeLearn AI 저장소, `templates/roadmap_prompt_template.md` 132~137행

셋 중 하나를 고르시면 됩니다. **잘 모르겠으면 "그대로 진행"** 을 고르세요. 나중에 언제든 바꿀 수 있습니다.

이 확인을 받기 전에는 계획표 파일을 만들지 않도록 규칙에 못 박혀 있습니다.

> **중요**: 사용자 승인 전에는 Roadmap 파일을 생성하지 마세요.
>
> — VibeLearn AI 저장소, `templates/roadmap_prompt_template.md` 20행

### 두 번째 — 매일 시작할 때

계획표가 생긴 뒤, 매일 "오늘 학습을 시작해 주세요"라고 하면 AI는 **오늘 할 일을 제안하고 또 물어봅니다.** 승인해야 실제로 진행합니다.

승인할 때 세 가지 중 고를 수 있습니다.

| 고를 수 있는 것 | 이럴 때 |
|---|---|
| **승인** ("시작합니다") | 계획이 괜찮다 |
| **수정 요청** | 조정하고 싶은 부분이 있다 |
| **난이도 조정** ("좀 더 쉽게" / "좀 더 심화") | 너무 어렵거나 쉽다 |

*— VibeLearn AI 저장소, `templates/daily_learning_prompt.md` 302~319행*

### 왜 두 번이나 물어보나

**AI가 혼자 판단해서 일을 벌이지 않게 하려는 것**입니다.

계획을 잘못 세운 채로 진행하면, 나중에 되돌리는 게 훨씬 번거롭습니다. 계획을 고치는 건 5분이지만 만든 걸 고치는 건 훨씬 오래 걸립니다.

처음에는 이 물어봄이 번거롭게 느껴질 수 있습니다. 익숙해지시면 대부분 "그대로 진행"을 누르게 되지만, **초반에는 AI가 무엇을 하려는지 읽어 보는 습관**을 들이시는 편이 좋습니다.

> 💡 **피곤하거나 시간이 없을 때는 그대로 말씀하세요.** "오늘 좀 피곤해요"라고 하면 AI가 난이도를 낮추고 분량을 줄여서 제안합니다. 무리해서 진도를 빼는 것보다 낫습니다.

## 계획표에서 확인할 것

받은 계획표를 전부 이해하실 필요는 없습니다. **아래 정도만 훑어보시면 충분합니다.**

### 전체를 볼 때

- [ ] 단계(M1, M2 …)가 몇 개이고, 각각 무엇인지 대충 알겠다
- [ ] 내가 생각한 것과 크게 다르지 않다
- [ ] 마지막에 전체를 묶는 단계가 있다

### 각 단계를 볼 때

각 단계에는 아홉 가지가 들어 있어야 합니다. 저장소가 정한 필수 항목입니다.

> - 모듈 기본 정보 (번호, 제목, 예상 시간)
> - 학습 목표 (3-5개, 측정 가능)
> - 핵심 개념 (이론 20-30%)
> - 실습 과제 (실습 70-80%)
> - 예상 산출물
> - Definition of Done (DoD) 체크리스트
> - 자기 평가 체크리스트
> - 시간 배분
> - 참조 자료
>
> — VibeLearn AI 저장소, `CLAUDE.md` 58~67행

전부 확인하실 필요는 없고, **아래 세 개만 있으면 됩니다.**

- [ ] **예상 시간**이 적혀 있다 — 하루에 할 수 있는 크기인지 판단할 수 있다
- [ ] **DoD**(Definition of Done, 완료 기준)가 체크박스로 있다 — "여기까지 하면 끝"을 알 수 있다
- [ ] **학습 목표가 "할 수 있다"로** 쓰여 있다 — "이해한다"면 확인할 방법이 없다

## 이론은 적게, 해보기를 많이

계획표를 보시면 실습 비중이 크게 잡혀 있을 겁니다. 저장소가 정한 원칙입니다.

> **실습 우선**: 70-80% 실습, 20-30% 이론
>
> — VibeLearn AI 저장소, `CLAUDE.md` 97행

**대략 이론 3 : 해보기 7** 정도로 생각하시면 됩니다. 읽기만 해서는 남지 않습니다.

시간에는 여유분도 들어갑니다.

> **시간 존중**: 사용 가능한 시간에 맞춰 범위 조정, 20% 버퍼 유지
>
> — VibeLearn AI 저장소, `CLAUDE.md` 114행

계획한 시간의 **20%는 예상 못 한 일을 위한 여유**로 남겨 둡니다. 그래서 계획이 자꾸 밀리지 않습니다.

## 마음에 안 들면 그냥 말하세요

계획표는 확정된 문서가 아닙니다. 언제든 바꿀 수 있습니다.

```
단계가 너무 많아 보여요. 절반으로 줄여 주세요.
```

```
2단계가 어려워 보이는데, 더 작게 나눠 주세요.
```

```
이 부분은 저한테 필요 없을 것 같아요. 빼 주세요.
```

## 다 했다고 말할 수 있는 기준

각 단계 끝에는 **DoD**(Definition of Done, 완료 기준)가 있습니다. 체크박스를 다 채우면 그 단계는 끝입니다.

그리고 **자기 평가**도 있습니다. 여기서 중요한 건 평가 기준이 예전과 다르다는 점입니다.

> **"모든 디테일을 암기할 필요는 없다. AI에게 효과적으로 지시할 수 있는 수준의 이해면 충분하다."**
>
> — VibeLearn AI 저장소, `README.md` 367행

외웠는지를 묻지 않습니다. **AI에게 제대로 시킬 수 있는지**를 봅니다. 이게 이 방식의 기본 태도입니다.

## 잘 안 될 때

**AI가 물어보지도 않고 계획표를 만들어 버렸어요**
가끔 있는 일입니다. 그냥 말씀하시면 됩니다.

```
기간이 적당한지 먼저 검토해 주세요. 계획표는 그다음에 만들어 주세요.
```

**만들어진 파일에 `{ }` 중괄호나 이상한 기호가 남아 있어요**
서식이 제대로 채워지지 않은 경우입니다. 이렇게 말씀하시면 됩니다.

```
이 파일에 채워지지 않은 부분이 남아 있어요. 다시 만들어 주세요.
```

**계획표가 너무 짧거나 대충인 것 같아요**
AI가 서식을 줄여서 만들었을 수 있습니다. 다시 만들어 달라고 하시면 됩니다.
