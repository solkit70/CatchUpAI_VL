## M5 - 활용편① 3단계를 제대로 쓰는 법

**모듈**: M5 / **상태**: ✅ 완료 (2026-08-10) / **예상 학습 시간**: 2.5시간

이 폴더는 가이드북 **5장(제대로 쓰는 법)**을 채운다. 설치를 끝낸 참가자가 **AI를 예전 방식(챗봇)으로 되돌아가 쓰지 않도록** 붙잡는 것이 목적이다. 도구를 갖췄어도 쓰는 방식이 그대로면 아무것도 달라지지 않는다.

**참가자 기준 읽는 시간**: 12~15분

## 📚 학습 순서

1. [01-why-not-chatbot.md](01-why-not-chatbot.md) — 챗봇식과 갈리는 네 가지(기억·완료·산출물·이식성) + 언제 챗봇식이 나은지
2. [02-starting-well.md](02-starting-well.md) — 목표 구체화, Topic 이름 짓기, "할 수 있다"로 목표 쓰기 + Do/Don't
3. [03-roadmap-checklist.md](03-roadmap-checklist.md) — 두 번의 승인 게이트, 계획표에서 확인할 것, 이론3:실습7과 20% 여유

## 이 모듈에서 정한 것

**"익숙한 장면"으로 열었다.** 원칙을 먼저 말하면 안 읽는다. "지난주에 잘 풀렸는데 오늘 다시 하려니 어디까지 했는지 기억이 안 난다"는 경험부터 꺼내고, **"문제는 기억력이 아니라 남는 게 없는 방식으로 썼기 때문"**이라고 짚었다.

**네 축을 각각 원문 인용으로 뒷받침했다.** 기억(`daily_learning_prompt.md` 491~493행), 완료(`README.md` 317~349행), 산출물(`README.md` 207행), 이식성(`CLAUDE.md` 46행). 저장소에 "챗봇보다 낫다"는 직접 비교문은 없으므로, **네 개 조항을 조합해 논지를 만들고 각각의 출처를 밝혔다.**

**"챗봇식이 나쁘다"고 하지 않았다.** 간단한 질문에는 그게 더 빠르다고 명시하고, **언제 무엇을 쓸지 판단표**를 줬다. 무조건 Topic을 만들라고 하면 오히려 안 쓰게 된다.

**저장소의 개발 예시를 우리 예시로 번역해 병기했다.** `Docker-Fundamentals` 같은 예시는 원문 인용으로 두되, 바로 아래에 `광복절-발표-준비`·`엑셀-피벗테이블-기초` 표를 덧붙였다. 원문을 지우면 출처가 무의미해지고, 원문만 두면 독자가 자기 일에 대입하지 못한다.

**승인 게이트를 "안전장치"로 설명하고 근거를 붙였다.** 처음 보면 "왜 안 하고 물어보지" 싶은 지점이다. 두 게이트의 원문 문구를 그대로 인용해 **이게 설계된 규칙**임을 보였다.

**9개 항목 중 확인할 것을 3개로 줄였다.** 전부 확인하라고 하면 아무도 안 한다. 예상 시간·DoD·"할 수 있다" 목표 셋만 짚었다.

**실습 비율을 "대략 3:7"로 통일했다.** 저장소 안에서 70-80%·70%·50%로 수치가 엇갈리므로(M1에서 확인), 가이드에서는 하나로 정리하고 원문 인용은 `CLAUDE.md` 97행 하나만 썼다.
