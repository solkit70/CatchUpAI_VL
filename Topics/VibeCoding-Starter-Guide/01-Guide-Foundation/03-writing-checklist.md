## 이 문서의 용도

M2~M7의 모든 문서를 쓴 뒤 이 체크리스트로 검수한다. 제1원칙을 머릿속에 두는 것과 체크박스로 확인하는 것은 결과가 다르다. **문서 하나를 끝낼 때마다 이 목록을 처음부터 훑는다.**

## 1. 쉬운 언어

- [ ] `02-glossary.md`에 없는 전문 용어가 풀이 없이 등장하지 않는다
- [ ] `02-glossary.md`의 **대체 표현 표에서 금지한 단어**가 하나도 없다 (리포지토리, 디렉토리, 실행한다, 인스톨, 에러 등)
- [ ] 새로 쓴 용어가 있다면 `02-glossary.md`에 먼저 추가했다
- [ ] 한 문장이 세 줄을 넘지 않는다
- [ ] 영어 약자를 쓸 때 처음 한 번은 **원어 full form과 우리말 풀이를 함께** 붙였다
      (예: "DoD(Definition of Done, 완료 기준)") — 이후에는 약자만 쓴다

## 2. 한 동작 = 한 단계

- [ ] "다운로드하고 설치하세요"처럼 **두 동작이 한 단계에 묶인 곳이 없다**
- [ ] 각 단계가 번호로 나뉘어 있고, 하나의 동작만 담고 있다
- [ ] 클릭해야 할 버튼은 **색과 이름**을 함께 적었다 (예: "파란색 Download 버튼")
- [ ] Windows와 macOS가 갈리는 지점을 표시했다

## 3. 체크포인트

- [ ] 각 단계 끝에 "이 화면이 보이면 성공"에 해당하는 확인 문구가 있다
- [ ] 확인 문구가 **눈에 보이는 것**을 말한다 (내부 상태가 아니라 화면·결과)
- [ ] 한 절이 끝날 때마다 "여기까지 됐으면 다음으로" 신호가 있다

## 4. 격려 + 현실

- [ ] 문제 상황을 **"에러"가 아니라 "자주 있는 일"**로 표현했다
- [ ] 잘되는 이야기만 있지 않다 — 막히는 지점을 정직하게 적었다
- [ ] 반대로 겁주는 표현("어렵습니다", "주의하지 않으면")으로 끝나는 문단이 없다
- [ ] 비용이 드는 부분(Claude 구독)을 숨기지 않고, 무엇을 얻는지 함께 적었다

## 5. 출처 명시 (M5·M6 필수)

- [ ] 주장마다 근거 파일 또는 문서가 표기돼 있다
- [ ] 숫자를 인용할 때 **무엇이 포함되고 무엇이 빠졌는지** 정확히 적었다
      (예: Clearly "9.5시간에 산출물 22개" — 영상 제작분 약 8시간은 별도)
- [ ] 추측이나 기억으로 쓴 문장이 없다
- [ ] 볼트 회고의 Self-Assessment 점수는 동기 부여용으로만 썼다 (근거로 내세우지 않았다)

## 6. 영상 링크 병기

- [ ] 박창수가 만든 영상을 언급한 곳마다 **그 자리에** 유튜브 링크가 있다
- [ ] 링크를 `vl_materials/video-references.md` 표에서 가져왔다 (표에 없는 링크 0건)
- [ ] 한국어판 본문에 영어 영상 링크를 넣지 않았다
- [ ] 재생 시간을 알고 있으면 함께 적었다
- [ ] **아직 없는 영상**을 있는 것처럼 안내하지 않았다
      (설치 과정 영상, 이선생님 Voice Legacy 영상 — 둘 다 없음)

## 7. 이중 용도

- [ ] 참가자가 혼자 읽어도 막히지 않는다
- [ ] 진행자가 옆에서 보며 안내하기에도 순서가 자연스럽다
- [ ] 진행자만 알아야 할 내용은 본문이 아니라 진행자용 매뉴얼로 뺐다

## 8. 문서 형식

- [ ] **파일명이 `01-`, `02-` … 번호로 시작한다** (아래 규칙 참조)
- [ ] 프론트매터(`title`, `created`, `tags`)가 있다
- [ ] 첫 줄이 제목(H2 이상)으로 시작한다 — 프론트매터 뒤에 붙는 글이 없다
- [ ] 표 앞에 빈 줄이 있다
- [ ] 섹션 사이에 가로줄(`---`)을 쓰지 않았다
- [ ] 한 문장짜리 문단이 홀로 서 있지 않다 (2~3문장으로 묶었다)
- [ ] 위키 링크가 실제 존재하는 파일을 가리킨다

## 파일명 규칙 — 정렬 순서 = 학습 순서

**모든 산출물 파일명은 `NN-` 번호로 시작한다.** GitHub과 Obsidian은 파일을 **알파벳순**으로 보여주기 때문에, 번호가 없으면 README에 적은 학습 순서와 화면에 보이는 순서가 어긋난다. 읽는 사람은 화면 순서대로 클릭하므로 엉뚱한 문서부터 열게 된다.

| | 번호 없을 때 (알파벳순) | 번호 있을 때 |
|---|---|---|
| 실제 학습 순서 | 개념 → 사례 → 협업 | 개념 → 사례 → 협업 |
| 화면에 보이는 순서 | ai-as-partner(3번째가 먼저) → beyond-coding → what-is… | 01-what-is… → 02-beyond… → 03-ai-as-partner |

**규칙**

- 번호는 **두 자리**로 (`01-`, `02-` … ). 한 자리면 10번째부터 순서가 깨진다
- 번호는 **README의 "학습 순서" 절과 반드시 일치**시킨다. 순서를 바꾸면 파일명도 함께 바꾼다
- **`README.md`는 번호를 붙이지 않는다.** GitHub이 폴더 본문 아래에 자동으로 펼쳐 주므로 목록 위치와 무관하고, 번호를 붙이면 그 자동 표시가 깨진다
- 파일명을 바꿀 때는 **그 파일을 가리키는 모든 링크를 함께 갱신**한다 (README, 다른 본문의 "다음/이전" 링크, WorkLog·Roadmap의 산출물 경로)

## 최종 통독 (모듈 완료 시)

- [ ] 처음 보는 사람 관점으로 처음부터 끝까지 읽었다
- [ ] **이해가 멈추는 문장이 0곳**이다
- [ ] 읽는 사람이 "그래서 지금 뭘 하면 되지?"라고 묻게 되는 지점이 없다
