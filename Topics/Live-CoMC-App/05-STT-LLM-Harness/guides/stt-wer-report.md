## 1. 측정 조건 — BGM 조건을 재지 않은 이유

Roadmap M5 실습 1은 `일반 조건 + BGM 조건` 두 가지를 요구한다. 이번에는 **일반 조건만** 측정했다.

이 방송에서는 **BGM을 헤드폰으로 듣는다.** BGM이 마이크에 들어가지 않으므로, BGM을 틀어도 마이크가 받는 신호는 일반 조건과 동일하다. 스피커로 BGM을 트는 셋업을 가정한 요구사항이라 그대로 따르면 오히려 잘못된 측정이 된다.

**악조건 커버리지가 비어 있는 것은 아니다.** 이 파이프라인에서 마이크에 실제로 섞여 드는 소리는 BGM이 아니라 **AI 자신의 TTS 출력**이고, 그건 M4 실습 4에서 이미 측정했다(에코 게이트 off 5건 검출 vs on 0건). 소음원이 다를 뿐 악조건 검증은 되어 있다.

> BGM을 스피커로 트는 셋업으로 바뀌면 이 측정을 다시 해야 한다.

## 2. 왜 WER과 CER을 함께 재는가

**WER**은 공백으로 나눈 어절 단위다. 한국어는 조사 하나만 틀려도 그 어절 전체가 오답이 되어 오류율이 부풀려진다. **CER**(문자 단위)은 그 왜곡이 작다.

실제로 둘이 정반대를 가리켰다.

| | WER | CER |
|---|---:|---:|
| 질문형 | 15.0% | 16.7% |
| 명령형 | **31.4%** | **12.3%** |

명령형은 WER이 두 배 나쁜데 CER은 오히려 좋다. 원인이 다르기 때문이다.

- **명령형** — 호출어 한 덩어리만 틀린다. 어절 하나가 통째로 오답이 되어 WER은 뛰지만 나머지 문장은 멀쩡해서 CER은 낮다
- **질문형** — 영어 기술 용어가 여러 개 흩어져 틀린다. 짧은 오류가 여러 곳이라 CER이 올라간다

**하나만 봤으면 정반대 결론을 내렸을 것이다.** 영어 기준 공개 WER 수치와 직접 비교하면 안 되는 이유이기도 하다.

## 3. 표기 허용 기준 — 오류의 성격을 다시 봄

원본 기준으로 가장 나빴던 문장들을 열어 보면 이렇다.

| # | 정답 | 전사 |
|---|---|---|
| 09 | Remotion하고 After Effects 중에… | 리모션하고 애프터이펙트 중에… |
| 05 | 이 코드는 GitHub에 공개되어… | 이 코드는 깃허브에 공개되어… |
| 03 | Qwen3-TTS 맞나요? | 코엔쓰리 TTS 맞나요? |

**알아듣지 못한 것이 아니라 한글로 적은 것이다.** 발음은 정확하다. 다음 단계가 LLM이라면 `깃허브`는 아무 문제가 없다.

그래서 영어 용어의 한글 표기를 정답으로 함께 인정하는 **alternative transcription** 기준으로 다시 쟀다.

```
09  Remotion / After Effects   CER 64.5% → 0.0%     실제로는 완벽 전사
05  GitHub                     CER 33.3% → 0.0%     실제로는 완벽 전사
02  RAG                        CER 31.8% → 20.0%
```

전체 CER이 **16.7% → 8.6%** 로 절반이 된다. 그리고 질문형·명령형의 관계가 뒤집힌다.

```
질문형  16.7% → 5.7%     영어 표기가 원인의 전부였다
명령형  12.3% → 12.3%    변화 없음 — 진짜 문제가 남아 있다
```

**어느 기준이 맞는가**는 다음 단계가 무엇이냐에 달렸다. 전사문을 화면에 그대로 띄운다면 원본 기준이 맞고, LLM에 넘긴다면 표기 허용 기준이 실질에 가깝다. 이 파이프라인은 후자다.

## 4. 호출어는 20번 중 0번 잡혔다

`코엠씨`가 포함된 11문장에서 **정확 전사 0건**이다. 그것도 매번 다르게 쓴다.

```
외임씨 · 포엠씨 · 후엠씨 · QM씨 · 고엠씨 · 호엠씨 · 퀘엠씨 · 구MC · 그(누락)
```

다른 전사기도 마찬가지였다.

| 모델 | `코엠씨` 전사 |
|---|---|
| gpt-4o-transcribe | 오엠씨 |
| gpt-transcribe | MC |
| whisper-1 | 우엠씨 |

### 설계상 결론

**전사문에서 호출어를 찾는 방식은 쓸 수 없다.** 사전에 없는 신조어라 어떤 전사기도 안정적으로 복원하지 못한다.

호출어 감지는 STT **이전 단계**에서 끝나야 한다. M4에서 openWakeWord로 만든 경로가 여러 대안 중 하나가 아니라 **유일한 길**이었다는 뜻이다.

> 대안으로 사전에 있는 단어를 호출어로 바꾸는 방법도 있지만, 흔한 단어일수록 오탐이 늘어난다. M4가 측정한 오탐률(최대 점수 0.1953, 임계값 2.6배 여유)을 다시 재야 한다.

## 5. 3단 폴백 검증

| 강제 실패 | 사용된 단계 | 평균 지연 |
|---|---|---:|
| 없음 | `gpt-4o-transcribe` | 1,160ms |
| 1단 | `gpt-transcribe` | 1,547ms |
| 1·2단 | 로컬 whisper (small) | 6,051ms |

전 단계에서 자동 전환이 확인됐다. 로컬 폴백은 **5배 느리다** — GPU가 없어 CPU 추론이기 때문이고, 최후 수단인 이유다.

### ⚠ Roadmap 1단계 모델은 존재하지 않았다

Roadmap은 1단계를 `gpt-live-transcribe`로 지정했으나, 그 모델은 파일 전사 엔드포인트에 없다.

```
POST /v1/audio/transcriptions  →  404 "Invalid URL"
```

Realtime API(WebSocket) 전용이다. 파일 기반 오프라인 측정에는 쓸 수 없으므로 사다리를 `gpt-4o-transcribe → gpt-transcribe → 로컬 whisper`로 교정했다.

**`gpt-live-transcribe`의 한국어 정확도는 실시간 경로에서 따로 재야 한다** — M7 과제로 넘긴다. 스트리밍은 부분 전사(partial)가 계속 갱신되므로 측정 방법 자체가 달라진다.

## 6. STT는 병목이 아니다

```
STT          1.2초   ←  이 단계
LLM 응답    10.8초 ~ 21.6초   ←  병목
```

같은 세션에서 잰 LLM 지연(claude 10.8초 / openai 21.6초 / gemini 14.8초)과 비교하면 STT는 전체의 10% 미만이다.

**지연 대책은 STT가 아니라 ⑥ LLM 단계에 집중해야 한다.** 진행자가 제안한 대기 필러("네, 확인해 볼게요")가 필요한 구간도 정확히 여기다.
