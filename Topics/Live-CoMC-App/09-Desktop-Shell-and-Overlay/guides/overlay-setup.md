# OBS 오버레이 설정과 검증

**검증일**: 2026-08-31 · **OBS 32.2.2** · 프로필 `Untitled`

## 구조

```
06_render_output.py ──→ overlay.json ─┐
hotkeys.py ──────────→ session_state.json ─┼──→ [overlay_server.py] ──SSE──→ OBS Browser Source
hotkeys.py ──────────→ mode.json ─────┘
```

서버는 세 파일을 감시하고, 바뀌면 **SSE 로 즉시 밀어 넣는다.** 화면은 폴링하지 않는다.

## OBS 설정

1. **Sources `+` → 브라우저(Browser)**
2. 이름 `Co-MC 오버레이`
3. 설정
   | 항목 | 값 |
   |---|---|
   | URL | `http://127.0.0.1:8777/` |
   | 너비 · 높이 | **1920 × 1080** |
   | 보이지 않을 때 소스 종료 | ☑ |
   | 장면이 활성화될 때 새로고침 | ☑ |
4. **OK** → 소스 우클릭 → **변환 → 화면에 맞추기** (`Ctrl+F`)

> 4번을 빠뜨리면 오버레이가 화면 일부에만 작게 나온다. 페이지가 **1920×1080 기준
> 하단 정렬**이라 캔버스를 꽉 채워야 의도대로 보인다.

## 서버 실행

```bash
cd 09-Desktop-Shell-and-Overlay/examples/engine
python overlay_server.py                 # http://127.0.0.1:8777/
python overlay_server.py --selftest      # 사람 없이 검증
```

`/state` 로 현재 상태를 JSON 으로 볼 수 있다 — 화면이 이상할 때 서버가 무엇을 보고
있는지 먼저 확인하는 용도다.

## 화면 설계

| 요소 | 판단 |
|---|---|
| **배경 투명 + 하단만 그라디언트** | 방송 화면 위에 얹힌다. 영상 어디에 놓아도 글자가 읽히도록 아래쪽만 어둡게 깐다 |
| **본문 4줄에서 자름** | 오버레이가 방송 화면을 다 덮으면 안 된다 |
| **모드 배지** | `MUTE` 는 붉게, `REVIEW` 는 주황. **`LIVE` 일 때는 안 보인다** — 정상 상태를 굳이 표시하지 않는다 |
| **페이드 인/아웃 0.28초** | 텍스트가 없으면 사라진다. 툭 나타나면 방송에서 튄다 |

### 왜 모드를 화면에 띄우는가

진행자가 **방송 화면만 보고도 지금 AI 가 꺼져 있는지** 알아야 한다.
상태를 숨기면 *"왜 대답을 안 하지"* 하고 같은 질문을 반복하게 된다.

## 🔴 실사용 검증에서 잡힌 결함 — 파트가 안 바뀌었다

**자기 검증은 통과했는데 실제로 써 보니 틀렸다.** 이 문서에서 가장 중요한 기록이다.

### 증상

핫키로 파트를 5로 바꿨는데 **오버레이는 `PART 3` 을 계속 표시**했다.

```
핫키 → session_state.current_part_id = 5   ← M7 이 정한 권위값
                                              ✗ 화면이 안 봄
⑥ 렌더 → overlay.json.part_id = 3          ← 마지막 발화 시점의 스냅샷
                                              ✓ 화면이 이걸 봄
```

### 원인

서버가 `part_id` 를 `overlay.json` 에서 읽었다. 그 파일은 **⑥ 단계가 발화를 렌더할
때만** 갱신된다. 핫키는 `session_state.json` 만 바꾼다.

M7 은 이렇게 못박아 두었다.

> `current_part_id` 는 **권위값**이다. 핫키·음성 명령·클릭으로만 바뀐다.

**화면은 권위값을 보여야 하는데 스냅샷을 보고 있었다.**

### 실전이었다면

진행자가 다음 파트로 넘어가 말하고 있는데 **방송 화면에는 이전 파트 번호가 떠 있다.**
시청자는 진행자가 헷갈린 것으로 본다.

### 왜 자기 검증이 못 잡았나

`--selftest` 는 세 가지를 봤다 — 페이지가 뜨는가, 상태를 주는가, 파일이 바뀌면
전달되는가. **전부 통과했다.** 그런데 **어느 파일이 권위값인지는 안 봤다.**

> **동작 검증과 의미 검증은 다르다.** 파이프가 뚫려 있는지 확인했지만,
> 그 파이프에 **맞는 물이 흐르는지**는 확인하지 않았다.

이건 이 Topic 이 반복해 온 패턴이다 — M8 은 파서가 *조용히* 잘못된 값을 넣는 것을,
오늘 오전에는 *신호 없는 0* 을 고장으로 읽은 것을 찾았다. 셋 다 **"돌아가긴 하는데
틀린 것"** 이다.

### 고친 뒤

- `session_state.json` 을 감시 대상에 추가
- `snapshot()` 에서 **권위값이 `overlay.json` 을 덮어쓰도록**
- 자기 검증에 **「part_id 가 session_state 권위값과 일치」** 항목 추가

사용자 확인 — *"예 파트가 잘 바뀝니다"* (2026-08-31)

## 자기 검증 항목

```
✅ HTML 페이지 서빙
✅ 현재 상태 반환                        part=5 mode=MUTE
✅ SSE 접속 시 초기 상태 수신
✅ 파일 변경이 SSE 로 전달
✅ part_id 가 session_state 권위값과 일치   ← 결함 이후 추가
```

> ⚠️ **OBS 에서 실제로 보이는지는 자동 검증이 못 한다.** 브라우저 소스를 추가하고
> 사람이 화면을 봐야 한다. 위 결함도 그렇게 잡혔다.
