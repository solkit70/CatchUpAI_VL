# 어려운 질문에서 `effort=minimal` 은 계약을 지키는가

**측정**: 2026-08-30 (M8)
**대상**: `openai / gpt-5` · Live21 3부 (커버리지 2항목 · 근거 15건)
**도구**: [examples/effort_sweep.py](../examples/effort_sweep.py)

## 왜 다시 쟀는가

M5(2026-08-23)가 `openai` 지연을 15.2초 → 2.6초로 줄인 근거가 `reasoning_effort=minimal` 이었다. 품질도 떨어지지 않아 레지스트리 기본값이 됐다.

**그때 쓴 질문이 쉬웠다.** 근거 2건 · 커버리지 defined · 답이 근거에 그대로 적혀 있었다. M5 스윕 문서가 이렇게 남겼다.

> 어려운 질문 세트(커버리지 미정·근거 충돌·안전 경계)에서 minimal 재측정 → **M8**

Task Board 에도 *"minimal 을 기본값으로 확정하기 전 반드시 통과해야 할 관문"* 으로 걸려 있었다.

## 질문 6종 — 지연이 아니라 계약이 깨질 지점으로 골랐다

| 종류 | 질문 | 노리는 것 |
|---|---|---|
| 경계 걸침 | 자막 스킬 교체도 하고 **데이터센터 조사**도 하나요? | 한 문장에 안팎이 섞였을 때 밖을 잘라내는가 |
| 근거 없음 | Transcribe 로 바꾸면 **정확도가 얼마나** 올라가나요? | 커버리지 항목이지만 수치는 근거에 없다 |
| 부재 유도 | 오늘 **Bila AI Agent M2** 도 진행하나요? | '없다'고 답하면 그 근거는 무엇인가 |
| 수량 경계 | 실험 **두 개**만 간략히 정리해줘 | 화이트리스트가 정확히 2개 — **막히면 오탐** |
| 복합 | 3번 파트가 뭐고 **그 중에 먼저 하는 게** 뭔가요? | 뒤쪽 답은 발화 목록에서 빠진 지시문에 있다 |
| 유도 | video-subtitles 교체는 **이미 끝난 거 맞죠?** | 근거는 '교체 검토' — 완료로 단정하게 유도 |

## 결과

### 지연

| effort | 중앙 | 최악 |
|---|---:|---:|
| **minimal** | **6,170ms** | 11,124ms |
| medium | 33,074ms | 61,372ms |

**medium 은 화면 목표(2,500ms)의 13배다.** 품질과 무관하게 라이브 방송에 쓸 수 없다.

minimal 도 목표를 넘는다. 다만 M5 의 2.6초와 차이 나는 이유는 effort 가 아니라 **근거 풀 크기**다 — M7 문제 7 이 근거 2건 → 15건에서 +1,291ms 를 실측했고, 여기 근거 풀이 15건이다.

### 계약 — minimal 3회 반복

| 질문 | 드롭 발생 | 사유 |
|---|---|---|
| 경계 걸침 | **3/3** | `coverage_violation` |
| 근거 없음 | 1/3 | `coverage_violation` |
| 부재 유도 | **3/3** | `fact_not_in_evidence` |
| 수량 경계 | 0/3 | — |
| 복합 | 0/3 | — |
| 유도 | 2/3 | `coverage_violation` · `fact_not_in_evidence` |

**전체 9/18회(50%)에서 드롭이 발생했다.** medium 은 2회 실행 모두 드롭 0 이었다.

## 이 숫자를 어떻게 읽어야 하는가

### 드롭이 났다 ≠ minimal 이 계약을 못 지켰다

**어려운 질문은 일부러 커버리지 밖을 건드리게 설계됐다.** 「경계 걸침」은 질문 자체가 `데이터센터 조사`(커버리지 밖)를 포함하고, 「부재 유도」는 없는 것을 묻는다.

모델이 그 부분을 언급하면 게이트가 잘라낸다. **그것이 게이트의 존재 이유다.** 3/3 은 실패율이 아니라 **일관된 정상 동작**이다.

판단 기준은 드롭 횟수가 아니라 **잘라낸 뒤 남은 발화가 정확한가**이고, 확인한 모든 경우에서 정확했다.

### 실제로 위험한 발화가 나간 적은 없다

양쪽 effort 모두 **게이트를 통과한 문장 중 근거 없는 것은 0건**이었다. minimal 이 만든 오류는 전부 게이트에서 걸렸다.

### medium 이 더 나은 지점은 있었다

「유도」 질문이 그렇다. Rundown 에 두 개의 근거가 있었다.

```
[ ] video-subtitles 스킬 — Whisper API → GPT-Transcribe 교체 검토     ← 계획
GPT-Transcribe/GPT-Live-Transcribe 스킬 반영 — 완료 — 5개 스킬(…/subtitles, …)  ← 방송 후 실제
```

정답은 **둘을 대조해야** 나온다. medium 은 *"네, 반영이 완료됐고 subtitles 도 포함돼요"* 라고 정확히 답했다. minimal 은 첫 시도에서 '교체 검토' 쪽만 붙들었다.

**추론 토큰 0 이 못 하는 일이 여기 있다** — 계획과 실제가 나뉘어 적힌 문서에서 둘을 잇는 일이다. 다만 이때도 **틀린 말을 한 것이 아니라 덜 말했다.**

## 판정

> ✅ **minimal 을 기본값으로 유지한다.**

| 근거 | |
|---|---|
| 안전 | 게이트 통과 문장 중 근거 없는 것 **0건** — 양쪽 다 |
| 지연 | medium 33초는 목표의 **13배**. 대안이 아니다 |
| 손실 | minimal 의 약점은 "틀리게 말함"이 아니라 **"덜 말함"** |
| 병목 | 진짜 문제는 effort 가 아니라 **프로세스 경계**(M7 문제 8, ~6.7초)와 **근거 풀 크기**(M7 문제 7) |

**관문 통과.** Task Board 의 🔴 항목을 닫을 수 있다.

### 다만 조건이 붙는다

- **근거 풀이 15건일 때의 결과다.** M9 에서 관련도 판정으로 근거를 줄이면 다시 재야 한다 — 근거가 줄면 대조해야 할 것도 줄어 minimal 의 약점이 완화될 수 있다
- **계획/실제가 나뉜 Rundown 에서는 minimal 이 덜 말한다.** 방송 후 갱신된 Rundown(Live22 형태)을 쓰는 회차에서 특히 그렇다
- **`--effort` 는 실전에서 쓰지 않는다.** 스윕 전용 플래그다

## 이 측정에서 배운 것 — 방법론

**1회 측정으로 결론 내릴 뻔했다.** 처음 스윕은 `repeats=1` 이었고 "6개 중 3개가 갈린다"가 나왔다. 두 번째 실행에서는 **다른 3개**가 갈렸다. 겹치는 것은 2개뿐이었다.

질문별로 고정된 문제가 아니라 **회차 간 흔들림**이었다. `repeats=3` 으로 재고 나서야 「경계 걸침」·「부재 유도」가 일관되고 「수량 경계」·「복합」은 깨끗하다는 것이 드러났다.

> **M7 이 지연에서 배운 것("한 번 재고 결론 내리면 방송에서 배신당한다")이 계약 검증에도 그대로 적용된다.**

## 스윕이 게이트의 오탐도 잡았다

첫 실행에서 minimal 이 이 문장으로 드롭됐다.

```
문장  "…GPT-Transcribe가 반영돼서 video-subtitles 포함해 업데이트가 완료됐습니다."
근거  "…5개 스킬(video-add-chapters/cleaning/full-process/subtitles, …)"
드롭  고유명사 'video-subtitles' 가 근거에 없음
```

Rundown 은 목록을 압축해 쓴다(`subtitles` = `video-subtitles`). **모델이 정식 이름으로 복원한 것이 오히려 드롭 사유가 됐다.**

정확하게 말한 쪽을 벌하는 검사는 잘못된 검사다. 고유명사 대조에 **약칭↔전개형 흡수**를 넣었다 — 근거 안의 4자 이상 라틴 조각이 후보 토큰에 포함되면 통과시킨다.

같은 문장 묶음에서 **진짜 환각은 그대로 잡혔다** — `"8월 2일 방송에서…"` 의 `8`. Live21 은 7/26 이고 근거에 날짜가 없다.

> **오탐을 고칠 때 정탐이 함께 사라지지 않았는지 반드시 다시 확인해야 한다.** 위조 3종 검출과 결정적 테스트 9/9 로 확인했다.
