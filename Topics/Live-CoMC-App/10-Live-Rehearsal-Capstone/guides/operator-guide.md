## 먼저 — 이 앱의 「UI」는 무엇인가

**브라우저 탭 하나**다. `start_comc.ps1` 을 돌리면 PowerShell 창 하나(콘솔 프로세스)와 브라우저 탭 `http://127.0.0.1:8778/` 이 열린다. 질문 · 모드 · 패닉 · 파트 · 프리플라이트 · 결과 · 로그를 전부 그 탭에서 본다. PowerShell 창은 건드리지 않아도 된다 — 끝낼 때 Ctrl+C 를 누르는 곳일 뿐이다.

| 무엇 | 어디 |
|---|---|
| 보는 것 | 콘솔 탭 「오버레이」 칸은 전체 답변. OBS 미리보기는 승인 상태 또는 현재 음성 묶음의 자막. 침묵이면 화면이 비어 있음 |
| 듣는 것 | Buds(모니터) — LIVE 일 때만 (또는 「대기 발화 승인 → 소리」를 눌렀을 때) |
| 넣는 것 | 콘솔 탭 「질문」 칸에 치고 Enter — 시청자 채팅을 그대로 옮겨 쳐도 되고 내 질문을 쳐도 된다 |
| 바꾸는 것 | 콘솔 탭의 모드 · 패닉 · 파트 버튼. **핫키** Ctrl+Alt+… 도 그대로 살아 있다 |

### 왜 창 하나로 바꿨나 (CVL 3, 2026-09-17)

CVL 2 까지는 오버레이 서버 · 재생기 · 핫키 · 엔진이 PowerShell 창 4개였다. 9/17 실사용에서 「어느 창에 치나 · 핫키 창이 죽었는지 어떻게 아나 · 결과는 어디서 보나」가 전부 막혔다. 그래서 네 모듈을 **프로세스 하나**(`comc_console.py`)에 스레드로 넣고, 진행자가 보는 면을 로컬 웹 페이지 하나로 모았다. 검증된 모듈 코드는 그대로 import 한다 — 새 로직은 콘솔 HTTP 뿐이다. 이 과정에서 잡은 실사고 하나: 재생기를 스레드로 돌리자 WASAPI 콜백 스트림이 「Unanticipated host error」로 죽었다 → 스레드마다 COM 초기화(`spoken_player._com_init`) 로 해결 ([incident-classification.md](incident-classification.md) 사고 17).

## 전체 기능 테스트 문서

[수동 회귀 테스트 77건과 방송 시연 순서](manual-regression-test-cases.md)를 기준으로 정상 동작·안전·저장·복구를 검사한다. 현재 콘솔은 전체 답변을 보여 주지만 OBS는 승인 상태와 음성 진행에 맞춘 3줄 자막을 보여 주므로 두 화면의 글자가 항상 같은 것은 아니다. 퀵 버튼도 현재 기본은 질문란 채우기이며 즉시 전송은 선택 옵션이다.

## 1. 켜기 — 방송 30분 전

PowerShell 하나 열고 (어느 폴더든):

```
comc
```

`C:\Users\dougg\comc.cmd` 가 `start_comc.ps1` 을 부른다. 회차는 `AI\Roundup` 의 최신 「LiveNN Weekly Rundown」에서 자동으로 읽는다 (다른 회차는 `comc 29`). **PowerShell 창을 닫으면 콘솔·오버레이 서버·재생기·핫키가 전부 같이 꺼진다** — OBS 오버레이도 사라진다.

이 한 줄이 ① 오늘 Rundown 파싱 ② 1부 컨텍스트 ③ 모드 REVIEW ④ 콘솔 기동(오버레이 서버 · 재생기 · 핫키 · 엔진) ⑤ 브라우저 탭 열기까지 한다. 약 5초 뒤 탭이 뜨면 「프리플라이트 → 지금 점검」을 누르고 **FAIL 0** 인지 본다 (WARN 2 는 정상 — 1부 커버리지 미정 · 타임라인 샘플). FAIL 이 있으면 그 줄을 읽고 고친 뒤 다시.

OBS 는 `Untitled` 프로필 그대로 — Audio Input Capture 모니터링 Enabled · 모니터링 장치 Buds. **Scene Collection 이 `Live` 인지 본다** (상단 메뉴 Scene Collection). 컬렉션은 둘이다 — **9/25 실제 생성·파일 확인** (9/20 에 계획만 적혀 있었고 실제로는 `Untitled` 하나였다). Desktop Audio·Mic/Aux 장치는 컬렉션에 저장되므로 고르는 것만으로 바뀐다. ⚠️ **장치를 바꾸기 전에 반드시 컬렉션부터 전환한다** — 켜진 컬렉션의 값이 덮어써진다 (9/25 복제 전에 바꿔 녹화용까지 방송용이 됐다):

| Scene Collection | Desktop Audio | Mic/Aux | 언제 |
|---|---|---|---|
| **`Live`** | Speaker (Realtek) — Buds 로 두면 CoMC 소리가 두 번 난다 · 🆕 브라우저 소리는 아래 「브라우저 소리」 소스로 | Motiv Mix (Shure) | 라이브 방송 |
| `Recording` | Headphones (Galaxy Buds2 Pro) | Microphone Array (내장) | 마이크 없이 화면+유튜브 소리+목소리 녹화 |

🔴 **`Live` 에 「브라우저 소리」 소스를 둔다 (2026-10-02 추가)** — 방송 중 유튜브에서 튼 음악이 방송에 안 들린다는 진행자 제보. OBS 설정 파일로 확인한 원인: `Live` 의 Desktop Audio 는 **Speaker (Realtek) 한 장치만** 잡는데, 진행자는 Buds 로 들으므로 브라우저 소리는 Windows 기본 출력인 Buds 로만 나간다 → OBS 가 못 잡는다. CoMC 음성은 따로 `CABLE Output` 으로 잡으므로 들린다. Desktop Audio 를 Buds 로 바꾸면 CoMC 소리가 두 번 나므로 그 대신 **브라우저 앱 소리만 따로 잡는다**:

1. Scene Collection 을 **먼저** `Live` 로 (위 ⚠️)
2. Sources ➕ → **Application Audio Capture (BETA)** → 이름 `브라우저 소리`
3. Window — 음악 · 캐치를 띄울 브라우저 (`[chrome.exe]` 또는 `[msedge.exe]`) · Window Match Priority = **Match executable name**
4. 오디오 믹서의 `브라우저 소리` 막대가 음악에 맞춰 움직이는지 · 모니터링 **Off** (진행자는 이미 Buds 로 듣는다)
5. 짧게 녹화해 **음악 · CoMC 음성 · 마이크가 모두, 한 번씩만** 들리는지 확인 — 캐치(브라우저 앱)를 방송에서 시연하면 그 목소리도 이 소스로 들어간다

- 브라우저 소리가 너무 크면 믹서에서 `브라우저 소리` 를 -10 dB 안팎으로 낮춘다 (음악은 진행자 목소리 아래로)
- 음악을 Realtek 스피커로 내보내는 방법(Windows 「앱 볼륨 및 장치 기본 설정」)은 스피커 소리가 마이크로 다시 들어갈 수 있어 쓰지 않는다

📌 **매주 방송 전 — `Live` 의 채팅 Browser 소스 URL 을 이번 주 방송 ID 로 바꾼다** (`https://studio.youtube.com/live_chat?is_popout=1&v=<방송ID>`). 9/25 확인 때 지난 방송 ID(`o7EdTYymoRs`)가 남아 있었다. `CoMC-Test` 컬렉션은 영상 소스가 없어 쓰지 않는다.

⚠️ Motiv Mix 는 USB 를 꽂아야 목록에 나온다 — 꽂기 전에 `Live` 를 열면 Mic/Aux 가 비어 보인다. **Buds 마이크(Headset)는 어느 쪽에서도 고르지 않는다** — 고르는 순간 블루투스가 통화 모드로 바뀌어 Buds 출력 음질이 떨어지고 Desktop Audio 캡처가 끊긴다 (9/20 Live #28 이어폰 무음의 유력 원인). ~~영상을 틀 회차면 `Live` 에서 Desktop Audio 를 Buds 로 되돌린다.~~ → 2026-10-02 부터는 Desktop Audio 를 바꾸지 않고 위 「브라우저 소리」 소스로 영상 · 음악 소리를 잡는다 (Buds 로 바꾸면 CoMC 소리가 두 번 난다).

⚠️ **OBS 가 먼저 켜져 있었다면** Browser Source 가 서버 없는 상태로 굳어 오버레이가 안 보인다 (9/17 실사고 15). Sources 에서 「Co-MC 오버레이」 클릭 → 소스 툴바 **Refresh**. 순서를 `start_comc.ps1` → OBS 로 하면 이 일이 없다. 「Co-MC 오버레이」가 2개면 하나는 눈을 꺼 둔다 (겹치면 글자가 두꺼워진다).

## 2. 말 시키기

콘솔 탭 「질문」 칸에 한 줄 치고 **Enter** (Shift+Enter 는 줄바꿈). 「이 파트 뭐 다뤄요?」「첫 항목이 뭐죠?」 버튼은 현재 파트에 맞춘 질문을 채운다. 수정 후 Enter로 보내며, 「즉시 전송」 옵션에서는 바로 보낸다.

```
오늘 2부에서 뭘 다루나요?
```

약 5초 뒤 「오버레이」 칸과 「결과」 목록에 답이 뜬다. 결과는 세 가지 중 하나다:

| 결과 | 뜻 | 할 일 |
|---|---|---|
| 답이 뜬다 | 근거 있음, 게이트 통과 | REVIEW 면 화면만 · LIVE 면 소리도 |
| **「비어 있음 — 침묵」** | 근거 없음 / 다른 파트 질문 / 못 알아들음 → 침묵. 결과 줄에 `⛔ 04 …` 사유가 붙는다 | 내가 직접 답하거나 질문을 바꿔 친다. 앱이 틀린 게 아니라 **말하지 않기로 한 것** |
| 결과 줄에 `hitl` · `completion_confusion` | 모호해서 멈춤 (예: 이미 완료된 항목?) | 질문을 구체적으로 다시 |

**소리를 내려면 모드가 LIVE 여야 한다.** REVIEW 에서 뜬 답을 그 한 번만 소리로 내보내려면 「**대기 발화 승인 → 소리**」 버튼 (답이 대기 중일 때만 보인다).

## 2-b. 코엠씨 캐주얼 — 방송 내용 밖의 말 (CVL 4, 2026-09-17)

방송 내용(오늘 뭘 하나)은 Rundown 만 근거로 짧고 정확하게 — 그건 그대로다. 그 밖에 **주간 맥락·날씨·잡담·시청자 인사**는 두 번째 근거 풀 「캐주얼 브리프」(이번 주 Weekly Progress · Daily Roundup · Journal 구술 · 지난 방송 기록 · Open-Meteo 날씨)로 말한다. `start_comc.ps1` 이 방송 전에 만들고, 탭의 「캐주얼 브리프」 카드에 근거 수·날씨가 보인다. 날씨를 새로 받으려면 「다시 만들기」.

| 하고 싶은 것 | 치는 말 (버튼 있음) | 길이 |
|---|---|---|
| 날씨 | `오늘 서울이랑 시애틀 날씨는 어때요?` | ≈10초 |
| 이번 주 한 일 | `이번 주에 뭘 했어요?` | ≈50초 |
| 인사이트 | `이번 주 인사이트가 뭐예요?` | ≈50초 |
| **잠깐 자리 비움** | `잠깐 물 마시고 올게요. 그동안 시청자분들께 재미있는 얘기 해 주세요` / `니가 진행하고 있어` | **≈50초** (450자 상한) |
| 지금까지·남은 일 | `잠깐 볼일 보고 올게요. 지금까지 한 일과 앞으로 남은 일을 설명해 주세요` | ≈50초 |
| **시청자 인사** | 「시청자 · 이번 회차 참여 기록」에 이름 추가 → 이름 선택 → 「선택한 분께 인사」 → 묶음 버튼 | ≈10초 |
| 영어로 | 아무 질문 끝에 `영어로 답해 주세요` | 영어 목소리(Jenny)로 나감 |
| **🌏 15개 국어 자기소개 (샘플)** | 버튼 (확인창) 또는 `15개 국어로 소개해 주세요` | **15개 언어 · 약 2분** — 방송 중간 시연용. 「안녕하세요, 저는 Catch Up AI 라이브의 AI 부MC 코엠씨입니다. 만나서 반갑습니다.」 언어마다 오버레이. 패닉으로 중단 |
| **🌏 시그니처 끝인사** | 버튼 (확인창) 또는 `끝인사 해 주세요` | **15개 언어 · 2분 16초** — 배경음악 위로. 언어마다 오버레이에 그 언어 줄. 패닉으로 중단 |

- CVL6 명단 인사는 표시 이름·회차별 참여 기록만 근거로 사용한다. 이전 수동 질문용 `private/viewers.json` 메모를 자동으로 참여 기록에 가져오지 않는다. 명단과 런타임 파일은 공개 레포에서 제외된다
- 잡담 소재를 미리 주고 싶으면 Rundown 에 `## 코엠씨 잡담 소재` 섹션을 만들고 불릿으로 적는다 — 브리프가 읽는다
- 긴 발화(≈50초)는 **패닉**으로 언제든 끊는다. LIVE 면 바로 소리, REVIEW 면 승인 뒤 소리
- 다국어 대본·번역은 `output/private/signoff.json`(끝인사) · `intro.json`(자기소개) — 고치면 `python signoff_build.py [--set intro]` 로 바뀐 줄만 다시 합성 (방송 중엔 합성 안 함, 미리 만든 mp3 를 튼다). 순서는 한국어 → 총 화자 수 순 (English · 中文 · हिन्दी · Español · Français · العربية · বাংলা · Português · Русский · اردو · Bahasa Indonesia · Deutsch · 日本語 · Tiếng Việt)
- 코엠씨가 아는 것은 브리프에 있는 것뿐이다 — 「이번 주 기록에 없는 것」은 말하지 않는다 (침묵이 정답)

## 3. 모드 — 버튼 또는 핫키

| 버튼 / 키 | 뜻 |
|---|---|
| **REVIEW · 화면만** / Ctrl+Alt+R | 화면만, 소리 없음 (기본) |
| **LIVE · 소리** / Ctrl+Alt+L | 답이 곧바로 소리로 나간다 (**2부 CoMC 구간에서만**) |
| **MUTE** / Ctrl+Alt+M | 화면만, 소리 없음, 재생 중이면 즉시 끊김 |
| **■ 패닉** / Ctrl+Alt+Space | 재생 즉시 끊고 MUTE 로. ⚠️ **다시 소리를 내려면 LIVE 버튼(또는 Ctrl+Alt+L)** — REVIEW 는 화면만이라 소리가 안 난다 (9/17 연습에서 헷갈린 지점) |
| 파트 버튼 / Ctrl+Alt+1~9 · ← → | 파트 이동 — 엔진이 다음 질문 전에 컨텍스트를 다시 만든다. 지금 파트는 흰 테두리 |

핫키는 콘솔 프로세스 안에서 등록된다 — 별도 창이 없으니 「핫키 창이 죽었나」를 볼 필요가 없다. 로그에 `hotkeys 15개 등록` 이 있으면 살아 있는 것이다.

## 4. 멈추기

| 상황 | 방법 |
|---|---|
| **지금 말하는 걸 당장 끊기** | **■ 패닉** 버튼 또는 Ctrl+Alt+Space (MUTE 버튼도 같다). 재생기가 수십 ms 안에 끊는다 — 9/17 콘솔 실측: 재생 3.9초 시점 패닉 → `⛔ 중단 … mode=MUTE` |
| 소리만 끄고 화면은 계속 | REVIEW — 이것도 재생 중이면 끊긴다 |
| OBS 에서 AI 소리만 뮤트 | 믹서 「Audio Input Capture」 스피커 아이콘 (진행자 목소리는 그대로) |
| **자막(오버레이)만 치우기** | 오버레이 칸 오른쪽 **「화면 지우기」** 버튼 — 소리·모드는 그대로. 급하면 OBS 「Co-MC 오버레이」 눈 아이콘 |
| 앱 전부 종료 | PowerShell 창에서 **Ctrl+C** 한 번. 오버레이 서버도 같이 꺼지므로 OBS 오버레이가 사라진다 |

⚠️ **Space 만 누르지 않는다** (9/26 리허설) — 패닉 핫키는 **Ctrl+Alt+Space** 다. 콘솔 탭에서 Space 만 누르면 브라우저가 **마지막에 누른 버튼을 다시 누른다** — 「15개 국어」는 확인 창이 떠서 멈췄지만 날씨·이번 주 한 일 같은 버튼이면 확인 없이 바로 말을 시작한다. 9/26 콘솔 수정: 버튼은 누르는 즉시 포커스를 놓고, 버튼 위의 Space·Enter 는 무시한다(콘솔 재시작 후 적용). 화면 안내 문구도 「Ctrl+Alt+Space = 패닉」으로 고쳤다.

## Persona 선택 (CVL7 · 2026-10-01)

`comc`를 재시작한 뒤 「AI 코엠씨 · Persona」에서 캐릭터를 선택한다. 기본 코엠씨는 기존 기본 음성을 쓰며, 하늘(고등학생)과 지우(친구)는 편한 반말, 다온(대학생)과 서연(아나운서)은 존댓말이다. 학생·친구·경력·나이는 가상 캐릭터 설정이고, 실제 사람 행세를 하지 않는다. 정의는 [personas.json](../../07-CoMC-Engine-POC/data/personas.json)에서 이름·배경·말투·음성 등을 고칠 수 있다.

변경은 다음 질문부터 적용된다. 생성 중인 답변과 승인 대기 음성은 생성 당시 캐릭터와 목소리로 남으므로, 상단의 새 선택과 기존 결과의 캐릭터 이름이 다를 수 있다. 「선택한 캐릭터 자기소개」로 AI 소개와 말투를 확인하고, REVIEW에서 대기 발화를 승인해 실제 목소리를 들어 본다. 자기소개는 날씨·캐주얼 브리프가 없어도 사용할 수 있다. 한 질문을 캐릭터별로 반복해 숫자·이름·완료 상태도 비교한다.

| 선택 | 말투 | 한국어 음성 | 영어 음성 | 속도 · 높이 |
|---|---|---|---|---|
| 기본 코엠씨 | 친근한 존댓말 | 기존 기본 설정 | 기존 자동 영어 음성 | 기존 설정 |
| 하늘 · 고등학생 | 밝고 쉬운 반말 | SunHi | Jenny | +6% · +8Hz |
| 다온 · 대학생 | 또렷한 존댓말 | InJoon | Eric | +2% · 0Hz |
| 서연 · 아나운서 | 차분한 존댓말 | Hyunsu Multilingual | Aria | -4% · 0Hz |
| 지우 · 친구 | 편한 반말 | InJoon | Guy | 0% · -6Hz |

캐릭터 네 종은 edge-tts를 사용하며 다온과 지우는 한국어 기본 목소리를 공유하되 말투·속도·높이를 다르게 설정했다. 영어 답변은 질문 끝에 「영어로 답해 주세요」를 붙인다. 미리 만든 15개 국어 자기소개·끝인사 음원은 Persona 선택으로 다시 합성되지 않는다.

친구에게 진행자의 예전 이야기나 추억을 물으면 수동으로 웹·창작을 선택했어도 실제 볼트 기록만 검색한다. 기록이 없거나 민감한 개인 이야기이면 침묵하며 결과에서 거절 사유를 확인한다. 현재 방송 파트의 설명은 기존 Rundown·파트 권위 규칙을 따른다. 정상 반말을 허용하면서 `~다요` 같은 어미와 기존 인용·숫자·고유명사 검사는 유지한다. 실존 학생·친구 행세, 지어낸 공동 경험은 추가 검사로 차단하지만, 의미 전체를 규칙만으로 증명할 수는 없으므로 REVIEW에서 내용도 확인한다.

「이번 회차 사용 기록 · 반응 메모」에는 선택·답변 생성·실제 재생 완료를 구분해 보여 준다. 생성이나 승인 대기를 실제 재생으로 기록하지 않으며, 반응 메모는 진행자가 직접 입력해 저장한다. 기록은 비공개 `output/private/personas/state.json`에 유지한다. 단어·숫자를 다시 쓰지 않고 누락된 문장 부호만 보완해 반말 답변도 문장 사이에 쉬어 갈 수 있도록 했다.

## 시청자 명단과 참여 기록 (CVL6 · 2026-10-01)

콘솔을 재시작한 뒤 「시청자 · 이번 회차 참여 기록」에서 방송 날짜를 확인한다. 표시 이름을 입력하고 「추가」를 누르면 명단에 남으며, 여러 명은 쉼표로 구분한다. 같은 이름은 중복되지 않고 같은 회차로 `comc`를 다시 켜면 명단이 유지된다. 유튜브 댓글에서 자동 수집하지 않으며, 진행자가 이름을 직접 등록한다.

이름 버튼을 눌러 한 명 또는 여러 명을 선택한 뒤 「선택한 분께 인사」를 누른다. 「아직 인사 안 한 분 모두」도 사용할 수 있다. 아래 인사 묶음 버튼을 하나씩 누르고, REVIEW에서는 결과를 확인한 뒤 「대기 발화 승인」을 누른다. 이전 묶음의 재생·승인이 끝나기 전에는 다음 묶음을 시작하지 않는다. ✓는 실제 재생이 정상 종료된 경우에만 표시되며, 실패·음소거·중단·승인 대기는 인사 완료로 세지 않는다. 일부 이름만 통과했다면 그 이름만 완료되므로 「아직 인사 안 한 분 모두」로 나머지를 다시 준비한다.

「수정」에서 표시 이름과 읽는 법을 지정한다. 표시 이름 수정은 모든 회차에 반영되고 읽는 법은 음성에만 적용돼 자막에는 계정 이름이 보인다. 「이번 회차 삭제」는 이 회차에서만, 「전체 기록 삭제」는 모든 회차에서 삭제한다. 별개의 사람을 같은 표시 이름만으로 구별하는 기능은 없으므로 v1에서는 진행자가 이름을 구별해서 입력한다.

「전체 참여자 · 연말 인사」를 펼치면 이름별 참여 횟수·처음 회차·마지막 회차를 확인할 수 있다. 「전체 감사 인사 준비」는 최대 네 명씩 묶으며, 현재 시청 여부를 가정하지 않고 그동안의 참여에 감사한다. 명단은 `07-CoMC-Engine-POC/output/private/viewers/roster.json` 한 파일의 회차 구획에 즉시 저장된다. 날짜는 실제 방송 날짜를 진행자가 확인·수정하고, 등록 시각과 인사 완료 시각은 현지 시각으로 남긴다.

## 퀵 버튼 전송 방식 (CVL5 · 2026-10-01)

질문 카드의 「퀵 버튼」 기본값은 「질문란에 채우기 → 수정 후 Enter」다. 날씨·이번 주 한 일·인사이트·자리 비움·파트 질문 버튼을 누르면 질문만 채우고 입력란에 커서를 둔다. 내용을 수정한 뒤 Enter 또는 「보내기」로 전송하며 Shift+Enter는 줄바꿈이다. 한글 조합 중 Enter는 전송하지 않는다.

「즉시 전송」을 선택하면 기존처럼 퀵 버튼을 누르는 즉시 질문한다. 이 선택은 같은 브라우저·주소의 로컬 설정에 저장되어 새로고침 후 유지되며, 저장을 사용할 수 없으면 기본값으로 동작한다. 전송 실패나 엔진 처리 중 거절에는 질문을 지우지 않으며, 요청을 보내는 동안 같은 입력의 중복 전송을 막는다. 승인·패닉·시청자 인사·Persona 자기소개 버튼은 이 옵션의 대상이 아니다.

## 같은 발화 반복 억제 (CVL5 · 2026-10-01)

직전 발화가 정상 재생 완료된 뒤 30초 안에 같은 문구·Persona·음성 설정으로 다시 재생을 요청하면 합성·재생을 건너뛴다. 공백·줄바꿈 차이는 같은 문구로 판단하며, 기존 TTS용 정규화도 적용한다. LIVE와 REVIEW 승인 모두 적용하고 콘솔 로그에 「같은 발화 반복 억제」를 표시한다. 화면의 생성 답변은 그대로 보인다.

다른 답변이 사이에 정상 재생됐거나 30초가 지나면 다시 재생할 수 있다. Persona·정의·회차·음성 설정 변경은 비교 청취를 위해 별도로 취급하며, 중단·합성 실패·음소거는 완료로 기록하지 않아 재시도가 가능하다. 억제된 요청은 시청자 인사 완료나 Persona 재생 완료로 기록하지 않는다. 판정 기록은 재생기 프로세스 메모리에만 있어 콘솔·재생기 재시작 시 초기화되며, 별도 재생기 여러 개 사이에는 공유되지 않는다. 의도적으로 같은 말을 즉시 반복하려는 요청도 이 규칙을 따르므로 30초 뒤 다시 요청한다. 미리 만든 다국어 인사·CLI 테스트 음성은 대상이 아니다.

## 음성에 맞춘 긴 답변 자막 (CVL5 · 2026-10-02)

새 답변은 OBS에 최대 3줄씩 표시하고 해당 음성 묶음의 재생 직전에 다음 자막으로 전환한다. 긴 문장은 구절·단어 경계를 우선해 나누며 콘솔의 전체 답변과 근거는 그대로 유지한다. 한국어·영어 모두 적용하고 화면의 시청자 이름과 음성용 읽는 법도 분리한다. REVIEW에서는 「답변 준비됨 · 승인 대기」를 표시하고 승인 후 합성 중에는 「음성 준비 중」을 표시한다. 마지막 자막은 재생 완료 후 3초 동안 유지하고 지운다.

패닉·MUTE·재생 중단·합성 실패에는 자막을 숨긴다. 화면 지우기를 누른 뒤에도 옛 자막이 다시 나타나지 않으며, 새 답변이 생성되면 이전 답변의 자막을 섞지 않는다. OBS 서버의 확인 주기 때문에 자막 전달에는 최대 약 0.2초에 네트워크·브라우저 처리 시간이 추가될 수 있다. 단어별 타임코드가 아니라 음성 묶음 단위 동기화다.

모든 묶음을 먼저 합성해 재생 사이에 네트워크 대기를 없앤다. 이 때문에 첫 음성이 나오기까지 준비 시간이 늘 수 있고 문장 묶음 사이의 억양 연결은 실제 청취로 확인해야 한다. 테스트 문구의 두 묶음(약 24초 음성)은 이번 합성에서 약 4초 준비가 걸렸으며 일반적인 지연 보장값은 아니다. 새 기능은 콘솔과 오버레이 서버를 재시작하고 OBS 브라우저 소스를 새로고침해 적용한다. 기존 OBS URL은 그대로 사용한다. 1920×1080 브라우저 소스 설정을 권장한다.

검증 순서: REVIEW에서 긴 답변을 요청 → 전체 내용 확인 → 승인 → 소리와 자막 전환 확인 → 마지막 3초 후 숨김 확인 → 다른 질문 재생 중 패닉 확인. 기존 사전 합성 다국어 인사는 기존 표시 경로를 유지한다. 자막 런타임과 리허설 음성은 `output/private/`에만 저장한다.
