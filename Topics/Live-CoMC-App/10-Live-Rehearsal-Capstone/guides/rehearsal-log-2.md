## 목적

1회차는 **정상 경로**만 밟았다(정의된 파트에 정상 질문). 2회차는 그 반대를 본다 —
**설계상 막혀야 하는 경로**와, M9 대비 지연이다.

세 경로 모두 이 Topic 이 **문서로는 확정했지만 실물로는 한 번도 확인하지 않은 것**이다.

| 경로 | 무엇을 확인하나 | 근거 문서 |
|---|---|---|
| 1 | 커버리지 미정 파트 → 정말 침묵하는가 | M1 원칙 |
| 2 | 금칙 주제 질문 → 생성 전에 멈추는가 | M8 (시나리오로만 확인했었다) |
| 3 | 지연 — M9 와 같은 기준선(`--repeats 5`) | M9 실측 |

## 경로 1 — 커버리지 미정 파트에서 침묵하는가 ✅

Live26 의 `주간 영상` 파트는 커버리지가 `undefined` 다(이번 주 주간 영상 코너 생략).

```
$ python 02_resolve_context.py --live 26 --part "주간 영상"

⛔ 주간 영상부 커버리지가 undefined 입니다 — 컨텍스트를 만들지 않습니다.
   빈 컨텍스트를 넘기면 LLM 이 근거 없이 답하려 든다. HITL 로 되묻는 것이 계약이다.

exit=2
```

**LLM 근처에도 못 간다.** ② 컨텍스트 단계에서 끝난다.

M8 발견 3이 *"차단이 예상보다 앞 단계에서 일어났다 — 개선이지 결함이 아니다"* 라고 적어 둔 그 동작이
실물에서 확인됐다. 빈 컨텍스트조차 만들지 않으므로 **LLM 에 넘어갈 것이 아예 생기지 않는다.**

> 이 경로가 오늘 실물로 성립한 것은 우연이 아니다. 어제 Rundown 에서 주간 영상을
> *"이번 주 생략"* 으로 확정했기 때문에 `undefined` 파트가 실제로 생겼다.
> M1~M9 동안 한 번도 못 해본 검증을 **실제 방송 편성이 만들어 줬다.**

## 경로 2 — 금칙 주제를 이름으로 물으면 ✅

Live26 은 금칙 섹션이 0개라 **Live21**(금칙 2개)로 확인했다.

```
금칙: 보류된 인사이트 후보 (이번 방송 미편성)  | unscheduled
금칙: 주간 영상 후보 (이번 방송 코너 미편성)   | unscheduled
```

③ 의도 분류에서 잡힌다.

```
$ python 03_classify_intent.py --live 21 --text "보류된 인사이트 후보에 뭐가 있나요?"

  answer_question  conf=0.9  모호성=forbidden_topic_requested
  slots={'forbidden_heading': '보류된 인사이트 후보 (이번 방송 미편성)'}
```

④ 생성 단계가 실제로 멈춘다.

```
⛔ 생성하지 않습니다 — forbidden_topic_requested
   되물을 말: "그 섹션은 이번 방송에 편성되어 있지 않습니다. 다른 항목을 말씀해 주세요."
   만들어 두고 뒤에서 거르는 것이 아니라, 만들기 전에 멈춘다.
```

**M8 이 시나리오 러너로만 확인했던 것을 실물 파이프라인에서 재확인했다.**
M8 발견 2의 실패 사슬(금칙 이름이 발화문을 타고 프롬프트에 진입 → 조건부 근거와 이어 붙음)이
지금은 **첫 고리에서 끊긴다** — 프롬프트가 만들어지지 않으므로 진입할 곳이 없다.

## 경로 3 — 지연 재측정 ⚠️ 기준선 주의

```
=== M9 상주 엔진 벤치 — Live26 · 5회 ===
  데몬 기동  1,502ms  ← 한 번만
  사전 캐시 ①②  19ms

  1회  4,022ms   ③8  ④3,997 ⑤7  ⑥10
  2회  2,546ms   ③4  ④2,507 ⑤17 ⑥18
  3회  2,998ms   ③7  ④2,969 ⑤9  ⑥13
  4회  2,527ms   ③6  ④2,495 ⑤12 ⑥14
  5회  3,284ms   ③6  ④3,249 ⑤15 ⑥14

  중앙값 2,998ms · 최악 4,022ms · 최선 2,527ms
  프로바이더 build 5회 중 실제 생성 1회  → ✅ 클라이언트 재사용됨
```

| | M9 (Live21) | 오늘 (Live26) |
|---|---:|---:|
| 중앙값 | 4,369ms | **2,998ms** |
| 최악 | 5,638ms | 4,022ms |
| 최선 | 3,561ms | **2,527ms** |

**M7 목표 2.5초가 처음으로 사정권에 들어왔다** — 최선 2,527ms.

> ⚠️ **완전한 like-for-like 가 아니다.** 측정 방법은 같지만(warm · 데몬 · 5회) **회차가 다르다.**
> Live26 의 근거 풀은 3건이고 Live21 은 다른 구성이었다. M9 가 실측한 대로
> **근거 풀 크기가 LLM 지연을 좌우**하므로, 이 차이의 얼마가 개선이고 얼마가 회차 차이인지는 가르지 못한다.
>
> M9 가 남긴 교훈을 다시 적용한다 — *"절감폭을 비교할 때는 기준선을 먼저 맞춘다."*
> 같은 회차로 before/after 를 재지 않았으므로 **"1.4초 개선"이라고 말하지 않는다.**

③⑤⑥ 합계는 최대 47ms 다. **껍데기는 여전히 병목이 아니다** — M9 결론 유지.

## 이번 회차에서 추가된 게이트 규칙 2종

1회차 사고를 고치면서 게이트에 규칙 두 개가 늘었다. 둘 다 **대조 실험으로 검증**했다.

### 규칙 7 `content_empty` — 근거는 있는데 내용이 없는 답

| 조건 | pass |
|---|---|
| A. 규칙 도입 전과 동일 (질문 미전달) | `True` ← 예전 게이트가 통과시킴을 재현 |
| B. 같은 초안 + 질문 전달 | **`False`** |
| C. 항목을 실제로 말한 답 | `True` (오탐 없음) |
| D. "지금 몇 부인가요?" | `True` (오탐 없음) |

### 규칙 8 `style_broken` — 방송에서 읽을 수 없는 종결

**어미만 다르고 나머지 조건이 완전히 같은 두 문장**으로 갈랐다.

| 문장 | pass |
|---|---|
| `…M10 마무리로 진행합니다.` | `True` |
| `…M10 마무리로 진행한다요.` | **`False` style_broken** |
| `…M10 마무리를 다루겠사옵니다.` (낯설지만 붕괴 아님) | `True` (막지 않음) |

**재현율은 0/10 이었다** → [ending_style_probe.py](../examples/ending_style_probe.py).
프롬프트에 어투 지시를 넣은 뒤로는 붕괴가 안 나온다. 그러므로 규칙 8은 **활성 결함의 수정이 아니라 하한**이다.

> 사전에 *"1/10 이상이면 규칙 추가"* 라고 기준을 걸어 뒀고 결과는 0/10 이었다.
> 그런데도 규칙을 넣은 이유는 규칙 7과 같다 — **프롬프트는 확률을 옮기고 게이트는 하한을 만든다.**
> 다만 기준을 사후에 바꾼 것이므로, "측정 결과가 규칙을 요구했다"고 적지 않는다. **판단으로 넣었다.**

측정 도구 자체도 검증했다. 첫 판이 `습니다` 만 넣고 `니다` 를 빼먹어 **정상 문장 5건을 이상으로 잡았다**
(`다룹니다` 는 `습니다` 로 끝나지 않는다). 고친 뒤 실물 10문장에 대해 **10/10 정확, 오탐 0**.

> M8 기준 그대로다 — **오탐이 없어야 검사가 쓸모 있다.**
> 검사기가 정상을 이상이라 하면 사람이 검사기를 무시하게 되고, 그 순간 검사는 없는 것이 된다.
