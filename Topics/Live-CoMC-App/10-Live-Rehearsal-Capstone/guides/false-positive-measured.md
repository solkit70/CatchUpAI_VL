## 이 측정이 왜 이월돼 있었나

M4 실습 3은 **30분 배경 녹음**으로 오탐 0회를 재고 **3시간으로 환산**했다.
그리고 README 에 이월 과제를 남겼다.

> 과거 라이브 방송 3시간 오디오를 오프라인 채점해 **환산이 아닌 실측 오탐률** 확보

2026-08-15 부터 밀려 있었다. 이유는 **도구가 없어서**였다 — `wake_probe.py` 는 마이크 입력만 받았고,
3시간을 실시간으로 앉아서 재는 것은 현실적이지 않다. 그리고 그렇게 재도 **매번 다른 소리라 재현이 안 된다.**

2026-09-06, Live #26 방송 중에 `--mode file` 을 추가해 해결했다.
파일 채점은 마이크·스피커를 쓰지 않으므로 **방송에 간섭하지 않는다**
(→ [방송 중 가능/불가 판정](what-can-run-during-broadcast.md)).

## 측정 조건

| 항목 | 값 |
|---|---|
| 소스 | `AIInAction_20260724_full.mp4` — **실제 AI in Action 방송 풀 녹화** |
| 길이 | **183.7분** (3시간 4분) |
| 모델 | `hey_jarvis` · `alexa` · `hey_mycroft` (openWakeWord 사전학습) |
| 임계값 | 0.5 (M4 실습 3과 동일) |
| 쿨다운 | 1.0초 (중복 카운트 방지) |
| 처리 속도 | 21.0분 소요 — **실시간의 9배** · 프레임당 평균 9.04ms |

M4 가 요구한 *"과거 라이브 방송 3시간 오디오"* 조건을 그대로 만족한다.

## 결과 — 환산이 틀렸다

| 모델 | M4 환산 (30분 기준) | **3시간 실측** |
|---|---:|---:|
| `hey_jarvis` | 0회 | **0회** |
| **`alexa`** | **0회** | **1회** ⚠️ |
| `hey_mycroft` | 0회 | **0회** |

```
⚠️오탐  alexa  score=0.595  @8028.80s   (2시간 13분 48초 지점)
```

> **30분에 0회였다고 3시간에 0회인 것이 아니었다.**
> 이월 과제가 의심한 바로 그 지점이고, 실측이 그것을 확인했다.

M4 는 *"최대점수 0.1953, 임계값 2.6배 여유"* 라고 적었다. 30분 창에서는 사실이었다.
3시간에서는 **0.595 가 나왔다** — 임계값 0.5 를 넘겼고 여유는 0.095 뿐이다.

### 이것이 뒤집는 것과 뒤집지 않는 것

**뒤집지 않는 것**: 호출어 방식 자체는 여전히 쓸 만하다. 3시간에 1회다.

**뒤집는 것**: *"오탐 0회"* 라는 문장은 더 이상 쓸 수 없다. 그리고 **표본이 작으면 0이 나온다**는 것을
이 Topic 이 실물로 배웠다 — 30분 창은 오탐이 없다는 증거가 아니라 **오탐을 볼 만큼 길지 않았다**는 뜻이었다.

## 그래서 어떻게 할 것인가 — 선택지 셋

실측이 나왔으므로 대책을 근거 위에서 고를 수 있다.

| 안 | 내용 | 3시간 예상 오탐 | 대가 |
|---|---|---:|---|
| **A** | **`hey_jarvis` 단일 모델**로 고정 | **0회** (실측) | 호출어가 "헤이 자비스" 로 고정됨 |
| **B** | 3모델 유지 + **임계값 0.6** | **0회** (0.595 < 0.6) | 진짜 호출도 놓칠 확률 증가 — 감지율 재측정 필요 |
| C | 현행 유지 (3모델 · 0.5) | 1회 | 3시간 방송 중 한 번 잘못 깨어난다 |

**A 가 낫다고 본다.** 이유가 둘이다.

1. **실측 근거가 직접적이다.** B 의 0.6 은 *"이번 표본의 0.595 보다 큰 값"* 이라 표본에 맞춘 값이고,
   다음 방송에서 0.62 가 나오면 그대로 무너진다. A 는 모델 자체가 3시간 동안 한 번도 반응하지 않았다.
2. **어차피 한국어 커스텀 호출어("코엠씨")는 별도 학습이 필요하다.** M4 가 이미 적어 둔 대로
   지금 3모델은 **방법론 검증용**이지 최종 호출어가 아니다. 최종본까지 3개를 들고 갈 이유가 없다.

> ⚠️ **다만 A 를 채택해도 "0회"라고 쓰지 않는다.** *"3시간 1회 표본에서 0회"* 라고 쓴다.
> 이 문서가 존재하는 이유가 바로 그 구분이기 때문이다.

## 남은 것

- [ ] **감지율 재측정** — 오탐을 줄이는 선택(A·B)이 진짜 호출을 놓치게 만드는지는 아직 안 쟀다.
      오탐만 보고 고르면 **안 깨어나는 시스템**이 된다
- [ ] 다른 회차 방송으로 **2차 표본** — 1회가 이 방송 특유의 소리 때문인지 확인.
      `--mode file` 이 생겼으므로 이제 회차만 바꾸면 된다
- [ ] 8028.8초 지점에 **무슨 소리가 있었는지** 확인 — 영어 발화인지, 음악인지, 특정 자음 배열인지

세 번째가 가장 값싸고 정보량이 크다. 그 30초를 들어 보면 오탐의 성격을 알 수 있다.

## 도구

```bash
# 3시간 방송 녹화 오프라인 채점 (마이크 불필요, 방송 중 실행 가능)
python wake_probe.py --mode file --audio "<영상 또는 오디오 파일>"

# 모델·임계값을 바꿔 재측정
python wake_probe.py --mode file --audio "<파일>" --models hey_jarvis --threshold 0.6
```

전체를 메모리에 올리지 않고 ffmpeg 파이프에서 프레임 단위로 흘린다.
가상 시계를 쓰므로 **결정적**이다 — 같은 파일은 몇 번을 돌려도 같은 결과가 나온다.
