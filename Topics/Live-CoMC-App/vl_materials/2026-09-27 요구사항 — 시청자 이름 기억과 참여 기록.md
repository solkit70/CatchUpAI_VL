## 배경

2026-09-27 Live #29 방송 중 진행자 요청. 지금의 「시청자 언급 (이름 입력)」 버튼은 누를 때마다 이름을 새로 타이핑해야 하고, 입력한 이름은 어디에도 남지 않는다(`comc_console.py` 의 `greet()` 가 `prompt()` 로 받아 바로 질문 문장으로 보낸다). 진행자 원문 요지:

- 방송 중에 이름을 **한 번만** 타이핑하면 기억했다가, 감사 인사 때 AI 가 그 이름을 언급한다
- 다른 분이 댓글로 인사하면 **언제든 이름을 추가**할 수 있어야 한다
- 이름은 **방송 회차와 함께 기록**해서 어느 방송에 누가 참여했는지 남긴다
- **연말 등에 그동안 참여한 모든 분께 인사**할 수 있게 쌓아 둔다

> 이번 방송(Live #29)에서는 개발하지 않는다. 주중 Enhancement 작업(CVL)에서 구현한다.

## 요구사항

| # | 요구사항 | 완료 기준 |
|---|---|---|
| **R1** | **방송 중 시청자 명단** — 콘솔에 명단 칸을 두고, 이름을 언제든 추가한다(한 명씩 · 쉼표로 여러 명) | 이름을 입력하면 명단에 칩(버튼)으로 남는다. 같은 이름을 두 번 넣어도 한 번만 남는다 |
| **R2** | **다시 타이핑하지 않는 인사** — 명단의 이름을 눌러(하나 또는 여러 명 선택) 감사 인사를 시킨다. 「아직 인사 안 한 분 모두」 버튼 | 이름을 다시 입력하지 않고 인사 발화가 나간다. 인사한 이름은 표시가 바뀐다(인사 완료) |
| **R3** | **콘솔을 다시 켜도 명단 유지** — 명단은 회차별 파일에 즉시 저장된다 | 방송 중 `comc` 를 재시작해도 그 회차 명단이 그대로 보인다 |
| **R4** | **회차별 참여 기록** — 회차 번호 · 방송 날짜 · 이름 · 처음 추가된 시각 · 인사했는지 | 방송이 끝나면 그 회차에 누가 참여했는지 목록이 남는다 |
| **R5** | **다시 온 분 알아보기** — 이전 회차 기록에 있는 이름을 추가하면 「지난번에도 와 주신 분」으로 표시하고, 인사에 그 사실을 넣을 수 있다 | 이전 회차에 있던 이름을 넣으면 참여 횟수가 보이고, 인사 문장에 「다시 와 주셔서」가 들어갈 수 있다 |
| **R6** | **전체 참여자 모아 보기 (연말 인사)** — 지금까지 모든 회차의 참여자를 모아, 이름별 참여 횟수 · 처음 온 회차 · 마지막 회차를 보여 준다 | 버튼 하나(또는 명령 하나)로 전체 목록이 나오고, 「그동안 참여해 주신 분들께 인사」 발화를 만들 수 있다 |
| **R7** | **이름 고치기 · 지우기 · 읽는 법** — 오타 수정, 잘못 넣은 이름 삭제, 영어·이모지 계정 이름의 **읽는 법**(TTS 가 읽을 표기) 지정 | 이름을 고치면 기록에도 반영되고, 읽는 법이 있으면 음성은 그 표기로 읽는다 |

## 지킬 것

- 🔴 **이름 기록은 공개 레포에 올리지 않는다.** 저장 위치는 이미 `.gitignore` 대상인 `07-CoMC-Engine-POC/output/private/` 아래(예: `private/viewers/live29.json` · `private/viewers/roster.json`). 이 요구사항 문서에는 실제 이름을 쓰지 않는다
- 저장하는 것은 **방송 채팅에 보인 표시 이름**뿐이다. 이메일 · 연락처 · 채팅 내용은 저장하지 않는다
- 인사 발화는 지금의 `greet_viewer` 캐주얼 레인을 그대로 쓴다 — 게이트 규칙(길이 · 인용)은 바꾸지 않는다
- 명단 추가는 **진행자 손으로만** 한다(v1). 유튜브 라이브 채팅을 자동으로 읽어 이름을 모으는 것은 v2 후보로 남긴다

## 설계 메모 (구현할 때 확인)

- 지금 흐름: 콘솔 `greet()` → 「OO 님이 댓글 남겨 주셨어요. 감사 인사 해 주세요」 문장 → ③ `greet_viewer` 의도 → ④ 캐주얼 레인 → ⑤ 게이트 → ⑥ 재생. **R1·R2 는 콘솔 쪽만 바꾸면 되고 엔진은 그대로** 둘 수 있다
- 회차 번호는 콘솔이 이미 알고 있다(`Live #29` 헤더) — 회차별 파일 이름에 쓴다
- R6 의 연말 인사는 이름이 많으면 500자 상한을 넘는다 → 여러 번 나눠 말하거나 오버레이에 목록으로 띄우는 방식을 함께 검토
- Personal Ops Board 의 「마크다운이 원본」 원칙과 맞추려면, 회차 기록을 JSON 대신 비공개 마크다운으로 두는 선택지도 있다 — 구현 때 결정 기록으로 남긴다
