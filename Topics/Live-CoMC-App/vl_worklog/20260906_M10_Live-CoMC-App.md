## 한 것

### 1. 스트리밍 vs 안전 게이트 — 채택하지 않기로 결론

문장 단위 증분 게이트로 **M8 원칙을 지키면서 스트리밍하는 설계가 성립**한다는 것은 확인했다.
게이트 6규칙 전부 문장 단위 판정이 가능하고, 규칙 6(길이 컷)은 오히려 스트리밍에서 더 자연스럽다.

그런데 숫자가 결정을 뒤집었다.

| 방식 | 첫 소리 |
|---|---:|
| 필러 | **≈1.20초** |
| 문장 단위 스트리밍 | ≈2.6~3.1초 |

**스트리밍이 필러보다 1.4초 늦다.** LLM 이 첫 문장을 뱉는 시간 자체를 스트리밍이 줄여 주지 않기 때문이다.
위험(롤백 불가)을 감수하고 얻는 것이 이미 필러가 더 잘 해결한 문제였다.

부수 소득으로 **M6 필러 설계가 오측정 위에 서 있던 것**을 잡았다. `T_filler` 0.9초는 케이블 314ms 전제인데
M9 가 그 값을 63ms 로 정정했다. 같은 의도를 정정값 위에서 다시 계산하면 **1.14초**다.
0.9초를 두면 의도보다 0.25초 일찍 소리가 나 진행자 말과 겹칠 수 있었다.

→ [streaming-vs-safety-gate.md](../10-Live-Rehearsal-Capstone/guides/streaming-vs-safety-gate.md)

### 4. 게이트 규칙 7 `content_empty` 신설

사고 3을 프롬프트로만 고쳤더니 **3회 중 1회만** 항목을 말했다. 비결정적이라 보장이 안 된다.
M8 원칙대로 규칙 기반 검사를 추가했다.

대조 실험으로 검증했다 — *"게이트를 꺼도 같은 결과가 나온다면 아무것도 확인하지 않은 것이다."*

| 조건 | pass |
|---|---|
| A. 규칙 도입 전과 동일 (질문 미전달) | `True` ← 예전 게이트가 통과시킴을 재현 |
| B. 같은 초안 + 질문 전달 | **`False` content_empty** |
| C. 항목을 실제로 말한 답 | `True` (오탐 없음) |
| D. "지금 몇 부인가요?" | `True` (오탐 없음) |

**회귀**: M8 결정적 테스트 **9/9 유지**, 볼트 Rundown **16편 전수 파싱 이상 0건**
(파트·항목·하위섹션 수가 M8 기록과 전부 일치 — Live14=14 · Live16=12/2 · Live17=26/7 · Live18~25=19·24·17·5·7·6·7·15).

### 5. 리허설 2회차 — 막혀야 할 것이 막히는가 (사고 0건)

1회차는 정상 경로만 밟았다. 2회차는 **설계상 막혀야 하는 경로**를 봤다.
세 경로 모두 이 Topic 이 문서로는 확정했지만 **실물로는 한 번도 확인하지 않은 것**이다.

| 경로 | 결과 |
|---|---|
| 커버리지 미정 파트(주간 영상) 질문 | ✅ ② 컨텍스트 단계에서 차단, `exit=2` — LLM 근처도 안 간다 |
| 금칙 주제를 이름으로 지목 (Live21) | ✅ ③ 에서 `forbidden_topic_requested`, ④ 생성 거부 + 되물을 말 준비 |
| 지연 `--repeats 5` | 중앙값 **2,998ms** · 최선 **2,527ms** — M7 목표 2.5초 사정권 |

경로 1이 오늘 성립한 것은 우연이 아니다. **어제 Rundown 에서 주간 영상을 "이번 주 생략"으로
확정했기 때문에 `undefined` 파트가 실제로 생겼다.** M1~M9 동안 못 해본 검증을 실제 편성이 만들어 줬다.

지연은 M9(4,369ms)보다 낮지만 **회차가 달라 like-for-like 가 아니다.**
근거 풀 구성이 다르고, M9 가 실측한 대로 근거 풀 크기가 LLM 지연을 좌우한다.
그래서 **"1.4초 개선"이라고 적지 않는다.**

### 6. 게이트 규칙 8 `style_broken` 추가 — 재현율 0/10인데도 넣은 이유

사고 4(어미 붕괴)를 10회 재측정했더니 **0/10** 이었다. 프롬프트에 어투 지시를 넣은 뒤로 안 나온다.
사전에 걸어 둔 기준은 *"1/10 이상이면 규칙 추가"* 였으므로, 기준대로면 규칙은 불필요했다.

그런데 넣었다. 규칙 7과 같은 논리다 — **프롬프트는 확률을 옮기고 게이트는 하한을 만든다.**
런타임 비용이 문자열 검사 하나이고, 이것이 `LIVE` 자동 발화를 막고 있던 유일한 사유였다.

> **다만 기준을 사후에 바꾼 것이므로 "측정이 규칙을 요구했다"고 적지 않는다. 판단으로 넣었다.**
> 이 구분을 흐리면 다음에 "측정했더니 필요했다"는 문장을 근거 없이 쓰게 된다.

측정 도구 자체도 틀렸다가 고쳤다. 첫 판이 `습니다` 만 넣고 `니다` 를 빼먹어 **정상 문장 5건을 이상으로 잡았다** —
`다룹니다` 는 `습니다` 로 끝나지 않는다(다루+ㅂ니다). 고친 뒤 실물 10문장에 **10/10, 오탐 0**.

## Insights (인사이트)

### 아홉 모듈이 한 번도 같이 돌아본 적이 없었다

`--live` 가 샘플 4회차에 묶여 있었다는 것은, **M1~M9 전체가 실제 방송 회차로 한 번도 기동된 적이 없다**는 뜻이다.
각 모듈은 자기 샘플 위에서 전부 통과했고, DoD 도 다 채웠다.

> 모듈별 통과의 합은 통합의 통과가 아니다. 캡스톤이 아니면 안 나왔을 결함이다.

M7 이 재현성을 위해 사본을 고정한 것은 옳은 설계였다. 문제는 **그 옆에 실물 경로를 열어 두지 않은 것**이다.
고정과 실물은 배타적이지 않다.

### 안전의 반대편은 무용함이다

M1~M9 가 막은 것은 전부 *"틀린 말"* 이다 — 근거 없는 발화, 금칙 주제, 위조된 숫자, 부재 주장.
그 방어가 완성되자 **맞는 말도 못 하는 상태**가 드러났다.

```
질문   오늘 2부에서 진행할 실험이 뭐가 있나요?
답     …후보 전체 목록 중에서 선별된 항목들입니다.   ← 이름을 하나도 안 말함
게이트  통과
```

**게이트 통과는 유용성의 보증이 아니다.** 근거가 있는 문장만 남겼을 뿐, 질문에 답했는지는 아무도 안 봤다.

원인은 두 층의 정의 불일치였다 — M8 게이트는 화이트리스트를 신뢰 출처로 인정하는데,
M7 프롬프트는 *"위 근거만 사용해"* 라며 재료에서 뺐다. **같은 대상에 대한 정의가 층마다 달랐다.**

### 프롬프트 수정은 보장이 아니다

사고 3을 프롬프트로 고치고 3회 돌렸더니 **1회만** 항목을 말했다. 사고 4(어미 붕괴)도 같은 성질이다 —
프롬프트·컨텍스트·모델이 전부 동일한데 출력만 갈렸다.

> **비결정적 출력에 거는 보장은 규칙으로만 만들 수 있다.**
> 프롬프트는 확률을 옮기고, 게이트는 하한을 만든다. 둘은 대체재가 아니다.

이 구분이 없으면 "프롬프트를 고쳤으니 해결됐다"고 적고 넘어가게 된다. 실제로 그럴 뻔했다 —
수정 후 4회 연속 성공했기 때문이다. **성공 4회는 보장이 아니라 표본이다.**

### 내가 그 함정에 실시간으로 빠졌다

사고 3의 원인을 찾으려고 `output/prompt.txt` 를 읽고 *"화이트리스트에 Caregiver 가 없다"* 고 결론냈다.
**그 파일은 8/30 Live21 실행 때 것이었다.**

M9 가 남긴 교훈 그대로다 — *"측정 대상이 내가 생각한 것과 다르다."*
`--dump-prompt` 를 줘서 오늘 프롬프트를 새로 뽑고 나서야 진짜 원인(화이트리스트는 있는데 지시가 배제)이 보였다.

`output/` 에 오늘 파일과 일주일 전 파일이 **아무 표시 없이** 섞여 있다는 것이 위험의 실체다.
파일 이름에 회차를 넣으면(`prompt.26.txt`) 이 오독은 성립하지 않는다.

### 프리플라이트가 스스로 같은 함정에 빠졌다 — 네 번째 반복

7번(오버레이) 검사가 *"서버가 응답하는가"* 만 보고 PASS 를 줬다. 그런데 표시 중인 파트가
**어제 세션의 5부**였고, 오늘 Rundown 에는 5부가 없다.

M9 의 오버레이 결함과 형태가 같다 — 파이프가 뚫렸는지는 봤고 맞는 물이 흐르는지는 안 봤다.
**이 Topic 에서 네 번째다.**

| 언제 | 무엇 |
|---|---|
| M8 (8/30) | 파서가 발화 항목 18개를 조용히 삭제 |
| M9 오전 | 신호 없는 0 을 장치 고장으로 읽음 |
| M9 오후 | 권위값 대신 스냅샷을 표시 |
| **M10 (오늘)** | **프리플라이트가 응답만 보고 내용은 안 봄** |

같은 실패가 네 번 반복됐다는 것은 개인의 부주의가 아니라 **검사 설계의 기본값 문제**다.
그래서 7번을 고칠 때 "표시 파트가 오늘 Rundown 에 실재하는가"까지 넣었다.

> **동작 검증은 기본값으로 두고, 의미 검증을 매번 따로 붙여야 한다.**
