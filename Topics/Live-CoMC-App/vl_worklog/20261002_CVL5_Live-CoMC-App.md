## 📚 진행 내용

[caption_pages.py](../07-CoMC-Engine-POC/src/caption_pages.py)는 원문을 최대 3줄 페이지로 나누고 문장·구절·단어 경계를 우선한다. 각 페이지의 원문으로 음성을 합성하며 단어·숫자를 요약하거나 삭제하지 않는다. 자막은 원래 표시 이름을 유지하고 합성할 때만 기존 시청자 읽는 법을 치환한다.

[spoken_player.py](../09-Desktop-Shell-and-Overlay/examples/engine/spoken_player.py)는 전체 페이지를 먼저 합성하고 로드한 뒤 각 페이지를 재생하기 직전에 자막을 게시한다. 실패하면 부분 답변을 시작하지 않고, 중단되면 나머지 페이지를 재생하지 않는다. 정상 완료 후에만 기존 시청자·Persona 완료와 반복 억제 기록을 남긴다. 기본 음성의 언어 판단도 전체 답변 기준으로 고정해 페이지마다 목소리가 바뀌지 않는다.

[overlay_server.py](../09-Desktop-Shell-and-Overlay/examples/engine/overlay_server.py)는 전체 답변 파일을 콘솔용으로 유지하면서 별도 자막 상태를 OBS에 보낸다. 답변 토큰이 다른 옛 자막은 무시하고 세션의 현재 파트와 AI Persona 표시는 유지한다. REVIEW는 준비됨, 합성은 음성 준비 중, 재생은 현재 페이지, 종료는 마지막 페이지 3초 후 숨김, MUTE·패닉은 숨김으로 처리한다. 자막 파일은 비공개 런타임에 원자적으로 교체한다. → [운영 절차](../10-Live-Rehearsal-Capstone/guides/operator-guide.md#음성에-맞춘-긴-답변-자막-cvl5--2026-10-02)

## 🐛 문제 해결 로그

기존 4줄 잘라내기는 긴 답변의 뒷부분을 보여 주지 못했다. 글자 수 기반 시간 추정 대신 실제 음성 페이지 시작으로 전환하고, 브라우저 폭에 따라 넓은 영문 글자를 줄이도록 화면 처리를 추가했다. 화면의 표시 이름과 음성 읽는 법이 섞이지 않도록 두 데이터를 분리했다.

테스트의 비공개 런타임 경로를 처음에 잘못 지정해 화면 지우기 검사가 실패했다. 실제 common.out 경로로 고친 뒤 통과했으며 자막도 비공개 경로 목록에 추가했다. 실제 음성 합성은 저장만 했고 사용자 장치로 재생하지 않았다.

## 💡 Daily Retrospective

실제 재생 경계에 연결하면 Persona 속도가 달라져도 자막을 글자 수 시간 추정에 의존하지 않아도 된다. 전체 선합성으로 묶음 사이 네트워크 대기를 없애는 대신 최초 준비 시간이 늘며, 별도 합성된 문장 사이의 억양은 실제 청취로 판단해야 한다.

단어별 타임코드 방식은 아니며 서버 폴링 최대 약 0.2초와 브라우저 처리 시간이 추가된다. 다음 확인은 콘솔·오버레이 재시작과 OBS 소스 새로고침 후 긴 답변 승인·재생·패닉 리허설이다.

최종 pytest는 기존 75건과 자막 신규 12건을 합쳐 87건이 통과했다. 별도 실제 HTTP/SSE 서버와 Chromium에서 24개 페이지의 전환·3줄 높이·자동 만료·MUTE 숨김을 확인했고 JS 오류는 없었다.

## 전체 기능 수동 회귀 문서 작성

사용자 요청으로 [수동 회귀 테스트·방송 시연 시나리오](../10-Live-Rehearsal-Capstone/guides/manual-regression-test-cases.md)를 작성했다. 현재 콘솔의 기존 기능과 M11·시청자·Persona·퀵 버튼·반복 억제·3줄 자막을 74건으로 정리하고, 단계·기대 결과·준비 자료·판정·비공개 결과 기록표·새 기능 추가 시 유지 규칙을 포함했다. 동일 질문의 생성 문구는 비결정적이므로 반복 억제는 검토된 동일 발화 봉투를 비공개 리허설에서 재주입하는 절차로 재현한다.

원본 사례는 전부 미실행으로 시작하며 실제 방송·청취·장애 검사는 이번 문서 작성에서 실행하지 않았다. README와 운영 가이드에 진입 링크를 추가하고, 과거 ‘퀵 버튼 즉시 전송’ 및 ‘콘솔·OBS 동일 내용’ 설명을 현재 구현으로 고쳤다.

## Codex 사전 회귀 실행

사용자 요청으로 전체 수동 문서에 대응하는 격리 검사를 실행했다. pytest 87건과 분류·안전·파트 권위 31건, 총 118건이 통과했고 실제 Chromium·로컬 HTTP/SSE 검사 36개가 통과했다. 현재 Live30 Rundown의 로컬 파싱도 정상이다. 최초 실제 API 호출은 자료 외부 전송 범위가 불명확해 자동 승인 검토가 거절했다. 이후 공개 Rundown·합성 문장만 사용하라는 사용자 승인을 받아 아래 추가 검사를 실행했다. 장치 재생·실제 송출은 확인하지 않았다.

74개 수동 사례는 PASS 10 · PARTIAL 43 · BLOCKED 21로 기록했고 전체 통과로 판정하지 않았다. 검사 장치의 초기 상태·누적 로그 계산을 보정했으며 수행 범위에서 앱 결함은 관찰하지 않았다. 비공개 실행 결과는 `07-CoMC-Engine-POC/output/private/regression-runs/20261002-agent/result-report.md`에 있으며 원본 사례는 재사용을 위해 NOT RUN을 유지한다.

## 공개·합성 자료 실제 API 추가 검사

10/2 격리 자동 검사 118건·브라우저 36개 통과. 사용자 승인 후 공개 Rundown·합성 자료로 실제 API 파이프라인 24회·재검사 4회, 한국어·영어 TTS 8개 합성·디코딩 성공. 수동 74건은 PASS 10 · 일부 확인 51 · 미확인 11 · FAIL 2. 웹 답변 근거 검사 실패 2회와 학생 자기소개 계약 위반·안내 문구 낭독을 확인해 수정·재검사 필요. 실제 청취·OBS·라이브 확인은 남아 있다. 비공개 결과: `Live-CoMC-App/07-CoMC-Engine-POC/output/private/regression-runs/20261002-agent/result-report.md`.

검색 API 연결 자체는 성공했지만 답변 승인까지 진행하지 못했고, 학생 자기소개는 재시도에서 생성됐으나 안내 문구를 그대로 출력했다. 일반 물 마시기 표현의 filler 분류 누락도 관찰했다. 합성 시청자 인사의 초기 실패는 검사 장치가 근거 경로를 잘못 차단한 것이며 이를 보완한 재검사는 성공했다. 앱 소스는 수정하지 않았다.

## 두 API 실패 수정 및 재검사

두 API 실패를 소스 수정 후 재검사했다. 최종 pytest 90건 통과, 공개 웹 답변 3회 연속·고등학생 자기소개 3회 연속 게이트 전체 통과. 다른 네 Persona와 학생 영어 소개도 실제 모델 검사 통과. 웹 답변 격리 REVIEW 승인 및 생성된 웹·한국어 소개·영어 소개 3개 실제 TTS 합성·디코딩 성공. 실제 장치 청취·OBS 송출은 미확인.

수동 74건 최신 집계는 PASS 10 · PARTIAL 53 · BLOCKED 11 · FAIL 0으로 갱신했다. 수정 파일은 `04_compose_answer.py`, `evidence_lanes.py`, `persona_store.py` 및 관련 두 테스트 파일이다. 초기 실패와 수정 중간 기록은 비공개 검사 폴더에 보존했고 전체 방송 GO나 실제 청취 완료로 판정하지 않았다. 콘솔 재시작 후 운영 확인이 필요하다.
