## 📚 진행 내용

### 1. 비공개 명단과 회차별 기록

[viewer_store.py](../07-CoMC-Engine-POC/src/viewer_store.py)는 표시 이름·읽는 법·회차별 날짜·등록 시각·인사 완료 시각을 `output/private/viewers/roster.json`에 저장한다. 별도 회차 파일과 전체 색인의 이중 갱신 대신 한 파일에 회차 구획을 두어 원자적으로 교체하며, 스레드·프로세스 잠금으로 콘솔과 독립 재생기의 동시 갱신을 보호한다. 이메일·URL·제어 문자·지나치게 긴 이름은 입력 단계에서 거부하고, 손상된 기존 기록을 빈 목록으로 덮어쓰지 않는다. → [요구사항 지킬 것](../vl_materials/2026-09-27%20요구사항%20—%20시청자%20이름%20기억과%20참여%20기록.md#지킬-것)

현재 회차에서의 이름 중복은 제거하고, 전체 참여 횟수와 과거 회차 참여 횟수를 구분한다. 이름 수정은 같은 내부 ID의 모든 회차에 반영하며 이름 충돌은 거부한다. 삭제는 현재 회차만 또는 모든 회차를 선택한다. 날짜는 기본 현지 날짜를 보여 주고 진행자가 실제 방송 날짜로 수정한다. 표시 이름만으로 동일인을 판단하는 v1이므로, 동명이인은 진행자가 구별해 입력해야 한다.

### 2. 선택 인사·재방문·전체 참여자

[comc_console.py](../09-Desktop-Shell-and-Overlay/examples/engine/comc_console.py)에 이름 추가, 선택 칩, 인사 완료·재방문 표시, 날짜 수정, 전체 참여자와 수정·삭제 버튼을 추가했다. 선택 인사와 아직 인사 안 한 분 인사, 전체 감사 인사는 최대 네 명·이름 합계 100자씩 묶어 진행자가 하나씩 누른다. 현재 회차 인사와 과거 전체 감사 인사를 구분해, 연말 인사에서 현재 시청이나 댓글 작성을 가정하지 않는다. → [운영 가이드](../10-Live-Rehearsal-Capstone/guides/operator-guide.md#시청자-명단과-참여-기록-cvl6--2026-10-01)

이름은 진행자가 수동으로 등록하며 채팅 자동 수집은 추가하지 않았다. 엔진에는 문자열에서 재추출한 이름 대신 저장소에서 읽은 구조화된 레코드를 전달하고, 기존 `greet_viewer` 캐주얼 레인의 길이·인용 규칙으로 검증한다. 캐주얼 브리프 생성이 실패해도 명단 자체의 근거로 인사할 수 있다.

### 3. 실제 재생 완료와 읽는 법

⑥ 렌더 단계는 게이트를 통과한 최종 문장에 실제로 남은 이름만 재생 요청의 수신자 목록에 넣는다. 읽는 법은 음성 문자열에만 적용하고 자막에는 표시 이름을 유지한다. 선택된 이름이 하나도 남지 않으면 일반 인사만 재생하지 않고 멈춘다.

[spoken_player.py](../09-Desktop-Shell-and-Overlay/examples/engine/spoken_player.py)는 재생이 정상 종료된 뒤 수신자의 `greeted_at`을 저장한다. 음소거·미승인·TTS 실패·패닉 중단은 완료로 세지 않으며, 이전 요청 이후 이름을 수정·삭제했다면 낡은 수신자 정보로 완료 표시를 덮어쓰지 않는다. 재생 도중 새 요청이 쓰인 경우에는 이전 재생기의 정리 작업이 새 요청을 삭제하지 않도록 요청 시각도 비교한다. → [재생 회귀 테스트](../07-CoMC-Engine-POC/tests/test_viewers.py)

### 4. 공개 샘플과 비공개 런타임

명단만 비공개에 둬도 기존 공개 런타임 파일에 이름이 복제되므로 [common.py](../07-CoMC-Engine-POC/src/common.py)의 `out()`에서 인텐트·초안·판정·출력·자막·음성 요청·재생 로그·지연 로그·디버그 오디오를 `output/private/runtime/`으로 라우팅했다. 추적 로그도 같은 비공개 경로로 옮겼으며, 기존 공개 `output/*.json`은 실습 샘플로 보존하고 현재 런타임에서는 읽지 않는다. 콘솔·OBS 서버·독립 재생기·핫키가 공통 경로 함수를 사용하므로 재시작하면 새 경로를 함께 사용한다.

## 🐛 문제 해결 로그

실제 LLM이 구조화된 JSON 근거에서 일부 필드를 빼고 다시 쓴 인용은 게이트가 차단했다. 짧은 평문 근거와 원문 복사 지시로 바꾼 최종 실제 검증에서는 현재 회차·전체 감사 인사 모두 두 문장·두 이름이 통과했다. 테스트에 쓴 가상 이름과 원문 출력은 `output/private/viewer_rehearsal/`에만 두고 공개 문서에는 옮기지 않았다.

초기 통합 테스트는 캐주얼 브리프가 없어서 명단 인사까지 거부되는 의존성을 발견했다. 등록된 명단 인사는 브리프와 별개로 근거를 만들게 수정했다. 별도 기존 실시간 LLM 인용 샘플 스크립트는 격리 폴더에 Live21 컨텍스트가 없어 실행되지 않았으며 통과 건수에 포함하지 않았다.

## 💡 Daily Retrospective

### What went well

기존 안전 게이트와 승인 흐름을 유지하면서 명단 기능을 연결했고, 브라우저에서 실제 입력·선택·수정·재시작 후 유지까지 확인했다. 생성 성공과 재생 성공을 구별한 덕분에 인사 기록의 의미도 분명해졌다.

### What could be improved

정상 재생 끝과 저장 사이에 프로세스가 강제 종료되면 완료 시각이 남지 않아 다음에 다시 인사할 수 있다. 실제 재생은 CABLE Input까지 전달된 결과이며 시청자가 실제로 들었는지를 확인하는 기능은 아니다. 다음 라이브에서 이름 발음과 묶음 크기, 실패 후 재시도 흐름을 관찰한다.
