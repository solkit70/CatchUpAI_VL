## 📚 진행 내용

### 1. 경로 선택과 검색

`evidence_lanes.py`를 기존 M7 엔진에 추가하고 ③ 의도 분류, ④ 답 작성, ⑤ 게이트, ⑥ 출력, M9 상주 엔진과 콘솔에 연결했다. 방송 내용은 Rundown 우선, 지난 기록은 볼트, 공개 일반 정보는 웹으로 찾으며 진행자가 콘솔에서 경로를 지정할 수 있다. 가상 이야기는 명시적으로 요청하거나 선택할 때만 허용한다.

볼트 색인은 SQLite FTS5이며 결과는 실제 파일의 섹션과 원문을 함께 가진다. 같은 문서가 근거 풀을 독점하지 않도록 문서별 최대 2개, 질문별 최대 10개의 근거를 선택하고 사용 직전에 원문을 다시 읽어 삭제·비공개 전환을 검사한다. 색인은 Git에서 제외되는 `07-CoMC-Engine-POC/output/private/m11/`에 저장하며 새 기록을 반영할 때 콘솔의 「볼트 색인 갱신」을 사용한다.

### 2. 내부 자료와 개인 일 제외

`visibility: internal`, `private: true`, 「🔒 내부 자료」 문서는 제외한다. 내부 표시가 있는 README·폴더 인덱스의 하위 폴더, 개인 서류·정산·DM·메일링·신청 기록 및 명시적인 `.gitignore` 비공개 대상도 제외한다. 민감한 내용이 있는 소절은 통째로 제외하고 이메일·전화번호·주소 패턴을 제거한다.

루트 `.gitignore`의 5개 포괄 규칙은 볼트 전체를 scaffold 저장소에서 숨기는 용도여서 검색 제외로 해석하지 않는다. 그렇지 않으면 Journal·Roundup을 포함한 모든 지식이 검색에서 사라진다. 이 구현 결정을 [앱 경계의 M11 확장 범위](../02-Architecture-and-Boundary/guides/app-boundary.md#M11-확장-범위-2026-10-01)에 기록했으며 그 외 명시적 비공개 규칙과 하위 프로젝트의 규칙은 적용한다.

### 3. Tavily와 창작 계약

사용자가 제공한 Tavily 키로 실제 검색을 연결했다. 기존 `requests`로 Search API를 직접 호출하므로 SDK 설치는 필요 없으며, 키는 로컬 비공개 설정 파일에만 저장했다. 공식 요청·응답 규격은 [Tavily Search 문서](https://docs.tavily.com/documentation/api-reference/endpoint/search)를 확인했고 basic 검색·결과 4개·원문 전체 수집 없이 제한된 타임아웃을 사용한다.

창작은 어댑터에 엔진이 명시적으로 `evidence_mode=creative`를 넘기는 경우에만 빈 `claim_map`을 허용한다. 사실 답변의 인용 필수 계약은 유지하며, 창작은 「지어낸 이야기인데요,」 표시·실존 인물 관련 금칙어·숫자·라틴 고유명사·길이·종결 형태를 검사한다. 한글 실존 인물을 규칙만으로 모두 판별하거나 문장의 의미를 완전히 검증할 수는 없으므로 REVIEW에서 진행자가 확인한다.

### 4. 콘솔과 승인

질문란 아래 답변 근거 선택과 볼트 색인 갱신 버튼을 넣었다. 결과에 경로 배지와 출처를 보여 주며 볼트·웹·창작은 LIVE 모드에서도 REVIEW로 보류한다. 다음 질문을 시작하면 이전 초안·승인 대기·음성 요청을 비워 이전 답을 새 질문의 답으로 승인하지 않도록 했다.

승인된 문장만 기존 재생기로 전달하며 Motiv Mix 장치·출력 스트림 코드는 바꾸지 않았다. 콘솔을 재시작해 새 UI를 확인한 뒤 「대기 발화 승인 → 소리」를 눌러 진행자가 실제 음성을 확인할 수 있다. 개발 과정에서 자동 음성 재생은 하지 않았다.

## 🐛 문제 해결 로그

- **큰 JSON 색인**: 전사 자료까지 포함하면 대형 JSON을 매번 읽어야 했다. SQLite FTS5로 바꾸어 검색 속도와 메모리 사용을 개선했다. Windows에서는 SQLite context manager가 연결을 닫지 않아 파일 교체가 실패하므로 명시적으로 연결을 닫은 뒤 원자적으로 교체한다.
- **창작 계약 충돌**: 기존 어댑터가 모든 문장의 인용을 강제해 창작이 생성 단계에서 거절됐다. 명시적 creative 호출에만 빈 인용 배열을 허용하고 게이트에서 별도 창작 정책을 검사한다.
- **인용 출처 불일치**: 경로와 인용을 근거 풀 전체에서 따로 검사하면 서로 다른 출처를 붙일 수 있었다. 같은 경로의 원문 안에서 인용을 찾도록 강화했다. 인용은 짧은 연속 구절을 그대로 복사하도록 프롬프트를 수정했다.
- **파트 제목 정규화**: ① 파서는 제목에서 번호·시간을 제거한다. 원문 헤딩과 정규화 제목을 그대로 비교하면 실제 파트 본문을 못 찾으므로 ①의 헤딩 파서를 재사용한 정확 일치로 수정했다. 표의 원형 숫자·위키링크 별칭·2칸 표도 함께 처리했다.
- **이전 파트 근거 잔존**: 새 파트가 미정일 때 이전 컨텍스트를 제거한다. 질문별 근거 fingerprint와 승인 대기 무효화로 이전 질문의 출처와 발화가 다음 질문으로 흐르지 않도록 했다.
- **PowerShell 문자 인코딩**: 초기 임시 스크립트의 기본 ASCII 파이프가 한국어를 손상시켰다. UTF-8 파이프로 수정하고 Journal 원문을 대조했으며 실제 한국어 질문 4경로 테스트를 다시 실행했다.

## 💡 Daily Retrospective

### What went well

기존 파일 계약·재생기를 재사용해 새 경로를 연결했고 사실 답변의 안전 게이트를 유지했다. 실제 LLM에서 인용이 불일치한 웹 문장을 게이트가 제외하는 것을 확인했으며, 코드 변경과 검증 결과는 위 표와 [M11 회귀 테스트](../07-CoMC-Engine-POC/tests/test_evidence_lanes.py)로 추적할 수 있다.

### What could be improved

프롬프트만으로 원문 인용을 항상 정확히 복사하게 하지는 못한다. 게이트가 틀린 인용을 차단하므로 통과한 문장으로 답하되, 실제 방송에서 자주 부분 통과가 생기는지 관찰하고 그 결과로 다음 보완을 판단한다.

### Insights

근거 종류를 넓히는 일은 검색기 추가와 동시에 계약을 바꾸는 작업이다. 창작의 빈 인용 배열을 사실 답변에 허용하지 않고, 과거 기록의 존재를 오늘 방송의 완료 상태로 바꾸지 않는 분리가 필요했다. 이 판단의 근거는 창작 어댑터 실패와 파트 전환 회귀 검증이다.

### Tomorrow's focus

사용자 순서에 따라 다음 개발은 시청자 이름 기억·참여 기록이다. 이후 Persona를 추가하고, Motiv Mix는 다음 라이브 관찰 뒤 수정 여부를 결정한다. → [[Journal/2026-10-01#CoMC 개발 순서와 Motiv Mix 재검증 (구술 원문)|사용자 원문]]
