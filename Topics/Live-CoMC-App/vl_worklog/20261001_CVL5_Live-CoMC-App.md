## 세션 개요

기존 CVL5 사고 손질 중 퀵 버튼 전송 옵션과 같은 발화 반복 억제를 구현했다. 요청 범위는 [CVL5 작업의 체크리스트](../../../../../AI/Tasks/items/Live-CoMC%20CVL5%20실전%20사고%20손질.md#체크리스트)에 정리되어 있으며, Motiv Mix·오버레이 변경은 이번에 수행하지 않았다.

> 퀵 버튼이 즉시 전송 → 「질문란에 채운 뒤 Enter」 옵션

## 🎯 오늘의 학습 목표

- [x] 질문을 먼저 편집할 수 있는 기본 동작과 기존 즉시 전송 옵션을 제공한다.
- [x] 선택 유지와 한글 입력·줄바꿈·실패 시 입력 보존을 확인한다.
- [ ] 실제 콘솔 재시작 후 진행자 운영 확인.

## 📚 진행 내용

[comc_console.py](../09-Desktop-Shell-and-Overlay/examples/engine/comc_console.py)의 질문 카드에 전송 방식 선택을 추가했다. 기본은 질문란을 채우고 커서를 이동하는 방식이며, Enter 또는 보내기로 현재 편집한 질문과 선택한 근거 레인을 전송한다. 즉시 전송 선택은 같은 브라우저 주소의 로컬 저장소에 유지하며 저장소 접근 실패에도 콘솔은 동작한다.

전송 중 중복 요청을 막고, 서버 거절·연결 오류에는 질문을 보존한다. 전송 중 사용자가 다른 초안을 입력했으면 성공해도 그 초안을 지우지 않는다. 한글 조합 중 Enter는 무시하고 Shift+Enter 줄바꿈을 유지했다. → [운영 방법](../10-Live-Rehearsal-Capstone/guides/operator-guide.md#퀵-버튼-전송-방식-cvl5--2026-10-01)

## 🐛 문제 해결 로그

기존 quick 함수는 질문란을 채운 직후 ask를 호출해 편집 기회가 없었다. 전송 방식에 따라 호출을 나누고, 기존 ask의 요청 전 입력 삭제도 성공 응답 이후로 옮겨 실패 시 질문 손실을 방지했다.

## 📊 DoD 체크리스트

- [x] 기본 채우기 모드에서 API 호출 없이 입력란에 질문과 커서 표시.
- [x] 수정 후 Enter 전송 및 Shift+Enter 줄바꿈.
- [x] 한글 조합 중 Enter 전송 방지.
- [x] 즉시 전송과 양쪽 선택의 새로고침 후 유지.
- [x] 서버 거절 시 질문 유지와 오류 표시.
- [x] 저장소 접근 불가 시 기본 모드 동작.
- [x] 실제 Chromium에서 JS 오류 없음.
- [ ] 실제 방송 콘솔 운영 확인.

검증은 콘솔 HTML을 실제 Chromium에 띄우고 API 응답을 대체해 진행했다. 엔진·음성 재생을 실행한 리허설은 아니며, 서버의 기존 질문 처리 경로는 바꾸지 않았다.

## 💡 Daily Retrospective

퀵 버튼은 초안을 준비하는 도구가 되고 전송은 진행자가 결정할 수 있게 됐다. 다음 확인은 콘솔을 재시작해 기본 모드에서 날씨 질문을 편집·전송하는 것이며, 반복 발화 억제까지 구현했고 실제 음성 리허설은 남아 있다.

## 추가 개발 — 같은 발화 반복 억제

사용자 후속 요청으로 [spoken_player.py](../09-Desktop-Shell-and-Overlay/examples/engine/spoken_player.py)의 실제 재생 경계에 반복 억제를 추가했다. 직전 정상 재생 완료 후 30초 이내 동일 TTS 정규화 문구·Persona·정의·회차·음성 설정 요청이면 합성하지 않고 소비한다. 억제 시각으로 제한 시간을 연장하지 않으며 서로 다른 답변이 사이에 완료되면 재생을 허용한다. → [운영 규칙](../10-Live-Rehearsal-Capstone/guides/operator-guide.md#같은-발화-반복-억제-cvl5--2026-10-01)

중단·실패·음소거를 완료 기록으로 만들지 않아 재시도할 수 있고, 억제는 시청자 인사·Persona 재생 완료 기록을 추가하지 않는다. 다른 요청이 새로 게시됐으면 지우지 않으며 콘솔 로그에 억제 이유를 표시한다. 기록은 프로세스 메모리이고 재시작하면 초기화된다. 다국어 사전 합성 인사와 CLI 테스트 재생은 범위 밖이다.

[반복 억제 자동 검사](../07-CoMC-Engine-POC/tests/test_repeats.py)는 중복 합성 차단·공백 차이·30초 경계·억제 시각으로 연장 안 함·다른 답변 후 재생·중단 및 실패 재시도·Persona와 음성 설정 구분·새 요청 보존을 검증한다. 실제 출력 장치로 반복 요청하는 운영 리허설은 남아 있다.

반복 억제 신규 7건과 기존 68건을 함께 실행해 pytest 총 75건이 통과했다. 실제 음성은 자동 검사에서 재생하지 않았다.
