> ⏳ **초안 (09-12 밤).** 「실제 방송 투입 결과」절은 09-13 Live #27(3회차) 뒤에 채운다. 그 전까지 이 문서는 Topic 을 닫지 않는다.

## Topic 완료 요약

`Live-CoMC-App` 은 진행자의 라이브 방송(AI in Action Live, 매주 일요일 05:00 PST)에서 **Rundown 에 적힌 것만 근거로 말하는 보조 MC 앱**을 만드는 프로젝트형 Topic 이었다.
2026-08-02 로드맵부터 09-12 까지 **6주 · 13세션**에 M1~M10 을 돌았고, 그 사이 실제 방송 Live #22~#27 여섯 회차가 지나갔다.

결과를 한 줄로 적으면: **「근거 없으면 말하지 않는다」를 지키는 엔진과 그것을 방송 화면에 띄우는 경로는 완성됐고, 그 답을 목소리로 내는 경로와 목소리로 묻는 경로는 부품이 각각 검증된 채 아직 이어지지 않았다.**
LIVE 투입 판정은 그래서 갈래별로 다르다 — [go-nogo-decision.md](../10-Live-Rehearsal-Capstone/guides/go-nogo-decision.md): **A 화면 보조 GO(조건부) · B 음성 출력 NO-GO · C 음성 입력 NO-GO**.

## VibeLearn AI 방법론 평가 — 프로젝트형 Topic 으로서

### 잘 작동한 것

**파일 기반 계약.** M3 에서 스키마를 파이프라인 지점마다 1:1 로 못박은 것이 M5·M7 에서 그대로 코드가 됐다. 엔진의 ①~⑥ 이 전부 파일을 주고받으므로 사고가 나면 어느 파일이 틀렸는지 사람이 열어 보면 된다. M10 의 사고 1·2·3 전부 그렇게 잡았다. **AI 가 코드를 짜는 프로젝트일수록 계약이 파일로 남아 있어야 사람이 검증할 자리가 생긴다.**

**HITL 게이트.** 커버리지 미정 → 침묵, 게이트 실패 → 발화 안 함, `mode.json` 손상 → REVIEW 폴백. 세 겹이 전부 「모르면 안 한다」 쪽으로 떨어진다. 2회차 경로 1·2 가 이것을 실물로 확인했다. 방법론의 HITL 원칙이 앱의 안전 원칙과 같은 모양이었다는 것이 M3 회고의 발견이다(*"확인 질문을 던진다 = `block_generation` + `hitl_ask`"*).

**실측 하네스 모듈(M4~M6)을 따로 둔 것.** 이 세 모듈이 없었으면 「무료 TTS 가 가장 빠르다」「호출어는 STT 로 못 잡는다」「30분 0회가 3시간 0회가 아니다」를 몰랐다. 셋 다 설계로는 안 나오고 재야 나오는 것이다.

**의존성보다 실제 막힌 양을 따진 것.** M7 은 M6 미완 상태에서 시작했다 — 막힌 것은 16h 중 30분어치였다. 방송 일정이 있는 프로젝트에서 순서를 고지식하게 지켰으면 2주를 잃었을 것이다.

### 작동하지 않은 것

**회고가 다음 세션으로 넘어가지 않았다.** 같은 교훈을 세 번 다시 배웠다 — M4 *"고정 창 녹음이 결정론적"* → M4b 에서 실시간 스트림으로 다시 짬 / M7 *"사례가 하나면 규칙이 아니라 관찰"* → M8 에서 두 사례로 만든 규칙을 그대로 씀 / M8 *"안전해 보이는 0 을 정상으로 읽지 마라"* → M6c 에서 무음 0 을 마이크 고장으로 오진. **Daily Retrospective 는 쓰였지만 읽히지 않았다.** 개선 제안 2.

**모듈별 통과의 합이 통합의 통과가 아니었다.** M10 09-06 에 `--live` 가 샘플에 묶여 실제 회차로 한 번도 돈 적 없다는 것이 드러났고, 09-12 에 `spoken.json` 을 읽는 코드가 없다는 것이 드러났다. 둘 다 각 모듈 DoD 는 채운 상태였다. **DoD 가 「내 모듈 안에서」만 정의돼 있었다.** 개선 제안 3.

**시간을 적지 않았다.** 위 통계 참조. 개선 제안 1.

**로드맵의 확신 문장이 실측인지 추론인지 구분되지 않았다.** VoiceMeeter 가 "충돌할 수 있다"는 가정 위에 있었고 재 보니 없었다(M6b). 3회차 정의가 "마이크 전 구간"으로 적혀 있었는데 로드맵 원문은 "동일 조건"이었다(M10). 개선 제안 4.

## 주요 인사이트 (모듈 회고에서 추린 것)

1. **에러가 없는 실패가 가장 위험하다** (M4b) — 무음인데 peak 92%, 파서가 못 읽으면 `undefined`→HITL 이라 정상처럼 보임(M8), 캐시 미작동이 "느림"으로만 보임(M9). 이 Topic 의 사고 대부분이 예외 없이 그럴듯한 값을 냈다.
2. **차단을 검증할 때는 항상 A/B** (M4b→M8) — "막혔다"는 "안 막으면 뚫린다"와 함께 보여야 성립한다. 게이트 새 규칙 두 개가 처음엔 정상 문장도 떨어뜨렸다.
3. **호출어는 전사기로 풀 수 없다** (M5) — 신조어는 어느 STT 도 안정적으로 못 쓴다. 감지는 STT 이전에 끝나야 한다.
4. **"느리다"의 원인은 계산이 아니라 연결일 때가 많다** (M9) — `OpenAI()` 를 매번 새로 만든 것이 3초. 200ms 짜리 단계 세 개는 파이썬 기동 비용이었다.
5. **안전의 반대편은 무용함이다** (M10) — 틀린 말을 다 막고 나니 맞는 말도 못 하는 상태가 보였다. 「내용 없는 발화」는 M1~M9 어디에도 유형이 없었다.
6. **검증 대상을 넓히는 것 자체가 검증이었다** (M8) — 파서 결함 5종 중 코드를 읽어 찾은 것은 0건. 전부 새 실물을 넣었을 때 나왔다.
