## 어디서 나온 과제인가

M5 세션에서 진행자가 제안했다. 응답을 기다리는 동안 AI가 미리 준비한 말을 하게 하자는 것.
방향은 맞지만 **문구가 안전 설계와 충돌할 수 있다**는 점이 그때 함께 지적됐고,
트리거·중복 방지·문구 변형은 M6로 넘겼다. 이 문서가 그 몫이다.

## 요구가 오늘 바뀌었다

같은 세션에서 잰 [LLM 지연 스윕](../../05-STT-LLM-Harness/guides/llm-latency-sweep.md) 결과가
필러의 설계 요구를 바꿔 놓았다.

| | M5 시점 | 지연 튜닝 후 |
|---|---|---|
| 첫 발화까지 | ~17초 | ~4.5초 |
| 필러에 필요한 것 | 여러 마디 + 자연스러운 이어붙이기 | **짧은 한 마디 하나** |
| 실패 시 인상 | 어색한 독백 | 짧은 뜸 |

17초를 메우려면 필러가 사실상 **하나의 발화**가 되어야 했다. 그건 위험하다 —
내용이 있어야 하고, 내용이 있으면 근거가 필요하고, 근거가 없으면 M1의
"커버리지 없으면 침묵" 원칙을 필러가 어긴다.

4.5초는 다르다. **내용 없는 한 마디로 덮인다.** 필러가 정보를 전달할 필요가 없어졌고,
그래서 안전 원칙과 충돌하지 않는 설계가 가능해졌다.

→ 지연을 줄인 것이 필러를 쉽게 만들었다. **필러는 지연 대책이 아니라 지연 대책의 보완재다.**
   순서를 뒤집어 필러부터 만들었다면 훨씬 위험한 물건이 나왔을 것이다.

## 절대 제약 — 답변을 약속하지 않는다

파이프라인은 `⑥ LLM → ⑦ 안전 검증 게이트 → ⑧ 발화` 순서이고,
**⑦이 차단하는 것이 정상 동작**이다. 근거를 못 찾으면 말하지 않는 것이 이 시스템의 설계다.

그런데 필러는 ⑥이 끝나기 **전에** 나간다. 즉 필러를 말하는 시점에는
그 뒤에 답변이 나올지 침묵이 올지 아직 모른다.

```
"답변 드릴게요"  →  ⑦ 차단  →  침묵
                        지키지 못한 약속. 시청자에게는 고장으로 읽힌다
```

침묵 자체보다 **약속 뒤의 침묵**이 훨씬 나쁘다. 그냥 조용하면 "안 들었나 보다"지만,
답한다고 해놓고 조용하면 "망가졌다"가 된다.

**규칙: 확인은 약속하되 답변은 약속하지 않는다.**

| | 예시 | 왜 |
|---|---|---|
| ○ | "네, 확인해 볼게요" | 확인은 실제로 한다. 결과가 무엇이든 거짓이 아니다 |
| ○ | "잠깐 찾아볼게요" | 위와 같음 |
| ○ | "그 부분 한번 볼게요" | 위와 같음 |
| ✗ | "답변 드릴게요" | ⑦이 차단하면 거짓이 된다 |
| ✗ | "알려드릴게요" | 위와 같음 |
| ✗ | "좋은 질문이네요" | 내용 판단이다. 근거 없이 질문을 평가하고 있다 |

마지막 항목은 덜 분명하지만 같은 범주다. 질문을 아직 처리하지도 않은 상태에서
"좋은 질문"이라고 말하는 것은 근거 없는 발화다.

## 후속 문구도 함께 준비돼야 한다

필러는 짝이 있어야 완성된다. 차단됐을 때 아무 말도 하지 않으면
필러가 남긴 기대가 그대로 방치된다.

```
필러      "네, 확인해 볼게요"
  ↓
⑦ 통과   → 답변 발화
⑦ 차단   → "그건 근거를 못 찾았습니다"      ← 이 문구가 없으면 필러를 쓰면 안 된다
```

차단 문구는 **사과하지 않는다.** "죄송하지만"을 붙이면 차단이 실패처럼 들리는데,
차단은 이 시스템의 정상 동작이다. 담백하게 사실만 말한다.

## 트리거 조건

필러는 항상 나가면 안 된다. 빠른 응답에 필러가 겹치면 말이 두 번 나온다.

```
⑤ STT 완료
   ↓
   타이머 시작 ──── T_filler 경과 전에 ⑧ 준비됨 → 필러 생략
   ↓
   T_filler 경과 → 필러 발화 (⑥ 아직 진행 중)
```

`T_filler` 는 **1.2초**로 시작한다. 근거는 이렇다.

- 튜닝된 LLM 지연 중앙값이 2.6초(openai minimal)다
- 사람의 대화에서 1초를 넘는 침묵부터 "반응이 없다"로 느껴지기 시작한다
- 1.2초에 트리거하면 필러가 끝날 무렵 답변이 준비된다 — 이어붙이기가 자연스럽다
- 너무 이르면(0.5초) 빠른 응답에도 필러가 붙어 말이 겹친다

실측으로 조정할 값이다. M7에서 실제 6단계를 붙인 뒤 재야 한다.

## 중복 방지

필러가 반복되면 필러 자체가 소음이 된다.

1. **세션당 연속 반복 금지** — 같은 문구를 연달아 쓰지 않는다. 목록을 돌려 쓰되
   직전에 쓴 것은 제외한다
2. **한 질문에 하나** — 필러가 나간 뒤에는 그 질문이 끝날 때까지 다시 나가지 않는다.
   답변이 더 늦어져도 두 번째 필러를 얹지 않는다. 두 번 말하면 "기다리게 해서 미안"이라는
   신호가 되고, 그건 문제를 강조하는 꼴이다
3. **진행자 발화 중 금지** — 진행자가 말하는 중이면 필러를 내보내지 않는다.
   M4 에코 게이트와 같은 원칙 — AI 음성이 사람 음성 위에 겹치면 안 된다

## 어느 프로바이더로 합성하나

필러는 **미리 합성해 둔다.** 실시간 합성하면 필러 자체가 지연을 만든다 —
덮으려던 침묵에 TTS 지연이 더해지는 자기모순이 된다.

| | 필러 | 답변 |
|---|---|---|
| 문구 | 고정 (소수의 목록) | 매번 다름 |
| 합성 시점 | **방송 시작 전 미리** | 실시간 |
| 비용 | 사실상 0 (재사용) | 발화당 발생 |
| 프로바이더 | 답변과 **같아야 한다** | 실습 2 결과로 결정 |

프로바이더를 같게 두는 이유는 목소리 일관성이다. 필러와 답변의 목소리가 다르면
한 사람이 말하다 다른 사람이 이어받는 것처럼 들린다.

→ **서킷 브레이커가 강등되면 필러도 함께 강등돼야 한다.** 미리 합성한 필러를
프로바이더별로 각각 준비해 두고, 활성 프로바이더에 맞춰 고른다.
이 요구가 실습 4의 강등 로직에 추가로 걸린다 — M7 통합 시 확인할 것.

## 필러 목록 (초안)

`filler_catalog.json` 로 관리한다. 문구를 코드에 박지 않는 이유는
레지스트리 원칙과 같다 — 방송 중에 문구만 바꿔야 할 일이 생긴다.

| 상황 | 문구 | 비고 |
|---|---|---|
| 대기 | "네, 확인해 볼게요." | 기본 |
| 대기 | "잠깐 찾아볼게요." | |
| 대기 | "그 부분 한번 볼게요." | |
| 차단 | "그건 근거를 못 찾았습니다." | 사과 없음 |
| 차단 | "그건 오늘 다루는 내용에 없네요." | 커버리지 미정일 때 |
| 실패 | "지금은 답을 준비하지 못했습니다." | 전 프로바이더 실패 → HITL |

세 번째 범주(실패)는 ⑦ 차단과 다르다. 차단은 "근거가 없다"이고
실패는 "시스템이 답을 못 만들었다"이다. 시청자에게 같은 말로 뭉뚱그리면
근거 없는 질문과 시스템 장애가 구분되지 않는다.
