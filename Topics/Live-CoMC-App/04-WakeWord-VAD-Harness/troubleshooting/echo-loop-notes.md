# 에코 루프 차단 검증 — 실습 4

**모듈**: M4 - Wake Word / VAD 하네스
**측정일**: 2026-08-15
**프로브**: [`examples/echo_probe.py`](../examples/echo_probe.py)

---

## 결론 먼저

TTS 재생 중 `wake_gate`를 닫으면 wake 이벤트가 **0건**으로 차단된다. 게이트를 끈 동일 조건에서는 **5건**이 감지되므로, 0건은 "신호가 없어서"가 아니라 **게이트가 실제로 막은 결과**다.

| 조건 | 재생 구간 감지 | 억제 | 입력 peak |
|---|---:|---:|---:|
| `--gate off` (기준선) | **5건** (0.537~0.994) | 0 | 26.0% |
| `--gate on` | **0건** ✅ | **5건** (0.566~0.982) | 45.7% |

재생 종료(12.0s) + hangover 200ms 이후인 **14.18s·17.46s에서 감지가 재개**되어, 게이트가 닫힌 채 남지 않고 정상적으로 다시 열리는 것도 확인했다. Roadmap DoD의 "재생 종료 후 500ms 이내 재개방" 기준을 200ms 설계값으로 충족한다.

M3 계약(`session_state.schema.json`의 `wake_gate: open|closed`)이 실측으로 검증된 첫 사례다.

## 측정 설계 — 왜 기준선을 따로 재는가

게이트를 켠 상태에서 0건이 나오는 것만으로는 아무것도 증명되지 않는다. 신호 자체가 마이크에 안 닿아도 0건이기 때문이다. 그래서 프로브는 `--gate off/on` 두 번 측정을 강제하고, **off에서 0건이면 실험 무효**라고 경고를 띄운다.

```
--gate off : 게이트 없이 측정 → 감지가 나와야 에코 루프가 실재함이 증명된다
--gate on  : 같은 조건에 게이트 적용 → 0건이어야 차단 성공
```

실제로 이 경고 덕분에 초반 4회의 무효 측정을 "차단 성공"으로 잘못 기록하지 않았다.

## 양성 신호를 어떻게 만들었나

**애초 설계**: 스피커로 TTS를 재생 → 마이크가 그 소리를 주워 호출어로 오인.

**실측 결과**: Shure MV7은 **지향성 다이나믹 마이크**라 스피커 소리를 peak **3.7%**로만 받았다. 이 레벨에서 openWakeWord는 TTS 속 "alexa"를 감지하지 못했다(순수 TTS 파일 오프라인 채점은 0.643인데, 스피커→마이크 경로를 거치면 0에 가깝다).

**대안**: TTS 재생 중 **사용자가 마이크에 직접 "alexa"를 발화**해 wake 이벤트를 주입했다. 게이트의 정책은 "TTS가 말하는 동안에는 **출처와 무관하게** wake 이벤트를 받지 않는다"이므로, 이는 약한 음향 에코보다 **더 강한 조건의 게이트 검증**이다.

### 이 방법으로 검증되는 것과 안 되는 것

| | 검증됨 |
|---|---|
| ✅ | 게이트 정책 — 재생 구간 wake 이벤트 차단, 종료 후 재개방 |
| ❌ | 음향 에코 경로 자체의 재현 (이 볼륨·마이크 조합에서는 재현되지 않음) |

음향 경로 재현은 **낮 시간대 방송 볼륨으로 보완 측정**이 필요하다. 다만 아래 "부수 발견"에서 보듯, 재현이 안 된다는 사실 자체가 리스크 평가에 쓸모 있는 정보다.

## 부수 발견 — 물리적 1차 방어

MV7이 스피커 소리를 3.7%로만 받는다는 것은, **실사용 세팅에서 에코 루프 위험이 물리적으로 낮다**는 뜻이다. 지향성 마이크가 진행자 쪽을 향하고 스피커가 축 바깥에 있으면 소프트웨어 게이트가 없어도 에코가 잘 성립하지 않는다.

**단, 이것에 의존하면 안 된다.** 마이크 위치·스피커 볼륨·모니터링 방식이 바뀌면 조건이 무너진다. 게이트는 그대로 유지하고, 물리적 배치는 **2차 방어선**으로 취급한다.

## 디지털 루프백 시도 (미완)

음향 경로 대신 재생 신호를 100% 디지털로 캡처해 최악 조건을 만들려 했으나 둘 다 실패했다.

| 경로 | 결과 |
|---|---|
| Stereo Mix (Realtek) | 16kHz mono int16 으로 열리지 않음 |
| MOTIV Mix Virtual Output (Shure) | 스트림은 열리나 라우팅 비활성 — peak 1/32767 (무음) |

MOTIV Mix는 Shure 앱에서 라우팅을 켜야 동작하는 것으로 보인다. 다음 세션에서 재시도하면 볼륨과 무관한 최악 조건 회귀 테스트로 쓸 수 있다.

## 하네스 함정 4건 — 이 실습에서 실제로 겪은 것

측정값보다 이 목록이 재사용 가치가 크다. 넷 다 **조용히 잘못된 결과를 만드는** 종류다.

### 1. `sd.rec()` + `sd.play()` 동시 사용 → 녹음이 죽는다

sounddevice의 편의 함수 `play()`·`rec()`는 **모듈 레벨 스트림 하나를 공유**한다. `rec()` 진행 중 `play()`를 호출하면 녹음 스트림이 중단되고, 미리 할당된 버퍼는 0으로 남는다.

증상이 고약하다 — 에러가 없고, 녹음본에 **재생 시작 시점의 클릭 한 번만** 담긴다. peak는 30205(92%)로 찍혀서 "레벨 정상"으로 보이지만 0.5초 RMS는 전 구간 0이고 스펙트럼 중심이 4502Hz(>3kHz에 72.6%)인 순수 트랜지언트였다.

**해결**: 입력은 명시적 `sd.InputStream(callback=...)`, 출력만 `sd.play()`로 분리.

### 2. 입력 스트림 `read()` 지연 ~7초

`InputStream.read()` 루프로 실시간 채점했더니, TTS 파일 내 5.44s의 "alexa"가 벽시계 12.44s에 감지됐다. 약 7초의 입력 버퍼링이다.

**해결**: M4 실습 1·2에서 확립한 **고정 창 녹음 → 오프라인 채점** 패턴을 그대로 적용. 실시간성이 필요 없는 측정에서는 항상 이쪽이 결정론적이다.

### 3. 출력 장치 오픈 지연 4~9초 → 정렬 실패

`sd.play()` 호출 시각과 실제 소리가 나오는 시각이 최대 9초까지 벌어진다. 포락선 상호상관으로 정렬하려 했으나, 스피커→마이크 경로의 TTS가 너무 조용해 잡음 속에서 엉뚱한 지점을 잡았다(1.25s로 추정 → 실제 5.7s).

**해결**: 재생 앞에 **1kHz 비프 250ms + 간격 250ms**를 붙이고, 정규화 톤 검출로 비프 위치를 찾아 정렬. 좁은 대역 신호라 잡음 대비 5~14배로 뾰족하게 검출된다. 정렬 강도(SNR)가 3배 미만이면 경고를 띄운다.

### 4. 장치 인덱스가 계속 바뀐다 ← 가장 위험

같은 세션 안에서 Shure MV7의 인덱스가 **1 → 22 → 3 → 1**로 바뀌었다. USB 기기를 옮기거나 오디오 장치가 재열거될 때마다 밀린다. 번호를 하드코딩한 측정은 **조용히 다른 마이크로 측정**된다 — 실제로 "마이크를 스피커에 가까이 옮겼는데 레벨이 더 떨어지는" 모순으로 드러났고, 그때 device 1은 MV7이 아니라 노트북 내장 어레이였다.

또한 같은 이름의 장치라도 호스트 API 변형(WASAPI 등)은 16kHz를 못 열어 `PaErrorCode -9997`로 죽는다.

**해결**: `resolve_device()` — 이름 일부로 검색하고 `check_input_settings(samplerate=16000)`까지 통과한 첫 장치를 쓴다. **스트림을 여는 직전에** 해석한다(미리 잡아두면 그 사이 또 밀릴 수 있다).

```powershell
python echo_probe.py --mode echo --gate off --device "MV7" --output-device "Speaker (Realtek"
```

`wake_probe.py`에도 같은 해석기를 넣었다. 30분짜리 오탐 측정을 엉뚱한 마이크로 날리지 않기 위해서다.

## 재현 방법

```powershell
cd 04-WakeWord-VAD-Harness/examples
python echo_probe.py --make-tts                     # 호출어 포함 TTS 생성 (edge-tts)
python echo_probe.py --list-devices                 # 스피커 출력인지 반드시 확인
python echo_probe.py --mode echo --gate off --device "MV7" --output-device "Speaker (Realtek"
python echo_probe.py --mode echo --gate on  --device "MV7" --output-device "Speaker (Realtek"
```

`--gate off`에서 감지가 0건이면 그 회차는 **무효**다. 볼륨을 올리거나, TTS 재생 중 마이크에 직접 호출어를 발화해 양성 신호를 만든 뒤 다시 측정한다.
