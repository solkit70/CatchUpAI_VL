## 판정

**통과** — 3시간 환산 오탐 **0회**, 임계치(3시간당 2회 이하)를 여유 있게 충족한다.

| 지표 | 값 |
|---|---|
| 측정 길이 | 30분 (22,500 프레임 @ 80ms) |
| 임계값 0.5 초과 | **0회** |
| **3시간 환산** | **0회** |
| 최대 점수 | **0.1953** (임계값의 39%) |
| p99.9 / p99 / 중앙값 | 0.0007 / 0.0001 / 0.00000 |
| 평균 프레임 처리시간 | 6.39ms (80ms 프레임 대비 12배 여유) |

## 0회가 "운"이 아니라는 근거

오탐 0회는 그 자체로는 약한 증거다. 환경이 무음이었거나 점수가 임계값 바로 아래에서 아슬아슬했다면 조건이 조금만 변해도 무너진다. 그래서 두 가지를 함께 확인했다.

### 1. 측정 환경이 무음이 아니었다

| RMS 구간 | 프레임 비율 |
|---|---:|
| > 100 (매우 조용 이상) | 77.2% |
| > 300 (조용 이상) | 63.8% |
| > 1000 (보통 이상) | **31.7%** |
| > 3000 (활발) | 1.2% |

중앙값 RMS 585, p90 1801, 녹음 peak 75.7%. 프레임의 3분의 1에 보통 이상의 음향 활동이 있었으므로 "아무 소리도 없어서 0회"가 아니다.

### 2. 점수가 임계값 근처에도 오지 않았다

| 임계 | 프레임 수 |
|---|---:|
| ≥ 0.5 (실제 임계값) | 0 |
| ≥ 0.3 | 0 |
| ≥ 0.2 | 0 |
| ≥ 0.1 | 2 |
| ≥ 0.05 | 3 |

30분 전체에서 0.2를 넘은 프레임이 **하나도 없다.** 유일한 근접은 1138.6~1139.3s(약 19분) 한 곳으로 최대 0.1953이었고, 그 외에는 p99가 0.0001로 사실상 0이다. **임계값까지 2.6배의 여유**가 있어, 조건이 다소 나빠져도 곧바로 오탐으로 이어지지 않는다.

## 측정 조건과 실제 방송의 차이 ← 해석에 반드시 필요

실제 방송은 **매주 일요일 새벽 5시 ~ 8시**다. 오늘 측정(23시)과 비교하면 방향이 엇갈린다.

| 요인 | 오늘 측정 | 실제 방송 | 오탐 리스크 |
|---|---|---|---|
| 주변 소음 | 보통 (활동 31.7%) | 새벽이라 **더 조용** | 방송이 **유리** |
| 한국어 연속 발화 | 간헐적 | **3시간 연속 진행** | 방송이 **불리** ← 핵심 |
| 측정 길이 | 30분 → 6배 환산 | 3시간 실측 | 환산 오차 |

**오탐은 정적이 아니라 발화에서 난다.** 호출어와 비슷한 음절이 나올 때 터지므로, 조용한 새벽이라는 점은 위안이 되지 않는다. 오히려 3시간 내내 진행자가 말하는 방송은 오늘 측정보다 **발화 밀도가 훨씬 높다**. 따라서 이 리포트의 0회는 **필요조건을 통과한 것이지 방송 안전성을 확정한 것이 아니다.**

### 남은 검증 — 실제 방송 오디오 채점

환산 대신 실측으로 대체할 방법이 있다. 이 채널의 유튜브 아카이브([`Ingest/YouTube/`](../../../../YouTube/_status.md))에 **과거 AI in Action 라이브 방송 3시간 영상**이 보관되어 있다. 그 오디오를 받아 동일한 프로브로 오프라인 채점하면 진행자 목소리·말투·BGM·게스트가 모두 포함된 **실제 조건 3시간 실측 오탐 횟수**를 얻을 수 있다.

```powershell
python -m yt_dlp -f "bestaudio[abr<=70]/bestaudio" -x --audio-format wav `
  --postprocessor-args "-ar 16000 -ac 1" -o broadcast.wav "https://www.youtube.com/watch?v=VIDEO_ID"
python wake_probe.py --mode score-file --file broadcast.wav --models alexa
```

이것이 M4의 핵심 질문("wake word냐 핫키냐")에 대한 가장 강한 근거가 된다. 다음 세션 과제로 남긴다.

## 호출어 선택에 대한 별도 판단

측정된 `alexa`의 수치는 좋지만, **실사용 호출어로는 부적절할 수 있다.**

- 이 채널은 AI를 다루므로 방송 중 "알렉사"가 **자연스럽게 언급될 가능성**이 있다. 그 경우 오탐이 아니라 "정상 감지지만 의도하지 않은 호출"이 되어 측정치로는 잡히지 않는다.
- 원래 목표 호출어는 한국어 **"코엠씨"(Co-MC)** 로, 방송 중 우연히 나올 일이 거의 없어 이 조건에 훨씬 잘 맞는다.

즉 이번 측정으로 검증된 것은 **`alexa`라는 단어의 안전성이 아니라 openWakeWord 방식의 오탐 특성과 하네스**다. 실사용 호출어는 별도로 정해야 한다.

## 다음 단계 판단

| 선택지 | 판단 근거 | 현재 상태 |
|---|---|---|
| 한국어 커스텀 호출어 학습 | 오탐 여유 2.6배 + 실시간 여유 12배 → **투자 가치 있음** | 유력 |
| 핫키 전용 전환 | 오탐률이 높았다면 선택했을 대안 | 보류 (근거 부족) |

**현 시점 결론**: 오탐률은 커스텀 호출어 학습에 투자할 근거가 되기에 충분하다. 다만 최종 결정은 위의 **실제 방송 오디오 3시간 채점** 결과를 확인한 뒤 내린다.

## 재현 방법

```powershell
cd 04-WakeWord-VAD-Harness/examples
python wake_probe.py --mode record --seconds 1800 --device "MV7" --models alexa
```

측정 중에는 평소처럼 작업하되 호출어를 발화하지 않는다. 결과 해석 시 **감지 횟수만 보지 말고 최대 점수와 활동량(RMS 분포)을 함께 확인**해야 한다. 0회라도 최대 점수가 0.45면 위태로운 것이고, 활동량이 0이면 측정 자체가 무의미하다.
