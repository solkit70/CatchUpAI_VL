## 진행 내용

### 1. 기존 산출물 점검

M4의 기존 산출물은 이미 `README.md`, `concepts/role-taxonomy.md`, `guides/role-title-reading-guide.md`, `examples/resume-bullet-transformations.md`로 구성되어 있었다. 내용은 FDE와 Solutions Engineer, Applied AI Engineer, Solutions Architect, Consultant, ML Engineer 등의 차이를 설명하고 있었지만, 학습자가 직접 판별하고 적용하는 활동은 더 보강할 여지가 있었다.

### 2. README 보강

`04-Role-Taxonomy/README.md`에 daily learning 기준 재점검 기록을 추가했다. 또한 오늘의 학습 활동 3개를 넣어 학습자가 role map 작성, title trap 판별, 자기 경험 bullet 변환을 순서대로 수행할 수 있게 했다.

### 3. Role Taxonomy 보강

`concepts/role-taxonomy.md`에 학습자가 먼저 던져야 할 질문, 2축 지도 해석법, 직무 분류표 실습, 흔한 오해 바로잡기, 자기 위치 표시 질문을 추가했다. 핵심은 FDE를 "고객-facing 개발자"로 단순화하지 않고, customer discovery와 production ownership의 결합으로 이해하는 것이다.

### 4. 직무명 읽기 가이드 보강

`guides/role-title-reading-guide.md`에 판독 점수표와 mini practice를 추가했다. 이를 통해 학습자는 공고 문장을 읽고 FDE, FDE-adjacent, Solutions/Architect/ML 계열을 구분하는 연습을 할 수 있다.

### 5. Resume Bullet 변환 실습 보강

`examples/resume-bullet-transformations.md`에 worksheet, 배경별 추천 변환 방향, 자기 평가 질문을 추가했다. 학생, 주니어, 시니어 전환자, 비IT 배경자 모두 자신의 경험을 discovery-build-deploy-adoption 언어로 재구성할 수 있게 했다.

## 문제 해결 로그

- 문제: M4는 이미 완료 상태였지만, 사용자가 요청한 "같은 방식"은 daily learning plan 승인 후 재진행을 뜻한다.
- 해결: 기존 완료 산출물을 삭제하거나 새 구조로 갈아엎지 않고, 승인된 범위 안에서 학습 활동과 self-assessment 중심으로 보강했다.

## Daily Retrospective

### 오늘 배운 것

FDE를 구분하는 핵심은 title이 아니라 책임 범위다. 특히 미국 AI 기업 채용시장에서는 Applied AI Engineer, Solutions Architect, Field Engineer 같은 title이 FDE와 겹칠 수 있으므로, 공고 속 동사와 success metric을 읽는 능력이 중요하다.

### 잘한 점

기존 M4 산출물의 구조를 유지하면서 학습자가 직접 판단하고 적용할 수 있는 실습을 추가했다. 이 덕분에 M4가 단순 비교 문서에서 채용공고 판독과 이력서 변환 도구로 확장됐다.

### 개선할 점

M6에서 실제 미국 채용공고를 더 많이 수집하면 M4의 판독 점수표를 실제 데이터로 검증할 수 있다. 현재 M4는 개념과 실습 틀 중심이므로, 이후 공고 분석 결과를 다시 연결하면 더 강해진다.

### Tomorrow's Focus

- M5를 진행할 때 FDE 직무 구분 기준을 AI FDE 기술 스택과 연결한다.
- 특히 Applied AI Engineer와 FDE의 차이를 delivery lifecycle, eval, production integration 관점에서 다시 확인한다.
