# Senior FDE Resume Narrative

## 재작성 원칙

Senior FDE resume는 기술 목록보다 책임 범위를 보여줘야 한다. 좋은 bullet은 customer problem, technical action, production impact, reusable learning이 모두 들어간다.

## 기본 공식

```text
Scoped [ambiguous customer/workflow problem], built or integrated [technical system], deployed/operated it across [users/systems], improving [metric], and codified [reusable learning].
```

## 출신별 Before / After

### Software Engineer

**Before**

```text
Developed backend APIs and improved system performance for enterprise customers.
```

**After**

```text
Scoped recurring enterprise workflow bottlenecks with customer engineering teams, redesigned backend APIs and deployment flow, and improved production reliability while documenting reusable integration patterns for future customer rollouts.
```

```text
Built a RAG-based support workflow prototype on top of internal documents, added a 40-case eval set and latency/error logging, and used failure analysis to define production hardening requirements.
```

## Project Narrative Template

```markdown
### Project: [Name]

**Customer Problem**
[Who had what workflow problem? Why did it matter?]

**Ambiguity**
[What was unclear at the start? Scope, data, stakeholders, success metric, technical feasibility?]

**Technical Action**
[What did you design, build, integrate, deploy, or operate?]

**Production Impact**
[What changed in time, cost, reliability, adoption, quality, or risk?]

**Reusable Learning**
[What playbook, tool, pattern, architecture, or product feedback came out of it?]

**AI FDE Gap / Add-on**
[How would you extend or retrofit this project with LLM/RAG/agent/eval/observability?]
```

## Resume Quality Checklist

- [ ] Bullet starts with customer/workflow problem, not only technology.
- [ ] Direct ownership is clear: scoped, built, integrated, deployed, operated, measured.
- [ ] Production or adoption impact is visible.
- [ ] Stakeholder or customer-facing context is included.
- [ ] Reusable pattern or field feedback is included.
- [ ] AI/LLM readiness evidence is attached where relevant.
- [ ] Claims are specific enough for interview follow-up.
