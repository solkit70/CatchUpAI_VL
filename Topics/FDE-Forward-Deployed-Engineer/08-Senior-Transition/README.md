- SI, consultant, PM, software engineer, solutions architect 출신별 전환 전략을 만들 수 있다.

- 기존 경력의 강점을 버리지 않고 AI/LLM production pattern으로 보완할 수 있다.

## 핵심 요약

IT 시니어 전환자는 주니어와 출발점이 다르다. 주니어는 작은 프로젝트로 FDE형 신호를 새로 만들어야 하지만, 시니어는 이미 가진 delivery, 운영, 고객, stakeholder management 경험을 FDE 언어로 다시 포장해야 한다. 다만 기존 경험만으로 충분하지는 않다. M6 공고 기준으로 evals, LLM/agent implementation, AI observability, security boundary, reusable product feedback loop를 보강해야 한다.

## 전환 원칙

1. **경력명을 바꾸지 말고 책임의 끝을 바꿔 설명한다.** "SI 프로젝트 수행"보다 "ambiguous customer workflow를 production system으로 전환"이 FDE에 가깝다.
2. **AI gap을 인정하고 빠르게 보완한다.** seniority가 있어도 LLM/RAG/agent/eval 경험이 없으면 AI FDE에는 부족하다.
3. **고객 성과와 운영 책임을 전면에 둔다.** FDE는 구현량보다 production adoption, measurable workflow impact, field feedback이 중요하다.
4. **대표 프로젝트 3개를 FDE narrative로 재작성한다.** 모든 경력을 나열하지 말고 FDE 증거가 강한 사례를 깊게 보여준다.
