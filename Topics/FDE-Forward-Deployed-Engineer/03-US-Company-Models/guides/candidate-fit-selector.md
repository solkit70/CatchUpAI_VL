# FDE 지원자-fit 선택 가이드

## 사용 방법

아래 질문에 답하면서 자신이 어떤 FDE archetype에 가까운지 판단한다. 각 질문에서 가장 가까운 선택지를 고르고, 마지막에 점수가 높은 유형을 확인한다.

## 2. 결과 해석

### Palantir형 점수가 높다면

당신은 operational problem, high-stakes environment, data-driven decision workflow에 끌리는 유형이다. 준비는 data modeling, full-stack custom app, stakeholder communication, ambiguous problem scoping 중심으로 해야 한다.

**추천 포트폴리오**:
- 공급망 리스크 dashboard
- 공공 서비스 자원 배분 simulation
- 운영 데이터 기반 의사결정 app

### OpenAI형 점수가 높다면

당신은 frontier model을 실제 업무 시스템에 넣는 문제에 끌리는 유형이다. 준비는 LLM API, RAG, agent, eval, production full-stack deployment, security/GRC awareness 중심으로 해야 한다.

**추천 포트폴리오**:
- enterprise knowledge assistant with evals
- domain workflow copilot
- LLM-powered internal tool with rollout metrics

### Anthropic형 점수가 높다면

당신은 technical advisory, architecture, enterprise adoption journey에 강점이 있는 유형이다. 준비는 Claude/API architecture, eval design, safety/reliability framing, executive communication 중심으로 해야 한다.

**추천 포트폴리오**:
- Claude adoption architecture proposal
- enterprise eval framework design
- AI safety/reliability deployment playbook

### Scale형 점수가 높다면

당신은 data, infrastructure, agents, evals를 통해 AI application을 가능하게 하는 유형이다. 준비는 ETL, cloud, data warehouse, vector DB, agent evaluation, human-in-the-loop workflow 중심으로 해야 한다.

**추천 포트폴리오**:
- customer data ingestion + RAG pipeline
- agent evaluation dashboard
- multi-agent workflow with HITL review

### Cursor형 점수가 높다면

당신은 개발팀의 workflow와 productivity 문제를 AI로 푸는 유형이다. 준비는 developer tools, GitHub automation, CI/CD, code review agent, migration workflow, production reliability 중심으로 해야 한다.

**추천 포트폴리오**:
- PR review loop automation
- spec-to-implementation coding workflow
- incident-to-fix AI workflow

### Hebbia/Vertical형 점수가 높다면

당신은 특정 산업의 지식 workflow를 깊게 이해하고 AI platform을 붙이는 유형이다. 준비는 domain documents, data connectors, workflow automation, domain-specific eval, customer narrative 중심으로 해야 한다.

**추천 포트폴리오**:
- due diligence research assistant
- legal contract review workflow
- healthcare intake/workflow assistant

| 비IT 도메인 전문가 | FDE 직행보다 AI solutions consultant, domain specialist, implementation analyst부터 검토 |

## 4. 주의할 점

직무명만 보고 판단하면 안 된다. 같은 "Forward Deployed Engineer"라도 어떤 회사는 production coding이 핵심이고, 어떤 회사는 architecture/advisory가 핵심이며, 어떤 회사는 data infrastructure가 핵심이다. 공고에서 반드시 확인해야 할 항목은 다음이다.

- 직접 code를 쓰는가?
- 고객 현장에 얼마나 embed되는가?
- pre-sales인가 post-sales인가?
- 성공 지표가 adoption인가 revenue/deal support인가?
- product/research feedback loop가 있는가?
- travel/onsite 요구가 있는가?
- 요구 경력이 new grad인지 senior인지?

## 5. 가상 후보자 적용 예시

### 후보자 A: Backend SWE, 5년차

**배경**:
- B2B SaaS backend 개발 5년
- API integration, auth, billing, internal admin tool 경험
- LLM API로 internal support assistant prototype 제작 경험
- 고객 미팅 경험은 제한적

**질문지 결과**:
- Q1: B - OpenAI +2
- Q2: B - OpenAI +2
- Q3: B - OpenAI +2
- Q4: D - Cursor형은 신중히 검토
- Q5: A - OpenAI, Cursor, Hebbia 추천

**해석**:
OpenAI형 AI Lab FDE 또는 Hebbia 같은 Vertical Workflow FDE가 잘 맞는다. 다만 customer-facing discovery 경험이 약하므로 portfolio에서 고객 문제 정의, rollout plan, eval plan을 강하게 보여줘야 한다.

**추천 보완**:
- enterprise workflow discovery case study 작성
- RAG/agent project에 eval과 rollout metric 추가
- 고객 stakeholder와 협업한 경험을 resume bullet로 재구성

### 후보자 B: Data Engineer, 6년차

**배경**:
- Snowflake, Airflow, dbt, Spark 경험
- ML feature pipeline과 data quality monitoring 경험
- LLM app은 간단한 RAG demo 수준
- 금융권 데이터 프로젝트 경험

**질문지 결과**:
- Q1: D - Scale +2
- Q2: D - Scale +2
- Q3: D - Scale +2
- Q4: F - OpenAI/Cursor/Scale형 model behavior/eval 문제는 신중히 검토
- Q5: B - Scale, Palantir 추천

**해석**:
Scale형 Data·Agent Infrastructure FDE 또는 Palantir형 Operational Platform FDE가 가장 잘 맞는다. AI application frontend보다 data integration, eval pipeline, customer data boundary를 강조하는 포트폴리오가 유리하다.

**추천 보완**:
- agent evaluation dashboard project
- customer data ingestion + RAG pipeline
- data permission/audit/security boundary 설계 문서

### 후보자 C: 전략 컨설턴트, 비전공자

**배경**:
- 제조/공급망 전략 프로젝트 7년
- executive communication과 workflow analysis 강점
- 코딩 경험은 거의 없음
- 최근 AI transformation 프로젝트 PMO 경험

**질문지 결과**:
- Q1: A - Palantir +2
- Q2: C - Anthropic +2
- Q3: C - Anthropic +2
- Q4: C - Scale형은 신중히 검토
- Q5: D - Palantir, Anthropic, Scale with technical upskilling

**해석**:
순수 FDE 직행보다는 Deployment Strategist, Applied AI Architect adjacent, AI Solution Consultant, Domain Specialist 경로가 현실적이다. FDE를 목표로 한다면 API, data, LLM/RAG, prototype literacy를 최소한 확보해야 한다.

**추천 보완**:
- no-code/low-code 수준을 넘어 간단한 API/RAG prototype 제작
- 제조 supply chain AI workflow case study 작성
- technical counterpart와 협업한 산출물 정리
