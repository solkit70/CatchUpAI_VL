# Candidate Fit Selector

## Purpose

This guide helps candidates choose which FDE archetype to target. It is not a personality test. It is a practical filter for matching your experience to the company model where your evidence will be most credible.

## Step 1: Score Yourself

Rate each item from 1 to 5.

| Area | Question | Score |
|---|---|---|
| Software Engineering | Can you build and debug production-like software systems? | 1-5 |
| Data/Backend | Can you work with APIs, databases, pipelines, and integration boundaries? | 1-5 |
| AI Workflow | Can you design RAG, agent, eval, or LLM application workflows? | 1-5 |
| Customer Facing | Can you work directly with customers or stakeholders under ambiguity? | 1-5 |
| Developer Workflow | Do you understand how software teams build, test, review, and ship code? | 1-5 |
| Domain Expertise | Do you understand a complex industry workflow deeply? | 1-5 |
| Regulated Context | Can you reason about security, privacy, compliance, and governance? | 1-5 |

## Step 2: Match to Archetype

| Strongest Scores | Likely Fit |
|---|---|
| Software Engineering + AI Workflow + Customer Facing | AI Lab FDE |
| Developer Workflow + Software Engineering + Customer Facing | Developer Tool FDE |
| Data/Backend + Regulated Context + Customer Facing | Data/Agent Infrastructure FDE |
| Domain Expertise + AI Workflow + Customer Facing | Vertical AI FDE or FDE-adjacent role |

## Step 3: Identify the Gap

| Target Role | Common Gap | How to Close It |
|---|---|---|
| AI Lab FDE | Not enough enterprise deployment evidence | Build a portfolio with API integration, evals, and rollout plan |
| Developer Tool FDE | Not enough developer workflow credibility | Show AI coding workflow analysis or internal tool adoption project |
| Data/Agent Infra FDE | Not enough data/integration depth | Build connector, ETL, or agent workflow project |
| Vertical AI FDE | Not enough hands-on technical artifact | Build domain RAG or review copilot prototype |

## Step 4: Choose Portfolio Evidence

| Candidate Background | Best Portfolio Project |
|---|---|
| Junior engineer | RAG assistant with eval and demo script |
| Backend engineer | Enterprise integration workflow with auth and observability |
| Data engineer | Ticket or document triage agent with labeled eval set |
| Consultant | Domain workflow automation with rollout and metric plan |
| Non-IT domain expert | Domain-specific review copilot with technical minimum |

## Step 5: Build the Application Narrative

Use this structure:

```text
My strongest fit is [archetype] because my background combines [technical evidence], [customer/domain evidence], and [deployment/adoption evidence]. My main gap is [gap], and I am closing it through [portfolio project or learning evidence].
```

## Example

```text
My strongest fit is vertical AI FDE because my background combines financial operations workflow knowledge, stakeholder-facing project work, and an AI review copilot prototype. My main gap is deeper backend integration, and I am closing it by adding API-based document ingestion, eval logging, and a rollout plan to the project.
```

## Final Decision Rule

Apply first where your evidence is strongest, not where the title sounds most attractive. FDE hiring is evidence-driven. The company must believe you can be trusted in front of a real customer with an ambiguous technical problem.
