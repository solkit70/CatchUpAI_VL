# Technical Stack Map for AI FDE

## Stack Layers

| Layer | What the FDE Needs to Understand | Depth Required |
|---|---|---|
| Frontend | Demo UI, workflow UX, user feedback surfaces | Basic to intermediate |
| Backend | APIs, auth, services, business logic | Intermediate to strong |
| Data | schemas, SQL, documents, retrieval, quality issues | Intermediate |
| Cloud/Deployment | environments, secrets, logs, reliability basics | Basic to intermediate |
| LLM | prompts, structured output, tool use, RAG, agents | Intermediate |
| Evals | golden sets, scoring, regression, human review | Intermediate to strong |
| Security | access control, PII, audit, data boundary | Intermediate |
| Observability | logs, traces, error cases, model behavior review | Intermediate |
| Customer Workflow | stakeholder, adoption, rollout, training | Strong |

## Junior Track Minimum

Junior candidates should focus on:

- one backend framework
- basic API integration
- SQL and document ingestion
- one RAG project
- simple eval set
- clear README and demo script
- customer scenario framing

The goal is not mastery. The goal is credible evidence that the candidate can build and reason about a customer workflow.

## Senior IT Track Minimum

Senior IT candidates should focus on:

- translating existing delivery experience into FDE language
- adding AI/LLM workflow patterns
- showing system design and rollout judgment
- demonstrating eval, security, and observability thinking
- building one AI prototype that connects to an enterprise-style workflow

## Non-IT Track Minimum

Non-IT candidates should focus on:

- API and data basics
- domain workflow mapping
- AI assistant or review copilot prototype
- technical vocabulary for working with engineers
- security and compliance awareness
- FDE-adjacent roles first if technical depth is still developing

## Technology Is Not the Whole Role

The FDE stack is not only technical. It includes customer problem framing, stakeholder alignment, adoption metrics, and product feedback. A technically strong candidate who cannot work with ambiguous customers is incomplete. A strong domain expert who cannot discuss data, APIs, and evals is also incomplete.

## Priority Order

For most AI FDE candidates, the learning order should be:

1. Customer workflow and use case framing
2. API/backend basics
3. Data and retrieval
4. LLM application patterns
5. Evals and failure analysis
6. Security and permissions
7. Observability and rollout
8. Portfolio packaging
