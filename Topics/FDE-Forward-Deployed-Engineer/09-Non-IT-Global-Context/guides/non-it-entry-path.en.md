# Non-IT Entry Path to FDE

## Core Judgment

Direct entry into FDE from a non-IT background is possible but uncommon. It becomes realistic only when domain expertise, customer-facing experience, AI workflow understanding, and minimum technical implementation ability come together.

Domain knowledge alone is not enough. FDE work requires translating workflows into software, data, model behavior, integration, rollout, and measurable adoption.

## Direct Entry vs Adjacent Path

| Factor | Helps Direct Entry | Makes Direct Entry Difficult |
|---|---|---|
| Domain Expertise | Deep knowledge of finance, healthcare, manufacturing, public sector | General business experience only |
| Customer Communication | Can align business, IT, and leadership stakeholders | Has not owned implementation outcomes |
| Technical Minimum | Understands API, data, workflow, and AI basics | Only uses no-code tools without system understanding |
| Evidence | Built a prototype or workflow automation | Has only learning history |
| Target Role | Vertical AI or domain-heavy FDE | Core infrastructure or developer tool FDE |

## Realistic Bridge Roles

| Path | Good Fit | FDE Connection |
|---|---|---|
| Domain Solution Specialist | Industry experts | Converts domain workflow into solution requirements |
| AI Consultant | Strategy or operations background | Builds discovery, scoping, adoption experience |
| Implementation Analyst | ERP/CRM/data operations | Learns rollout, integration, and handoff |
| GTM Engineer | RevOps, pre-sales, growth | Builds technical demos and customer narrative |
| Solutions Engineer Associate | Technical learner | Closest bridge to FDE-style work |
| Vertical AI Product Specialist | Domain PM or analyst | Converts field signal into product direction |

## Technical Minimum

Non-IT candidates should learn:

- REST API basics
- JSON and authentication concepts
- SQL and data schema basics
- prompt, RAG, tool calling, and eval concepts
- simple Python or JavaScript automation
- security, permissions, audit, and compliance basics
- rollout and adoption metrics

## Application Strategy

Do not market yourself only as "interested in AI." Show how your domain workflow can become an AI system. For example:

- insurance claim triage assistant
- compliance review copilot
- manufacturing maintenance report summarizer
- HR policy Q&A assistant
- legal document risk checklist

The goal is to prove that you can translate domain problems into technical workflows.
