# 12-Month Plan for Non-IT Backgrounds

## Goal

This plan does not assume direct FDE entry in 12 months. The goal is to build enough technical minimum, portfolio evidence, and AI delivery language to apply for FDE-adjacent roles and move toward FDE over time.

## Monthly Plan

| Month | Focus | Output |
|---|---|---|
| 1 | Understand FDE and adjacent roles | Target role map |
| 2 | API, JSON, SQL, and basic scripting | Small API or data script |
| 3 | Domain workflow inventory | 10 workflow problem list |
| 4 | AI workflow basics | Simple Q&A or assistant prototype |
| 5 | Data and retrieval | Domain document RAG demo |
| 6 | First portfolio project | Project README and demo |
| 7 | Adoption thinking | Rollout plan and metric |
| 8 | Security and compliance | Risk memo |
| 9 | Integration thinking | Architecture sketch |
| 10 | Second portfolio project | Workflow automation or review copilot |
| 11 | Career packaging | Resume bullets and LinkedIn summary |
| 12 | Applications and interview prep | Target company list and mock answers |

## Success Criteria

| Period | Success Signal |
|---|---|
| Months 1-3 | Can explain FDE, AX, and adjacent roles without confusing them |
| Months 4-6 | Has one working AI prototype tied to a domain workflow |
| Months 7-9 | Can discuss security, adoption, integration, and rollout |
| Months 10-12 | Has two portfolio artifacts and can apply to FDE-adjacent roles |

## Recommended Portfolio Types

- domain RAG assistant
- workflow triage agent
- review copilot
- operations dashboard

## Main Warning

Do not wait until you "become a developer" before doing anything. Also do not assume domain expertise alone is enough. The practical middle path is to build small technical artifacts around real domain workflows.
