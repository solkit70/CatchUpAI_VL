# 비IT 배경자 12개월 준비 계획

## 계획의 기준

이 계획은 비IT 배경자가 바로 FDE가 되는 것을 목표로 하지 않는다. 12개월 동안 domain expertise를 AI delivery evidence로 바꾸고, FDE 또는 FDE 인접 직무에 지원 가능한 포트폴리오를 만드는 것이 목표다. 핵심은 기술 학습량을 늘리는 것이 아니라 고객 문제를 technical artifact로 번역하는 반복을 만드는 것이다.

## 12개월 로드맵

| 기간 | 목표 | 학습/실습 | 산출물 |
|---|---|---|---|
| 1개월차 | FDE와 인접 직무 이해 | FDE, Solutions Engineer, AI Consultant, Implementation Analyst 비교 | 개인 target role map |
| 2개월차 | 기술 minimum 확보 | API, HTTP, JSON, SQL, Python/JS 기초 | API 호출 mini notebook 또는 script |
| 3개월차 | 도메인 문제 inventory | 현재/과거 업무에서 반복 workflow 10개 추출 | domain workflow problem list |
| 4개월차 | AI workflow 기초 | prompt, RAG, tool calling, eval 개념 학습 | 업무 Q&A bot prototype |
| 5개월차 | 데이터 연결 | CSV/DB/문서 기반 retrieval, data cleaning | domain document RAG demo |
| 6개월차 | 첫 portfolio 완성 | 문제, 사용자, 데이터, demo, metric 정리 | Portfolio Project 1 README |
| 7개월차 | adoption 관점 강화 | 사용자 교육, KPI, feedback loop 설계 | rollout plan + adoption metric |
| 8개월차 | 보안/권한 이해 | PII, role-based access, audit, compliance 기초 | risk and security memo |
| 9개월차 | integration 감각 확보 | CRM/ERP/ticketing/email/calendar 중 하나 연동 설계 | integration architecture sketch |
| 10개월차 | 두 번째 portfolio | 더 복잡한 workflow automation 또는 review assistant | Portfolio Project 2 demo |
| 11개월차 | career packaging | resume bullet, LinkedIn summary, case narrative 작성 | FDE-adjacent application package |
| 12개월차 | 지원/면접 루프 | customer scenario interview, portfolio demo 연습 | mock interview answers + target company list |

## 월별 성공 기준

| 단계 | 성공 기준 |
|---|---|
| 1-3개월 | FDE와 AX를 혼동하지 않고, 자신의 도메인 문제가 어떤 AI workflow로 바뀔 수 있는지 설명한다 |
| 4-6개월 | 작동하는 작은 AI prototype 1개를 만들고 README에 customer problem과 success metric을 쓴다 |
| 7-9개월 | prototype을 실제 조직 도입 관점으로 확장해 security, adoption, integration risk를 설명한다 |
| 10-12개월 | 두 번째 portfolio와 지원 자료를 완성하고 FDE 인접 직무 20개를 분석해 지원한다 |

## 추천 포트폴리오 유형

| 유형 | 예시 | 보여주는 역량 |
|---|---|---|
| Domain RAG Assistant | 사내 정책, 계약서, 규정 문서 검색/질의 | domain knowledge, retrieval, answer quality |
| Workflow Triage Agent | 고객 문의, claim, ticket, 요청서를 분류하고 다음 action 추천 | process understanding, automation, eval |
| Review Copilot | 보고서, 계약, 심사 문서의 누락/위험 항목 체크 | judgment support, checklist, human-in-the-loop |
| Operations Dashboard | AI 사용 결과, 처리 시간, error case를 시각화 | adoption metric, observability, stakeholder reporting |

## 주간 루틴

| 요일/블록 | 활동 | 산출 기준 |
|---|---|---|
| 2시간 | 기술 minimum 학습 | 작은 script 또는 notebook |
| 1시간 | 도메인 문제 정리 | workflow map, pain point, stakeholder |
| 1시간 | AI prototype 개선 | demo 기능 1개 추가 |
| 1시간 | 문서화/지원 자료 | README, resume bullet, case note |

## 피해야 할 패턴

비IT 배경자는 "개발자가 되기 전에는 아무것도 지원할 수 없다"는 식으로 접근하면 속도가 느려진다. 반대로 "도메인만 알면 FDE가 가능하다"는 판단도 위험하다. 현실적인 중간 지점은 domain expertise를 살리되, 작은 prototype과 technical conversation 능력을 빠르게 확보하는 것이다.

또한 한국 AX나 일본 DX to AX 문맥에서 일한 경험을 미국 FDE로 그대로 번역하면 안 된다. 미국 채용시장에서는 role outcome, customer deployment, technical artifact, measurable adoption을 더 직접적으로 요구한다. 따라서 프로젝트 명칭보다 "내가 어떤 고객 문제를 어떤 시스템 변화로 연결했는가"를 중심으로 서술해야 한다.
