# Junior FDE Skill Checklist

## Skill Areas

| Area | Beginner | Intermediate | Job-Ready Signal |
|---|---|---|---|
| Coding | Can write basic scripts | Can build simple web/API apps | Can build and explain a working workflow demo |
| Backend/API | Understands HTTP and JSON | Can call external APIs and handle auth basics | Can design integration boundaries |
| Data | Can work with CSV and basic SQL | Can clean and query structured data | Can explain data quality and schema trade-offs |
| AI Apps | Uses LLM tools | Builds RAG or structured-output apps | Adds evals and failure analysis |
| Cloud/Deployment | Runs locally | Deploys simple app | Understands logs, secrets, and environment variables |
| Communication | Explains what was built | Explains user problem and trade-offs | Leads a customer-style demo |
| Domain | Has general interest | Studies one workflow deeply | Maps domain workflow to AI system design |

## Minimum Job-Ready Bar

A junior candidate does not need senior-level system design, but should be able to:

- build a small AI workflow
- explain the customer problem
- show architecture and data flow
- define eval criteria
- discuss security and privacy basics
- run a 5-minute demo
- write clear README documentation

## Self-Assessment Questions

- Can I explain why the project matters to a real user?
- Can I show how data enters and leaves the system?
- Can I explain what can go wrong?
- Can I measure answer quality or routing accuracy?
- Can I explain how the tool would be piloted with users?

## Common Junior Gaps

| Gap | Fix |
|---|---|
| Project feels like a toy | Add a concrete customer scenario and success metric |
| No evals | Create a small golden dataset and scoring rubric |
| Weak README | Add workflow map, architecture, demo script, risks |
| No customer context | Interview a user or use a realistic domain scenario |
| No deployment story | Add rollout plan and monitoring notes |
