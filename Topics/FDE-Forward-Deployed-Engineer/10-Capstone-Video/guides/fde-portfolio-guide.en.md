# FDE Portfolio Guide

## Core Principle

An FDE portfolio is not just proof that you can write code. It is proof that you can understand a customer problem, design a technical workflow, handle constraints, evaluate quality, plan rollout, and explain adoption.

## Required Portfolio Elements

| Element | Question | Output |
|---|---|---|
| Customer Scenario | Who has the problem and why does it matter? | Case brief |
| Workflow Map | What is the current process and bottleneck? | Flow diagram |
| Architecture | What systems, data, model, and APIs connect? | Architecture diagram |
| Prototype | What can the user actually do? | Demo app or notebook |
| Eval | How is quality measured? | Eval set and rubric |
| Security Boundary | What data and permissions must be protected? | Risk checklist |
| Rollout Plan | How does the pilot become adoption? | 30/60/90 plan |
| Success Metric | How is impact measured? | Adoption or business metric |

## README Template

```markdown
# Project Name

## Customer Problem
Describe the user, workflow, pain point, and business outcome.

## Current Workflow
Show the current process and where it fails.

## Proposed AI Workflow
Explain what the AI system does and what stays human-controlled.

## Architecture
Show frontend, backend, data, LLM, eval, observability, and auth boundaries.

## Demo Script
Describe a 3-5 minute demo flow.

## Evaluation
Define golden examples, scoring rubric, failure modes, and human review.

## Rollout and Adoption
Define pilot users, training, success metrics, and feedback loops.

## Risks and Trade-offs
Discuss security, latency, cost, hallucination, data quality, and change management.
```

## Portfolio Evaluation Checklist

- [ ] Starts from a real customer workflow.
- [ ] Includes architecture and data flow.
- [ ] Includes evals and failure modes.
- [ ] Includes security and permission boundaries.
- [ ] Includes rollout and adoption metrics.
- [ ] Can be demoed in five minutes.
- [ ] Can produce strong resume bullets.
