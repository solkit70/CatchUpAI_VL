# FDE Interview Prep

## Final Candidate Package

| Document | Purpose |
|---|---|
| One-page FDE Narrative | Explains why the candidate fits FDE |
| Portfolio README | Shows the main project as customer-facing evidence |
| Architecture Diagram | Shows technical reasoning and system boundaries |
| Demo Script | Prepares a concise project walkthrough |
| Resume Bullets | Converts experience into FDE language |
| Interview Bank | Prepares customer, technical, and behavioral answers |
| Target Company Matrix | Matches candidate evidence to company archetype |

## Interview Loop

| Stage | What It Tests |
|---|---|
| Recruiter Screen | Motivation, communication, location, basic fit |
| Hiring Manager | ownership, ambiguity, customer judgment |
| Technical Screen | coding, APIs, data, AI workflow debugging |
| System Design | architecture, evals, security, trade-offs |
| Customer Scenario | discovery, scoping, stakeholder thinking |
| Portfolio Demo | evidence and communication |
| Executive/Bar Raiser | business impact and product feedback |

## Customer Scenario Framework

1. Clarify the customer outcome.
2. Map the existing workflow.
3. Identify data, users, and constraints.
4. Propose a narrow pilot.
5. Define evals and success metrics.
6. Explain rollout and handoff.
7. Identify reusable product feedback.

## 60-Second Introduction

```text
I am a [background] who works at the intersection of [customer/domain] and [technical delivery]. In my recent work, I focused on [customer problem] and built or led [solution] that produced [impact]. I am interested in FDE roles because I like turning ambiguous customer workflows into working systems and feeding those lessons back into product.
```

## Final Checklist

- [ ] I can explain why FDE fits my background.
- [ ] I can demo one project in five minutes.
- [ ] I can explain architecture, eval, and security.
- [ ] I can answer customer discovery questions.
- [ ] I can show adoption or rollout thinking.
