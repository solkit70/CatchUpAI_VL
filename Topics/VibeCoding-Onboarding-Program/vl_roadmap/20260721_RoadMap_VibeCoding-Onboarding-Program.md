## 🧭 이 Topic의 제1원칙 — 대상 독자 기준

이 로드맵의 모든 산출물은 아래 분들이 읽는다는 전제로 만든다.

> **자기 분야에서 오래 일해 경험과 지식은 풍부하지만, 컴퓨터는 그렇게 익숙하지 않고,
> 바이브 코딩은 처음이거나 어디서 시작할지 모르는 분.**

따라서 모든 모듈에서 다음을 지킨다.

| 원칙 | 실천 방법 |
|------|----------|
| 쉬운 언어 | 전문 용어 최소화. 꼭 필요한 용어는 처음 나올 때 일상 언어로 풀이 병기 (예: "터미널 = 컴퓨터에게 글자로 명령을 내리는 창") |
| 한 번에 한 걸음 | 문서의 모든 절차는 "한 동작 = 한 단계"로 쪼갠다. 단계마다 "이 화면이 보이면 성공" 체크포인트 |
| 격려 + 현실 | 성공 스토리로 용기를 주되, 실제 막히는 지점도 정직하게 안내 (Build with AI 영상의 격려+현실+도전 3박자와 동일) |
| 이중 용도 | 각 문서는 진행자(나)가 보며 가이드할 수도, 참가자가 혼자 보고 따라할 수도 있게 작성 |

## 📚 학습 개요

### Topic 소개
도메인 지식이 풍부한 비개발자를 위한 바이브 코딩 온보딩 지원 프로그램 구축. 신청 접수(Google Form)부터 온보딩 커리큘럼, 참가자용 세팅 가이드, 경험담, 통합 가이드북까지 만든다. 유타주 이선생님이 "세팅만 도와드렸더니 며칠 만에 앱을 완성"한 실제 사례가 이 프로그램의 출발점이다.

### 학습 목표
- [ ] 대상 독자가 부담 없이 쓸 수 있는 신청 Google Form을 완성해 배포할 수 있다
- [ ] Build with AI 영상에 넣을 신청 안내 문구를 완성할 수 있다
- [ ] 신청자의 전체 여정을 담은 온보딩 커리큘럼을 설계할 수 있다 (1:1 / 그룹 겸용)
- [ ] 컴퓨터가 낯선 분 눈높이의 세팅 가이드를 만들 수 있다 (VS Code + Claude Code)
- [ ] 이선생님 사례 등 경험담을 "나도 할 수 있겠다"는 확신을 주는 스토리로 정리할 수 있다
- [ ] 진행자용/참가자용으로 모두 쓸 수 있는 통합 가이드북을 완성할 수 있다

### 예상 학습 기간
1-2주 (오늘 M1 최우선)

### 학습 환경
- OS: Windows 11 (참가자는 Windows/macOS 가능 — 가이드는 Windows 우선, macOS 추후 보강)
- 도구: Google Forms, VS Code + Claude Code, Markdown/Obsidian
- 사전 지식: 필수 없음 / 권장 — Build with AI 자료, 이선생님 동행 경험

### M1 - 신청 접수 Form + 영상 안내 문구

**난이도**: ⭐
**예상 시간**: 1.5h
**산출물 폴더**: `01-Application-Form/`

#### 학습 목표
- [ ] 대상 독자가 부담 없이 답할 수 있는 4개 문항(이름/이메일/사는 곳/만들고 싶은 앱)을 설계할 수 있다
- [ ] 실제로 작동하는 Google Form을 만들어 응답 시트와 연결할 수 있다
- [ ] 배포용 링크를 확보하고 제출 테스트를 통과할 수 있다
- [ ] Build with AI 영상에 넣을 신청 안내 문구를 작성할 수 있다

#### 주요 개념
1. **문턱 낮추기**: 신청 문항이 어렵거나 많으면 대상 독자는 신청을 포기한다. 꼭 필요한 4개만 받는다
2. **쉬운 질문 문구**: "애플리케이션 아이디어를 기술하세요"(X) → "어떤 앱을 만들어 보고 싶으신가요? 편하게 적어 주세요"(O)
3. **사는 곳은 국가/주까지만**: 개인정보 부담을 줄이면서, 워싱턴주 거주자에게는 오프라인 안내 가능 여부를 판단할 수 있는 수준
4. **응답 수집(Google Sheets 연동)**: 신청이 들어오면 자동으로 표에 쌓여 관리할 수 있다

#### 실습 과제

**실습 1: Form 문항·안내문 설계** ⭐
- **목적**: Google Forms에서 바로 붙여넣을 수 있게 문항과 안내문을 문서로 먼저 확정
- **단계**:
  1. Form 제목·인사말 작성 — 프로그램 취지를 대상 독자의 언어로 (예: "코딩을 몰라도 됩니다. 컴퓨터 세팅부터 옆에서 도와드립니다")
  2. 이름(단답형, 필수) 문항 확정
  3. 이메일(단답형, 필수, 형식 검증) 문항 확정
  4. 사는 곳 — 나라 + 주(도) (단답형, 필수) 문항 확정, "도시까지는 안 적으셔도 됩니다" 안내 포함
  5. 만들고 싶은 앱 소개(장문형, 필수) 문항 확정 — 부담을 낮추는 예시 문구 포함
- **예상 시간**: 30분
- **난이도**: ⭐
- **검증 방법**: `01-Application-Form/form-questions.md`에 문항 전체가 "그대로 복사 가능한" 상태로 정리됨

**실습 2: Google Form 제작·배포** ⭐
- **목적**: 오늘 안에 실제로 신청을 받을 수 있는 상태로 만든다
- **단계**:
  1. Google Forms에서 새 양식 생성, 실습 1 문항 입력
  2. 응답 → Google Sheets 연동
  3. 미리보기에서 테스트 제출 1회
  4. 배포용 링크 확보
- **예상 시간**: 30분
- **난이도**: ⭐
- **검증 방법**: 테스트 제출이 Sheets에 기록되고, 배포 링크가 시크릿 창에서도 정상 작동

**실습 3: 영상 신청 안내 문구 작성** ⭐
- **목적**: 지금 만들고 있는 Build with AI 영상에서 이 프로그램을 소개하고 신청을 유도
- **단계**:
  1. 영상 아웃트로/설명란용 안내 문구 작성 (대상 독자에게 말 걸듯: "이 영상을 보고 나도 해보고 싶다는 생각이 드셨다면...")
  2. Google Form 링크 삽입 위치 결정 (설명란 + 아웃트로 화면)
  3. 사용자 리뷰
- **예상 시간**: 20분
- **난이도**: ⭐
- **검증 방법**: 사용자 승인

### M2 - 온보딩 여정 커리큘럼 설계

**난이도**: ⭐⭐
**예상 시간**: 2.5h
**산출물 폴더**: `02-Onboarding-Journey/`

#### 학습 목표
- [ ] 신청자가 신청부터 자기 앱 완성까지 겪는 전체 여정을 단계 지도로 그릴 수 있다
- [ ] 각 단계에서 진행자가 할 일과 참가자가 할 일을 구분해 정의할 수 있다
- [ ] 1:1 가이드와 그룹 가이드 두 방식의 운영 절차를 설계할 수 있다
- [ ] 대상 독자용 "쉬운 용어 사전"의 뼈대를 만들 수 있다

#### 주요 개념
1. **여정(Journey) 설계**: 프로그램은 문서 모음이 아니라 "신청 → 사전 준비 → 세팅 세션 → 첫 성공 → 내 앱 만들기 동행 → 커뮤니티 연결"로 이어지는 하나의 길이다
2. **첫 성공(First Win)**: 세팅 직후 참가자가 자기 손으로 무언가 만들어지는 경험을 해야 이후 여정이 이어진다 (이선생님 사례의 핵심)
3. **진행자/참가자 역할 분리**: 같은 단계라도 진행자가 준비할 것과 참가자가 하는 것이 다르다 — 커리큘럼 문서에 두 열로 병기
4. **쉬운 용어 사전**: 가이드 전반에서 반복 사용할 용어 풀이 모음 (터미널, 설치, 폴더, 프롬프트 등)

#### 실습 과제

**실습 1: 온보딩 여정 지도 작성** ⭐⭐
- **목적**: 프로그램 전체를 한 장으로 보는 지도를 만든다
- **단계**:
  1. 이선생님 사례를 복기해 실제 여정 단계를 추출
  2. 단계별로 정의: 목표 / 진행자가 하는 일 / 참가자가 하는 일 / 성공 기준
  3. 1:1과 그룹 진행 시 달라지는 부분 표시
  4. Mermaid 다이어그램으로 여정 지도 시각화
- **예상 시간**: 1.5h
- **난이도**: ⭐⭐
- **검증 방법**: 여정 지도만 보고 "다음 신청자가 오면 무엇부터 하면 되는지" 즉시 답할 수 있는가

**실습 2: 쉬운 용어 사전 초안** ⭐
- **목적**: 모든 가이드 문서가 공유할 용어 풀이 기준을 만든다
- **단계**:
  1. 세팅~첫 앱 과정에서 등장할 수밖에 없는 용어 목록화 (10-15개)
  2. 각 용어를 일상 언어 한 문장으로 풀이
  3. "이 용어는 아예 쓰지 말고 이렇게 말하자" 대체 표현 목록도 작성
- **예상 시간**: 40분
- **난이도**: ⭐
- **검증 방법**: 용어 사전을 대상 독자 관점에서 읽어 어색한 풀이가 없는지 확인

### M3 - 참가자용 세팅 가이드 작성

**난이도**: ⭐⭐
**예상 시간**: 3h
**산출물 폴더**: `03-Setup-Guide/`

#### 학습 목표
- [ ] VS Code + Claude Code 설치를 대상 독자가 혼자서도 따라할 수 있는 단계 문서로 만들 수 있다
- [ ] 각 단계에 "이 화면이 보이면 성공" 체크포인트를 넣을 수 있다
- [ ] 실제 세팅에서 막혔던 지점을 "괜찮아요, 이렇게 하면 됩니다" 톤으로 정리할 수 있다
- [ ] 세팅 완료 직후 5분 안에 첫 성공을 경험하는 미니 실습을 설계할 수 있다

#### 주요 개념
1. **한 동작 = 한 단계**: "다운로드하고 설치하세요"(X) → "① 파란색 Download 버튼을 누릅니다 ② 내려받은 파일을 두 번 클릭합니다"(O)
2. **체크포인트**: 각 단계 끝에 참가자가 스스로 확인할 수 있는 화면/결과 명시
3. **막힘 대비(안심 문구)**: 문제 상황을 "오류"가 아니라 "자주 있는 일"로 표현해 심리적 장벽을 낮춤
4. **첫 성공 실습**: 세팅 직후 Claude Code에게 한 문장을 부탁해 결과물이 눈에 보이는 경험 (예: "내 소개 웹페이지 한 장 만들어 줘")

#### 실습 과제

**실습 1: 세팅 절차 본문 작성** ⭐⭐
- **목적**: 이선생님께 실제로 해드렸던 세팅 과정을 대상 독자 언어로 문서화
- **단계**:
  1. VS Code 설치 (다운로드→설치→첫 실행) 단계별 작성
  2. Claude Code 설치·로그인 단계별 작성
  3. 작업 폴더 만들기와 열기 단계별 작성
  4. 각 단계에 체크포인트 삽입
- **예상 시간**: 1.5h
- **난이도**: ⭐⭐
- **검증 방법**: M2 용어 사전 기준 위반(풀이 없는 전문 용어) 0건

**실습 2: 막힘 대비 섹션** ⭐⭐
- **목적**: 실제로 겪었던 문제를 안심 문구 톤으로 정리
- **단계**:
  1. 세팅 중 막혔던 지점 목록화 (권한 창, 로그인, 경로 등)
  2. 각 항목을 "이런 화면이 나오면 → 이렇게 하세요" 형식으로 작성
- **예상 시간**: 40분
- **난이도**: ⭐⭐
- **검증 방법**: 실제 경험 사례 최소 2건 반영

**실습 3: 첫 성공 미니 실습 설계** ⭐
- **목적**: 세팅 직후 5분 안에 "내가 만들었다"는 경험 제공
- **단계**:
  1. 첫 부탁 문장(프롬프트) 예시 2-3개 작성
  2. 예상 결과와 "성공했는지 확인하는 법" 작성
- **예상 시간**: 30분
- **난이도**: ⭐

### M4 - 먼저 걸어간 분들의 이야기

**난이도**: ⭐⭐
**예상 시간**: 2h
**산출물 폴더**: `04-Pioneer-Stories/`

#### 학습 목표
- [ ] 이선생님 사례를 "나도 할 수 있겠다"는 확신을 주는 스토리로 쓸 수 있다
- [ ] 성공만이 아니라 시행착오도 함께 담아 현실감을 줄 수 있다
- [ ] Build with AI의 핵심 메시지를 대상 독자 언어로 연결할 수 있다
- [ ] 앞으로 참가자 사례가 쌓일 수 있는 문서 구조를 만들 수 있다

#### 주요 개념
1. **동일시(Identification)**: 대상 독자는 "개발자의 성공담"이 아니라 "나 같은 사람의 성공담"에서 용기를 얻는다 — 이선생님의 출발점(컴퓨터가 낯설었다)을 생략하지 않는다
2. **격려+현실+도전**: 잘된 것만 보여주면 비현실적, 어려움만 보여주면 포기 — 두 가지를 함께
3. **고속도로 비유의 재사용**: "AI는 100마일 중 5마일만 10차선" — 좁은 진입로(세팅)를 함께 넘으면 넓은 길이 나온다는 이 프로그램의 존재 이유
4. **성장형 문서**: 참가자가 늘 때마다 스토리가 추가되는 구조

#### 실습 과제

**실습 1: 이선생님 스토리 작성** ⭐⭐
- **목적**: 프로그램의 원형이 된 사례를 완결된 이야기로
- **단계**:
  1. 시작 전 상황(컴퓨터 익숙도, 만들고 싶었던 것) 정리
  2. 세팅 세션에서 있었던 일 정리
  3. 그 후 벌어진 일(며칠 만에 Voice Legacy 앱 완성, 이민 생활 회고 시작) 정리
  4. 이 사례가 주는 메시지 한 문단
- **예상 시간**: 1h
- **난이도**: ⭐⭐
- **검증 방법**: 대상 독자 관점에서 읽고 "나도 해보고 싶다"는 마음이 드는가

**실습 2: 시행착오와 배움 정리** ⭐
- **목적**: 현실감을 주는 "막혔던 순간들" 기록
- **단계**:
  1. 세팅·개발 과정에서 실제 막혔던 순간 목록화 (M3 troubleshooting과 연결)
  2. 각 순간을 "어떻게 넘어갔는지"와 함께 짧게 정리
  3. Build with AI에서 가져올 교훈(계획 먼저, 작게 나누기, AI는 도깨비방망이가 아니다)을 대상 독자 언어로 연결
- **예상 시간**: 40분
- **난이도**: ⭐
- **검증 방법**: 시행착오 최소 2건 + Build with AI 연결 최소 2개

#### 산출물

- [ ] 이 스토리를 영상·신청 안내·가이드북 어디에든 바로 인용할 수 있다

- **합계**: 2h
