## 2. Current Pipeline Analysis

After directly cloning and analyzing gobi-monorepo and gobi-ai/docs:

```
gobi-monorepo/specs (26 feature definitions)
        ↓ ⚠️ Manual conversion (no automation)
gobi-ai/docs (Mintlify MDX)
        ↓ ✅ Auto deployment
docs.gobihq.com
```

**Key findings**:
- The specs (feature definitions) → docs (user documentation) conversion is manual and not automated
- A `CODE_TO_SPECS` AI prompt already exists in gobi-monorepo (code → spec generation)
- The Orchestrator already supports per-Vault background Reflexes
- AI agents are already integrated into the LINEAR.md-based development pipeline

---

## 3. Vibe Guiding = SPECS_TO_GUIDE

Vibe Guiding is the reverse direction of the dev team's `CODE_TO_SPECS` (code → spec).

```
Dev team:      Code → AI (CODE_TO_SPECS) → Specs
Vibe Guiding:  Specs → AI (SPECS_TO_GUIDE) → User guides + in-app context
```

VibeLearn AI (CUA_VL) fills this `SPECS_TO_GUIDE` role.

---

## 4. Implementation Strategy: 3-Phase Approach

### Phase 1 — Immediate Proof (1-2 weeks, no GOBI team collaboration required)

**Goal**: Prove in-app Vibe Guiding works in Changsoo Vault

**Implementation**:

Step 1. Generate guides from specs using VibeLearn AI
```
gobi-monorepo/specs/*.md
        ↓ VibeLearn AI (SPECS_TO_GUIDE)
Vibe Guiding prompt files generated
```

Step 2. Add Vibe Guiding settings to Vault
```yaml
# Changsoo_Vault/.gobi/settings.yaml
orchestrator:
  enabled: true
  prompt_paths:
    - .gobi/prompts/vibe-guiding.md  ← Prompt generated by VibeLearn AI
  watch_patterns:
    - _Gobi_/Captures/**/*.md        ← Detect new captures
```

Step 3. Verify Reflex behavior
```
User creates a new capture
        ↓ Watch Pattern detects it
Vibe Guiding Agent runs:
  - Analyzes capture content
  - Searches Brain for related knowledge
  - Suggests connection points + next actions
        ↓
.gobi/outputs/vibe-guide.md or TTS guidance
```

**Resources required**: Changsoo works independently, 2 weeks
**Success metric**: Within 5 seconds of a new capture, relevant Brain knowledge + next-action suggestions are automatically output

**2-B. Docs Pipeline Automation Contribution**

**GOBI team collaboration**: Decide Skill distribution method, review docs PR

---

### Phase 3 — Native App Integration (1-3 months, GOBI team collaboration)

**Goal**: Users experience Vibe Guiding without any manual setup

**Features to implement together with the GOBI team**:

1. **Ambient Mode + Vibe Guiding routing**
   - Specific Wake Word → connect to Vibe Guiding Agent
   - Auto-detect current screen/feature context → deliver tailored guidance

2. **Schedule trigger implementation** (marked as "future" in spec 19)
   - Daily / weekly Vibe Guide auto-generation
   - Discovery and guidance for unused features

3. **Public Gobi Space Vibe Guiding Brain**
   - Operate guides generated by VibeLearn AI as a public Brain
   - Community Vibe Guiding hub

## 5. VibeLearn AI + CVL Automation Pipeline

```
gobi-monorepo/specs updated
        ↓ (change detected)
VibeLearn AI (SPECS_TO_GUIDE)
  - Read changed specs
  - Extract Core Concepts
  - Generate per-user-persona guides
  - Update Vibe Guiding prompts
        ↓
Vibe Guiding Skill auto-updated
        ↓
All users' Vibe Guiding automatically improves
```

This is CVL (Continuous Vibe Learning) — as the GOBI product evolves, Vibe Guiding evolves automatically.
