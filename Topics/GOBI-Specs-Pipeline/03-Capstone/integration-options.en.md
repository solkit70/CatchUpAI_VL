# Vibe Guiding Integration Options — Comparative Analysis

**Created**: 2026-04-07
**Based on**: M1 (structure analysis) + M2 (spec analysis) results

---

## 4 Options Under Comparison

---

### Option A: specs → VibeLearn AI → docs Pipeline Automation (Documentation Integration)

**Concept**:
```
gobi-monorepo/specs (Markdown)
        ↓ VibeLearn AI (SPECS_TO_GUIDE)
gobi-ai/docs (MDX auto-generated)
        ↓ Mintlify auto deployment
docs.gobihq.com
```

**Pros**:
- Closes the manual conversion gap in the current pipeline
- Dev team updates a spec → docs automatically reflect it (CVL)
- Achieves the official documentation quality the GOBI team wants

**Cons**:
- Users must actively visit docs.gobihq.com (push model not supported)
- Far from Vibe Guiding's core value of "personalized real-time guidance"
- Spec (feature definition) → MDX (user docs) conversion quality needs validation

**Feasibility**: ✅ High
**GOBI Team Collaboration**: △ PR process alignment needed for gobi-ai/docs
**Vibe Guiding Value Delivered**: ⭐⭐ (closer to docs automation)

---

### Option B: In-App Vibe Guiding via Second Brain Agent Reflex (Immediate Proof)

**Concept**:
```
.gobi/settings.yaml
  prompt_paths: [vibe-guiding.md]   ← Generated by VibeLearn AI
  watch_patterns: [_Gobi_/Captures/**/*.md]
        ↓ Reflex fires on new capture detected
Vibe Guiding Agent response
  → Saved to .gobi/outputs/vibe-guide.md
  → (Optional) Spoken via TTS
```

**Pros**:
- Can be prototyped in Changsoo Vault right now, without GOBI team code changes
- Closest to the GOBI team's expectation of "in-app real-time Vibe Guiding"
- Natural voice UX when combined with Ambient Mode
- Personalized: guidance based on each user's Vault context

**Cons**:
- Current Reflex triggers are limited to file change / manual execution (schedule not yet implemented)
- Hard to distribute to other users without Skill packaging
- Ambient Mode routing comes after Phase 2

**Feasibility**: ✅ Very high (Phase 1, immediate)
**GOBI Team Collaboration**: ❌ Not required (Phase 1)
**Vibe Guiding Value Delivered**: ⭐⭐⭐ (core value delivered)

---

### Option C: Standalone Vibe Guiding via Gobi CLI

**Concept**:
```
VibeLearn AI → Vibe Guiding Brain (standalone Vault)
        ↓
gobi brain ask --vault-slug vibe-guiding --question "..."
or
gobi brain publish → Publish Vibe Guiding Brain to Gobi Space
```

**Pros**:
- Fully standalone — minimal dependency on GOBI infrastructure
- Immediately implementable with current GOBI CLI features (brain ask, brain publish)
- When published to Gobi Space, accessible to all GOBI users
- Upload VibeLearn AI outputs directly to the Brain

**Cons**:
- User must type CLI commands manually (low UX)
- No in-app automatic triggers — manual queries only
- "Active query" model, not "real-time guidance"

**Feasibility**: ✅ Very high (immediately via current CLI)
**GOBI Team Collaboration**: ❌ Not required
**Vibe Guiding Value Delivered**: ⭐⭐ (closer to manual lookup)

---

### Option D: Mixed Strategy (Phase 1 → Phase 2 → Phase 3 sequential)

**Concept**:
```
Phase 1 (Immediate, 1-2 weeks):
  Option B to prototype in Changsoo Vault
  + Option C to publish the Vibe Guiding Brain

Phase 2 (2-4 weeks):
  Package Vibe Guiding Skill → distribute to other GOBI users
  + Option A to contribute docs pipeline automation

Phase 3 (1-3 months):
  Native Ambient Mode integration with GOBI team
  Auto guide generation after schedule trigger is implemented
```

**Pros**:
- Immediate value proof + progressive expansion
- Each Phase is independently complete (risk distributed across phases)
- Build trust with the GOBI team by showing phased results
- Phase 3 achieves the native experience the GOBI team wants

**Cons**:
- Time investment spans 3 Phases
- Potential design changes at Phase transitions

**Feasibility**: ✅ Very high
**GOBI Team Collaboration**: Increases incrementally per Phase
**Vibe Guiding Value Delivered**: ⭐⭐⭐ (highest at Phase 3)
