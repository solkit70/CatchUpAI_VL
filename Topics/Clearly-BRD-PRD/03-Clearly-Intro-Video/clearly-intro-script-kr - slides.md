# 🎵 Vibe Coding과 문제 제기

---

## 🎵 Vibe Coding이란?

> **코드를 직접 작성하는 대신, AI에게 "비전(Vibe)"을 전달하여 코드를 생성하는 개발 방식**

| 전통적 개발 | 바이브코딩 |
|-----------|----------|
| 코드를 직접 작성 | 아이디어를 AI에게 전달 |
| "어떻게(How)" 집중 | "무엇을(What)" 집중 |
| 구현 세부사항 | 비전과 요구사항 |

^ 먼저 바이브코딩에 대해 잠깐 얘기해볼게요. 바이브코딩이란 코드를 직접 짜는 대신, AI에게 내가 원하는 것의 "비전"을 전달해서 코드를 생성하는 방식을 말합니다. 예를 들어 "사용자가 로그인하면 대시보드가 나오는 웹앱을 만들어줘"라고 하는 거죠. 여기서 개발자의 역할이 바뀝니다. 코드를 직접 쓰는 사람에서, AI에게 무엇을 만들지를 명확하게 지시하는 아키텍트이자 커뮤니케이터로 변화하는 거예요.

---

## ⚠️ 바이브코딩의 핵심 문제

```
AI에게 "홈페이지 만들어줘" → ??
```

- **문제**: AI가 만드는 결과물이 내 머릿속의 것과 다르다!
- **이유**: AI는 명확한 지시가 없으면 **가정(assumption)** 으로 채운다

> **"입력 품질 = 출력 품질"**
> Clear Requirements → Better AI-Generated Code

^ 그런데 문제가 있습니다. 바이브코딩이 잘 되려면 AI에게 내 아이디어를 명확하게 전달해야 하는데, 이게 생각보다 어렵습니다. "홈페이지 만들어줘"라고만 하면 AI는 수많은 가정을 해서 자기 마음대로 만들어버립니다. 타겟이 누구인지, 어떤 기능이 필요한지, 디자인은 어떻게 해야 하는지 — AI가 이 모든 걸 추측하는 거예요. 그래서 결과물이 내가 원하던 것과 달라지는 겁니다. 핵심 원칙이 있습니다. 입력 품질이 출력 품질을 결정한다. 명확한 요구사항이 있으면 AI가 훨씬 더 정확한 코드를 만들어줍니다.

---

## 💡 BRD/PRD가 바이브코딩의 해결책

**Vibe Coding 워크플로우:**

```
아이디어 → BRD → PRD → 바이브코딩 프롬프트 → 코드 생성
```

- **BRD**: "왜 만드나? 무엇을 만드나?" (비즈니스 관점)
- **PRD**: "어떻게 만드나?" (제품/기술 관점)
- 이 두 문서가 AI에게 전달되면 → **훨씬 정확한 코드 생성**

^ 그래서 등장한 것이 BRD와 PRD입니다. BRD는 Business Requirements Document, 즉 비즈니스 요구사항 문서입니다. "왜 이 프로젝트를 하는지, 무엇을 만들어야 하는지"를 정의하고요. PRD는 Product Requirements Document, 제품 요구사항 문서입니다. "어떻게 만들 것인지"의 기술적인 세부사항을 담습니다. 이 두 문서를 AI 코딩 도구에게 주면, AI가 내 프로젝트를 훨씬 잘 이해하고 더 정확한 코드를 만들어줍니다. 그리고 Clearly는 바로 이 BRD와 PRD를 쉽게 만들어주는 도구입니다.

---

## 🔄 AI 시대, 개발자 역할의 변화

**전통적 개발자 → AI 시대 개발자**

- ❌ 모든 코드를 직접 작성
- ✅ **명확한 요구사항을 정의**하는 아키텍트

**BRD/PRD의 새로운 역할:**
- 단순한 문서가 아니라 **AI에게 전달하는 프롬프트**
- 팀 소통 도구 → **AI 코딩 도구의 컨텍스트**

**가장 중요한 스킬**: AI에게 효과적으로 지시하는 능력

^ 사실 BRD와 PRD는 원래 대규모 소프트웨어 개발에서 팀 간 소통을 위해 쓰던 문서였습니다. 그런데 AI 시대에 이 문서의 역할이 바뀌었어요. 이제는 AI에게 전달하는 프롬프트, 즉 맥락 정보가 됩니다. AI 코딩 도구들, 예를 들어 Claude Code나 Cursor 같은 도구들은 프로젝트 시작 시 이런 문서를 참고해서 개발 방향을 잡거든요. 그래서 AI 시대에 가장 중요한 스킬 중 하나가 바로 AI에게 효과적으로 지시하는 능력이 된 겁니다. 암기나 코딩 실력보다 이게 더 중요해지는 시대예요.

- 한국어 출력 지원

^ 자, 이제 Clearly 앱 자체에 대해 알아봅시다. Clearly의 핵심은 세 단계 워크플로우입니다. 첫째, BRD Wizard에서 AI가 질문을 하고, 사용자가 답변하면 BRD를 자동으로 생성합니다. 질문은 대략 3~5개 정도인데, Clearly가 충분한 정보를 수집했다고 판단하면 BRD 생성 버튼이 활성화됩니다. 둘째, PRD Wizard에서 BRD를 바탕으로 더 기술적인 질문들을 통해 PRD를 만듭니다. 셋째, Output Tool 단계에서 Claude Code, Cursor, v0 같은 AI 개발 도구에 최적화된 파일을 자동으로 생성해줍니다. 특히 좋은 점은 각 질문마다 3가지 예시 답변을 보여준다는 거예요. 처음 써보는 분들도 어떻게 답해야 할지 감을 잡기가 쉽습니다.

## 📊 BRD vs PRD: 핵심 차이점

| 구분 | BRD | PRD |
|------|-----|-----|
| **핵심 질문** | Why? + What? | What? + How? |
| **관점** | 비즈니스 | 제품/기술 |
| **대상** | 이해관계자, 경영진 | 개발팀, 디자이너 |
| **추상화** | 높음 (고수준) | 낮음 (상세) |
| **내용** | 목표, KPI, 사용자 니즈 | 기능 명세, API, 데이터 모델 |

**순서**: 아이디어 → **BRD** → **PRD** → 개발

^ BRD와 PRD의 차이를 좀 더 명확하게 정리해 드릴게요. BRD는 비즈니스 관점에서 왜 이걸 만드는지, 무엇을 만드는지를 다룹니다. 주 독자는 경영진이나 이해관계자고요, 추상적이고 고수준입니다. 반면 PRD는 제품과 기술 관점에서 어떻게 만들 것인지를 다룹니다. 개발팀과 디자이너를 위한 문서고요, 구체적인 기능 명세와 기술 스택이 들어갑니다. 순서는 항상 아이디어가 먼저, 그다음 BRD, 그다음 PRD, 마지막으로 개발입니다.

## ⚙️ Clearly의 두 가지 모드

**Plain Mode** (비기술적 사용자용)
- BRD + PRD + 바이브코딩 프롬프트 생성
- v0, Bubble 같은 No-Code 도구에 최적화

**Technical Mode** (개발자용)
- BRD + PRD + **상세 기술 태스크 목록** 생성
- 의존성, 우선순위 포함
- Claude Code, Cursor 같은 AI 코딩 도구에 최적화

> 현재는 두 모드가 통합되어 하나로 운영됩니다 (2026년 기준)

^ Clearly에는 두 가지 모드가 있습니다. Plain Mode는 비기술적 사용자를 위한 모드로, BRD와 PRD에 바이브코딩 프롬프트까지 생성해줍니다. v0나 Bubble 같은 No-Code 도구와 함께 쓰기 좋습니다. Technical Mode는 개발자를 위한 모드로, BRD와 PRD에 더해서 상세한 기술 태스크 목록까지 만들어줍니다. Claude Code나 Cursor 같은 AI 코딩 도구와 함께 쓰기에 최적화되어 있습니다. 참고로 제가 사용했을 때는 두 모드가 이미 통합되어서 하나로 운영되고 있었습니다.

## 🎯 Clearly = Vibe Coding의 시작점

```
아이디어
   ↓
Clearly (BRD → PRD)
   ↓
Output Tool (개발 도구 설정 파일 생성)
   ↓
AI 코딩 도구 (Claude Code, Cursor 등)
   ↓
완성된 제품
```

> **"Clearly는 단순한 문서 도구가 아니라, Vibe Coding 워크플로우의 출발점이다"**

^ 제가 Clearly를 써보고 가장 인상 깊었던 점은, 단순히 문서를 만드는 도구가 아니라는 겁니다. Output Tool 단계를 거치면 Claude Code나 Cursor 같은 AI 코딩 도구에서 바로 사용할 수 있는 설정 파일들이 자동으로 생성됩니다. 즉, 아이디어에서 시작해서 Clearly로 BRD와 PRD를 만들고, Output Tool로 개발 도구 설정까지 자동 생성하면, AI 코딩 도구에서 바로 코드 개발을 시작할 수 있는 거예요. 이게 바이브코딩의 완전한 워크플로우입니다.

## 🤖 Step 2: BRD Wizard

**진행 방식:**
- AI가 질문 하나씩 제시
- 각 질문에 3가지 **예시 답변** 제공
- 진행률: "Questions answered: X/5+"
- **"Generate BRD" 버튼**: Clearly가 충분한 정보를 수집했다고 판단하면 활성화
  - 2~3개 답변 후에도 활성화될 수 있음
  - 총 약 5개 내외의 질문이 제시됨

**주요 질문 영역:**
1. 비즈니스 목표 — "이 프로젝트의 핵심 가치는?"
2. 기술 스택 — "어떤 기술/플랫폼을 사용할 것인가?"
3. 타겟 사용자 — "누구를 위한 서비스인가?"
4. 콘텐츠 관리 — "어떻게 운영할 것인가?"
5. 리스크 — "예상되는 제약사항은?"

## 💡 BRD Wizard 답변 팁

**잘 답변하는 방법:**

- ✅ **구체적으로**: "빠르게" → "3초 이내 로딩"
- ✅ **측정 가능하게**: "쉽게 쓸 수 있게" → "3단계 이내 완료"
- ✅ **우선순위 부여**: Must have / Should have / Nice to have
- ✅ **예시 답변 활용**: 구조는 따르되 내용은 내 프로젝트에 맞게

**사전 준비 팁:**
- 답변할 내용을 텍스트 파일에 미리 정리해두기
- URL, 타겟 사용자, KPI 등을 사전에 파악해두기

^ BRD Wizard에서 답변할 때 몇 가지 팁이 있습니다. 첫째, 구체적으로 쓰세요. 빠르게가 아니라 3초 이내 로딩처럼요. 둘째, 측정 가능하게 쓰세요. 쉽게가 아니라 3단계 이내 완료처럼요. 셋째, 우선순위를 부여하세요. Must have, Should have, Nice to have로 나눠서 쓰면 AI가 더 정확한 문서를 만들어줍니다. 그리고 실용적인 팁 하나 더! 답변할 내용을 미리 텍스트 파일에 정리해두면 훨씬 빠르게 진행할 수 있습니다.

## 🤖 프로 팁: AI로 BRD/PRD 답변 미리 준비하기

**Clearly Wizard 질문의 특성:**
- AI 생성 질문 → **매번 조금씩 달라진다**
- 예상치 못한 질문이 나올 수 있다

**핵심 전략: 사전에 AI와 프로젝트를 충분히 논의하자!**

```
① Clearly에서 질문이 나오면
② AI에게 질문을 복사 & 붙여넣기
③ "이 질문에 대한 답변 작성해줘"
→ 내 프로젝트에 최적화된 상세한 답변!
```

**포인트:** AI와 사전 대화가 많을수록 더 정확한 답변이 나온다

^ 여기서 특별한 팁 하나를 드릴게요. 저는 실제로 Clearly의 BRD/PRD Wizard 질문에 대한 답변을 AI 도구를 활용해서 만들었습니다. Clearly의 Wizard 질문은 AI가 생성하기 때문에 매번 조금씩 달라지는데요. 그래서 예상치 못한 질문이 나올 때 막막할 수 있습니다. 핵심 전략은 이겁니다. Clearly를 사용하기 전에 AI 도구, 예를 들어 Claude Code나 ChatGPT 같은 도구와 내 프로젝트에 대해 충분히 이야기해두는 거예요. 목표가 무엇인지, 타겟 사용자가 누구인지, 기술 스택은 무엇인지를 AI와 미리 논의해두면, AI가 내 프로젝트를 깊이 이해하게 됩니다. 그러면 Clearly에서 어떤 질문이 나오더라도 그 질문을 AI에 붙여넣고 "이 질문에 대한 답변 작성해줘"라고 하기만 하면, 내 프로젝트에 딱 맞는 훌륭한 답변을 만들어줘요. 사전에 논의를 많이 할수록 더 정확하고 상세한 답변이 나오는 거죠.

**Tier 3** (대규모): 신규 프로젝트, 아키텍처 설계 → **필수**

**특히 유용한 상황:**
- 🚀 바이브코딩으로 새 프로젝트를 시작할 때
- 📝 팀 프로젝트에서 요구사항을 정리해야 할 때
- 🎓 요구사항 작성법을 배우고 싶을 때
- 💼 투자자나 팀원에게 프로젝트를 설명해야 할 때

^ Clearly를 어떤 상황에서 쓰면 좋은지도 말씀드릴게요. 소규모 스크립트나 유틸리티 작업은 Clearly 없이도 괜찮습니다. 하지만 중간 규모의 기능 추가나 모듈 개발에는 권장하고, 새로운 프로젝트나 아키텍처 설계가 필요한 대규모 작업에는 거의 필수라고 생각합니다. 특히 바이브코딩으로 새 프로젝트를 시작할 때, 팀 프로젝트에서 요구사항을 정리할 때, 그리고 투자자나 팀원에게 프로젝트를 설명해야 할 때 Clearly가 정말 유용합니다.
