## 3. 핵심 학습 내용

### Clearly 앱의 가치

Clearly는 단순한 문서 생성 도구가 아니라 **Vibe Coding의 시작점**입니다:
1. AI Wizard가 비기술자도 체계적인 요구사항 문서를 작성하도록 안내
2. BRD → PRD → Output Tool의 3단계 구조로 점진적으로 구체화
3. Output Tool이 AI 코딩 도구(Claude Code, Cursor 등)에 최적화된 설정 파일을 자동 생성
4. "아이디어 → 구조화된 요구사항 → 개발 시작"의 전체 흐름을 하나의 도구에서 완결

### BRD vs PRD 핵심 차이

| 관점 | BRD | PRD |
|------|-----|-----|
| 초점 | Why & What | What & How |
| 대상 | 경영진, 이해관계자 | 개발팀, 디자이너 |
| 수준 | 비즈니스 목표, KPI | 기술 사양, API, 데이터 모델 |
| Wizard 질문 | 비즈니스 목표, 제약, 리스크 | 기술 스택, 구현 방식, 디자인 시스템 |

### 반복을 통한 품질 향상 (핵심 발견)

3회 반복을 통해 발견한 패턴:
- **v1**: 기본 구조 파악, 도구 학습
- **v2**: 경험 기반 빠른 진행, 품질 기본선 확보
- **v3**: 이전 답변의 갭을 보강, 새 관점 추가 → 최고 품질

이 패턴은 BRD/PRD뿐 아니라 모든 AI 도구 활용에 적용 가능한 원리입니다.

## 4. 발생한 문제와 해결

### Bug 대응

| 문제 | 영향 | 해결 |
|------|------|------|
| BRD 날짜 오류 | Low - 문서 수정으로 해결 | 개발자 보고 → Fixed |
| 세션 만료 | High - PRD 진행 불가 | 개발자 보고 → Fixed, 답변 미리 준비로 예방 |
| 프로젝트 접근 불가 | Critical - 전체 재작업 | 개발자 보고 → Fixed |
| 대시보드 표시 버그 | Critical - 프로젝트 사라짐 | 워크어라운드: 로컬 백업 + 연속 진행 |

### 시간 초과 원인

M2가 계획(3-4h) 대비 초과(5.5h)된 이유:
- Bug #2, #3으로 Session 1에서 PRD 진행 불가 → Session 2에서 재시작
- Bug #4로 Session 2에서 Output Tool 미진행 → Session 3에서 재시작
- **버그가 없었다면 2회(~3h)로 완료 가능했을 것으로 추정**
