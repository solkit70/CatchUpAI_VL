## 1. Introduction
본 문서는 Catch Up AI의 2026년 홈페이지 구축 프로젝트를 위한 비즈니스 요구사항을 설명합니다. 새로운 홈페이지는 YouTube 채널을 중심으로 운영되는 Catch Up AI의 핵심 콘텐츠와 활동을 체계적으로 소개하는 정보 허브 역할을 수행하며, 방문자들이 채널의 주요 프로젝트와 방법론을 쉽게 이해하고 AI 커뮤니티와의 연결을 강화하는 것을 목표로 합니다.

### 2.2. Target Users
- **AI에 관심 있는 개발자 및 비개발자:** 새로운 AI 학습 방법론에 관심 있는 사람으로, Catch Up AI의 5가지 핵심 프로젝트를 한눈에 파악하고 가치를 이해하며, 관련 YouTube 재생 목록 시청 또는 상세 페이지로 이동하기를 기대합니다.
- **시애틀 지역 AI 커뮤니티 멤버:** '시애틀 AI 생태계' 섹션에서 최신 이벤트 정보를 확인하고, AI4PKM 코호트와 같은 커뮤니티 활동에 참여 신청하기를 기대합니다.
- **Vibe Coding/Learning 방법론에 관심 있는 학습자:** 방법론의 개요를 이해하고 실제 적용 사례를 확인한 뒤, YouTube 채널을 구독하여 지속적으로 학습하기를 기대합니다.

### 2.3. User Journey Map
1.  **홈페이지 방문:** 사용자는 Catch Up AI YouTube 채널, 소셜 미디어 또는 검색을 통해 홈페이지에 접속합니다.
2.  **핵심 콘텐츠 탐색:** 메인 페이지에서 5가지 핵심 프로젝트(Vibe Coding, Vibe Learning, Vibe Guiding, AI4PKM, 시애틀 AI 생태계)의 개요를 확인합니다.
3.  **관심 프로젝트 상세 탐색:** 관심 있는 프로젝트를 클릭하여 상세 페이지로 이동, 프로젝트의 목표, 방법론, 관련 YouTube 영상(임베드)을 확인합니다.
4.  **관련 콘텐츠 소비:** 임베드된 YouTube 영상을 시청하거나, 관련 YouTube 플레이리스트로 이동하여 더 많은 영상을 시청합니다.
5.  **커뮤니티 참여:** AI4PKM 코호트 신청 (Google Forms 연동), 시애틀 AI 이벤트 정보 확인, 뉴스레터 구독을 통해 Catch Up AI 커뮤니티에 참여합니다.
6.  **지속적인 연결:** YouTube 채널 구독, 소셜 미디어 팔로우를 통해 Catch Up AI와의 연결을 유지합니다.

## 3. Business Objectives
### 3.1. Primary Objectives
- Catch Up AI의 5가지 핵심 프로젝트(Vibe Coding, Vibe Learning, Vibe Guiding, AI4PKM, 시애틀 AI 생태계)를 방문자가 명확히 이해할 수 있도록 체계적으로 소개합니다.
- YouTube 채널의 콘텐츠를 주제별로 쉽게 탐색할 수 있는 구조를 제공하여 콘텐츠 접근성을 높입니다.
- 시애틀 지역 AI 커뮤니티와의 연결을 강화하고, 커뮤니티 활동(코호트, 이벤트) 참여를 유도합니다.
- AI 학습 및 연구 분야에서 Catch Up AI의 전문적이고 신뢰할 수 있는 이미지를 구축하고 인지도를 높여 잠재적 파트너십 및 지속 가능한 성장 기반을 마련합니다.

### 3.3. Business Value
- **콘텐츠 체계화:** 산재된 YouTube 콘텐츠를 구조화하여 사용자 경험을 개선하고, 핵심 방법론의 가치를 명확히 전달합니다.
- **커뮤니티 활성화:** 지역 AI 커뮤니티와의 양방향 소통 채널을 제공하여 참여를 증대시키고, Catch Up AI의 영향력을 확대합니다.
- **브랜드 인지도 및 전문성 강화:** 전문적인 웹사이트를 통해 Catch Up AI의 신뢰도를 높이고, AI 학습 방법론 연구 분야의 리더십을 확보합니다.
- **지속 가능한 성장 기반 마련:** 잠재적 파트너 및 코호트 참여를 유도하여 장기적인 비즈니스 성장 동력을 확보합니다.

## 4. Technical Context
### 4.1. System Architecture Overview
본 프로젝트는 백엔드 없이 HTML, CSS, JavaScript로만 구성된 정적 웹사이트(Static Website)로 구축됩니다. 콘텐츠는 Product Owner가 AI 코딩 도구를 활용하여 직접 HTML 파일을 수정하는 방식으로 관리하며, Amazon S3를 통해 호스팅됩니다. YouTube 플레이리스트 임베드, Google Forms 연동 등 외부 서비스는 클라이언트 측에서 직접 연동됩니다.

### 4.2. Technical Constraints
- **정적 웹사이트:** 서버리스(Serverless) 아키텍처로 백엔드 개발 및 운영 비용이 없습니다.
- **호스팅:** 기존 사용 중인 Amazon S3 정적 웹사이트 호스팅 사용.
- **예산 제약:** 유료 서비스 사용을 최소화하고 단순한 기술 스택을 유지합니다.
- **개발 방식:** AI 코딩 도구를 활용한 Vibe Coding 방식으로 개발을 진행합니다.
- **데이터베이스 부재:** 동적 콘텐츠 관리 시스템(CMS) 없이 HTML 파일 직접 수정을 통한 콘텐츠 업데이트.
- **YouTube API 사용 제한:** YouTube Data API v3의 무료 할당량(일 10,000 units) 내에서만 사용합니다.

### 4.3. Scalability Requirements
- **트래픽 증가 대응:** 초기에는 S3 호스팅만으로 충분하나, 트래픽이 급증할 경우 Amazon CloudFront CDN을 추가하여 성능을 확보할 수 있습니다.
- **콘텐츠 증가 대응:** 콘텐츠 양이 증가할 경우, JSON 기반 동적 로딩 방식으로 전환을 고려하여 확장성을 확보합니다. Product Owner가 JSON 파일만 수정하도록 하여 HTML 직접 수정의 부담을 줄일 수 있습니다.
- **다국어 지원:** 초기부터 한국어/영어 다국어 지원을 구현하여 글로벌 사용자에게 확장 가능한 구조를 갖춥니다.

## 5. Functional Requirements
### 5.1. Core Features
- **메인 페이지:**
    - Catch Up AI 소개 및 핵심 메시지 (Priority: Must Have)
    - 5가지 핵심 프로젝트(Vibe Coding, Vibe Learning, Vibe Guiding, AI4PKM, 시애틀 AI 생태계) 개요 및 각 프로젝트 상세 페이지로의 링크 (Priority: Must Have)
    - 최신 YouTube 영상 또는 추천 영상 썸네일 및 링크 (Priority: Must Have)
    - 뉴스레터 구독 CTA (Priority: Must Have)
    - 소셜 미디어 링크 (YouTube, LinkedIn 등) (Priority: Must Have)
- **프로젝트 상세 페이지 (각 5개 프로젝트별):**
    - 각 프로젝트의 목표, 주요 내용, 진행 방식 상세 설명 (Priority: Must Have)
    - 관련 YouTube 플레이리스트 임베드 (최신 영상 자동 반영) (Priority: Must Have)
    - Product Owner가 선별한 '추천 영상' 3-5개 표시 (Priority: Should Have)
    - 프로젝트별 특징 및 가치 시각화 (Priority: Should Have)
    - 관련 커뮤니티 활동(예: AI4PKM 코호트 신청) CTA (Priority: Must Have)
- **AI4PKM 코호트 신청 페이지:**
    - 코호트 소개 및 참여 안내 (Priority: Must Have)
    - Google Forms 연동을 통한 신청 기능 (Priority: Must Have)
- **시애틀 AI 생태계 페이지:**
    - 시애틀 AI 커뮤니티 소개 및 Catch Up AI의 역할 설명 (Priority: Must Have)
    - 시애틀 AI 관련 이벤트 정보 (수동 업데이트 방식) (Priority: Must Have)
    - 관련 외부 커뮤니티 및 리소스 링크 (Priority: Should Have)
- **뉴스레터 구독 페이지/섹션:**
    - 뉴스레터 구독 양식 (Google Forms 연동) (Priority: Must Have)
    - 뉴스레터 샘플 보기 기능 (Priority: Nice to Have)
- **다국어 지원:**
    - 한국어/영어 전환 버튼 (페이지 간 전환) (Priority: Must Have)
    - 모든 콘텐츠의 한국어 및 영어 버전 제공 (Priority: Must Have)
- **반응형 디자인:**
    - 데스크톱, 태블릿, 모바일 환경에서 최적화된 레이아웃 및 기능 제공 (Priority: Must Have)

### 5.2. User Stories
- **콘텐츠 탐색:**
    - As a AI 학습자, I want to easily find information about Catch Up AI's 5 core projects so that I can understand their value and choose what to explore further.
    - As a new visitor, I want to see a clear overview of Catch Up AI's methodology (Vibe Coding -> Vibe Learning -> Vibe Guiding) so that I can understand its logical progression.
    - As a YouTube subscriber, I want to find the latest videos related to a specific project on the website so that I don't miss new content.
- **커뮤니티 참여:**
    - As a Seattle AI community member, I want to quickly find upcoming AI events so that I can plan my participation.
    - As a potential cohort participant, I want to easily apply for the AI4PKM cohort so that I can join the learning program.
    - As an interested user, I want to subscribe to the newsletter so that I can receive updates from Catch Up AI.
- **사이트 경험:**
    - As a global user, I want to switch between Korean and English content so that I can consume information in my preferred language.
    - As a mobile user, I want the website to be easy to navigate and read on my smartphone so that I can access information on the go.

## 6. Non-Functional Requirements
### 6.1. Performance
- **페이지 로딩 시간:** 모든 페이지는 3초 이내에 로드되어야 합니다. (목표: 2초 이내)
- **응답 시간:** 사용자 인터페이스 요소의 클릭 또는 상호 작용에 대한 응답 시간은 1초 이내여야 합니다.
- **동시 접속자:** 월간 최대 10,000명의 동시 접속자를 안정적으로 처리해야 합니다.

### 6.2. Security
- **HTTPS:** 모든 트래픽은 HTTPS를 통해 암호화되어야 합니다.
- **데이터 보호:** Google Forms를 통해 수집되는 개인 정보(이름, 이메일 등)는 Google의 보안 정책을 따르며, Catch Up AI 웹사이트 자체에서는 민감한 개인 정보를 직접 저장하지 않습니다.
- **악성 코드 방지:** 웹사이트에 악성 코드가 삽입되거나 배포되지 않도록 정기적인 보안 점검을 고려합니다.

### 6.3. Usability
- **직관적인 내비게이션:** 사용자가 원하는 정보를 최소한의 클릭으로 찾을 수 있도록 명확하고 일관된 내비게이션 구조를 제공해야 합니다.
- **접근성:** 웹 콘텐츠 접근성 지침(WCAG) 2.1 AA 수준을 준수하여 다양한 사용자가 접근할 수 있도록 노력합니다.
- **일관된 UX/UI:** Catch Up AI의 브랜드 아이덴티티를 반영하는 일관된 디자인 시스템을 적용하여 전문성과 신뢰성을 전달해야 합니다.

### 6.4. Reliability
- **가용성:** 웹사이트는 연중무휴 99.9%의 가용성을 유지해야 합니다.
- **백업 및 복구:** S3에 호스팅되는 정적 파일은 S3의 기본 복원력을 따르며, Git을 통해 버전 관리를 하여 필요한 경우 이전 버전으로 복구할 수 있습니다.
- **오류 처리:** 사용자에게 친숙한 오류 메시지를 제공하여 문제가 발생했을 때 사용자가 상황을 이해할 수 있도록 합니다.

## 7. Constraints & Assumptions
### 7.1. Budget Constraints
- 본 프로젝트는 예산이 거의 없는 개인 프로젝트이므로 유료 서비스 사용을 최소화하고 무료 또는 저렴한 솔루션을 우선적으로 활용합니다.
- 개발 및 유지보수 비용은 최소화되어야 합니다.

### 7.2. Timeline
- MVP(최소 기능 제품)는 2026년 3분기 내에 완성하는 것을 목표로 합니다.
- 전체 기능 구현 및 고도화는 2026년 4분기까지 점진적으로 진행됩니다.

### 7.3. Assumptions
- Product Owner는 AI 코딩 도구를 활용하여 HTML 파일을 직접 수정하고 Git을 통해 배포할 수 있는 기본적인 기술 역량을 갖추고 있습니다.
- Google Forms, Google Sheets, YouTube Embed 등 외부 무료 서비스는 안정적으로 운영될 것입니다.
- 초기에는 복잡한 동적 콘텐츠나 사용자 상호작용 기능이 필요하지 않을 것입니다.
- 콘텐츠 관리를 위한 별도의 CMS 솔루션은 도입하지 않습니다.

## 9. Dependencies
- **YouTube:** YouTube 채널 콘텐츠(영상, 플레이리스트) 제공 및 임베딩.
- **Google Forms:** AI4PKM 코호트 신청 및 뉴스레터 구독 기능 제공.
- **Google Sheets:** Google Forms를 통해 수집된 데이터 저장.
- **Amazon S3:** 웹사이트 호스팅 인프라 제공.
