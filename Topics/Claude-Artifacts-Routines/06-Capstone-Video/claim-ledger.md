## 적용 범위

[슬라이드 플랜](video-slide-plan.md)의 모든 장면 S01–S28을 C01–C28로 대응시킨다. 공개 후보는 확인된 경험·최소 실습·설명 도식이며, 내부 자료·비공개 계정 정보 원본은 제작 에셋으로 옮기지 않는다. 공개 가능한 내용이라도 실제 화면은 개인정보 가림과 자료 경계 검수가 필요하다. 사용자 구술 인용은 볼트의 원문을 확인했으며 공개 영상에 쓸 정확한 문장을 아래에 보존한다.

## 기록을 읽으며 확인한 정정과 미확인 사항

- M2의 댓글 불가 결론은 M3의 작성자 댓글 실측으로 정정됐다. 공개 링크 방문자까지 확인한 기록은 없다.
- M2의 공개 db 페이지·익명 데이터 불가 실측과 M3의 조직 내부 공유 규칙은 같은 조건이라고 단정할 수 없다. 공유 범위의 최신 결론은 보류하고 당시 날짜를 붙인다.
- M1·M2의 5개 watch와 M3의 10개 watch 기록도 시점이 달라 현재 숫자로 소개하지 않는다.
- Topic README는 M2 45분, M2 WorkLog는 55분이다. 영상에서 전체 실소요나 시간 절약 수치를 사용하지 않는다.
- WBLP의 실패 푸시를 「알림 전무」로 오해하면 안 된다. 실패를 운영 문제로 읽는 데 시간이 걸렸다는 내용으로 표현한다.
- 과거의 환경 설정 캡처·현재 실행 상태·메일 본문은 이 폴더에 확보돼 있지 않다. [캡처 요청](capture-request.md)을 따른다.

## 공식 문서와 공개 자료 확인

2026-10-04 [Claude Code Artifact 공식 문서](https://code.claude.com/docs/en/artifacts)와 [Routines 공식 문서](https://code.claude.com/docs/en/routines)에 접근했다. 두 기능의 제품 범위·정의와 댓글 접근 조건을 확인했으며, 현재 공개 문서만으로 로컬 runtime contract의 db 공유 규칙 차이를 해결하지 않았다. 과거 실측을 최신 계정의 사용 가능성으로 확대하지 않는다.

공개 GitHub 원격은 `solkit70/CatchUpAI_VL`, 브랜치는 `main`이다. Topic README·공유 실험·db 왕복·루틴 audit·local-vs-cloud·플레이북의 raw 파일 GET은 모두 HTTP200으로 확인했다. [플레이북 페이지](https://github.com/solkit70/CatchUpAI_VL/blob/main/Topics/Claude-Artifacts-Routines/05-Usage-Patterns/guides/artifacts-routines-playbook.md) 본문도 읽었다. 이 확인은 링크가 공개 접근된다는 뜻이며, 각 문서의 상충하는 주장까지 새 실측으로 검증했다는 뜻은 아니다.
