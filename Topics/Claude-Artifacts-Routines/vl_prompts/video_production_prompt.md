## 사용 방법

이 문서를 영상 제작 AI에게 읽히고 「이 프롬프트에 따라 영상 제작을 시작해 주세요」라고 요청한다. 아래 실행 지시는 새 대화에서도 그대로 사용할 수 있으며, 첫 실행에서는 자료 검토와 슬라이드 플랜까지 작성한 뒤 사용자 리뷰를 받는다. 이후 승인된 단계부터 이어서 진행한다.

## 실행 프롬프트

당신은 실제 학습·실험 기록을 시청자가 이해하기 쉬운 영상으로 만드는 기획자이자 Remotion 제작자다. 아래 Topic의 학습 결과를 바탕으로 한국어 YouTube 영상을 제작하라. 사용자는 학습을 마쳤으며, 이제 그 정보와 경험을 다른 사람에게 전달하려고 한다. M1부터 학습을 다시 시작하지 말고, M6 영상 제작으로 이어 간다. 영상이 완성됐다고 미리 기록하지 않는다.

### 2. 영상의 목적과 시청자

기본 시청자는 Claude의 Artifacts·Routines를 처음 접하는 일반인이다. 시청자가 다음을 이해하고 자기 일에 적용할 수 있도록 설명한다.

1. Artifacts와 Routines가 각각 무엇을 하는지, 실제 어떤 일을 맡길 수 있는지.
2. 사람이 도구 이름을 몰라도 명확한 목적을 제시하면 AI가 적합한 기능을 찾아 제안할 수 있다는 사용자의 경험.
3. 만들어진 결과가 실제로 공유되고 작동하는지 사람이 확인해야 하는 이유.
4. 공유 대상, 데이터 변경, 자동화 실행 환경·알림을 어떤 기준으로 선택하는지.
5. 자세한 재현 방법은 공개된 GitHub 학습 자료와 플레이북에서 찾는 방법.

**분량 상한은 없다.** 5~8분이나 고정 슬라이드 수에 맞춰 설명을 줄이지 않는다. 필요한 장면을 먼저 구성한 뒤 내레이션과 실측 음성 길이로 러닝타임을 산정한다. 같은 설명을 반복해 길이를 늘리지 않고, 길어질 경우 챕터와 짧은 중간 정리로 흐름을 돕는다. 한국어 본편을 기본으로 하며 영어판은 별도 요청이 있을 때 제작한다.

- 로컬 볼트 접근 여부는 이번 볼트·클라우드 환경의 조건이다. 모든 클라우드 자동화가 어떤 로컬 자료도 활용할 수 없다고 일반화하지 않는다.
- 계정·공유 범위·비용·커넥터 권한·기능 제공 여부 등 바뀔 수 있는 내용을 현재 사용법으로 설명하려면 공식 출처와 실제 환경에서 다시 확인한다. 확인할 수 없으면 학습 당시 날짜와 조건을 명시한다.

`visibility: internal` 또는 「🔒 내부 자료」가 있는 내용은 공개 영상·제작 에셋으로 옮기지 않는다. 실습 예제가 비공개라는 것은 그 예제를 시청자가 직접 열 수 없다는 뜻이며, 공유 상태를 임의로 바꾸지 않는다. 내부 자료를 포함한 장면은 공개 가능한 최소 예제나 도식으로 대체한다.

### 4. 서사와 장면 구성

가제는 **「내가 몰랐던 기능을 AI가 찾아냈다 — Claude Artifacts와 Routines를 실제 일에 써 본 경험」**이다. 자료를 검토한 뒤 과장 없는 제목 후보 3개와 추천안을 제시한다. 기능 목록을 읽는 강의보다 사용자의 실제 문제·결과·시행착오를 연결한 이야기로 구성한다.

다음 흐름을 출발점으로 삼되, 장면 수와 챕터 길이는 필요한 설명에 맞춰 조정한다.

1. **첫 30초**: 실제 결과와 「이 도구 이름을 몰랐는데 어떻게 만들었을까요?」 같은 질문으로 시작한다. 기능 이름을 아는 것보다 목적을 설명하고 결과를 검증하는 경험을 예고한다. 과장된 능력 주장이나 근거 없는 통계를 Hook으로 쓰지 않는다.
2. **발견의 계기**: 실제 일에서 두 기능을 만난 과정과 Journal의 구술을 보여 준다. 회의 중 만든 결과는 확인된 사례·자료만 사용한다.
3. **두 기능의 쉬운 설명**: Artifact는 결과를 보고 사용하는 페이지·앱, Routine은 정해진 때 실행되는 작업이라는 비유를 제시하고, 실제 작동 환경과 한계를 덧붙인다.
4. **Artifact의 실제 가치와 경계**: 공유용 정적 페이지와 함께 바꾸는 데이터를 비교한다. 필요한 사람에게 링크가 열리는지, 최신 버전이 보이는지 확인하는 과정을 보여 준다.
5. **사람과 AI가 같은 데이터를 바꿀 때**: 카운터 실험을 Before → 사람 수정 → 오래된 버전의 AI 수정 거부 → 다시 읽고 수정 순서로 시각화한다. 전문 용어는 화면에 보조로 쓰고 내레이션은 쉬운 말로 설명한다.
6. **목적에 맞는 기능 고르기**: user·assets·comments·다중 파일은 실제 쓰임 중심으로 소개한다. 필요하면 장면을 나누고, 세부 코드 전체는 GitHub 자료로 연결한다.
7. **자동화가 조용히 실패한 경험**: WBLP 실패 이력, 환경 제한 진단, 복구와 정기 실행 확인을 시간 흐름으로 보여 준다. 「결과가 없어서 조용함」과 「실패해서 조용함」을 비교한다.
8. **두 번째 루틴과 선택 기준**: 일회성·커넥터·항상 알림 사례를 앞 사례와 비교한다. 로컬 파일이 필요한 일인지, 외부 자료만으로 가능한지에 따라 실행 위치를 고르는 흐름을 보여 준다.
9. **시청자가 가져갈 기준**: 플레이북의 세 질문과 핵심 확인 절차를 정리한다. 목적·공유 대상·실행 위치·결과 확인을 AI에게 어떻게 요청하면 되는지 짧은 요청 예시를 제시하되, 예시는 실측과 구분한다.
10. **마무리**: 사용자가 일하며 배우고 기록한 경험을 정리하고, 관련 GitHub 자료로 다음 행동을 안내한다. 미검증 조건도 필요한 위치에서 명확히 알린다.

댓글 기능 판단을 정정한 경험은 「기록을 모으니 틀린 결론을 발견했다」는 짧은 장면으로 넣는 것을 기본안으로 제안한다. 포함 여부는 첫 플랜 리뷰에서 사용자가 결정할 수 있도록 표시한다.

### 5. 시각 자료와 설명 품질

밝은 배경, 충분한 대비·글자 크기, 한 장면 한 핵심을 지킨다. 화면에는 핵심 단어·라벨·도식을 남기고 자세한 설명은 내레이션이 맡는다. 용어는 첫 등장 때 쉬운 말로 풀며, 설정 안내는 「어디를 열고 → 무엇을 선택하고 → 어떤 결과를 확인하는가」가 실제 화면과 연결되도록 구성한다.

- 흐름은 `[WORKFLOW]`, 차이는 `[COMPARE]`, 실행 이력은 `[TIMELINE]`, 원문 인용은 `[QUOTE]`, 실물은 실제 화면 캡처로 표현한다. 숫자는 근거가 있는 경우에만 `[STAT]`로 쓴다.
- 같은 장면 유형을 세 장 이상 연속 사용하지 않는다. 동적 배경과 모션은 읽는 순서·변화를 돕는 수준으로 적용한다. 복잡한 코드나 긴 표를 한 화면에 축소하지 않는다.
- 실제 UI·설정·성공 결과는 실제 캡처를 사용한다. 없는 캡처를 AI 이미지로 만들어 실제 화면처럼 보여 주지 않는다. 설명용 재구성은 명확히 표시한다.
- 캡처가 부족하면 `capture-request.md`에 필요한 화면, 캡처 시점·행동, 보여야 할 요소, 민감 정보 가림 범위를 적는다. 확보된 자료로 나머지 기획을 진행하고 필요한 자료를 구체적으로 요청한다.
- AI 이미지는 개념·비유·전환 장면에 활용하고, 짧은 무음 클립은 필요한 소수 장면에만 사용한다. 기본은 사용자가 직접 생성할 수 있는 이미지·영상 프롬프트 문서다. API 직접 생성은 명시적 요청이 있을 때만 한다.
- 생성 프롬프트의 각 코드블록은 독립적으로 복사해 쓸 수 있게 스타일, 장면, 구성, 비율·해상도, 텍스트 공간, 금지 요소를 포함한다. 영상은 길이, 프레임률, 무음, 카메라와 움직이는 대상까지 블록 안에 적는다.
- 관련 장면에 공개 GitHub 문서의 QR과 짧은 목적 설명을 배치한다. 실제 원격 레포·브랜치·파일 경로와 공개 접근을 확인하고 생성한다. 비공개 Artifact URL이나 존재하지 않는 GitHub 페이지로 QR을 만들지 않는다. 미게시 문서는 준비 필요 상태로 표시한다.
- 이전 효과를 참고하되 이번 이야기에 맞는 새로운 표현을 시도한다. 버전 충돌이나 조용한 실패를 설명하는 모션처럼 내용 이해에 도움이 되는 새 기법을 우선한다.

### 6. 제작 위치와 산출물

Topic의 영상 기획·근거·요청 문서는 `06-Capstone-Video/`에 저장하고, 구현 프로젝트는 **`AI/RemotionStudio/`**에 만든다. 기존 영상과 충돌하지 않는 video-id를 확인해 정하고, 다른 영상의 코드·음성·에셋을 덮어쓰지 않는다. 기획 문서는 Topic의 파일을 기준으로 관리하고 구현에서 그 경로를 참조해 서로 다른 사본이 생기지 않게 한다.

단계에 맞춰 필요한 문서만 생성·갱신한다.

- Topic `06-Capstone-Video/`: `video-slide-plan.md`, `claim-ledger.md`, `capture-request.md`(필요할 때), `assets/`(공개 가능한 자료), `upload-materials.md`, 실제 진행을 안내하는 `README.md`.
- Topic `vl_worklog/`: 실제 작업 날짜 기준 M6 WorkLog, 완료 후 최종 회고.
- RemotionStudio: 독립된 영상 컴포넌트·데이터, `public/<video-id>/`의 이미지·영상 생성 프롬프트와 음성·에셋, `out/`의 최종 MP4. 정확한 파일 구조는 현재 제작 스킬과 프로젝트 구성에 따른다.

### 7. 실행 단계와 사용자 리뷰

**첫 실행에서는 1단계 결과를 완성해 제시하고 리뷰를 기다린다.** 사용자가 이미 승인한 단계를 새 대화에서 반복 승인받지 말고, 기록을 확인해 다음 필요한 단계부터 진행한다.

1. **자료 검토·슬라이드 플랜**: 제목 추천, 대상 시청자, 영상의 약속, 챕터, 예상 분량과 산정 근거, 밝기·테마, 장면별 핵심·화면 문구·시각 자료·모션·내레이션 초안·출처·QR 목적지를 작성한다. 근거 대장과 누락 캡처 요청을 함께 만든다. 최초 예상 시간은 확정값이 아니라 설명 분량을 바탕으로 한 추정임을 밝힌다. 사용자에게 검토 가능한 플랜을 보여 준 뒤 승인받는다.
2. **자료 준비·화면 구현**: 승인된 플랜에 따라 생성 프롬프트와 확보한 실제 자료로 화면을 구현하고 Studio 미리보기를 제시한다. 시각 리뷰와 수정 내용을 반영한다. 캡처·AI 자료가 미확보면 임시 요소를 분명히 표시하고 최종 완료로 처리하지 않는다.
3. **edge-tts 초벌**: 발음·문장·길이·흐름을 확인할 음성을 만들고 실제 길이로 타이밍을 갱신한다. 사용자가 들을 수 있는 파일·미리보기를 제공해 리뷰받는다. 이 단계에서는 MP4를 렌더링하지 않는다.
4. **Qwen3-TTS 최종 음성**: 초벌 승인 뒤 스킬에 따라 음성을 교체하고 길이를 다시 측정해 전체 타이밍을 조정한다. 음성 합성이 불가능하면 원인과 선택지를 알려 주고, 초벌을 임의로 최종본으로 간주하지 않는다. 최종 음성을 사용자에게 확인받는다.
5. **자막·최종 렌더**: 자막 사용 범위를 플랜 리뷰에서 정한다. 사용하면 확정 음성에 동기화하고 가독성·발음·누락·싱크를 확인한다. 사용자 승인 후 최종 렌더링하고 대표 장면 및 전환·음성 구간을 검수한다.
6. **전달·공개 준비**: MP4와 제목·설명·챕터·태그·썸네일 방향·관련 GitHub 링크·필요한 라이선스 표기를 전달한다. 업로드와 SNS 게시는 사용자가 명시적으로 요청한 범위에서만 수행한다. 실제 게시 전에는 URL이나 공개 완료 상태를 만들지 않는다. WorkLog·로드맵·README에 실제 상태를 반영하고, 최종 회고는 확인된 제작 결과를 기준으로 작성한다.

TTS는 화면 표기와 음성 발음을 분리해 관리한다. 한국어 월·브랜드 발음 등은 현재 스킬 기준으로 보정하며, 이름·제품명·버전·숫자를 실제로 들어 확인한다. 배경음악과 효과음은 YouTube 사용 권한·출처가 확인된 자산만 사용하고 내레이션을 가리지 않게 한다. 라이선스가 확인되지 않으면 사용하지 않는다.

### 8. 첫 결과에 포함할 항목과 완료 기준

첫 응답에는 「핵심 서사와 추천 제목」「챕터 흐름과 예상 길이」「저장한 슬라이드 플랜·근거 대장 경로」「필요한 캡처·미확인 사항」「사용자가 검토할 결정 사항」을 간결하게 제시한다. 계획만 말하고 끝내지 말고, 승인 범위 내에서 자료를 읽고 검토 가능한 초안을 실제 파일로 저장한다.

최종 전달 전 아래를 확인한다.

- [ ] 초심자가 두 기능의 차이와 자신의 일에 적용하는 기준을 이해할 수 있다.
- [ ] 첫 30초의 약속이 실제 본문으로 충족되고, 분량 때문에 핵심 설명이 잘리지 않았다.
- [ ] 장면마다 핵심 하나·근거·적절한 시각 자료가 있고, 원문 인용과 정정이 정확하다.
- [ ] 실제 UI와 설명용 재구성이 구분되고 내부 자료·개인정보가 노출되지 않는다.
- [ ] QR은 관련 공개 문서로 연결되고 실제로 스캔된다.
- [ ] 작은 화면 가독성, 텍스트 잘림, 자료 누락, 음성·자막 싱크를 확인했다.
- [ ] 초벌·최종 음성 리뷰 및 렌더 승인 이력이 있고, 음원 출처가 기록됐다.
- [ ] 최종 MP4·업로드 자료·실제 작업 상태·문서 링크가 서로 일치한다.
