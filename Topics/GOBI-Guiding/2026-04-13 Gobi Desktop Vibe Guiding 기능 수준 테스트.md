## 1. 테스트 개요

*   **일시**: 2026-04-13
*   **테스트 대상**: Gobi Desktop 내 커스텀 홈페이지 제작 기능 (Applet 제작 가이드)
*   **목표**: 현재 Gobi Desktop이 제공하는 가이드(Vibe Guiding 초기 단계)가 사용자의 실질적인 작업 완수를 얼마나 효과적으로 돕는지 확인

## 2. 테스트 결과 및 분석

### ✅ 긍정적 측면
*   **대화 기반 인터페이스**: AI와의 자연스러운 대화를 통해 작업 단계에 진입하고 기본적인 안내를 받는 흐름은 원활함.
*   **기본 지식 제공**: 현재 AI가 기본적으로 알고 있는 범위 내에서의 기능 설명과 코드 예제 제시는 적절함.

### ⚠️ 발견된 한계점 (Blockers)
*   **가이드 정밀도 부족**: 제공되는 안내가 실제 복잡한 설정을 완료하기에는 충분히 세밀하지 않음.
*   **작업 완수 실패**: 숙련된 유저임에도 불구하고, AI의 가이드만 따라가서는 최종적인 홈페이지 제작 및 적용 과정을 끝까지 마칠 수 없었음.
*   **컨텍스트 단절**: 사용자의 현재 설정 상태(Vault Path, Applet 경로 등)를 실시간으로 정확히 파악하여 가이드에 반영하는 능력이 아직 부족함.

## 3. 향후 보완 및 개선 방향

### 🚀 Vibe Guiding 엔진 강화 포인트 (추가 인사이트)

1.  **가이드 응답의 일관된 퀄리티 유지**:
    *   질문에 대한 답변이 여러 번 반복될 때 첫 번째와 두 번째 답변의 품질 차이가 크지 않아야 함.
    *   **퀄리티 체크 프로세스 도입**: 가이드가 출력되기 전, 반드시 '퀄리티 검증용 프롬프트(Quality Check Prompt)'를 거쳐 답변의 정확성과 정밀도를 상향 평준화해야 함.
    *   **코딩 로직 통합**: 단순 프롬프트 제어를 넘어, 앱 내 코딩 로직을 통해 출력 전 단계에서 답변의 품질을 강제하거나 보정하는 시스템 구축 필요.

2.  **사용자 상태 기반의 동적 가이딩 (User Status Collection)**:
    *   **정확한 정보 수집**: 현재 앱의 버전, 사용자의 OS 환경, 언어 설정(한/영 등), 현재 설정값 등을 실시간으로 수집하여 가이드에 반영해야 함.
    *   **할루시네이션 방지**: 이번 테스트에서 앱에 존재하지 않는 메뉴를 안내한 사례가 발생함. 지어낸 정보(할루시네이션)를 방지하기 위해 사용자의 실제 UI 상태를 확인하는 로직 필수.
    *   **동적 가이드 매핑**: 버전 업그레이드에 따른 버튼 위치 변경(A → B), 메뉴 명칭 변경 등을 추적하여 해당 유저의 버전에 맞는 정확한 가이드를 제공하는 '스테이터스 관리' 시스템 구축.
    *   **매뉴얼 구조화**: 가이드의 기반이 되는 매뉴얼 자체에서도 각 스테이터스/버전별로 기능 차이를 별도로 정리하여 AI가 혼동 없이 참조하도록 설계.

3.  **하이브리드 커뮤니케이션 활용 (Text/Image/Video)**:
    *   **매체별 정보 특성 활용**: 텍스트, 이미지, 영상은 각각 담고 있는 정보의 종류와 밀도가 다름을 인지하고 상황에 맞게 조합해야 함.
    *   **영상(Video)**: 정보량이 가장 많고 직관적이지만, 제작 및 소비에 시간과 속도 측면의 제약이 있음.
    *   **이미지(Image)**: 많은 시각적 정보를 빠르게 전달할 수 있는 강점이 있음.
    *   **텍스트(Text)**: 논리적 구조나 명확한 수치 등 텍스트로만 정교하게 표현 가능한 정보 영역이 존재함.
    *   **전략적 하이브리드 가이딩**: 가이드 제공 시 각 전달 매체의 장점을 극대화하여, 복잡한 단계는 영상으로, 위치 확인은 이미지로, 상세 설정값은 텍스트로 제공하는 식의 '하이브리드 소통 모델' 연구 필요.
    *   **개발팀 피드백 루프**: 가이드 과정 중 발생하는 디펙트 보고 시에도 이러한 하이브리드 방식을 적용하여 소통 효율을 극대화함.
