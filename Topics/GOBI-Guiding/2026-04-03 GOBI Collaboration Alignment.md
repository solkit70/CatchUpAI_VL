## 1. 현재 상황

팀이 나에게 기대하는 것과 내가 실제로 만들려는 것 사이에 간격이 있다.

> 팀의 기대: "문서(매뉴얼)를 만들어 줘"
> 나의 목표: "가이딩 시스템을 만들겠다"

## 2. 팀이 기대하는 나의 역할

Jin이 정의한 공식 역할:

- User Manual 작성자
- 기존 AI for Better Me 문서 대체
- 잘 정리된 구조화된 문서 제공
- 사용자 이해 중심

팀이 상정하는 흐름:

```
Spec → Manual → (사용자가 읽는다)
```

## 3. 현재 기대의 한계

Mika의 발언:

> "I don't want to think"

이 말이 시사하는 것:
- 문서는 필요하다
- 그러나 문서만으로는 충분하지 않다

## 4. 내가 만들려는 것

핵심 아이디어:

```
Manual → Guiding → Action
```

- 매뉴얼은 AI를 위한 구조화된 Context가 된다
- AI가 매뉴얼을 읽고 해석한다
- 사용자는 단계별 안내를 받는다

```
Context → Personalized Guidance → Action
```

## 5. Gap 분석

### Gap 1: 아웃풋 유형

| 팀 | 나 |
|----|-----|
| 문서 | 행동 중심 가이드 |
| 읽는 것 | 하는 것 |
| 정적 | 동적 |

### Gap 2: 사용자 역할

| 팀 | 나 |
|----|-----|
| 사용자가 읽는다 | AI가 읽는다 |
| 이해가 필요하다 | 이해 불필요 |
| 능동적 사용자 | 수동적 사용자를 지원 |

### Gap 3: 제품 목표

| 팀 | 나 |
|----|-----|
| 문서 시스템 | 경험 시스템 |
| 지식 전달 | 행동 생성 |
| 정보 | 의사결정 지원 |

### 핵심 Gap

> "문서를 만드는 것" vs "사용자의 행동을 이끄는 것"

## 6. 핵심 인사이트

이것은 충돌이 아니다 — **레이어의 차이**다.

매뉴얼과 가이딩은 경쟁 관계가 아니라 순서 관계다. 매뉴얼이 먼저 있어야 가이딩이 가능하다.

## 7. 올바른 시스템 구조

```
Spec (팀)
    ↓
Manual (내 책임)
    ↓
Guiding (내 확장)
    ↓
User Action (최종 목표)
```

> 매뉴얼은 최종 아웃풋이 아니라 중간 레이어다

## 8. 팀 Alignment 전략

### 하지 말아야 할 것

- 문서화를 거부하는 것
- 가이딩을 대체재로 밀어붙이는 것

### 올바른 접근

> 먼저 매뉴얼을 만들고, 그것을 가이딩으로 진화시킨다

### 핵심 포지셔닝 메시지

> "매뉴얼을 기반으로 먼저 만들고, 그것을 가이딩 시스템으로 발전시키겠다"

## 9. 역할 재정의

- **매뉴얼 레이어 오너**: 팀이 기대하는 역할을 충실히 수행
- **가이딩 레이어 빌더**: 그 위에 가이딩을 쌓아 올리는 역할

한 줄 정의:

> "문서를 경험으로 전환한다"

## 10. 실행 단계

### Phase 1 — 팀 기대 충족

- 구조화된 매뉴얼 작성
- 명확성과 사용성 확보
- AI 소비에 최적화된 구조로 설계

### Phase 2 — 가이딩으로 확장

- 매뉴얼을 단계별 플로우로 전환
- 의도 기반 내비게이션 구현
- 개인화 경로 지원

### Phase 3 — 제품 통합

- GOBI Applets과 연결
- 실시간 가이던스 구현
- 가이딩 플로우 자동화

## 11. 매뉴얼 설계 원칙

### 전통적 매뉴얼을 쓰지 않는다

❌ 기존 방식:
> "GOBI를 사용하려면..."

✅ Vibe Manual 방식:
```
목표: GOBI 시작하기

Step 1: 앱 열기
Step 2: Vault 연결
Step 3: "create brain update" 말하기
```

### AI 소비 최적화 원칙

- **Structured**: 명확한 구조
- **Atomic**: 각 단계가 독립적
- **Context-rich**: AI가 판단할 수 있는 맥락 포함

매뉴얼 = Prompt-ready structure

## 12. 팀에게 전달할 메시지

> 매뉴얼 레이어부터 시작하는 것은 좋은 출발점이라고 생각합니다.
> 사람과 AI 모두가 소비하기 좋은 잘 구조화된 매뉴얼을 만드는 데 집중하겠습니다.
> 동시에, 이 매뉴얼을 최종 아웃풋이 아니라 가이딩의 기반으로 바라봅니다.
> 읽는 것이 아니라, 컨텍스트 기반으로 사용자를 단계별로 안내하는 경험으로 진화시키겠습니다.
> 그래서 매뉴얼을 처음부터 가이딩 경험으로 자연스럽게 발전할 수 있는 구조로 설계하겠습니다.

## 13. 성공 기준

1. **팀 기대 충족**: 고품질 매뉴얼 납품
2. **차별화**: 매뉴얼을 가이딩으로 확장
3. **실행으로 증명**: 데모 빌드, 실제 사용 시연

## 14. 핵심 전략

> 매뉴얼을 만든다 → 가이딩으로 진화시킨다 → 경험으로 증명한다

## 15. 최종 결론

> 팀이 부여한 역할로 진입하고
> 그 역할을 제품 방향으로 확장한다

**한 줄 요약**:

> "Transform documentation into guided experience"
