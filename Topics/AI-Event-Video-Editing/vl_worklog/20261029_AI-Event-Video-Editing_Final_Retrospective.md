## 회고의 범위

2026-10-17~2026-10-30 기록을 바탕으로 조사·실습·매뉴얼 작성의 성과와 미완료 항목을 정리했다. 파일명은 로드맵의 최종 회고 경로를 따르지만 **현재는 완료 전 검토 초안**이다. M1·M4·M5와 M6의 일부 DoD가 열려 있고, 사용자 자기평가를 AI가 대신 채우지 않았다.

## 목표별 달성 상태

| 목표 | 근거와 현재 판단 |
|---|---|
| 방법 8개 이상 조사와 비교 | M2의 5개 범주·9개 카드 작성. 문서 조사 완료와 실제 성능 시험을 구분 |
| 추천안 1~2개 | 기존 도구 우선·Vidio 조건부 비교. 의뢰인 환경 미확인으로 최종 도입 확정은 보류 |
| 실제 영상으로 무료 경로 시험 | 로컬 요약·효과, Vidio Free, CapCut 생성형 인트로 실행·다운로드·디코드 확인. 생성형 영상에 의도치 않은 글자가 있어 바로 사용하기 어렵다. Premiere 전달 미실증 |

## 가장 가치 있었던 관찰

**결과의 설명과 실제 타임라인을 함께 확인해야 했다.** Vidio는 수정 완료를 설명했지만 UI 길이는 약 73초로 목표에 미달했다. Transcript에서 구간을 수동 복원한 뒤 UI 150초가 됐으며, 이를 자동 수정 성공으로 기록하지 않았다. → [수정 설명과 결과의 불일치](../04-HandsOn-Highlight/method-B.md#수정-적용-결과--설명과-실제-타임라인의-불일치)

**마무리 컷의 완결성이 사용자 선호에 영향을 줬다.** 사용자는 두 요약의 핵심 선택이 비슷하다고 보았지만 종료가 깔끔한 로컬을 조금 더 선호했다. 한 샘플의 선호를 서비스의 보편적 순위로 바꾸지 않는다. → [사용자 비교 결과를 반영한 판단](../04-HandsOn-Highlight/results-comparison.md#실무-선택에-반영할-판단)

**설명 문구만 믿지 말고 전체 영상을 내려받아 검수해야 했다.** Seedance 생성 설명은 중앙 여백을 만들었다고 했지만 다운로드 MP4에서는 `Penhin`이라는 의도치 않은 글자가 확인됐다. 생성 결과를 내려받아 전체 구간과 오디오를 다시 확인하는 단계가 필요하다. 이 짧은 인트로 생성은 수시간 행사에서 필요한 장면을 자동으로 선정하는 능력을 확인한 것은 아니다. → [다운로드 파일의 전체 프레임 결과](../05-HandsOn-Effects/intro-template-vs-generative.md#2026-10-29-다운로드와-전체-프레임-확인)

## 계획과 실제 진행의 차이

로드맵의 17시간은 계획값이다. 모든 세션의 능동 작업·대기·사용자 검토 시간을 동일 기준으로 측정하지 않아 총 학습 시간이나 절약률을 계산하지 않는다. 렌더 시간과 일부 UI 조작 시간은 각각의 작업 측정값으로만 남긴다.

사용자가 원본 발표 분리와 요약을 요청해 로컬 분리·효과 실습이 구체화됐다. 반면 의뢰인 답변, 장시간 원본의 클라우드 시험, 템플릿 편집기, 유료 XML 전달은 완료되지 않았다. 실습 결과를 얻을 수 있는 경로부터 진전시켰으나 미완료 DoD를 유지하는 관리가 필요했다.

## VibeLearn 방법론에 대한 평가

모듈별 근거·결과·DoD와 WorkLog를 남겨 공식 설명, 실제 계정 관찰, 사용자 평가를 구분할 수 있었다. 사용자 피드백을 받으며 결과를 개선했고, 실패한 수정도 후속 사용자가 확인할 자료로 남았다.

개선점은 상태 동기화와 캡처 계획이다. 최상위·영어 README와 일일 프롬프트가 최신 WorkLog보다 뒤처져 이번 검토에서 맞췄다. 다음 실습부터는 처음부터 공개 가능한 계정·예제 화면을 정하고 단계별 캡처를 수집하면, 사람 얼굴이 있는 기존 화면을 공개 자료로 재사용해야 하는 문제를 줄일 수 있다.

## 매뉴얼 검토와 캡처 상태

문서 기준으로 준비·입력·실행·수정·출력·검수 단계, 지시문 연결과 비용 확인 지점을 대조했다. 지원하지 않는 자연어 입력을 Premiere 전사 패널에 넣도록 안내하지 않았고, Vidio 무료 출력 성공과 v3 저장 미확인을 구분했다. 이는 문서 검토이며 의뢰인 환경에서 재현한 결과가 아니다.

기존 Vidio 처리·자동 수정·수동 보정 화면은 공개 Topic 밖 로컬 비교 폴더에 있다. 실제 행사 인물 화면이 포함된 기록이므로 공개 매뉴얼에 복사하지 않았다. 후속 작업에서 실제 행사 인물이 없는 CapCut 생성형 예제 결과·다운로드 도구·템플릿 로딩 상태 캡처 3개를 확보해 매뉴얼에 넣었다. 다운로드 MP4 전체 프레임은 일부 미리보기와 다르게 의도치 않은 문자를 포함했다. 전체 단계 캡처와 실제 따라 하기 검토는 여전히 필요하다.

## 완료 전 사용자 자기평가

아래 질문은 아직 답변을 받지 않았으며 점수와 응답을 대신 작성하지 않는다. 결과를 검토한 사용자가 답하면 최종 회고에 반영한다.

1. 이 Topic의 추천 순서와 한계를 1분 안에 설명할 수 있는가?
2. 실제 사용할 경로를 고르고, 막힌 단계에서 어떤 공식 자료를 볼지 찾을 수 있는가?
3. 자동 편집 결과의 발언 의미·길이·출력 파일을 검토하고 수정할 수 있는가?
4. 새로운 도구를 같은 기준으로 비교할 수 있는가? 각 항목의 자신감을 1~5로 평가한다.

## 다음 실무 적용

의뢰인의 버전·구독·납품 예시와 업로드 허용 범위를 확인한 뒤 한 짧은 사본으로 따라 하기 검토를 진행한다. Premiere XML과 템플릿 인트로, 미완료 M4 비교 조건을 보완하며, 실제 결제 없이 검증할 수 없는 항목은 의뢰인 계정에서 함께 볼 범위로 정한다. 해당 결과와 자기평가를 반영해 회고를 확정하고 Topic 완료 여부를 판단한다.
