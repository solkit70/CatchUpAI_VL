## 5. 데이터 계획 — CSV + API 병행

### 5-1. 왜 둘 다 쓰는가

**CSV 만으로는 부족하다는 판단이 맞다.** 다만 API 도 CSV 를 완전히 대체하지 못한다.
**서로 못 하는 일이 다르다.**

| | YouTube Studio CSV | YouTube Analytics API |
|---|---|---|
| 차원·지표 조합 | **Studio UI 가 주는 것만** | **임의 조합** (`dimensions` × `metrics`) |
| 일 단위 시계열 | 화면 범위 안에서만 | `dimensions=day` 로 전 기간 |
| 영상별 × 기간 교차 | 어렵다 | **가능** — 시차 분석의 핵심 |
| 유입 경로 | 제한적 | `insightTrafficSourceType` |
| **노출 · 노출 클릭률** | ✅ **여기에만 있다** | 🔴 **없다 (Studio 전용 지표)** |
| 재현성 | 손으로 다시 받아야 함 | **스크립트 재실행** |

> 🔴 **노출/CTR 은 Analytics API 에 없는 것으로 알려져 있다.** 썸네일·제목 효과를 보려면
> **CSV 가 반드시 필요하다.** M1 의 첫 확인 항목으로 넣는다 — 실제로 안 나오는지 API 로 한 번 쳐 보고
> 확정한다. **이 한 가지 때문에라도 CSV 를 버리지 않는다.**

### 5-2. API 구성

| API | 용도 | 스코프 |
|---|---|---|
| **YouTube Analytics API** | 성과 지표 — `views`, `estimatedMinutesWatched`, `averageViewPercentage`, `subscribersGained`, `subscribersLost` | `yt-analytics.readonly` |
| **YouTube Data API v3** | 영상 메타데이터 — 제목·공개일·길이·태그·썸네일 | `youtube.readonly` |

**뽑을 조합 (M1 실습 과제)**

```
① 일 단위 구독 시계열      dimensions=day        metrics=subscribersGained,subscribersLost
                            → 주 단위로 집계 (브레인덤프: "일주일 단위로 뽑아야 할 것 같음")
② 영상별 성과              dimensions=video      metrics=views,estimatedMinutesWatched,
                                                          averageViewPercentage,subscribersGained
③ 유입 경로                dimensions=insightTrafficSourceType
④ 시차 분석용              ②를 공개일 기준 D+1 / D+3 / D+7 / D+14 구간으로 잘라 반복
```

**④ 가 API 를 넣는 진짜 이유다.** 가설 4(조회수 3자리 진입과 구독 증가의 시차)는
**같은 영상을 여러 기간으로 잘라서** 봐야 답이 나오는데, CSV 로는 그 조합을 만들 수 없다.

### 5-3. 인증 — 이미 있는 것을 재사용한다

캘린더 MCP 용으로 만들어 둔 Google Cloud 프로젝트가 있다.

1. **같은 프로젝트**에서 `YouTube Analytics API` + `YouTube Data API v3` 를 켠다
2. OAuth 동의 화면은 이미 프로덕션으로 전환해 둔 상태 — **스코프만 추가**
3. ⚠️ **토큰 파일은 따로 둔다** (`.config/youtube-analytics/token.json` 등).
   캘린더 MCP 의 `tokens.json` 을 건드리면 **달력 연결이 깨진다**
4. 라이브러리: `google-api-python-client`, `google-auth-oauthlib`

> 이 단계가 M1 에서 가장 잘 막히는 곳이다. **막히면 CSV 로 먼저 진행하고 API 는 병행**한다 —
> 발표가 API 설정에 인질로 잡히면 안 된다.

### 5-4. 🔴 지표를 읽을 때의 제약 (발표에도 넣는다)

영상별 구독 지표는 **"그 영상의 시청 페이지에서 구독을 누른 횟수"** 뿐이다.

> *"will only include statistics from the specified video's watch page"*
> *"Channels can gain or lose subscribers in several places, including the video watch page,
> the channel page, and the guide"*

즉 **A 영상을 보고 마음이 움직였는데 채널 페이지에서 구독하면 공이 A 에 안 간다.**
그래서 **구독자 증가는 기여의 하한선으로만** 읽고, **구독자 감소는 원인 추적에 쓰지 않는다.**

또 하나 — **Analytics API 데이터는 보통 며칠 지연된다.** 발표 전날 숫자를 넣으려면
그 점을 감안해 **집계 마감일을 명시**한다 (*"9/14 기준"* 처럼).

이 한계를 발표에서 **먼저 밝히고 시작하는 것**이 오히려 신뢰를 만든다.
