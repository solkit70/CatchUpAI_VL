### Topic 소개

구독자 4,300명 부근에서 횡보하다 마이너스로 꺾였던 유튜브 채널을 AI와 함께 되살린 과정을,

2026-06 `The-AI-Powered-Creator` 토픽(채널 2년 여정 P1~P4)의 **속편**이다. 1편이
*"여기까지 어떻게 왔나"* 였다면 2편은 *"바닥을 치고 어떻게 되돌렸나"* 이고,

> 🎬 **별도 산출물 하나가 추가됐다 (2026-09-10 사용자 지시)** — **기술 영상**.
> 발표가 «무엇을 했더니 숫자가 어떻게 됐나» 라면, 이 영상은 «그 숫자를 어떻게 얻었나» 다.

## 📖 모듈별 상세 계획

### M1 — 데이터 파이프라인과 P5 정의

**난이도**: ⭐⭐⭐
**예상 시간**: 5h
**산출물 폴더**: `01-Data-Pipeline/`

#### 학습 목표

- [ ] Google Cloud 프로젝트에 YouTube Analytics API·Data API v3 를 켜고 OAuth 스코프를 추가할 수 있다
- [ ] `youtubeAnalytics.reports.query` 를 호출해 **200 응답**을 받을 수 있다
- [ ] 일 단위 구독자 시계열을 뽑아 **주 단위로 집계**할 수 있다
- [ ] **횡보 시작 시점과 마이너스 전환 시점을 날짜와 숫자로 특정**할 수 있다
- [ ] 1편 형식(`youtube-channel-growth-analysis.md`)으로 **P5 구간 분석 문서**를 쓸 수 있다

#### 주요 개념

1. **Analytics API vs Data API** — 앞은 **성과 지표**(조회수·시청시간·구독 증감), 뒤는 **메타데이터**(제목·공개일·길이·태그). 둘을 영상 ID 로 붙여야 「어떤 영상이 어떻게 됐나」가 나온다.
2. **dimensions × metrics** — Analytics API 의 핵심. `dimensions=day` 면 시계열, `dimensions=video` 면 영상별. **이 조합의 자유가 CSV 와의 결정적 차이**다.
3. **스코프와 토큰 분리** — 이미 있는 OAuth 클라이언트를 재사용하되 **토큰 파일은 반드시 따로 둔다.** 캘린더 MCP 의 `tokens.json` 을 덮으면 달력 연결이 깨진다.
4. **노출·CTR 은 Studio 전용으로 알려져 있다** — Analytics API 에 없다면 **CSV 를 버리면 안 되는 이유**가 된다. ⚠️ 이건 확인 대상이지 확정된 사실이 아니다. 실습 2에서 직접 쳐 보고 판정한다.
5. **Phase 정의** — 1편의 P1(DL 입문) → P2(외부 기술 전달) → P3(라이브) → P4(AI 영상)를 잇는 **P5**. 시작점을 어디로 잡느냐가 발표 서사의 출발점이다.

#### 실습 과제

**실습 1: YouTube Studio CSV 확보** ⭐
- **목적**: API 가 막혀도 발표가 살아 있게 하는 **안전판**을 먼저 만든다
- **단계**:
  1. YouTube Studio → 분석 → 고급 모드 진입
  2. **1편과 같은 폴더 구조**로 4종을 내려받는다 — `SubscribersByContents` · `ViewsByContens` · `WatchHoursByContents` · `RevenuebyContents` (각 `Chart data.csv` · `Table data.csv` · `Totals.csv`)
  3. 기간은 **2026-06-01 ~ 오늘** (P5 구간을 넉넉히 덮는다)
  4. `01-Data-Pipeline/data/youtube-analytics/` 에 저장
  5. **노출·노출 클릭률** 열이 있는 export 도 함께 받는다
- **예상 시간**: 30분
- **검증**: 폴더에 CSV 12개 이상, `Totals.csv` 를 열어 구독자 수치가 보인다

**실습 2: OAuth 연결과 첫 호출** ⭐⭐
- **목적**: API 경로를 뚫는다. **여기가 이 모듈에서 가장 잘 막히는 곳**이다
- **단계**:
  1. Google Cloud Console 에서 **기존 프로젝트**에 `YouTube Analytics API` + `YouTube Data API v3` 사용 설정
  2. OAuth 동의 화면에 스코프 추가 — `yt-analytics.readonly`, `youtube.readonly`
  3. 패키지 설치
     ```powershell
     python -m pip install google-api-python-client google-auth-oauthlib
     ```
  4. 토큰 저장 위치를 **캘린더 MCP 와 분리** — 예: `01-Data-Pipeline/.secrets/youtube_token.json`
     ⚠️ 이 경로를 `.gitignore` 에 넣는다
  5. `reports.query` 를 한 번 호출한다 (최근 7일, `metrics=views`)
  6. 🔴 **`impressions` · `impressionClickThroughRate` 를 metrics 에 넣고 한 번 더 호출** — 오류가 나면 「Studio 전용」이 확인된 것이다. **결과를 문서에 적는다**
- **예상 시간**: 60분
- **검증**: 200 응답과 숫자가 돌아온다. 캘린더 MCP 가 여전히 동작한다
- ⏰ **30분 넘게 막히면 중단하고 실습 3을 CSV 로 진행한다.** 발표가 API 설정에 인질로 잡히면 안 된다

**실습 3: 수집 스크립트와 P5 분석** ⭐⭐⭐
- **목적**: 다시 돌릴 수 있는 자산을 만들고, 그 결과로 P5 를 정의한다
- **단계**:
  1. `scripts/youtube_analytics.py` 작성 — 아래 4개 조합을 함수로
     ```
     ① dimensions=day    metrics=subscribersGained,subscribersLost,views
     ② dimensions=video  metrics=views,estimatedMinutesWatched,averageViewPercentage,subscribersGained
     ③ dimensions=insightTrafficSourceType
     ④ (M2 로 미룸) ②를 공개일 기준 D+1/D+3/D+7/D+14 로 잘라 반복
     ```
  2. 응답 원본을 `data/raw/*.json` 에 그대로 저장 (재현용)
  3. ①을 **주 단위로 집계**한다 (`subscribersGained - subscribersLost` 누적)
  4. Data API 로 영상 메타데이터를 붙인다 — 제목·공개일·길이
  5. 🔴 **`Ingest/YouTube/_status` 의 496편과 대조해 검산**한다. 개수가 크게 어긋나면 쿼리가 틀린 것이다
  6. `analysis/phase5-growth-analysis.md` 작성 — **1편의 표 양식·Shorts 제외 기준을 그대로 따른다**
  7. 🔴 **기억과 기록을 대조한다**

     | 항목 | 기억 | 데이터 |
     |---|---|---|
     | 횡보 시작 구독자 수 | *"4,300명 부근"* | ? |
     | 마이너스 전환 시점 | 미상 | ? |
     | 되살리기 시작 | 원문 *"한달(?)"* vs Task Board *"두 달 전"* | ? |
- **예상 시간**: 120분
- **검증**: 스크립트를 두 번 돌려 같은 결과가 나온다. 위 표의 `?` 가 전부 채워진다

### M2 — 가설 검증

**난이도**: ⭐⭐
**예상 시간**: 3h
**산출물 폴더**: `02-Hypothesis-Testing/`

#### 학습 목표

- [ ] 가설 4개 각각에 대해 **어떤 데이터로 답할 수 있는지** 설계할 수 있다
- [ ] 각 가설에 「맞다 · 아니다 · **알 수 없다**」 중 하나로 판정할 수 있다
- [ ] 판정마다 **근거 수치와 한계**를 함께 적을 수 있다
- [ ] 브레인덤프의 기억과 데이터가 어긋난 지점을 정리할 수 있다

#### 주요 개념

1. **「알 수 없다」도 결론이다** — 데이터가 없거나 표본이 작으면 그렇게 적는다. 이 영상·발표의 신뢰 근거가 그것이다.
2. **교란 변수** — 자막을 단 영상이 마침 좋은 주제였을 수도 있다. 단일 요인으로 단정하지 않는다.
3. **표본 크기** — P5 구간 영상이 몇 편인지 먼저 센다. 5편으로 「경향」을 말하면 안 된다.
4. **하한선 읽기** — 구독자 증가는 시청 페이지 집계뿐이다. 「A가 B보다 낫다」는 말할 수 있어도 「A가 N명을 데려왔다」는 말할 수 없다.

#### 실습 과제

**실습 1: 가설별 데이터 설계** ⭐
- **목적**: 뽑기 전에 **무엇으로 답할지** 정한다. 안 그러면 데이터를 보고 결론을 맞추게 된다
- **단계**:
