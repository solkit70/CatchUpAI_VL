## 🔴 코드를 돌리기 전에 읽는다

여기 적힌 것들은 **전부 오류를 내지 않는다.** 숫자는 나오고, 코드는 돌고, 결과는 그럴듯하다.
그래서 **모르면 그냥 지나간다.** 이 조사에서 실제로 한 번씩 다 걸렸고,
그중 몇 개는 **결론을 정반대로 만들 뻔했다.**

## 1부 — API 가 아예 안 주는 것

### ① 노출·클릭률(CTR)이 없다

```
metrics=impressions
→ 400 Unknown identifier (impressions) given in field parameters.metrics.
```

**썸네일과 제목의 효과를 보려면 이 두 지표가 필요한데 Analytics API 에 없다.**
Studio 화면과 CSV 에는 있다.

> 🔴 **「API 만 있으면 된다」가 성립하지 않는 지점이다.**
> 썸네일 A/B 를 판정하려면 **Studio CSV 를 반드시 병행**해야 한다.

### ② 구독자 「총수」의 시계열이 없다

일별 `subscribersGained` / `subscribersLost` 만 준다. **"그날 몇 명이었나"는 안 준다.**

총수 추이는 **Data API 의 현재값(`statistics.subscriberCount`)에서 거꾸로 빼며 역산**해야 한다.

| | |
|---|---|
| 신뢰할 수 있는 것 | **모양** — 언제 꺾였고 언제 회복됐나 |
| 신뢰하면 안 되는 것 | **절대값** — 스튜디오 표시와 몇 명 어긋난다 (스팸 계정 정리 등) |

**발표에 「그날 4,293명이었다」고 쓰려면 스튜디오 화면으로 한 번 더 확인**해야 한다.

### ③ 영상에 구운 자막은 API 로 확인할 수 없다

`captions.list` 는 **유튜브 자막 트랙**만 본다. **영상 파일에 구워 넣은 자막**은 안 보인다.
이 채널의 자막 작업은 후자라, **볼트의 작업 기록으로만 셀 수 있었다.**

> 이 사실을 모르고 `fetch_captions.py` 를 작성했다가 채널 주인의 지적으로 폐기했다.

## 2부 — 값은 주는데 잘못 읽기 쉬운 것

### ④ 🔴 구독 지표에는 **방향**이 있다

**이 문서에서 가장 중요한 항목이다.**

| | 읽는 법 |
|---|---|
| 구독 **증가**<br>`subscribersGained` | **기여의 하한선으로만.** 그 영상의 **시청 페이지에서 구독을 누른 횟수**뿐이다. 영상을 보고 채널 페이지로 가서 구독하면 **이 영상에 안 잡힌다** |
| 구독 **감소**<br>`subscribersLost` | 🔴 **원인 추적에 쓰지 않는다.** 해지도 **누른 페이지**에 기록된다 |

**감소를 원인으로 쓰면 왜 틀리는가** — Shorts 로 들어온 사람이 몇 달 뒤 롱폼을 보다가
해지하면, 그 기록은 **롱폼에** 남는다. 그래서 **「어느 영상이 사람을 내보냈나」는 알 수 없다.**

> 📌 **이 ④번을 한 번 어겼다가 채널 주인의 지적으로 바로잡았다** (2026-09-10).
> 「Shorts 의 구독 해지가 단 1건」이라는 숫자를 보고 *"Shorts 유입자가 안 나갔다"* 고
> 해석했는데, 성립하지 않는다.
> 채널 주인의 말 — *"그것은 시기를 보면서 정성적으로 판단할 사항인 것 같습니다."*

### ⑤ 비율 지표는 서로를 오염시킨다

**「1천뷰당 구독」과 「유입 경로 비중」이 대표적이다.** 둘 다 분모가 움직인다.

**실측 예 — 작전 2(라이브 요약 → 단일 주제) 전후 유입 경로**

비중(%)으로 보면 이렇게 읽힌다.

```
유튜브 검색   14.2%  →   4.7%    "검색 유입이 반토막 났다!"
구독 피드     37.0%  →  44.7%
```

**편당 절대 조회수로 다시 보면 이야기가 달라진다.**

```
구독 피드     23.2회 →  73.4회   3.17배   ← 이게 커져서
유튜브 검색    8.9회 →   6.8회   0.76배   ← 다른 것들의 «비중»이 줄었다
```

검색은 **반토막이 아니라 0.76배**다. 구독 유입이 3배로 뛰면 **아무 일이 없어도**
나머지 경로의 비중은 저절로 내려간다.

**1천뷰당 구독도 같은 함정이다.** 구독자가 많이 보면 전환율은 떨어진다 —
**구독자는 구독을 또 누를 수 없기 때문이다.** 그건 나빠진 게 아니다.

> 🎯 **비율을 쓸 때는 「분모가 무엇 때문에 움직였나」를 먼저 본다.**
> 한 편을 만들었을 때 몇 명이 새로 오는지가 궁금하면 **편당 절대값**이 맞는 지표다.

### ⑥ 「효과 없음」과 「아직 미숙」은 데이터에서 똑같이 생겼다

개입 뒤 결과 지표가 안 움직이면 「그 방법이 틀렸다」로 읽기 쉽다.
**학습 곡선이 있는 개입은 효과가 늦게 온다.**

실측 — 라이브 요약을 그만두고 단일 주제로 바꾼 뒤 **6주 동안 구독이 안 움직였다.**
그런데 같은 기간 **시청 지속률은 18.6% → 16.0% 로 떨어졌다가 27.2% 로 뛰었다.**
형식을 바꾼 직후엔 **오히려 서툴렀던 것**이다.

> **결과 지표(구독)만 보면 「6주간 무효」, 선행 지표(시청 지속)를 보면 「6주간 학습」이다.**
> ⚠️ 지속률은 **길이에 좌우된다.** 긴 영상은 무조건 낮으므로 **비슷한 길이끼리만** 견준다.

## 3부 — 호출이 조용히 어긋나는 곳

### ⑦ `dimensions=month` 는 날짜가 「그 달 1일」이어야 한다

말일도 거부당한다. 실측:

| endDate | 결과 |
|---|---|
| `2026-09-10` | ❌ does not align |
| `2026-08-31` (말일) | ❌ **여전히 거부** |
| `2026-08-01` | ✅ |

### ⑧ `dimensions=video` 는 한 번에 200행

**초과분은 오류 없이 그냥 잘린다.** 전체를 받으려면
`filters=video==id1,id2,...` 로 **200개씩 끊어** 부른다.

### ⑨ 🔴 API 가 같은 영상을 두 번 준다

`playlistItems.list` 페이징이 **같은 영상을 여러 페이지에 걸쳐** 돌려준다.
실측: **654행 → 고유 532개**, **122행 중복.**

제거하지 않으면 일부 영상이 두 번 세어져 **조회·구독이 조용히 부풀려진다.**
문서에 안 나오고, 오류도 안 나고, 결과는 그럴듯하다.

> 🔴 실제로 **「654편 분석했습니다」라고 보고했다가 나중에 발견해 전부 다시 계산**했다.
> 반드시 `set()` 으로 중복을 제거하고, **몇 행이 빠졌는지 로그로 남긴다.**

### ⑩ CSV 에 섞인 쓰레기 행

Studio CSV 를 API 입력으로 재활용할 때 두 가지가 걸린다.

- 영상 ID 앞뒤 **공백** → `Invalid value ( -PeOMp6ekwo)` 400
- 마지막 줄의 **`Showing top 500 results`** 꼬리표가 데이터 행으로 읽힘

**11자 ID 형식 검사로 거른다.**

## 체크리스트 — 숫자를 발표에 넣기 전에

- [ ] 이 숫자의 **분모**가 무엇이고, 비교 대상과 **같은 분모**인가
- [ ] 구독 **감소**를 원인 추적에 쓰고 있지 않은가
- [ ] 영상별 구독을 **기여의 하한선**이 아니라 정확한 값으로 말하고 있지 않은가
- [ ] 표본에 **중복**이 없는가 · 200행·500편에서 **잘리지 않았는가**
- [ ] 그룹 하나를 **한두 편이 지배**하고 있지 않은가
- [ ] 데이터를 **본 뒤에 나눈 기준**을 「검증했다」고 말하고 있지 않은가
