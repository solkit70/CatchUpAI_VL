# 07 — 기술 영상 재료

**발표(M5)·Substack(M6)과 별개의 산출물이다.**

| | 발표 · 글 | **이 영상** |
|---|---|---|
| 묻는 것 | *"무엇을 했더니 숫자가 어떻게 됐나"* | *"그 숫자를 어떻게 얻었나"* |
| 청중 | Builders Lounge · 창작자 | **직접 해보려는 사람** |
| 중심 | 채널 되살리기 서사 | **API·CSV·판정 방법론** |

> 🎯 **이 문서는 대본이 아니라 재료 창고다.** 모듈을 진행하며 기술적으로 막힌 것·
> 알아낸 것을 **그때그때 여기에 쌓는다.** 영상 제작은 발표가 끝난 뒤 별도로 한다.

## 왜 영상이 되는가

**「내 유튜브 채널을 API 로 분석해 봤다」는 흔한 주제인데, 흔한 영상은 대부분
`reports.query` 한 번 부르고 끝난다.** 실제로 해보면 그 앞뒤에 함정이 훨씬 많다.

이 조사에서 **실제로 막힌 것만 10가지가 넘는다.** 전부 화면과 오류 메시지가 남아 있다.
그게 이 영상의 값어치다 — **성공한 코드가 아니라 막힌 자리들.**

## 🎬 장면 후보

### 1막 — 시작하기 전에 이미 막힌다

**① 「이미 있는 OAuth 클라이언트를 재사용하면 되겠지」가 두 번 틀렸다**

- 1차: 계획서에 적어 둔 경로에 파일이 없었다 (`.config/google-calendar-mcp/` 에는 토큰만)
- 2차: 파일을 찾았는데 그 프로젝트가 **다른 구글 계정 소유**였다
  → 콘솔에서 *"You need additional access"*, 권한 5개가 Missing

> 📸 화면: Google Cloud "You need additional access" + Missing permissions 목록

**교훈**: 자산을 근거로 계획을 세울 때는 **존재뿐 아니라 「내가 그것에 권한이 있는가」**까지 본다.

**② 결과적으로 잘 됐다** — 유튜브 계정 소유 프로젝트에 새로 만들면
**캘린더 MCP 프로젝트를 아예 안 건드리게 된다.** 토큰 충돌 위험이 원천적으로 사라진다.

**③ 콘솔 UI 가 바뀌어 있다** — 예전 「OAuth 동의 화면」 하나가 4개로 쪼개졌다

| 하는 일 | 새 메뉴 (Google Auth Platform) |
|---|---|
| 앱 이름·지원 이메일 | **Branding** |
| User Type · 게시 상태 · 테스트 사용자 | **Audience** |
| 스코프 추가 | **Data Access** |
| 클라이언트 만들기 | **Clients** |

**④ Branding 저장이 안 된다** — Save 가 비활성인데 `Discard changes` 는 활성.
필수 표시(`*`)인 홈페이지·개인정보처리방침 URL 이 비어서다.
→ **채우지 말고 넘어가는 게 맞다.** 검증(verification)을 받을 때 필요한 항목이지
본인이 테스트 사용자로 동의하는 데는 필요 없다.

**⑤ 「확인되지 않은 앱」** — 민감한 스코프라 반드시 뜬다.
`고급` → `<앱 이름>(안전하지 않음)으로 이동`. **정상이다.**

> 📸 화면: "Google hasn't verified this app" + Advanced 링크

### 2막 — 🔴 채널이 5개면 엉뚱한 채널을 분석하게 된다

가장 조용하고 위험한 함정이다.

한 구글 계정에 채널이 다섯 개 있었다 — Wild Forager(기본, 1,010명) · 미생 영어 ·
AI Madang · Joosik Investment · **Catch Up AI(4,320명, 분석 대상)**.

`ids="channel==MINE"` 은 **인증된 신원의 채널**로 풀린다.
동의 과정에서 **채널 선택 화면을 무심코 넘기면 기본 채널의 지표를 받아 온다.**

**숫자가 그럴듯하게 나오기 때문에 발표 직전까지 눈치채기 어렵다.**

그래서 스크립트가 매 실행마다 채널을 확인하고, 다르면 **그 자리에서 멈춘다.**

```
🔴 엉뚱한 채널로 인증됐다.
   받은 채널  : Wild Forager (@wildforager)
   기대한 채널: Catch Up AI (@catchupai)
```

> 🎬 **이 장면 하나로 영상 하나가 된다.** 「데이터 분석에서 가장 무서운 건 틀린 답이 아니라
> 그럴듯한 답이다」

### 3막 — API 가 안 주는 것들 (전부 실측)

**① 노출·클릭률은 Analytics API 에 없다**

```
metrics=impressions
→ 400 Unknown identifier (impressions) given in field parameters.metrics.
```

→ **썸네일·제목 효과를 보려면 Studio CSV 를 반드시 받아야 한다.**
「API 만 있으면 된다」가 성립하지 않는 지점.

**② 구독자 「총수」를 안 준다**

일별 `subscribersGained` / `subscribersLost` 만 준다.
총수 시계열은 **오늘 수치에서 거꾸로 빼며 역산**해야 한다.
→ 모양은 신뢰할 수 있지만 **절대값은 스튜디오 표시와 몇 명 어긋난다** (스팸 정리 등).

**③ `dimensions=month` 는 날짜가 「그 달 1일」이어야 한다**

말일도 거부당한다. 실측:

| endDate | 결과 |
|---|---|
| `2026-09-10` | ❌ does not align |
| `2026-08-31` (말일) | ❌ **여전히 거부** |
| `2026-08-01` | ✅ |

**④ `dimensions=video` 는 한 번에 200행**

→ 전체를 받으려면 `filters=video==id1,id2,...` 로 **200개씩 끊어** 부른다.

### 4막 — 🔴 Studio CSV 는 500편에서 잘린다

파일 **마지막 줄**에 이렇게 적혀 있다.

```
Showing top 500 results
```

이 채널은 628편이라 **100편 넘게 통째로 빠진다.** 그것도 모른 채 「전체 분석」을 하게 된다.

> 📸 화면: CSV 마지막 줄 + 그 줄 때문에 난 API 400 오류
> (`Invalid value (Showing top 500 results)`)

**해법** — 두 API 를 이어 붙인다.

```
① Data API      업로드 재생목록 페이징 → 전체 영상 ID (532편, 중복 제거)
② Analytics API filters=video== 로 200개씩 → 지표
③ Data API      videos.list 50개씩 → 제목·공개일·길이
```

**부산물**: 채널 편수를 말하는 숫자가 넷이나 되는 이유가 풀린다.

| 숫자 | 정체 |
|---|---|
| ~~654~~ | 🔴 **중복 포함 행 수 — 실재하는 숫자가 아니다** |
| **532** | 업로드 재생목록 (중복 제거) — 비공개·미등록 포함 |
| 628 | 채널이 표시하는 **공개** 영상 수 |
| **505** | 그중 기간 내 조회가 있는 것 |
| 496 | 볼트 아카이브 (transcript 확보 기준) |

**⑤ 🔴 API 가 같은 영상을 두 번 준다**

`playlistItems.list` 페이징이 **같은 영상을 여러 페이지에 걸쳐** 돌려준다.
실측: **654행 → 고유 532개**, 122행 중복.

제거하지 않으면 일부 영상이 두 번 세어져 **조회·구독이 조용히 부풀려진다.**
오류가 안 나기 때문에 **그냥 지나간다** — 실제로 「654편 분석했습니다」라고
보고했다가 나중에 발견했다.

> 🎬 **이 함정이 이 영상에서 가장 실용적인 대목일 수 있다.**
> 문서에 안 나오고, 오류도 안 나고, 결과는 그럴듯하다.

**⑥ CSV 에 섞인 쓰레기 행** — 영상 ID 앞뒤 공백, 꼬리표 행.
그대로 API 에 넣으면 `Invalid value ( -PeOMp6ekwo)` 400.

### 4.5막 — 🔴 분류가 틀리면 통계가 통째로 거짓말을 한다

**CSV·API 를 다 뚫고 나서 진짜 함정이 나왔다 — 데이터가 아니라 「무엇을 무엇과 비교하는가」다.**

**① 제목 규칙으로 분류했더니 두 종류가 한 통에 들어갔다**

`AI in Action` 접두어가 붙은 영상이 두 종류였다.

| | 길이 | 정체 |
|---|---:|---|
| 방송 원본 | **174~193분** | 라이브 아카이브 (사람 나옴) |
| 요약본 | **10~16분** | 그 방송을 **Remotion 으로 다시 만든 것** (사람 안 나옴) |

**정반대 성격인데 제목이 같다.** 데이터상 두 무리 사이가 16분 ~ 120분으로 뚝 끊겨 있어
**길이로 가를 수 있었지만, 제목만 봤으면 끝까지 몰랐다.**

**② 더 큰 것 — 「AI 제작」 통에 옛날 카탈로그가 통째로 들어갔다**

`else: return "AI제작"` 이라는 **catch-all 한 줄**이 2024~2025년 화면공유 강의 352편을
전부 「AI 제작」으로 만들었다. 그 강의들은 **채널이 가장 잘 나가던 시기**의 것이다.

```
전체 기간 : AI제작 21.65  vs  사람 나옴 10.64  →  2.04배  ❌ 반대다
되살리기  : AI제작 12.06  vs  사람 나옴 10.33  →  0.86배  ➖ 차이 없다
```

**같은 가설, 같은 데이터, 정반대 결론.** 앞의 2.04배는 콘텐츠 형식이 아니라 **시기**를 재고 있었다.

> 🎬 **이 장면이 「분석 영상」과 「분석하는 척하는 영상」을 가른다.**
> 숫자는 둘 다 진짜다. 코드도 둘 다 돈다. **틀린 건 비교군이다.**

**③ 그래서 이렇게 했다**

| 하지 말 것 | 할 것 |
|---|---|
| 제목 문자열로 분류 | **제작 실물 폴더**로 대조 (`src/` · `_staging/`) |
| catch-all `else` 로 큰 통 만들기 | 안 걸리는 것은 **「미분류」로 두고 눈으로 본다** |
| 전체 기간 한 번에 비교 | **비교 가능한 구간**으로 끊는다 |

**④ 🔴 한 쌍인데 한쪽만 걸린다 — 이중 언어 채널의 함정**

이 채널은 영상을 **한국어·영어 한 쌍**으로 낸다. 그런데 제목 규칙은 **한쪽만 잡는다.**

| | 제목 |
|---|---|
| 🇰🇷 | `AI in Action - AI가 일을 너무 잘해서… \| **Live #17 Recap**` |
| 🇺🇸 | `AI Did My Work So Well, It Gave Me Even More to Do` ← **표시가 없다** |

같은 날 올린 같은 내용인데 **한쪽은 「요약본」, 한쪽은 「단일 주제」로 세어졌다.**
영어판 표기도 제각각이다 — `Recap` · `Summary` · `Highlights` · `Experiments from`.

> 🎬 **다국어 채널을 분석할 때 반드시 나오는 문제인데 아무도 말하지 않는다.**
> 해법은 **짝을 ID 로 손수 묶어 두는 것**뿐이다. 규칙으로는 안 된다.

**⑤ 🔴 「비중」은 착시를 만든다 — 반드시 편당 절대값으로 본다**

유입 경로를 **비중(%)** 으로 보면 이렇게 읽힌다.

```
유튜브 검색   14.2%  →   4.7%    “검색 유입이 반토막 났다!”
구독 피드     37.0%  →  44.7%
```

**편당 절대 조회수로 다시 보면 이야기가 달라진다.**

```
구독 피드     23.2회 →  73.4회   3.17배   ← 이게 커져서
유튜브 검색    8.9회 →   6.8회   0.76배   ← 다른 것들의 «비중»이 줄었다
```

검색은 **반토막이 아니라 0.76배**다. 구독 유입이 3배로 뛰면 **아무 일이 없어도**
나머지 경로의 비중은 저절로 내려간다. **비중은 서로를 오염시킨다.**

> 🎯 **비율 지표 두 개를 나란히 놓고 고르는 장면이 이 영상에서 가장 실용적일 수 있다.**
> 1천뷰당 구독도 같은 함정이다 — **구독자가 많이 보면 전환율은 떨어진다.**
> 구독자는 구독을 또 누를 수 없기 때문이다. 그건 나빠진 게 아니다.

**⑥ 사후에 찾은 축은 결론이 아니라 다음 가설이다**

분류를 고치자 **훨씬 센 축**이 보였다 — 내 콘텐츠 11.32 vs 남의 행사 녹화 3.88, **2.92배.**
기준(2.0배)을 넘지만 **데이터를 본 뒤에 나눴다.** 그래서 「검증됨」이 아니라
**「가설 5, 다음에 검증」**으로 적었다.

> 🎯 **여기서 유혹이 가장 크다.** 2.92배는 발표에서 제일 잘 먹힐 숫자인데,
> **그걸 검증 결과라고 말하면 이 조사 전체가 무너진다.**

### 5막 — 숫자를 어떻게 읽을 것인가 (방법론)

**① 판정 기준을 데이터보다 먼저 정한다**

```python
RATIO_STRONG = 2.0    # 2배 이상 → 맞다
RATIO_WEAK   = 1.3    # 1.3배 미만 → 차이 없다
MIN_N        = 5      # 표본 5편 미만 → 알 수 없다
```

숫자를 보고 기준을 정하면 **검증이 아니라 사후 해석**이 된다.

**② 절대 구독 수가 아니라 「1천뷰당 구독」으로 비교한다**

조회수가 다른 그룹을 절대 수로 견주면 조회가 많은 쪽이 무조건 이긴다.

**③ 🔴 구독 지표에는 방향이 있다**

| | 읽는 법 |
|---|---|
| 구독 **증가** | **기여의 하한선**으로만. 시청 페이지에서 누른 것만 잡힌다 |
| 구독 **감소** | **원인 추적에 쓰지 않는다.** 누른 페이지에 기록되므로, Shorts 로 들어온 사람이 롱폼에서 해지하면 롱폼에 남는다 |

**④ 「알 수 없다」도 결론이다**

### 5.5막 — 🔴 「같은 말」이 두 발표에서 다른 것을 가리켰다

**이 채널은 3개월 전에도 같은 분석을 발표했다.** 2편을 만들면서 같은 채널, 같은 구간을
계산했는데 **딴 숫자가 나왔다.**

| | 1편(창발 발표) | 2편(내가 처음 쓴 것) |
|---|---|---|
| **조회** | 「일반 영상 조회수」 = **Shorts 제외** | 채널 전체 |
| **구독** | **순증** (gained − lost) | gained |

```
P3 월평균 조회   Shorts 제외 4,730   /   포함 9,583   ← 두 배
```

2026-01 한 달에 Shorts 조회 **39,257** 이 몰려 있어서다. 정의 하나가 결론을 바꾼다.

**정의를 맞추자 값이 재현됐다** — P3 순증 **+125**(슬라이드 ~125),
P4 **+18**(슬라이드 ~18). **이 재현이 2편 전체의 신뢰 근거가 됐다.**

> 🎬 **속편을 만드는 사람 모두가 겪는 문제인데 아무도 안 말한다.**
> **1편의 열 이름을 다시 읽는 것이 2편의 첫 작업이다.**

### 5.7막 — 🔴 평균은 전환점을 지운다

개입(라이브 요약 → 단일 주제)의 효과를 평균으로 냈더니 **편당 구독 1.29배**였다.
「효과가 있었다」고 쓸 뻔했다. 주 단위로 풀어 보니 전혀 다른 그림이었다.

```
7/13 +2  7/20 +0  7/27 +1  8/03 −6  8/10 +1  8/17 +2   ← 개입 후 6주: 사실상 0
8/24 +16  8/31 +12                                      ← 여기서 꺾였다
```

**개입 그 자체는 6주 동안 아무 일도 일으키지 않았다.** 1.29배는 **뒤의 3주가 만든 값을
앞의 6주에 펴 바른 것**이다. 실제 원인은 8월 하순에 올린 콘텐츠의 **주제**였다.

> 🎯 **A/B 를 평균으로만 보면 「무엇이 언제 통했나」를 통째로 놓친다.**
> 개입 분석에는 **반드시 시계열을 함께 그린다.**

### 5.8막 — 🔴 「효과 없음」과 「아직 미숙」은 데이터에서 똑같이 생겼다

개입(라이브 요약 → 단일 주제) 뒤 **6주 동안 구독이 안 움직였다.**
나는 *"형식은 상관없었고 주제가 다였다"* 로 결론 낼 뻔했다. **채널 주인이 짚었다** —

> *"퀄리티를 올려야겠다고 생각했다고 해서 곧바로 올라가는 게 아니니까 (…)
> 꾸준히 노력한 결과가 **텀을 두고 나타난** 것 같습니다."*

**아직 안 쓴 지표가 데이터에 있었다** — `averageViewDuration` · `averageViewPercentage`.

```
                       평균 시청   지속률
요약 시대                107초    18.6%
전환 «직후» 6주           92초    16.0%   ← 오히려 떨어졌다
그 뒤 4주               136초    27.2%   ← 여기서 뛴다
```

**결과 지표(구독)만 보면 「6주간 무효」다. 선행 지표(시청 지속)를 보면 「6주간 학습」이다.**

⚠️ **길이 교란을 반드시 뺀다.** 긴 영상은 무조건 지속률이 낮으므로
**15분 이하끼리만** 견줬다. 안 그러면 65분짜리 한 편이 구간 평균을 무너뜨린다.

> 🎬 **A/B 를 하는 사람 전부에게 해당한다.**
> **학습 곡선이 있는 개입은 효과가 늦게 온다.** 결과 지표가 안 움직일 때
> 「방법이 틀렸다」와 「아직 서툴다」를 가르려면 **선행 지표가 필요하다.**

### 6막 — 데이터가 사람을 구한 순간

**① 숫자 하나가 이야기를 네 배로 부풀릴 뻔했다**

기록에 *"지난주 4,203까지 하락"* 이라고 적혀 있었다. 역산 최저는 4,264라 재현되지 않았다.
확인해 보니 **`4,293` 의 오기**였다.

> *"4,203 → 4,320"* 이면 **117명 회복**으로 들린다.
> 실제는 **4,293 → 4,320, 27명**이다.

**② 교란 요인을 못 봤으면 정반대 결론이 나올 뻔했다**

자막 작업 20편 중 13편이 **멤버 전용**이었다 — 멤버가 적어 조회가 사실상 0.
그대로 「자막 있음 vs 없음」을 돌렸다면 **"자막은 효과 없다"** 가 나왔을 것이다.

**③ 「자막」이 유튜브 자막 트랙인 줄 알았다**

`captions.list` 로 확인하려다 멈췄다 — **영상에 구워 넣은 자막**이라 API 에 안 보인다.
볼트의 작업 기록으로만 셀 수 있다.

> 🎯 **이 세 가지가 이 영상의 결론이다.**
> 셋 다 **AI 가 혼자 돌렸으면 그대로 지나갔을** 지점이고,
> 셋 다 **채널 주인이 「그거 아닌데요」 한마디로** 잡혔다.
