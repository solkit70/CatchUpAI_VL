## 📚 학습 개요

### 왜 v2인가 — v1 진단

v1은 M1~M4를 모두 완료하고 기사 초안까지 냈지만, 초안이 기고 가능한 수준에 미치지 못했다. 원인은 명확하다.

| 항목 | v1 실측 |
|---|---:|
| 보유 현장 트랜스크립트 | **30개 / 8,703줄** |
| 기사 초안이 인용한 현장 화자 | **0명** |
| 기사 초안의 현장 영상 링크 | **0건** |
| 기사 초안 참고 출처 20개 | **전부 외부 2차 자료** |

**구조적 원인은 v1 로드맵 자체에 있었다.** v1 M1의 실습 3은 "Catch Up AI 영상/Transcript 묶음 정리"였지만, 그 단계는 ①업로드 정보 문서 읽기 ②`_index.md` 확인 ③행사별 태깅이었고, 검증 기준도 "행사명, 영상 수"였다. 즉 로드맵이 요구한 것은 **메타데이터 정리**였지 트랜스크립트 정독이 아니었다. v1 로드맵 전체에 "트랜스크립트를 읽는다"는 과제가 한 번도 없다. 그래서 M2 비교표는 "이 행사는 X를 보여준다" 수준의 추상 명제에 머물렀고, 그 위에 쌓은 기사도 추상적일 수밖에 없었다.

악순환도 있었다. 사용자가 "초안을 더 충실하게"를 요청했을 때 v1은 **외부 기사를 더 읽는 쪽**(Madrona·GeekWire 2023~2025 회고)을 택했다. 살이 없는 원인을 2차 자료로 메우려 한 것이다.

### v2의 전제

**이 기사의 유일한 차별점은 사용자가 그 자리에 있었다는 사실이다.** 따라서 1차 자료 정독이 출발점이고, 외부 자료는 전면이 아니라 배경이다.

대비 사례 하나로 충분하다. v1이 Startup425를 다룬 문장 전부는 이것이다.

> "Startup425와 AI Demo Day는 AI가 창업자 진입 장벽을 어떻게 낮추는지를 보여준다."

같은 행사에 대해 이미 보유한 1차 자료는 이것이다.

> **Quiana Daniels** (C-Stork) — 유도분만으로 병상에 누운 채 고객 보험을 확인하다 담당 산부인과 의사에게 걸렸고, 그 순간이 창업 계기가 됐다. 비개발자로 ChatGPT·Claude·Gemini·Xano·WeWeb을 써서 직접 만들었다. 72시간 걸리던 보험 확인이 **60초**로 줄었다. 스케줄링 문제로 돌려보내던 고객 **30%**를 회수했다. **$750,000 견적을 8주 $275,000**으로 구축했다.

## 📖 모듈별 상세 계획

### M5 - 1차 자료 채굴 (Evidence Bank)

**난이도**: ⭐⭐⭐
**예상 시간**: 5~6h
**산출물 폴더**: `05-Evidence-Bank/`

> **이 모듈이 v2의 전부다.** v1이 실패한 지점이 정확히 여기고, 여기만 제대로 하면 M6~M8은 따라온다.

#### 학습 목표

- [ ] 트랜스크립트 30개를 전량 정독하고 채굴 여부를 추적표로 관리할 수 있다
- [ ] 인용 후보를 원문·번역·화자·소속·타임스탬프·영상링크 6요소를 갖춰 기록할 수 있다
- [ ] 기사에 쓸 수 있는 구체 수치를 맥락과 함께 분리해 낼 수 있다
- [ ] 여러 행사에 걸쳐 반복되는 주제를 현장 증거만으로 도출할 수 있다

#### 주요 개념

1. **Evidence Bank**: 기사 집필 전에 인용·수치·장면을 미리 채굴해 쌓아 두는 저장소다. 집필 중에 자료를 찾으면 이미 쓴 문장에 자료를 끼워 맞추게 되므로, 반드시 집필 **전에** 만든다.
2. **인용 6요소**: 원문(영어) / 한국어 번역 / 화자명 / 소속 / 타임스탬프 / 영상 링크. 하나라도 빠지면 기고 시 검증 불가다.
3. **장면(scene) vs 명제(claim)**: "AI가 진입장벽을 낮춘다"는 명제고, "병상에서 보험 확인하다 의사에게 걸렸다"는 장면이다. **기사를 살리는 것은 장면이다.**
4. **오해 포인트**: 트랜스크립트를 "요약"하면 안 된다. 요약은 명제를 만들고, 명제는 v1의 실패를 재생산한다. 채굴은 **원문 보존**이 원칙이다.
5. **반론 자료**: 행사 발표는 본질적으로 홍보성이다. 발표자가 스스로 밝힌 한계·실패·미해결 문제를 별도로 채굴해야 기사가 균형을 갖는다.

- **목적**: 30개에 적용할 포맷을 먼저 고정한다. 포맷 없이 시작하면 뒤에서 재작업이 생긴다.

  1. `vl_materials/evidence-index.md`에 30개 추적표를 만든다 (파일명 / 행사 / 화자 / 줄수 / 채굴상태).
  2. 가장 강한 자료 2건을 파일럿으로 채굴한다 — `C-Stork | Quiana Daniels` (113줄), `A Founder's Field Guide | Amit Gupta` (203줄).
  3. 인용 6요소가 모두 채워지는지 확인하고 포맷을 확정한다.
- **예상 시간**: 45분
- **검증 방법**: 파일럿 2건에서 인용 후보 각 3개 이상, 6요소 누락 0건.

### M6 - 연재 구조 설계

#### 학습 목표

- [ ] Evidence Bank의 실제 강도를 근거로 연재 편수(2편 또는 3편)를 확정할 수 있다
- [ ] 각 편의 역할·독자 효용·중심 주장을 한 문장으로 규정할 수 있다
- [ ] 각 편의 리드를 현장 장면으로 열도록 설계할 수 있다
- [ ] 외부 2차 자료를 배경 위치에 배치한 증거 배치도를 만들 수 있다

#### 주요 개념

1. **연재 편수는 자료가 정한다**: 편수를 먼저 정하고 자료를 나누면 약한 편이 생긴다. 강한 증거 묶음이 몇 개인지 세어 편수를 정한다.
2. **장면 리드(scene lead)**: 기사 첫 문단을 통계나 총론이 아니라 한 사람의 구체적 장면으로 여는 방식. 한인 매체 독자에게 특히 유효하다.
3. **증거 배치도**: 어느 단락에 어느 인용·수치가 들어가는지 미리 배정한 표. 집필 중 자료 탐색을 없애 준다.
4. **배경 강등**: 외부 통계는 현장 증거 **뒤에** 놓아 "이게 우리 동네만의 일이 아니다"를 확인시키는 역할만 맡긴다.
5. **오해 포인트**: 한인 매체라고 해서 "한인 등장인물"이 반드시 필요한 것은 아니다. 다만 7/27 Bellevue City Hall에서 42 Seoul 학생들과 만난 기록은 실재하는 한인 접점이므로 활용 가치를 검토한다.

#### 실습 과제

**실습 1: 증거 강도 평가 및 편수 확정** ⭐⭐
- **목적**: 자료 실측에 근거해 2편/3편을 결정한다.
- **단계**:
  1. M5 교차 주제 3~5개 각각에 대해 인용 수·수치 수·장면 수를 집계한다.
  2. "단독 1편을 지탱할 수 있는가"를 기준으로 강/중/약 판정한다.
  3. 강(强) 묶음 개수로 편수를 확정하고 근거를 문서에 남긴다.
- **예상 시간**: 45분
- **검증 방법**: 편수 결정 근거가 집계 수치로 제시된다.

**실습 2: 편별 설계서 작성** ⭐⭐
- **목적**: 집필 전에 각 편의 뼈대를 확정한다.
- **단계**:
  1. 편마다 제목 후보 3개, 중심 주장 1문장, 독자 효용 1문장을 쓴다.
  2. 리드로 쓸 현장 장면을 지정한다 (화자·상황 명시).
  3. 단락별 증거 배치도를 만든다 — 단락 / 주장 / 투입 인용·수치 / 출처.
  4. 외부 2차 자료가 배경 위치에만 있는지 확인한다.
- **예상 시간**: 90분
- **검증 방법**: 각 편 설계서에 리드 장면이 지정되고, 배치도의 모든 칸에 M5 출처가 붙는다.

**난이도**: ⭐⭐⭐

#### 주요 개념

1. **인용 번역 원칙**: 의역하되 뜻을 바꾸지 않는다. 수치·고유명사는 원문 그대로. 원문 병기는 핵심 인용에만.

3. **한계의 배치**: 한계를 마지막에 몰면 변명처럼 읽힌다. 해당 주장 바로 뒤에 붙인다.
4. **오해 포인트**: 초안을 "길게 쓰고 나중에 줄인다"는 유혹이 있으나, 배치도가 있으면 처음부터 규격에 맞춰 쓰는 편이 빠르다.

#### 실습 과제

**실습 1: 1편 집필** ⭐⭐

  3. 각 인용에 화자·소속을 본문 내에서 자연스럽게 밝힌다.
  4. 한계·반론을 해당 주장 뒤에 배치한다.
- **예상 시간**: 100분
- **검증 방법**: 배치도의 모든 증거가 본문에 반영되고, 근거 없는 단락이 0개.

  2. 편 간 중복 서술을 제거하고 상호 참조를 넣는다.

### M8 - 팩트체크 · 기고 패키지 (Capstone)

#### 학습 목표

#### 주요 개념

1. **1:1 대조**: 기사 문장 → 트랜스크립트 원문 줄까지 되짚는 검증. 기억이나 요약본에 의존하지 않는다.
2. **고유명사 리스크**: 화자 이름과 소속은 틀리면 정정보도 사안이 된다. frontmatter의 `speaker`, `speaker_affiliation`을 기준으로 삼는다.
3. **기고 패키지**: 원고만 보내지 않는다. 필자 소개, 사진·영상 링크, 인용 출처 목록을 함께 준비한다.
4. **오해 포인트**: 영상이 공개돼 있으므로 인용 허가 문제는 없다. 다만 **정확성 책임은 그대로 남는다.**

#### 실습 과제

**실습 1: 인용·수치 1:1 대조** ⭐⭐
- **목적**: 기고 후 정정 사태를 막는다.
- **단계**:
  1. 기사에 쓰인 인용을 전부 목록화한다.
  2. 각 인용을 원본 트랜스크립트에서 찾아 원문과 대조한다.
  3. 수치는 발표자 발언과 영상 설명(description) 양쪽으로 교차 확인한다.
  4. 화자명·소속을 frontmatter 기준으로 확인한다.
- **예상 시간**: 60분
- **검증 방법**: 대조표에 전 항목 ✅. 불일치 0건 또는 수정 완료.

**실습 2: 기고 패키지 구성** ⭐⭐

  2. 인용 출처 목록(영상 링크·타임스탬프)을 별첨으로 만든다.

- **예상 시간**: 40분

## 🔄 방향 전환 — 신문 기고에서 Substack으로 (2026-08-28)

> **결정**: 기사 기고는 **시기상 늦었다.** 지금까지 쓴 5편을 **Substack 게시용으로 개정**한다.

### 무엇이 바뀌나

| 항목 | 기존 (신문 기고) | **변경 (Substack)** |
|---|---|---|
| 매체 | 한인 매체 지면 | **Substack** |
| 분량 제약 | 편당 원고지 12~15매 (약 2,400~3,000자) | **제약 없음** — 현재 6,700~9,100자를 줄일 필요가 없다 |
| 영상 링크 | 별첨 목록 (`link-map.md`의 신문판) | **본문에 직접 삽입** |
| 초점 | 행사 리포트 + 참가 실용 정보 | **시애틀 지역 AI 트렌드**를 더 잘 드러내는 쪽 |
| 기고 패키지 | 필자 소개·출처 별첨 필요 | **불필요** — M8 실습 2 폐기 |

### 이 전환이 해소하는 문제

**분량 불일치가 문제가 아니게 됐다.** `07-Articles/README.md`의 표기(편당 약 2,700~3,000자)와 실제 본문(6,700~9,100자)이 2~3배 어긋나 M8에서 확정하기로 했던 항목인데, 지면 제약이 사라지면서 **줄일 이유가 없어졌다.** README 표기만 실측값으로 고치면 된다.

**영상 링크를 본문에 넣을 수 있게 됐다.** `link-map.md`가 신문판/Substack판을 나눠 관리하고 있었는데, 이제 Substack판만 쓴다. v2 성공 기준의 *"기사 내 현장 영상 링크 10건 이상"* 을 본문에서 직접 달성할 수 있다.

### 남은 작업

**사용자 리뷰 후 수정.** 완성된 5편을 읽고 위 방향 — Substack 형식, 영상 링크 본문 삽입, 시애틀 AI 트렌드 강화 — 으로 직접 손본다. 이 단계는 AI가 대신할 수 없고, 수정 요청이 나오면 그때 반영한다.

게재 전 필수 확인 사항 하나가 남아 있다.
