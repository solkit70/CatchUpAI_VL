### 1. `slides.md` 초안 작성

**목적**:
M2에서 만든 6장 구조를 실제 발표에 사용할 Markdown 슬라이드로 전환했다.

**과정**:
1. `03-Slides/slides.md` 파일을 만들었다.
2. 각 슬라이드를 `<!-- slide -->` 구분자로 나눴다.
3. 화면 문장은 짧은 문장 위주로 제한했다.

**결과**:
- 6장 발표 슬라이드와 제목 슬라이드가 포함된 `slides.md`를 작성했다.

**메모/인사이트**:
화면에는 메시지 중심 문장만 남기고, 사례와 가격 설명은 발표자 노트로 분리하는 것이 5분 발표에 적합하다.

### 2. 발표자 노트 추가

**목적**:
실제 발표에서 말할 근거와 설명을 슬라이드 아래에 정리했다.

**과정**:
1. 각 슬라이드에 `발표자 노트:` 섹션을 추가했다.
2. 본인 작업, 유타주 이선생님 프로젝트, Federal Way 한인회 행사 지원 사례를 검증 흐름에 배치했다.
3. 무료 기본 가이드, 멤버십, 유료 추가 가이드, 녹화 할인 설명을 슬라이드 5 노트로 압축했다.

**결과**:
- 화면용 텍스트와 발표자 노트가 분리된 발표자료가 완성됐다.

**메모/인사이트**:
슬라이드 5는 가장 정보량이 많으므로, M4에서 실제 70초 안에 말할 수 있도록 더 축약해야 한다.

### 3. CTA 슬라이드 정리

**목적**:
발표 후 청중이 할 수 있는 행동을 분명히 했다.

**과정**:
1. 직접 가입 요청보다 주변 소개 요청을 메인 CTA로 잡았다.
2. 대상자는 시니어, 시민단체 실무자, 앱/사업 아이디어가 있지만 첫 시작이 막힌 사람으로 정리했다.
3. YouTube 멤버십과 신청 Form은 M4에서 필요 시 보조 CTA로 넣기로 남겼다.

**결과**:
- 마지막 슬라이드는 “주변에 필요한 분을 소개해 주세요”로 확정했다.

**메모/인사이트**:
Builders Lounge 청중에게는 판매보다 소개 요청이 더 자연스럽다.

### 4. HTML 발표용 슬라이드 추가

**목적**:
Obsidian Markdown 문서 화면 대신 브라우저에서 바로 발표할 수 있는 시각 디자인 적용 슬라이드를 만들었다.

**과정**:
1. `03-Slides/slides.html` 파일을 생성했다.
2. 배경 패턴, 네트워크 다이어그램, 타임라인, 문제 카드, 작업 흐름 인포그래픽, 가격 표, CTA 대상 블록을 추가했다.
3. 키보드 방향키, PageUp/PageDown, Home/End, 클릭으로 슬라이드를 넘길 수 있게 했다.

**결과**:
- 브라우저에서 바로 열 수 있는 발표용 HTML 슬라이드가 추가됐다.

**메모/인사이트**:
발표자 노트는 Markdown 원본과 스크립트에 남기고, HTML 발표 화면에는 청중에게 보여줄 핵심 문장과 시각 구조만 남기는 것이 좋다.

## 🐛 문제 해결 로그

### 문제 1: 가격 숫자와 멤버십 레벨의 균형

**증상**:
가격과 멤버십 정보를 모두 화면에 넣으면 발표자료가 판매 페이지처럼 보일 수 있다.

**원인**:
무료 기본 가이드, 일반 유료, 녹화 할인, 멤버십 무료 가이드 혜택이 한 슬라이드에 모이기 때문이다.

**해결**:
화면에는 “무료 기본 가이드”와 “멤버십 또는 유료 옵션”만 남기고, 숫자는 발표자 노트에 넣었다.
