# Module Retrospective — M3 Muse 설치 · 첫 사용

**완료일**: 2026-10-11
**실습 범위**: Muse 단독 — Dots 접근 조건상 조사·비교만

## 계획 대비 실제

Muse 웹 첫 화면, 개인정보·권한 설정 구조, 읽기 중심 첫 과제와 공개 자료 조사를 확인했다. 일정 요약 과제는 첫 응답에서 전체 하루와 현재 이후 구간을 혼동했으나, 기준 시각과 지난 구간을 명시해 재질문하자 남은 시간을 다시 계산했다. 개인 일정의 값, 계정별 설정 상태, 화면 캡처는 공개 기록에 포함하지 않았다.

예상 학습 시간은 2시간이었지만 실제 시작·종료 시각을 기록하지 않아 소요 시간 비교는 할 수 없다. M3 산출물은 [모듈 README](../03-Hands-On/README.md), [Muse 설정 안내](../03-Hands-On/guides/setup-muse.md), [첫 과제 결과](../03-Hands-On/guides/first-task-results.md)다.

## 학습 목표 달성도

- [x] Muse 첫 화면에 도달했다.
- [x] 공개 결과에 재사용 가능한 웹 첫 사용·권한 확인 안내를 작성했다.
- [x] 읽기 중심 과제를 실행하고 답변의 오류 수정 과정을 기록했다.
- [x] 주장별 공식 URL을 확인하고 Meta 발표문·구독 도움말을 M1·M2 자료에 반영했다.
- [x] 새 유료 플랜 가입 없이 무료 범위에서 실습했다.
- [x] 상대 링크 검사에서 깨진 링크 0개, 빈 폴더 0개를 확인했다.

## 핵심 인사이트

1. 첫 응답의 유창함보다 시간대·범위·계산을 검산하고 오류를 특정해 재질문했을 때의 수정 여부가 더 유용한 신뢰성 지표였다.
2. 출처 패널에 링크가 있다는 사실은 공식성을 보장하지 않는다. 초기에는 제3자 자료가 보였고, 공식 URL을 요구한 뒤 Meta 발표문과 도움말을 받았다.
3. 승인 기본 설정은 모든 쓰기 작업에 적용되는 일괄 보증이 아니다. 커넥터별 작업 권한과 각 행동에 표시된 Ask/Allow를 확인해야 한다.
4. 제품의 일반 안내와 계정별 실제 설정은 구분해야 한다. 공개 문서에는 개인 계정 상태나 실제 일정·메일 내용을 옮기지 않는다.

## 방법론 평가 및 다음 모듈 준비

실습 계획은 공개 정보만 쓰는 방식에서 사용자가 선택한 연결 앱 권한 확인까지 확장되었다. 다음에는 범위가 바뀔 때 공개 기록에 남길 수 있는 정보와 제외할 정보를 먼저 정하고, M4에서는 로드맵대로 가상 데이터로 두 가지 과제를 비교한다. Dots는 직접 접근할 수 없으므로 같은 실행 비교 대상에 포함하지 않는다.

## DoD 및 링크 확인

M3의 범위 갱신 후 DoD를 완료했다. `check_links.py` 결과는 상대 링크 28개 정상, 깨진 링크 0개, 템플릿 예시 10개 제외, 빈 폴더 0개다.
