## 📚 진행 내용

### 1. Muse 웹 첫 화면 및 일정 요약 과제

**목적**: Muse의 첫 사용 경험과 연결 앱을 활용한 읽기 전용 작업을 확인한다.

**과정**:
1. 사용자가 Muse 웹에 직접 접속해 첫 화면에 도달했다.
2. 사용자가 연결 앱을 활용하는 실습을 선택해, 기존 공개 정보만 사용하는 계획에서 범위가 확장되었다. 구체적인 앱과 계정 상태는 공개 기록에서 생략한다.
3. 개인 일정의 제목·참석자·설명·링크를 제외하고, 일정 개수·시간 합계·빈 시간대만 요약하도록 요청했다.
4. 첫 답변의 시간 구간 해석에 오류가 있어 재질문했다. Muse는 하루 전체와 현재 이후의 시간을 다시 나눠 계산했고, 요청한 시애틀·한국 시간 병기 형식을 따랐다.

**결과**:
- 읽기 전용 요약에서 개인 일정의 세부 제목을 출력하지 않았다.
- 첫 계산은 현재 시각을 제대로 반영하지 못했다. 재질문 후 산술 검산과 남은 시간 구분이 개선되었다.
- 실제 일정 값은 공개 폴더에 기록하지 않는다.

### 2. Data controls 및 작업별 권한 화면 확인

**목적**: 개인정보 사용 제어와 연결 앱 권한이 어떻게 나뉘는지 확인한다.

**결과**:
- Data controls 화면에서 모델 개선 사용, 데이터 가져오기·다운로드, 초기화 항목을 확인했다. 계정별 설정 상태는 공개 기록에서 생략한다.
- Permissions 화면은 커넥터 및 웹 접근의 기본 승인 방식을 구분한다.
- Gmail·Calendar 권한은 읽기, 쓰기, 삭제, 외부 알림 등 작업별로 Allow/Ask를 설정할 수 있었다. 사용자의 계정별 설정값·예약 작업 이름·실행 시각은 기록하지 않는다.
- 따라서 “중요 작업은 항상 묻는다”고 일반화하지 않고, 실제 승인 동작은 작업별 권한과 설정에 따라 달라질 수 있다고 기록한다.
- 오늘 이 권한 화면을 검토하면서 메일 전송이나 일정 변경·삭제를 실행하지 않았다.

### 3. Muse의 공식 자료 조사 및 출처 확인

**목적**: 출처 패널과 후속 출처 요청이 공식성 및 사실 확인에 어떤 차이를 만드는지 살펴본다.

**결과**:
- 처음 답변의 Sources 패널에는 제3자 매체와 기타 비공식 출처가 보였다. 공식 출처만으로 답했다는 주장과 실제 출처 패널이 일치하지 않았다.
- 후속으로 주장별 공식 URL을 요청하자 Meta 발표문과 구독 도움말을 출처로 제시했다.
- Meta 발표문은 Muse Secure VM·Sentinel, 앱을 닫은 뒤 이어지는 작업, 기억 기반 제안, 무료 사용을 지원한다.
- Meta 구독 도움말은 무료 사용량 한도와 대기/업그레이드 선택, Power 월 $20·주 500M 토큰, Maximum 월 $100·주 3B 토큰, 월 자동 갱신을 명시한다.
- 무료 티어의 정확한 주간 토큰 수는 확인되지 않았다.

> “Muse is available for free with a usage limit.”

## 🐛 문제 해결 로그

### 출처 패널과 본문 출처 표시의 차이

**증상**: 초기 답변 본문에는 URL이 없고 Sources 패널에는 주로 제3자 출처가 보였다.

**해결**: 주장별 공식 URL과 페이지 제목을 직접 요청했다. Meta 발표문과 구독 도움말을 확인해 기능·요금 주장을 공식 근거에 맞춰 구분했다.

**학습**: 인라인 링크가 없더라도 출처 패널을 확인해야 한다. 다만 출처 패널의 존재만으로 출처의 공식성이 보장되지는 않는다.

## 💡 Daily Retrospective

### What went well (잘된 점)
- 계정 데이터가 아닌 계산 결과만 요청해 연결 앱 과제를 제한된 범위에서 시험했다.
- 잘못된 일정 계산을 지적하고 재질문해 오류가 수정되는 과정을 관찰했다.
- 출처 패널과 주장별 공식 URL 요청을 구분해 자료의 출처 수준을 검증했다.

### What could be improved (개선할 점)
- 첫 사용 실습 범위를 공개 정보 조사에서 실제 커넥터 연결로 바꾸기 전에, 공개 기록에 남길 수 있는 개인정보 범위를 먼저 분명히 해야 한다.
- 연결 전 작업별 읽기·쓰기·삭제 권한을 검토하고 필요한 권한만 허용하도록 안내해야 한다.

### Insights (인사이트)
- 에이전트의 정확성은 최초 답변만으로 판단하기 어렵다. 오류를 특정해 재질문했을 때 수정되는지도 확인해야 한다.
- Sources 패널은 유용하지만, 제3자 출처가 공식 자료처럼 제시될 수 있으므로 각 주장과 원문을 대조해야 한다.
- 권한 기본값은 모든 쓰기 작업의 승인 여부를 의미하지 않는다. 작업별 설정을 직접 확인해야 한다.
