# Module Retrospective — M4 내 일 하나 맡겨 보기

**완료일**: 2026-10-11
**실습 범위**: Muse 단독; 허구의 자료만 사용

## 계획 대비 실제

두 개의 과제를 설계해 Muse에서 실행하고 결과를 같은 사전 기준으로 판정했다. 일정 검토는 숫자와 충돌을 정확히 찾아 바로 쓸 만한 결과였다. 설명문 초안은 요구 형식에 맞았지만, 근거 없는 수사 표현이 첫 답변과 수정본 모두에서 남아 사람이 정리해야 했다.

계획했던 실행 시간·사람 검토 시간의 타이머 측정은 하지 못했다. 수작업 기준 시간도 측정하지 않아 절약 시간 비교는 하지 않았다. 미측정 값을 임의로 채우지 않은 점을 결과 문서에 명시했다. Dots는 이미 합의한 접근 조건에 따라 실습 범위에서 제외했다.

## 핵심 인사이트

1. 계산·검출 작업은 기대 정답을 먼저 만들면 오류 위치와 품질을 객관적으로 비교하기 쉽다.
2. 생성 결과는 형식 요구를 맞춰도 내용에 근거 없는 해석·홍보 문구를 섞을 수 있다. 형식 점수와 근거 점수를 분리해야 한다.
3. 구체적인 수정 요청은 일부 개선을 이끌었지만, 결과를 곧바로 게시하거나 복사해 쓰기 전에 최종 사람이 검토해야 한다.
4. 시간 절약을 주장하려면 에이전트 응답, 사람 검토·수정, 기준 수작업 시간을 같은 단위로 측정해야 한다.
5. 가상 입력과 외부 앱 미사용만으로 저장된 기억까지 배제된다고 단정할 수 없으므로, 엄격한 격리가 필요할 때 서비스의 기억 표시나 테스트 환경도 점검한다.
