# 에이전트 선택 예시

| 일의 예 | 권장 접근 | 근거와 제한 |
|---|---|---|
| 공개 자료를 조사해 사실 요약 | 검색·출처 기능이 있는 에이전트에 조사 초안을 맡기고, 공식 원문을 사람이 확인 | Muse의 첫 Sources 패널은 제3자 자료 위주였고, 공식 URL을 별도로 요구한 뒤 공식 자료를 확인했다. 출처 표시만으로 검증을 끝내지 않는다. |
| 가상 시간표의 충돌·합계 계산 | 에이전트에 분석을 맡기고, 정답을 별도로 계산해 대조 | Muse는 M4 가상 시간표에서 겹침과 합계를 정확히 찾았다. 실제 일정으로 같은 품질을 보장한다는 뜻은 아니다. |
| 메모를 정해진 형식의 게시 초안으로 변환 | 초안 생성에 활용하고, 사실 근거와 수사 표현을 사람이 편집 | Muse는 형식은 맞췄지만 근거 밖 표현을 남겨 최종 검토가 필요했다. 게시 자체는 하지 않았다. |
| 연결된 메일·일정에서 실제 행동 | 필요한 권한을 작업별로 확인하고, 가능하면 읽기·초안부터 시작; 외부 변경 전 사람이 검토 | Muse의 권한은 작업별로 다를 수 있다. 이번 M4는 커넥터 동작 성능을 시험하지 않았다. |
| 로컬 코드·파일 조작 | 이미 쓰는 코딩 도구와 작업 범위를 비교한 뒤 선택 | 이 Topic에서는 Codex·Claude Code를 동일 과제로 비교하지 않았으므로 성능 판정을 내리지 않는다. |
| 사용 조건을 충족하지 못한 서비스 | 공식 자료로 기능·접근만 기록하고 실제 적합성 판정은 보류 | Dots·Grok Bot·Instinct는 이번 실습 대상이 아니었다. |

## 예시 사용법

각 행을 그대로 보편 규칙으로 받아들이기보다 자료 민감도, 작업 영향, 현재 접근, 검증 방법을 해당 과제에 맞게 다시 확인한다. 특히 한두 번의 성공 사례는 서비스 전체의 정확도나 안전성을 보증하지 않는다.
